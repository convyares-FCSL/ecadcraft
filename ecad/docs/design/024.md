# Design 024: Outputs: locations, the PDF book, generated pages and reports

Brief: `docs/briefs/024-outputs.md` (Draft). Follows `008.md` §2 (click-first, one commit = one
JSON-equivalent transaction, Esc writes nothing, feedback in words, never crash), the frame,
title block, Properties panel and revisions of `019.md`, the devices of `018.md` and the nets and
Checks of `022.md`. Tokens: `tokens.md` (this spec adds §12). Format and ops: §2 (FP1–FP4
**approved by the overseer**, 2026-11-11). Owner questions: §14. *Revised 2026-11-11 (owner): a
location box is a rectangle or any closed polyline, and containment sets the location, live.*

## 0. What the code has today (checked)

- Component property `location` (`devices::PROPERTIES`), stored with a leading `+`; `setprop`
  takes `components: [id]` for several devices in one transaction (`props::edit_line`). The
  Properties panel's device rows show the stored value only; nothing inherits it.
- Page and project `location` / `function` (`book::LOCATION_KEY`), used by the title block
  (`frame::FrameInput`, page else project) and `pageprops` (`location_shown`).
- New devices get `LinkRepresentation { role: "main" }`; joined symbols get their symbol key as
  role (018 §10). Junctions and continuations are tagless components with property `kind` (022 FP4).
- Cables: properties `tag`, `designation`, `type` (drawn in the label box, `look.rs`); cores are
  `CableMember.conductor`.
- `project_page_with` projects one page into a CADCraft `Drawing` with frame, labels and cable
  views. The engine's `plot` (`layout.rs`) calls the installed plot hook (`io/src/pdf.rs::plot`),
  which with `pages: [{window, paper, landscape}]` and `margins: [0,0,0,0]` plots one model-space
  window per sheet into **one** PDF (`pdfbook` does exactly this); `MAX_PAGES` = 256; `paper` is a
  named size from `PAPER_SIZES`.
- The Project panel has Pages, Devices, Checks and History tabs (016, 022, 020).

## 1. Goal

One command prints the whole book as a PDF, generated pages included, and one window shows the
BOM, wire and cable reports and saves them as CSV; devices carry a location that the drawing, the
BOM and the reports agree on.

Proposed glossary rows:

| Word | Means |
| --- | --- |
| **location** | Where a device physically is (`+CP1`, `+FIELD`), IEC 81346 `+` aspect. A device's own value, else inherited. |
| **location box** | A dashed rectangle or closed polyline labelled `+…` on a page; every device symbol inside it takes its location, live. |
| **generated page** | A page whose content ECAD draws from the project (cover, contents, revision list, BOM by location). It has a number, title and folder like any page; nothing on it is stored. |
| **sheet** (of a page) | One printed A3 (or other) sheet. A generated page may need several. |
| **report** | A table derived from the project (BOM, wires, cables), shown and exported, never stored. |

## 2. Format and ops (FP1–FP4 approved by the overseer, 2026-11-11)

**No new op and no `.ecad` format change.** Everything is existing ops with new property keys,
which old builds keep as unknown properties (P7).

- **FP1. Generated page = a page property `generated` (approved).** Values `cover`,
  `contents`, `revisions`, `bom-location`. Set only by `newpage {generated}` in the same
  transaction as its `AddPage`; `pageprops` refuses to change it (`A page's kind is set when it is
  made; add a new page instead.`). *Why:* a generated page is a page for numbering, folders,
  Next/Total and contents; a property needs nothing new. *Alternative:* typed `Page.kind` field
  (format addition, `#[serde(default)]`): cleaner, but a format change for one string. *Rejected:*
  virtual pages added at print time: they would have no number, folder or place in the book.
- **FP2. Location box = a tagless component (approved).** `CreateComponent {properties: {kind:
  "location_box", location: "+CP1"}}`, one closed `Primitive::Polyline` item (a rectangle is a
  four-vertex one; layer `ECAD-LOCATIONS`, linetype `DASHED`) and `LinkRepresentation {form: Drawn,
  role: "box"}`. Moving, grips, erasing and undo come from today's commands, as for junctions. Its
  label text is derived (like tag texts). Containment is derived (§3.1); nothing is written on the
  devices inside. *Alternatives:* (b) **derived boxes** drawn around devices
  whose location differs from the page's: no storage, but the designer cannot place or size them
  and they overlap; (c) a plain rectangle item with a property: items have no properties.
- **FP3. Device location stays component property `location`** (018, approved). Inheritance is derived,
  never written; clearing returns to inherited. No key added.
- **FP4. No report settings in the file** (approved). CSV options and the BOM grouping are command
  parameters and session state. A later standards brief can move them to `ProjectSettings`.

## 3. Device location (brief scope 1)

### 3.1 Context of a symbol

Every representation on a page has a **context location**, first match wins:
1. the **innermost** location box on its page whose outline contains its **anchor**:
   - anchor: the symbol's insertion point (placement origin); for a drawn representation, its first
     connection point, else its first item's first point;
   - contains: point in polygon by the even-odd rule over the box's vertices; a point on the
     outline (within 0.01 mm) counts as inside;
   - innermost: of the boxes that contain it, the one with the smallest polygon area; ties by
     component ID. Boxes need not nest neatly: this rule always gives one answer;
2. the page's `location` property;
3. the project's `location` property;
4. none.

### 3.2 A device's location

1. Its own `location` property, if set (**explicit**).
2. Else the context of its **main** representation (role `main`; if none, the first representation
   in book order, then by position top-left to bottom-right). Source shown as `from box on 105`,
   `from page 105` or `from project`.
3. Else none: shown and reported as `?` (flagged, §8.3).

So the precedence is: the device's own value, then the box its main symbol is in, then that page,
then the project.

**Live and derived (owner default, 2026-11-11).** Containment writes no property on any device. A
device's box location is computed from where its symbol is and where the boxes are, so drawing,
moving, reshaping or erasing a box, or moving a symbol in or out, changes what Properties, tags,
the BOM and the reports show on the next frame, and `u` undoes it with the edit that caused it.
A device with its **own** value that differs from the box its main symbol is in keeps its value;
Checks lists it (§8.3) with go-to and **Use the box's location** (clears the device's own value,
`setprop … value: null`, one transaction). *Alternative, recommended against (Q1):* a **snapshot**
that writes `location` on every device inside when a box is drawn, moved or reshaped. It freezes
values at that moment, makes every box edit a many-op transaction, leaves stale values when a
symbol later moves out, and undo has to unpick them.

### 3.3 Symbols in different locations (brief scope 1, AC2)

A contactor whose coil is on `105` (`+CP1`) and whose contact is on `110`, inside a `+FIELD` box,
is **one device in one location**: §3.2 gives `+CP1` (from the coil, its main symbol). Nothing is
refused. To keep the drawing truthful, every tag text of a representation whose context differs
from its device's location shows the location as a prefix: the contact on 110 reads `+CP1-K01`;
the coil reads `-K01`. A device with no location shows no prefix. The hover lens adds
`Location: +CP1 (from the coil on 105; this symbol is inside +FIELD)`.

### 3.4 Setting it

- **Properties panel** (019 §8.2), device rows: **Location** shows the explicit value in
  `cad.text`, or the inherited one in `cad.text_faint` with its source: `+CP1 (from page 105)`,
  `+JB1 (from box on 110)`, `+CP1 (from project)`, or `?` in `ecad.check-warning` with hover
  `No location: set one here, on the page or in Project Properties.` Typing writes it (`setprop`);
  emptying clears it back to inherited. Several devices: as 019 (`*varies*` when the shown values
  differ; one transaction for all).
- **Hover lens** (018 §6.4): `Location: +JB1 (from box on 110)`.
- **Devices tab** rows: tag text with the location prefix when it differs from the row's page
  context, as on the drawing.
- **MCP / command line:** `setprop {component | components, key: "location", value}` (today);
  `devices` results gain `location_shown` and `location_from` (`device`, `box`, `page`,
  `project`, `none`) and, per representation, `context`.

### 3.5 Location boxes

**Tool:** **Location Box** in the ECAD tab of Tool Sets (`ecad.tool.locationbox`), interactive
`locationbox`. Two drawing modes; rectangle is the default and the mode is kept for the session.

| Step | Prompt / what the user sees |
| --- | --- |
| 1 | `Location for the box <+CP1>:` (default: the last one used, else the page's or project's). Text rules as 018 §6.1; `+` added. |
| 2 | `First corner or [Polyline/Select] <Rectangle>:`. `P` switches to polyline mode, `S` to making a box from an existing outline (below). Snaps as usual. |
| 3, rectangle | `Other corner:` with a dashed rubber-band rectangle in `ecad.preview` and the label at its top-left. |
| 3, polyline | `Next point or [Undo/Close]:` repeated, with a dashed rubber band from the last point and back to the first; `U` drops the last point; `C`, Enter, or a click on the first point closes it (at least 3 points). |
| live | While drawing, every device symbol whose anchor falls inside gets an `ecad.attach-preview` ring; one with its own different location gets an `ecad.check-warning` ring. |
| 4 | Second corner or close: one transaction `Location box +CP1`; echo `Location box +CP1: 4 devices inside, 3 now in +CP1 (1 keeps its own +CP2).` |

Esc at any step writes nothing. An outline enclosing less than 100 mm² is refused at step 4 with
`A location box needs at least 10 x 10 mm.`; the step stays open.

**Make location box from a closed polyline** (`S` at step 2, or right-click a closed polyline,
**Make location box**, `ecad.menu.makelocationbox`): pick a closed polyline drawn on the page; one
transaction turns that item into the box (`CreateComponent`, `LinkRepresentation` of the
**existing** item, and `ModifyItem` to layer `ECAD-LOCATIONS` and linetype `DASHED`). Not a closed
polyline: `Pick a closed polyline (an open one can be closed with PEDIT first).` Part of a symbol,
wire or another box: `That outline belongs to -K01; draw a box instead.` Both keep the prompt
open. Arcs in a CADCraft polyline become straight segments within 0.5 mm, as translate does for
other drawn items, and the echo says so.

**Look:** the outline on layer `ECAD-LOCATIONS`, `ecad.location-box` (ACI 7, ByLayer), linetype
`DASHED`, lineweight `ecad.wire-weight`; the label `+CP1` inside, at the top-left vertex (greatest
y, then least x), 1.5 mm in, `ecad.location-label-height` 3.5 mm, on the same layer, derived
(clicking it selects the box). It plots.

**Editing:** select the box (its outline), then MOVE, ERASE, or the grips: one per vertex, and one
per segment midpoint (dragging it adds a vertex). Each edit is one transaction, and what is inside
updates at once (§3.2). Properties: `ECAD · LOCATION BOX +CP1` with Location (editable, `setprop`
on the box component), Vertices (read-only) and Devices inside (read-only, `5, 1 keeps its own
location`). An outline that crosses itself is allowed (even-odd rule) and listed in Checks.

**MCP:** `locationbox {location, corners: [[x,y],[x,y]] | points: [[x,y], …] | item: id, page?}`
(write; exactly one of the three; default the active page) returns `{component, representation,
item, inside: n, keeps_own: n}`.

## 4. The PDF book (brief scope 2)

### 4.1 Print Book dialog

Opened by **Print Book** (`ecad.project.print`, the existing print glyph in `icons.rs`) in the
Project panel header, by **Print folder…** in a folder's right-click menu (scope preset to that
folder), or by `printbook`. A floating window, 420 px, as 019 §7.1.

```
┌ PRINT BOOK ────────────────────────────────────── [x] ┐
│ Pages   (•) All pages (14 sheets)                     │
│         ( ) Folder [Schematic layouts          ▾]     │
│         ( ) Pages  [100, 105-110              ]       │
│ File    [C:\…\demo.pdf                  ] [Browse…]   │
│ Colour  [Black on white ▾]   [x] Line weights         │
│ 2 values marked ? on generated pages.                 │
│                                    [Print] [Cancel]   │
└───────────────────────────────────────────────────────┘
```

- **Pages** text: page numbers and ranges, comma-separated; a range runs in book order from one
  number to the other. An unknown number is underlined in `ecad.check-warning` with hover
  `No page 107; it is left out.`; Print stays enabled while at least one page matches, the sheet
  count updates live. None matches: Print disabled, `No page matches.`
- **File:** default `<project folder>/<project name>.pdf`; Browse opens CADCraft's save dialog.
  An existing file is replaced after `Replace demo.pdf?` (CADCraft's overwrite prompt).
- **Colour:** `Black on white` (default: every ACI colour plots black, plot style
  `monochrome.ctb`) or `As on screen`. **Line weights** on by default.
- The `?` line appears only when generated pages in scope have flagged values; it never blocks.
- **Print** shows `Printing sheet 3 of 14…` in the dialog's status line, then closes and echoes
  `Printed 14 sheets (4 generated) to C:\…\demo.pdf (412 KB).` Esc or Cancel during printing
  stops it and writes nothing (`Printing stopped; nothing written.`).

### 4.2 How it is built (on CADCraft's path)

1. Resolve the pages in book order (§4.1 scope), then each page's **sheets** (one, or more for a
   generated page that overflows, §5.2).
2. For each sheet, project it as the page window draws it (`project_page_with` with the session's
   cable views; generated content §5), on a **scratch** `Drawing`, translated so sheet *i* sits
   at x = Σ previous widths + 50 mm, y = 0. Non-plotting layers stay non-plotting
   (`MARKER_LAYER`); highlights, rings and the selection are never projected.
3. Call the engine's `plot` once on that drawing with `layout: "Model"`, `pages: [{window: the
   sheet edge, paper, landscape: true}]`, `margins: [0,0,0,0]`, `lineweights`, `plotStyleTable`,
   `path`: exactly `pdfbook`'s call. The sheet edge is the plot window, so the sheet plots 1:1 on
   its paper.
4. **Paper:** A3–A0 by name. A custom sheet (019 §3.1) plots on the smallest named paper it fits,
   fitted, and the echo adds `Page 120 (500 x 300) is printed fitted on A2.`
5. **More than 256 sheets:** written as volumes `demo.pdf`, `demo-2.pdf`, … of up to 256 sheets,
   breaking between pages where possible; the echo names each file.

The scratch drawing is the worker's to place: a temporary, unowned session document that is
closed afterwards, or (if the engine cannot plot a drawing that is not a session document) a
one-function upstream seam that hands a `Drawing` to the plot hook, marked
`// ECAD-SEAM(owner):` and listed in `UPSTREAM-PATCHES.md` (Q7). No PDF code in ECAD.

`printbook` is a one-off on request: it projects every page in scope (a full build is allowed
here, as for the debugger's replay), on copies, and records nothing.

## 5. Generated pages (brief scope 3)

### 5.1 Adding one

The Project panel's **+** gains a drop-down arrow (`ecad.project.newpage.kind`): **Page**,
**Cover**, **Contents**, **Revision list**, **BOM by location**. Each runs `newpage {generated,
title?, number?, folder?}`: one transaction, placed and numbered as 019 §6.1. Default titles:
`Cover`, `Contents`, `Revision list`, `BOM by location`. A project may have any number of each
(two BOM pages show the same content; Q5). Tree rows of generated pages show a faint kind tag:
`900  BOM by location   generated` (`cad.text_faint`).

### 5.2 Layout (A3; scaled with the sheet's drawing area)

All content sits inside the frame above the title block, drawing area (15, 55)–(405, 285) on A3,
on the reserved layer `ECAD-GENERATED` (ACI 7, locked), lines `ecad.wire-weight`, text in the
title block's text style. Tables: header row 7 mm with labels 2.5 mm in
`ecad.frame-label`, body rows 5 mm, values 2.5 mm, one thin line under each row, column text 1 mm
in, cut with `…` as 019 §4. A table that does not fit continues on the next **sheet** of the same
page, header repeated; the title block's Page box shows the number, the page title gets ` (2/3)`,
Next on all but the last sheet shows the same number, and **Total** counts sheets (Q4). Rows per
A3 sheet: 44.

| Page | Content |
| --- | --- |
| **Cover** | Centred in the drawing area: project title (10 mm), drawing number (7 mm), customer (5 mm), status (5 mm), `Revision B, 2026-11-12` (5 mm, newest issued; `Not issued` if none), `14 sheets` (3.5 mm). Unset values leave their line out. |
| **Contents** | Columns `Page` (25 mm), `Title` (220), `Folder` (145, path `Schematic / Motors`). One row per page in book order, generated pages included, the contents page itself too. |
| **Revision list** | Columns `Rev` 15, `Date` 25, `Description` 200, `Drawn` 30, `Checked` 30, `Approved` 30, `Version` 60 (the `NameVersion` name). Every issued revision, newest first. None: one row `No revisions issued yet.` |
| **BOM by location** | One block per location, sorted naturally (`+CP1`, `+CP2`, `+CP10`), `?` (no location) last: a heading row `+CP1` (3.5 mm) then rows `Qty` 15, `Tags` 70, `Description` 140, `Maker` 70, `Part number` 95 (§6.1 rows, By location). A block may continue on the next sheet with `+CP1 (continued)`. |

`?` values are drawn as `?` in `ecad.check-warning` on screen; in a `Black on white` print they
are black, so §4.1's warning line is how a print run learns of them.

### 5.3 Behaviour

- Selecting any generated content selects nothing; hover shows `Generated from the project: edit
  the devices (or pages, revisions) instead.`
- Drawing on a generated page is refused before anything is written, with a way on:
  `Page 900 is generated (BOM by location). Draw on another page, or add one after it with +.`
  Paste, Place and Wire use the same message. The frame and title block work as on any page.

## 6. Reports (brief scope 4)

### 6.1 Rows and columns

**BOM** (devices and parts; never wires, cable cores, junctions, continuations or location boxes):
a **device** is a component with a `tag` and no `kind`. Rows group devices with the same maker,
part number and description (all trimmed; case kept, compared case-insensitively); a device with
no part number is a row of its own.

| Column | Value | `?` when |
| --- | --- | --- |
| Location | §3.2 (By location only) | none |
| Qty | devices in the row | never |
| Tags | `-K01, -K02` (tag order, prefix then number) | never |
| Description | `description` | empty |
| Maker | `maker` | empty |
| Part number | `part_number` | empty |

Grouping: **By location** (default; key adds the location; sorted by location, then first tag) or
**By part** (whole project; Location column becomes `Locations`, `+CP1 ×2, +FIELD ×1`). A
terminal device (`-X01`) counts once until 028 counts its terminals.

**Wire report:** one row per conductor (cable cores included, with their cable), sorted by wire
number naturally, then conductor ID.

| Column | Value | `?` when |
| --- | --- | --- |
| Wire number | the net's number (022) | unnumbered |
| From, To | `-K01:A1`; a junction end `junction 105-C-4`; a continuation `24V >` with the name | loose end |
| From location, To location | the device's location (§3.2); blank for junctions and continuations | device has none |
| Cross-section, Colour | stored value, else the potential's default (022 §6) | neither |
| Potential | the net's potential | never (blank) |
| Cable | `W01 core 3`, blank for a single wire | never |
| Page | `105-C-4` of the midpoint of the conductor's first route in book order | no route |

Ends are ordered so that From is the end with the lower (page, column, row) place, so a list reads
left to right through the book.

**Cable report:** one row per cable, sorted by tag naturally.

| Column | Value | `?` when |
| --- | --- | --- |
| Tag | `tag` | none |
| Type | `type` | none |
| Cores | member count | never |
| From, To location | the distinct locations of the devices at its cores' ends, sorted: one → From = To; two → From, To; more → From = first, To = the rest `+B, +C` | any core end has no device location, or more than two |
| Used, Spare | `—` with hover `Core usage comes with terminal strips (brief 028).` | never |

Columns `Maker`, `Length` and `Designation` follow when any cable has the property (free
properties already exist), so nothing is lost before 027's cable list.

### 6.2 The Reports window

Opened by **Reports** (`ecad.project.reports`, an existing table-like glyph) in the Project panel
header, or `reports`. A floating, resizable, non-modal window (default 900 × 480 px, square
corners, `cad.panel`), live while open.

```
┌ REPORTS ────────────────────────────────────────────────────────────── [x] ┐
│ [BOM (12)] [Wires (31)] [Cables (1)]                                       │
│ Group [By location ▾]  Find [        ]  [ ] Only ?   3 ?   [Export CSV…]   │
│ Location  Qty  Tags          Description            Maker    Part number   │
│ +CP1        1  -G01          Power supply 24 V DC   Generic  PSU-24V-5A    │
│ +CP1        1  -K01          Pump contactor         Generic  CT-9A-24VDC   │
│ +CP1        1  -S01          Stop                   ?        ?             │
│ +FIELD      1  -M01          Pump motor 0.75 kW     Generic  MOT-075-4P    │
└────────────────────────────────────────────────────────────────────────────┘
```

- Rows 20 px, monospace, virtualised; clicking a header sorts by it (again: reverse; kept per
  session). **Find** filters rows containing the text in any column. **Only ?** shows flagged
  rows; `3 ?` counts flagged cells and is hidden at 0.
- `?` cells: `ecad.check-warning` text, hover gives the reason (`-S01 has no maker.`).
- Click a row: go to it as Checks do (022 §8): BOM, the first tag's main symbol; wires, the
  conductor's first route; cables, the label box. Double-click a BOM or cable row: Properties
  shows it. Nothing is recorded.
- Empty: `No devices yet.` / `No wires yet.` / `No cables yet.` Read-only project: the same;
  export works.

### 6.3 CSV

**Export CSV…** opens CADCraft's save dialog with `<project>-bom.csv`, `-wires.csv` or
`-cables.csv`; it writes what the tab shows (grouping, sort and filter), all rows. UTF-8 with a
byte-order mark, comma separator, CRLF line ends, RFC 4180 quoting; headers as §6.1. A `?` cell
is written as `?`. **Excel-safe** (on by default, Q8): a cell starting with `=`, `+`, `-`, `@`, tab
or CR is written with a leading `'`, so `-K01` and `+CP1` are not read as formulas. Echo
`Wrote 12 rows to C:\…\demo-bom.csv (3 cells marked ?).`

### 6.4 Commands and MCP

All read the project (work with writes off) and record nothing:

| Command | Params | Returns |
| --- | --- | --- |
| `bom` | `group?` (`location` / `part`), `path?`, `excel_safe?` (true), `limit?` (500, max 5000), `after?` | `{rows: [{location, qty, tags, description, maker, part_number, flags: [column]}], flagged, next?}`; with `path`, also writes the CSV and returns `{path, rows}` |
| `wirelist` | same, no `group` | `{rows: [{conductor, wire_number, from, from_location, to, to_location, cross_section, colour, potential, cable, page, flags}], …}` |
| `cablelist` | same, no `group` | `{rows: [{cable, tag, type, cores, from_location, to_location, used: null, spare: null, flags}], …}` |
| `printbook` | `scope?` (`all` / `{folder}` / `{pages: "100, 105-110"}`), `path?`, `colour?` (`mono` / `screen`), `lineweights?` | `{files: [{path, sheets, bytes}], sheets, generated, flagged}`; without `path`, base64 `data` as `plot` returns |
| `reports` | none | opens the window (interactive only) |

Writes: `setprop` location (today), `locationbox` (§3.5), `newpage {generated}` (§5.1).
File writing with `path` follows whatever `export` and `plot` do under MCP today (worker checks;
no new rule here).

**MCP contract tests** (brief 011 rule), through `execute`: `setprop` location on one and on
several devices, `locationbox` and `newpage {generated: "bom-location"}` record one transaction
with `Author::Agent(<client>)` and are refused with writes off; `bom`, `wirelist`, `cablelist` and
`printbook` (no `path`) succeed with writes off and record nothing; `devices` shows
`location_from`.

## 8. What depends on what

### 8.1 Indexes kept by the project

- **Context index:** representation → context (§3.1) and its source; per page, the list of location
  boxes (vertices, bounding box, area); per box, the representations whose context it is.
- **Location index:** device → (location, source); source → devices (for project-level changes).
- **Report models:** BOM rows by group key, device → key; wire rows by conductor; cable rows by
  cable; conductor → cable (existing), connection point → conductors (022 connectivity).

Built on open, reload and first show; after that only by the map in §9. Old files (no
`generated`, boxes or device locations) read as before, except that devices now show inherited
page or project locations (display only, nothing written).

### 8.2 Sheet counts

A generated page's sheet count is `ceil(rows / 44)` (at least 1), from the report model it shows.
The book's total sheet count is kept as Σ; a change in one page's count changes `Total`.

### 8.3 Checks (022 tab), additions

| Kind | Severity | Entry |
| --- | --- | --- |
| Devices without a part number | Info · | one row `5 devices have no part number`, **Show** opens Reports, BOM, Only ? |
| Devices without a location (only when some location is set in the project) | Info · | one row, **Show** as above |

## 9. Update maps

Only the page on screen is redrawn; other pages with changes are marked stale. "Row" means that
row of the report model and, if shown, of the open Reports window and the active generated page.
Every op not listed changes nothing in that view.

**Location-box cost on the large tier** (500 pages, 5 000 components: about 10 device symbols and a
few boxes per page). A box edit tests that page's symbol anchors (about 10–40) against that page's
boxes (1–5, each up to 100 vertices): under 10 000 segment tests, well under 1 ms. A symbol move
tests one anchor against its page's boxes. Neither touches another page or rescans the project.

## 14. Owner questions, each with a recommendation

1. **Location boxes: live and derived, or a snapshot?** A box is a rectangle or a closed polyline;
   a device's own value wins, then the box its main symbol is in (insertion point inside the
   outline, innermost by area), then the page, then the project. Should containment be (a) **live
   and derived**, writing nothing on the devices, with a device whose own value differs keeping it
   and getting a Checks warning with a one-click **Use the box's location**; or (b) a **snapshot**
   that writes `location` on every device inside whenever the box is drawn, moved or reshaped?
   **Recommend (a), live**: undo, moves and reshapes just work, Properties says `from box on 110`,
   each edit stays one small transaction, and nothing goes stale when a symbol later moves out.
2. **Symbols in different locations (§3.3):** the device takes its main symbol's context and other
   symbols show the `+` prefix, with no refusal? **Recommend yes**: one device is in one place;
   the prefix is the IEC way of saying so on the drawing.
3. **Generated page storage (FP1, approved by the overseer):** a page property `generated`, set
   only at creation. **Recommend keep**: no format change.
4. **Overflow:** a generated page continues on extra sheets with the same number and `(2/3)`, and
   Total counts sheets? **Recommend yes**; the other way (consuming `901`, `902`) would clash with
   numbers the designer chose.
5. **Several BOM pages** (or contents pages) in one project: allowed, each showing everything?
   **Recommend allow**; a per-page filter (one location per page) is a small later step.
6. **Cables on the BOM:** left off (they are in the cable report; a cable-type list is 027)?
   **Recommend off for v0.1.**
7. **PDF seam:** if the engine cannot plot a scratch drawing without opening it as a session
   document, approve a one-function upstream seam? **Recommend approve**; it keeps all PDF writing
   in CADCraft.
8. **CSV Excel-safe** prefix `'` on cells starting `= + - @`, on by default? **Recommend on**: tags
   (`-K01`) and locations (`+CP1`) otherwise turn into formulas or errors in Excel, and it guards
   against formula injection from files made elsewhere; `excel_safe: false` writes plain values.
9. **Print colour:** black on white by default? **Recommend yes**: it is how panel books are
   issued; `As on screen` is one click away.
10. **Wire report rows for cable cores:** included, with a Cable column? **Recommend yes**: a core is
    a conductor and is wired like one; the cable report stays one row per cable.
11. **Terminal devices on the BOM** count once per device until 028 counts terminals per strip?
    **Recommend yes.**
