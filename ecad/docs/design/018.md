# Design 018: Components, tags and starter symbols

Brief: `docs/briefs/018-components-and-tags.md` (Approved 2026-11-08, feature F2 of
`docs/roadmap-v0.1.md`). Builds on `docs/design/008.md` (Place Symbol, connection points, hover, prompt
machine: one commit = one JSON-equivalent transaction, Esc changes nothing, click-first, feedback in
words, never crash) and `docs/design/010.md` §6 (derived text drawn by the projection). Tokens:
`docs/design/tokens.md` (this spec adds five, §11). Owner questions with recommended answers: §14.

## 0. Model check: one rule stands in the way

Ops needed: `EmbedDefinition`, `CreateComponent`, `AddTerminal`, `AddItem`, `LinkRepresentation`,
`ModifyItem`, `ModifyRepresentation`, `SetProperty`, `RemoveTerminal`, `UnlinkRepresentation`,
`AttachEnd`, `DeleteComponent`. All exist. **No new op and no change to what is serialised.**

One invariant blocks the brief's centre case. **I14** (`ecad-model/src/invariant.rs`): a symbol
representation must show *its component's own definition* (`Component.definition`, one per
component). A `-K1` whose definition is the coil therefore cannot have a contact drawn as a symbol
instance of the NO-contact definition. Two ways through, which give the user the same result on
screen (Q1):

- **Path B (recommended): relax I14.** A symbol representation may show **any embedded
  definition**. When it is not the component's own definition, it must carry `connection_points`
  for the connection points it shows, as a drawn representation does. `derive::shown_by` uses the connection
  points when there are any, else the key match it uses today. On MOVE/ROTATE of the instance the
  translation rewrites the connection points (`ModifyRepresentation`), as it already does for drawn
  representations. The serialised shape is unchanged. Older builds would refuse such a file. No such
  files have been released.
- **Path A (no rule change):** an added representation is **drawn form**. The definition's graphics
  are copied into plain items (`AddItem` per primitive) with `connection_points`. It works today,
  but a contact then becomes several loose CAD entities: picking one line and MOVE moves only that
  line. It has no link to its definition (no library update later), and F3 must recognise contacts
  by role.

The rest of this spec is written for **Path B**. Under Path A only §10's op lists change.

The **first** symbol placed for a new device is a plain symbol representation (role `main`, the
component's own definition), exactly as today's `place`.

## 1. Goal

The designer types a few letters, clicks a symbol, clicks it onto the page, and gets a real device
with an IEC tag (`-K1`). A contact clicked onto another page can join `-K1`, and every
representation shows the same tag and changes with it.

## 2. Tags

### 2.1 Form and storage

- Stored as the component property **`tag`**, in full: `-K1`. One `SetProperty` changes it
  everywhere, because every representation reads the same component.
- Accepted input: an optional leading `-`, then 1–3 letters A–Z, then 1–5 digits. Case-insensitive.
  Stored upper-case with the `-` added: `k1` → `-K1`, `-tb01` → `-TB01`. Anything else is refused:
  `` A tag is a letter code and a number, for example -K1 or -TB01. ``
- **Prefix** = the letters; **number** = the digits as an integer. `-K01` and `-K1` are the
  **same** tag for duplicate checks (number 1).
- Components without a tag (converted from lines, older projects) show no tag text. The lens shows
  `Tag: (none)`. Old `tag` values that do not fit the form (for example `K1` from fixture R) are
  shown as stored and take part in duplicate checks after the same normalisation.

### 2.2 Automatic tag on placement

A new device gets `-<prefix><n>`, where n is the **lowest free number** for that prefix (Q4).
"Free" is checked against every component's normalised tag. It is read from a derived **tag index**
(`normalised tag → component`, `prefix → set of numbers`). The index is updated from the components
each commit touched (brief 013's touched set) and never rebuilt by a scan on an ordinary commit.

### 2.3 Duplicates

Any command that would give two components the same normalised tag is refused and writes nothing:

`Tag -K1 is already used by -K1 (Contactor coil, page 1 "Supply").`

This names the holder's tag as stored, its `description` (else its symbol name, else `no
description`) and the page of its first representation in page order.

### 2.4 Where tags are drawn

The projection draws tags as derived text. Nothing is stored, as 010 §6.1 does for references.
Each tag is one CADCraft Text entity per representation, on the reserved layer **`ECAD-TAGS`**:

- **Text:** the tag as stored. Height `ecad.tag-height`, colour ByLayer (`ecad.tag`).
- **Placement:** take the representation's bounding box in page coordinates and the direction of
  its connection point axis (main connection points top to bottom after rotation and mirror).
  - **Vertical axis** (rotation 0° or 180°): anchor at `(box.min.x − ecad.tag-gap, box.centre.y)`,
    right-aligned, middle. The tag sits left of the symbol, IEC style.
  - **Horizontal axis** (90° or 270°): anchor at `(box.centre.x, box.max.y + ecad.tag-gap)`,
    centred, bottom-aligned. The tag sits above the symbol.
- **Connection point labels:** each connection point a representation shows gets its label as derived text on
  `ECAD-TAGS`, height `ecad.term-label-height`.
  - Vertical axis: 1 mm right of the connection point, 2.5 mm from it toward the symbol, left-aligned,
    middle.
  - Horizontal axis: 1 mm above it, 2.5 mm toward the symbol, centred, bottom-aligned.
- **Behaviour:** tag text and connection point labels are mapped to their representation in the handle map
  (a new kind), so hover and pick know them. They plot and export as shown. Other edits of them are
  refused, as for 010's text: `The tag text is derived; change the tag with Device Properties.` An
  ERASE selection that includes them is treated as selecting their representation.
- **What redraws:** after a tag change, only representations of the touched component on the page
  on screen redraw. Other open pages are marked stale (`ecad/CLAUDE.md`, derived views).

### 2.5 Editing a tag

See **Device Properties** (§6). Renaming `-K1` to `-K5` is one `SetProperty` on the component: one
transaction with label `Set tag`. Coil and contacts on every page show `-K5` after it, and `u`
brings `-K1` back everywhere.

## 3. One device, many representations

### 3.1 Joining

A placed symbol either makes a **new device** or **joins** an existing one (§5.3, option `Device`).
Joining adds a representation and new connection points to the existing component. It never creates a
component.

**Joinable symbols and their connection point labels.** Labels are unique within a device. A connection point's
`key` is its label (LIB-02 key per device). Today's key match therefore never shows a joined
contact's connection points on the main symbol.

| Kind | Labels when joining |
| --- | --- |
| Contacts (`no`, `nc`, `pbno`, `pbnc`, `sel`) | IEC sequence digit s = 1 + the highest s among the device's two-digit labels `s1`…`s4`. The first contact of a device is s = 1. NO → `s3`/`s4`, NC → `s1`/`s2`. Coil `-K1` + NO → `13`/`14`, then + NC → `21`/`22`. After s = 9: refused, `-K1 already has 9 contacts.` |
| Terminal (`terminal`) | 1 + the highest whole-number label (first: `1`) |
| PLC channel (`di`, `do`) | Next address in that letter's sequence: `I0.0`…`I0.7`, `I1.0`… (same for `Q`) |
| Others (coil, power contacts, MCBs, fuse, PSU, lamp, motors, transformer) | The definition's labels. Refused when any label already exists: `-Q1 already has connection point 1.` A device holds at most one of `coil`, `mcb1`, `mcb2`, `fuse`, `psu`, `lamp`, `motor3`, `motor1` and `trafo`: `-K1 already has a coil.` |

Joining across prefixes is allowed: an NC contact can join `-Q1` as an auxiliary contact. The tag
does not change.

### 3.2 On the drawing

Every representation draws the same tag (§2.4) and its own connection point labels. For example, `-K1` with
its coil on page 1 and a NO and an NC contact on page 2: page 1 shows the coil with `-K1` at its left
and `A1`/`A2`; page 2 shows two contacts, each with `-K1` at its left, `13`/`14` and `21`/`22`.
There are no cross-references (`/1.3`) yet: that is F3.

### 3.3 Moving and deleting

| Action | Result |
| --- | --- |
| MOVE / ROTATE / grip a representation | `ModifyItem` (and `ModifyRepresentation` for connection points). Other representations unchanged. |
| ERASE one representation of a device with others | One transaction: `AttachEnd → None` for wire ends on connection points this representation alone shows, `RemoveTerminal` for those connection points, `RemoveItem`, `UnlinkRepresentation`. Echo: `Removed -K1's NO contact 13/14 (page 2); -K1 is still shown on page 1.` Connection points also shown elsewhere stay. |
| ERASE the **last** representation of a device | Deletes the device in the same transaction (as `ecaddelete {component}` does). Echo: `Deleted -K1 with its last symbol; U brings it back.` (Q6) |
| **Delete Device** (§6.3) | Asks first, then deletes every representation on every page. |
| COPY a representation | As today (proposal §11 copy policy: a whole new component). The copy gets the next free tag. |

## 4. Starter symbols

These are built in (`ecad-cadcraft`, as `builtin_coil` today). Each one is embedded into a project
the first time it is used, by `EmbedDefinition`, with this origin:
- `library` = one fixed `LibraryId` for "ECAD starter symbols";
- `definition` = a fixed ID per symbol;
- `library_seq` = 1;
- `content_hash` per the proposal's §20.10 formula.

Later placements reuse the embedded copy, found by origin (library and definition), not by name.
Kind, prefix, aliases and default description come from the built-in catalogue, keyed by origin;
`Definition` stores none of them.

**Geometry** is in mm, local frame, y up, rotation 0, symbol centre at (0,0). Connection points lie on the
**5 mm grid** (Q8). Most symbols are 20 mm tall (connection points at y = ±10), so an A3 frame with columns
A–H (about 50 mm) and rows 1–6 (about 46 mm) holds one symbol, its tag and its wires per cell.
Definitions carry no linetype, so the **mechanical link** is drawn dashed as segments 1.5 mm long
with 1 mm gaps along y = 0.5. Text primitives are left-baseline. Shapes follow IEC 60617 forms but
are drawn new.

**Default description** for each symbol is its name without the alias list, for example
`Contactor / relay coil` or `MCB 1-pole`. It is set as the `description` property when a **new**
device is placed. Joining does not change the device's description.

The 008 experiment coil (`Coil (experiment)`) still draws in old projects. Search does not list it.
`place` without `symbol` or `definition` still places it (compatibility with existing tests).

## 5. Search and place

### 5.1 The search box

It sits at the top of the **Components** group of the ECAD tab in Tool Sets, above **Convert to
Component**:

| Element | Label / look | Does |
| --- | --- | --- |
| `ecad.symbolsearch` | Single-line text field, placeholder `Find symbol or device…`, monospace | Filters as you type (no Enter needed). At most 60 characters; longer input is cut. |
| `ecad.symbolresults` | List under the field, at most 10 rows, then `and N more`; rows `ecad.symbolresult.0`… | Click a row: starts **Place Symbol** with it (§5.3). Up/Down + Enter do the same. Esc clears the field. |

**Matching** is case-insensitive and on the trimmed query:
- **Symbols:** substring of the name or any alias, or the query equals the prefix with or without
  `-` (`-Q` and `q` both find `mcb1`, `mcb2`).
- **Devices** in this project: their tag starts with the query, normalised as in §2.1 (`-k` and `k1`
  find `-K1`, `-K10`…).

Results show devices first, then symbols. A query that starts with `-` lists devices first even
when symbols also match.

**Row format** (monospace, columns aligned):

```
-K1   Contactor / relay coil   3 symbols, pages 1, 2        (device)
no    NO contact               -K   13/14                    (symbol)
```

Empty field: the symbol list in table order. No match: `Nothing matches "xyz".`, dimmed. A
read-only project still lists results; clicking one gives the read-only refusal of 008 §3.

If Tool Sets cannot host a text field without an upstream change, the worker stops and asks (Q9).
Typing `place` at the command line (§5.3) gives the same search in any case.

### 5.2 Choosing a device row

Clicking a **device** row starts Place Symbol for that device. It first asks which symbol to add:
`Enter symbol to add to -K1 or [List] <no>:`. The default is `no`, else the first joinable kind
(§3.1). It then goes to §5.3 step 2 with `Device` already set to `-K1`.

### 5.3 Place Symbol (interactive `place`)

The **Place Symbol** button (`ecad.place`) and a bare `place` start at step 1. A symbol row starts
at step 2.

| Step | User does | Prompt / what they see |
| --- | --- | --- |
| 1 | — | `Enter symbol or [List] <coil>:`. The default is the last symbol placed in this session. A typed text is matched as §5.1: one symbol match is taken; several give `"contact" matches 5 symbols: no, nc, pbno, pbnc, sel.` and the prompt repeats; `L` lists all symbols, one per line. A typed device tag goes to §5.2. |
| 2 | — | `Specify insertion point (new device -K2, rotation 0) or [Rotate/Mirror/Device]:`, or `(joins -K1 as 13/14, rotation 0)` when joining. The preview follows the cursor in `ecad.preview`: the symbol, its tag at §2.4's place and its connection point labels, all as they will be drawn. |
| 2r | `R` | Rotates 90° counter-clockwise; the prompt and preview update. `M` mirrors, as today. |
| 2d | `D` / `Device` | `Enter device to join, or New <-K1>:`. The default is the device of the most recent placement in this command, else the most recently placed device whose prefix equals the symbol's, else `New`. A tag is matched as §2.1. Refusals of §3.1 come here with the prompt repeating; `No device -K9.` likewise. `N` / `New` places a new device. Then back to step 2. |
| 3 | Clicks (or types a point) | One `place` transaction (§10). Echo: `Placed -K2 (Contactor / relay coil) with connection points A1, A2.` or `Added NO contact 13/14 to -K1 (now on pages 1, 2).` **The command continues at step 2** with the same symbol, rotation and device choice. A new device gets the next number; a join gets the next labels. |
| — | Enter / Esc | The command ends. Nothing is written for the pending placement. |

**Snap and grid** work as today's `place`: CADCraft's object snap and grid snap apply to the
insertion point. The ECAD trial turns grid snap on at 5 mm on ECAD pages (Q8).

## 6. Properties

### 6.1 Keys

All are component properties written by `SetProperty`. Values have at most 200 characters, no
control characters, and are trimmed. Empty or `null` clears the key (unset, P7).

| Key | Shown as | Notes |
| --- | --- | --- |
| `tag` | `Tag` | §2 rules |
| `description` | `Description` | Default from the symbol (§4) |
| `maker` | `Maker` | |
| `part_number` | `Part number` | |
| `location` | `Location` | Stored with a leading `+` (added if missing). Not drawn yet (F6). |
| `function` | `Function` | Stored with a leading `=` (added if missing). Not drawn yet (F6). |

### 6.2 Device Properties (interactive `deviceprops`)

This is a new button, `ecad.deviceprops` **Device Properties**, in the Components group after
**Place Symbol**. Tooltip: `Click a device to see and change its tag, description, maker and part
number`. It uses command-line prompts and adds no panel (Q7).

| Step | User does | Prompt / what they see |
| --- | --- | --- |
| 0 | Clicks the button with one device selected (pickfirst) | Goes to step 2 for that device |
| 1 | — | `Select a device:`. Any item, tag text or connection point label of a representation names its device. A wire or cable: `That is not a device.`; empty space: `Nothing there. Click a device.` The prompt repeats. |
| 2 | — | Lists the current values, one per line (`Tag: -K1`, `Description: Contactor / relay coil`, `Maker: ?`…), then `Enter property to change [Tag/Description/Maker/Part/Location/Function] <Tag>:` |
| 3 | Picks a key | `New tag <-K1>:` (each key shows its current value as the default). Enter keeps it. A value is checked as §2/§6.1; a refusal repeats the prompt with the message (duplicate: §2.3). |
| 4 | Enters a value | One `setprop` transaction. Echo: `-K1 is now -K5 (3 symbols on pages 1, 2).` or `Maker of -K5 set to "Acme".` Back to step 2 for another key. |
| — | Enter at step 2 / Esc | The command ends. |

### 6.3 Delete Device (interactive `devicedelete`)

This is a new button, `ecad.devicedelete` **Delete Device**, after Device Properties. Select a
device as in §6.2. Then: `Delete -K1 and its 3 symbols on pages 1, 2? [Yes/No] <No>:`. `Y` runs
`ecaddelete {component}` as today, in one transaction. Echo: `Deleted -K1.` `N` / Enter / Esc: the
command ends with `Nothing deleted.`

### 6.4 Hover lens

The hover lens (`ecad.hover`, 500 ms, 12-line cap) on any item, tag text or connection point label of a
device representation shows:

```
Device -K1   Contactor / relay coil
Maker: Acme   Part number: CX-9-24DC
Location: +09-02   Function: =PWR             (only when either is set)
This symbol: NO contact 13/14, page 2 "Control"
Also: coil A1/A2 page 1 "Supply"; NC contact 21/22 page 2
  13 -> W5        14 (not connected)
id <component hex>
```

`Maker: ?` marks an unset key. The `Also` line lists at most 4 entries, then `+N more`. The connection point
line uses 008's `-> wire` form. A component with no tag starts with `Device (no tag)`. The debugger
(read-only) shows `tag` among the properties and lists a component's representations by page.

## 8. JSON forms and MCP

They reuse today's patterns: hex IDs, `[x,y]` points, `null` clears, and results that name what was
made.

- **`place`** (extended): `{at: [x,y], rotation?, mirror?, symbol?: key, definition?: id, device?:
  id, tag?: string}`.
  - `symbol` and `definition` are mutually exclusive.
  - `device` joins that component (§3.1); `tag` sets a new device's tag instead of the automatic
    one. `device` and `tag` together are refused: `` `tag` is for a new device; `device` joins an
    existing one ``.
  - Result: `{component, representation, item, definition, tag, joined: bool, terminals: [{key,
    label, terminal}]}`.
- **`setprop`** (existing): `{component, key: "tag", value}` applies §2's rules and refusals. The
  other keys follow §6.1. Today's behaviour for other keys and objects is unchanged.
- **`symbols {query?}`** (new, `.noundo()`, read-only): `{symbols: [{key, name, aliases, prefix,
  terminals: [label], box: [w,h], joinable: bool}], devices: [{component, tag, description,
  representations: n, pages: [n]}]}`. It matches as §5.1; without `query` it lists every symbol and
  device.
- **`devices {tag?}`** (new, read-only): `{devices: [{component, tag, description, maker,
  part_number, location, function, representations: [{representation, page, page_number, role,
  symbol, terminals: [label]}]}]}`. Ordered by prefix, then number, then ID.
- **`ecaddelete {component}`** (existing): Delete Device.

The interactive forms commit through exactly these JSON forms (008 §2 rule 3). MCP reaches them
through `ecad-mcp`'s `execute` tool with no MCP-only path. **MCP contract tests** (CLAUDE.md, brief
011) for `place` (new device, join), `setprop` tag (including a duplicate refusal), `symbols` and
`devices`: each checks the recorded transaction and `Author::Agent(<client>)`, and that writes are
refused with writes off.

## 9. Limits (never crash)

- At most 10 000 devices per prefix; the lowest-free search is bounded.
- At most 99 999 per number.
- Search query: 60 characters.
- Result lists: 10 rows in the UI and 500 entries in JSON, then `"more": n`.
- A hostile file with a non-finite symbol placement or connection point draws nothing for that
  representation and shows `cannot be drawn` in the lens.

## 10. Model mapping

| Action | Transaction (one, label) | Ops in order |
| --- | --- | --- |
| Place, new device | `Place symbol` | `EmbedDefinition` (first use only) · `CreateComponent {definition, properties: {tag, description}}` · `AddTerminal` × n (key = label) · `AddItem` (symbol instance) · `LinkRepresentation {form: Symbol, role: "main"}` |
| Place, join (Path B) | `Add symbol to -K1` | `EmbedDefinition` (first use) · `AddTerminal` × n (labels per §3.1) · `AddItem` (symbol instance) · `LinkRepresentation {form: Symbol, role: <symbol key>, connection_points: placed connection points}` |
| Place, join (Path A) | same | `AddTerminal` × n · `AddItem` × each primitive (transformed) · `LinkRepresentation {form: Drawn, role: <symbol key>, connection_points}` |
| Tag or property change | `Set tag` / `Set property` | `SetProperty` |

## 14. Owner questions, each with a recommendation

1. **I14 and added representations (§0).** Recommended: **Path B**. Relax I14 so a symbol
   representation may show another embedded definition, with its connection point positions as connection
   points. No new op and no serialised change, but it is a model rule change, so it needs your yes.
   Path A needs no rule change, but leaves contacts as loose lines and is weaker ground for F3 and
   library updates.
2. **Contactor prefix.** Recommended: `-K` for coils and contacts (common practice, your reference,
   the brief's example). IEC 81346-2:2019 would make power contactors `-Q`; the designer can retag.
3. **Tag numbers.** Recommended: `-K1` (no padding), with `-K01` accepted and equal to `-K1`. Your
   reference uses `-K01`. A project-wide padding setting would be a project-settings change: later.
4. **Next number.** Recommended: the lowest free number (fills gaps after a delete). Alternative:
   highest + 1, so a deleted tag is never reused.
5. **Prefixes for PSU and PLC.** Recommended: PSU `-G`, PLC channels `-A`, transformer `-T`.
6. **ERASE of the last representation.** Recommended: it deletes the device in one undoable
   transaction with an echo. Only **Delete Device**, which reaches other pages, asks first.
   Alternative: refuse it and point to Delete Device.
7. **Where properties are edited.** Recommended: command-line **Device Properties** for v0.1, and
   the hover lens for reading. A docked properties panel would share space with 016's project panel,
   so it should be designed with it later. **Overlap with 016:** step 3 of the quick start uses New
   Page / Open Page until 016's panel lands; this spec adds no page switching.
8. **Grid.** Recommended: starter symbols on a 5 mm connection point grid, mostly 20 mm tall, and the trial
   turns grid snap on at 5 mm on ECAD pages.
9. **Search box in Tool Sets.** Recommended: a text field at the top of the ECAD tab's Components
   group, in `ecad-trial`. If it needs a CADCraft change, that is an upstream patch for your
   approval. Until then, the `place` prompt's typed search covers it.
10. **Connection point labels on the drawing.** Recommended: draw them (derived, `ECAD-TAGS`) in this
    feature, since printed v0.1 pages need them.
11. **Tag position.** Recommended: automatic (left of the symbol, or above when rotated) for v0.1.
    Letting the user move a tag would store a position: later.
