## 0.1 What the code has today (checked on `origin/dev` `6729c8f1`)

- **Print Book** (`printbook.rs`): every page is projected onto one scratch drawing, sheets side by
  side 50 mm apart, then CADCraft's plot hook is called once per volume with one
  `{window, paper, landscape}` per sheet.
- **CADCraft's plotter** (`crates/io/src/pdf.rs`, `sheet()`): for **each** page of a `pages` plot
  it runs `cadcraft_render::build_plot(d, Space::Model, …)` over the **whole** model and writes
  every primitive, clipped to the page. Measured on the pack recreation (30 sheets, 32.2 MB): each
  page's content stream is 5.5 MB uncompressed and starts drawing about 6,600 pt left of its own
  page. It holds the geometry of all 30 sheets. Size and time therefore grow with sheets²; a sheet
  on its own is about 36 KB compressed. The file has no `/Font`: CADCraft's stroke font is always
  geometry (`PdfOptions::text_as_geometry`, "Stroke-font text is always geometry"). TrueType text
  is already written once per file as an embedded subset (`pdf/fonts.rs`), so lane T's sans font
  will share font resources without further work here.
- **Missing data:** generated tables draw a missing value as `?` in ACI 2 (`FLAGGED_ACI`,
  `ecad.flagged`). The pack was printed with `colour: "screen"`, so `?` came out yellow on white.
  With the default `mono` it prints black but is still a lone `?` in a busy table.
- **Contact tables** (`xref.rs`): `table_top` puts the table under the head's lowest connection
  point (`below`), or under the vertical run of its wire (`auto`), or to the right (`right`), or at
  a stored offset (`at dx,dy`). Rows go down from the top at 4 mm pitch with nothing checking the
  frame, so a coil low on the page puts its table over the title block (title-block top line at
  50 mm from the paper's bottom: `MARGIN_MM + TITLE_BLOCK_MM`).
- **Tags** (`ecad-model/src/tag.rs`): `normalise` stores every typed tag in upper case with a
  leading `-` (`k5` → `-K05`, `M02a` → `-M02A`, `N01 Slot02` → `-N01 SLOT02`). `format` writes
  `-`, the prefix in upper case and the padded number. `key` ignores case and an optional leading
  `-`, so identity does not depend on either. **The typed case is lost when the tag is stored**, so
  "case kept as typed" cannot be a display-only change (roadmap Q7 said display only).
- **Revisions** (`revisions.rs`): six fixed fields (`FIELDS`) plus `issued` and `released`;
  `list` ignores any other `rev.<n>.<field>` key. The title block shows up to 7 issued rows in six
  fixed columns; the Rev box shows the newest issued rev, or `-`.
- **Generated pages** (`generated.rs`): a page that needs several sheets prints them all with the
  page's own number; the title gets ` (2/3)`; Next shows the same number on all but the last sheet;
  Total counts sheets.
- **`table`** is CADCraft's command. ECAD cannot shadow it (`set_extension_commands`: "An id that
  is already taken is ignored by lookups, which find the built-in command first"). Its entity is
  refused by `convert::item_from` with `format!("{}s are not supported on ECAD pages yet",
  kind_name(..))`. For a table, `kind_name` falls through to `"object of this kind"`, which gives
  "object of this kinds are not supported…". The same pattern gives "hatchs" for a hatch.

## 1. Goal and text sizes

### 1.1 Goal

A printed book that is small, readable and honest: missing values visible on paper, contact
tables clear of the title block, page numbers as the pack numbers them, tags written as the
project writes them, the revision table the project needs, and a title block that says when the
drawing has changed since its last issue.

## 2. PDF size (brief scope 1a)

### 2.1 The fix

The plotter draws only what lies on each page. In `crates/io/src/pdf.rs` `sheet()`, when the page
has a window (every `pages` plot has one), a primitive whose bounds do not meet the window,
grown by half the widest line weight, is not written. The worker picks the cheaper of two places
and says which in its report:

- **(a)** in `pdf.rs`, skip the display list's primitives outside the window before writing; or
- **(b)** in `cadcraft_render::build_plot`, an optional `cull: Option<Bounds2>` in `Options` that
  skips entities whose extents miss it before tessellating. (b) also saves the build time: today
  each page tessellates the whole book.

Nothing ECAD-specific crosses the seam: a window and a bound. Plots without a window are
unchanged. Both are upstream patches (owner question Q1).

### 2.2 Targets

- **Bytes grow linearly with sheets:** a book of 20 copies of the same page is at most 2.2 times
  the size of a book of 10 (today about 4×).
- **The pack:** the 30-sheet pack recreation prints under **5 MB** (expected about 1–1.5 MB: 36 KB a
  sheet measured, plus fonts once lane T's font is in). Measured once by the owner or overseer on
  the private project; nothing from it is committed.
- **Bench:** `print25` (Print Book of the 25-page bench project, release build; bench of 027)
  records bytes and time before and after. Time should drop too, since each page no longer
  builds the whole book; no time target is set.

### 2.3 What does not change

Paper choice, volumes (`MAX_SHEETS`), page order, layers in the PDF, line weights, mono and screen
colours, links. The visible result of every page is identical. A test checks that pixel for pixel
on a 3-page book, rendered through the PNG device before and after culling.

## 3. Missing data in print (brief scope 1b)

### 3.1 The mark

A missing value in a generated table (`?`, the cells `flagged` already counts) is drawn as **`?`
in a box**: a thin rectangle (`ecad.wire-weight`) round the cell's text area, inset 0.5 mm, in the
same colour as the `?`.

| Where | Colour | Token |
| --- | --- | --- |
| On screen | yellow, ACI 2 | `ecad.flagged` (unchanged) |
| Printed, `colour: "mono"` | black (all colours are) | |
| Printed, `colour: "screen"` | **black, ACI 7** | `ecad.flagged-print` (new, §13) |

Printing builds its scratch drawing from the same projection the screen uses. `printbook::build`
recolours the flagged parts (ACI 2 on `ECAD-GENERATED`) to ACI 7 on the scratch copy. It
recolours nothing else, and nothing on screen changes.

The box makes the mark visible in any colour, and on paper it reads as "fill this in". Owner
question Q2.

### 3.2 Scope

Only the generated tables (BOM, cable schedule, terminal plan, contents, revision list). Other `?`
texts drawn on schematic pages (a location box with no location, `locations.rs`; a tag
placeholder, `look.rs`) belong to lane T's files. The same mark is offered to lane T as
`generated::missing_mark(at, height, room)`, which returns the parts; using it is lane T's
choice (follow-up FU1).

### 3.3 Print Book's words

Unchanged: the dialog's live line `3 values are missing (?).` and the reply's `flagged`.

## 4. Contact tables clear of the title block (brief scope 1c)

### 4.1 Rule

The table's box is computed before it is drawn. Its width is the table's own (from −10 mm to
12 mm plus the widest place text at the table's text size), its height 3 mm plus the rows and the
power/auxiliary gap. The page's **free area** is the frame's drawing area **above the title
block**: x from the frame's left to its right line, y from 2 mm above the title block's top line
(52 mm above the paper's bottom on every built-in sheet) up to the frame's top line.

For the **automatic** placements (`auto`, `below`, `right`, and the project default):

1. The table is placed as today. If its box lies in the free area, nothing changes.
2. Else, if the placement was `auto` or `below`, the table moves **right of the head** (the
   `right` placement). If that box lies in the free area, it is used.
3. Else the table is **lifted**: moved up until its bottom is on the free area's bottom. It is also
   pulled left if it runs past the frame's right line. A table taller than the free area is drawn
   from the top of the free area down and may still run into the title block; that needs more
   than 60 rows on A3, beyond `MAX_POLES` (32).

A table placed by the user (`at dx,dy`, Move Mirror Table) is never moved. If its box enters the
title block, Checks shows a warning: `The contact table of -K01 overlaps the title block on page
110.` with **Go to** and **Move table…** (starts `mirrormove`). Owner question Q3.

### 4.2 What the user sees

Nothing new to learn: a coil low on the page has its table to its right, or lifted, instead of
over the title block. The `contacts` reply gains `table: {top: [x,y], bottom: y, placement:
"auto", shown: "right" | "lifted" | "as placed"}`. `shown` says which step of §4.1 was used, and
the hover over the table's top bar says the same: `Contact table of -K01 (moved right: no room
below).`

### 4.3 Cost

Computing the box is O(rows), done where the table is already computed. The free area is a
constant of the page's sheet, which the xref map already watches (`SetProperty` page sheet;
`SetProjectSettings` sheet is its wide case).

## 5. Continuation sheets numbered in sequence (brief scope 2d)

### 5.1 Numbers

Sheet *i* (0-based) of a generated page numbered `N` is numbered:

- `N` with its trailing digits plus *i*, keeping their width (`400` → `400, 401, 402`; `0090` →
  `0090, 0091`; `B10` → `B10, B11`);
- for a number without trailing digits, `N`, then `N2`, `N3`… (`BOM` → `BOM, BOM2`).

This applies to every generated kind (BOM, contents, revision list, terminal plan, cable
schedule). The ` (2/3)` suffix on the page title stays, so a reader still sees the sheets belong
together.

### 5.2 Where the numbers show

| Place | Today | Now |
| --- | --- | --- |
| Page box of sheet *i* | `400` on every sheet | its own number |
| Next box | `400` on all but the last | the next sheet's number; the last sheet: the next page's |
| Next box of the page **before** | `400` | `400` (unchanged) |
| Total | sheets in the book | unchanged |
| Contents page | `400  BOM by location` | `400–402  BOM by location` (one row per page, its range) |
| Print Book "Pages" field | `400` selects the page | unchanged; `401` also selects page 400 (all its sheets) and the notes say `401 is sheet 2 of page 400; the whole page is printed.` |
| Project panel, Pages list | `400` | `400–402` in the number column, right-aligned as today |
| `pageprops {page}` reply | | adds `sheet_numbers: ["400","401","402"]` |

### 5.3 Clashes

A continuation number can be the number of another page: `402` exists and the BOM grows to four
sheets.

- **Typing a number** (`pageprops`, `newpage` with `number`, the number field in the Project
  panel) counts continuation numbers as taken: `Number 402 is sheet 3 of page 400 (BOM by
  location).`, the same refusal style as 019 §6.1.
- **`newpage` without a number** skips them, as it skips numbers in use.
- **A table that grows** cannot be refused: the data changed, not a number. Checks shows a warning
  `Page 400 (BOM by location) now runs to 403, and page 402 has that number.` with **Go to** (page
  402) and **Renumber…** (opens page 402's number field). The book still prints. The two sheets
  share a number until the user fixes it.

## 6. A pending revision in the title block (brief scope 2c; owner answer Q23)

### 6.1 When it shows

The project is **pending** when, after the newest issued revision, it holds an edit that is still
in effect:

- walk the undo stack from its top (`Ledger::stacks().0`) down;
- the first transaction that issues a revision (`revisions::issue_in`) ends the walk: **not
  pending**;
- the first edit or merge (`TxKind::is_edit`) whose ops are **not** all `SetProperty(Project,
  rev.<pending n>.*)` ends it: **pending**. Filling in the next revision's row is not a drawing
  change;
- no issue found on the stack: if an issued revision exists (issued before the snapshot the stack
  starts from), **pending** when the stack holds any such edit, else not. With no issued revision
  there is no marker.

Undo is part of this: editing after an issue and undoing the edit leaves the issue on top, so the
marker goes away. Undoing the issue itself makes the previous issue the newest, and the walk runs
again from it.

A project opened read-only at an issued revision (`openrevision`) is never pending.

### 6.2 How it shows

The project setting `revisions.pending` (§10, FP3) chooses the style:

| Value | Rev box | Cover |
| --- | --- | --- |
| `star` (**default**) | `D*` | `Revision D, 2026-11-10 (changed since)` |
| `draft` | `E (draft)`: the pending row's rev, else the suggested next (`revisions::pending_rev`) | `Revision E (draft)` |
| `off` | `D` | `Revision D, 2026-11-10` |

The Rev box keeps its 5 mm height (`TitleRev`) and is fitted by `frame::fit` (`E (draft)`
narrows to about 0.6 width in the 23 mm box). The revision table lists only issued revisions,
as today. The Print Book notes add `The drawing has changed since Rev D; the title block shows
D*.` when pending, so nobody prints a pending book by mistake.

### 6.3 Cost

The Project keeps a `pending: bool`. A commit sets it in O(1): an issue clears it; a qualifying
edit sets it; a pending-row edit leaves it. Undo, redo and open run the walk once. The walk is
bounded: it stops at the first decisive transaction, or after 10,000 entries, which count as
pending. A transaction the ledger cannot read (before the base and not in history) also counts as
pending: when unsure, say "changed". The frame is redrawn only when the flag **flips** (§9).

## 7. Revision table columns per project (brief scope 2b)

### 7.1 The setting

Project property `revisions.columns` (FP2): a comma list of columns in order. Each is
`field[:Header][@width]`:

```
rev, date, ecr:ECR, description, drawn, checked, validated:Validated, verified:Verified
```

- `field`: one of the six built-ins (`rev`, `date`, `description`, `drawn`, `checked`,
  `approved`), or a **custom field**: 1–20 characters `a-z 0-9 _`, not `issued` or `released`.
- `Header`: what the column says (1–20 printable characters). Default: the built-in's word (`Rev`,
  `Date`, …), else the field in upper case.
- `@width`: millimetres on A3, 6–200. Defaults: `rev` 12, `date` 24, `drawn`/`checked`/`approved`
  22, custom 20. `description` takes what is left.
- `rev` and `description` must be in the list, because issuing needs them (019 Q7); at most 10
  columns. Absent or empty means the six built-ins in today's order, so old projects look the
  same.
- If the fixed widths leave `description` less than 30 mm, all widths scale down to fit and the
  texts are narrowed by `fit`. The dialog says `Columns are narrowed to fit the 170 mm revision
  table on A3.` The setting is never refused for its width.

Refusals (words under the field, nothing written): `"ecr!" is not a field name. Use 1 to 20
letters, digits or _.` · `Rev and Description must be columns.` · `At most 10 columns.` ·
`"issued" is set by issuing.`

### 7.2 Custom fields

A custom field is stored as `rev.<n>.<field>` like the built-ins. `revisions::Revision` gains
`extra: BTreeMap<String, String>`, and `list` reads every field except `issued` and `released`.
The rules are the built-ins' rules: the pending row is edited with `revision {…, fields: {ecr:
"ECR-114"}}`; issued rows refuse edits (`Rev A is issued and cannot change.`); issuing needs only
rev, description and drawn. A field removed from the columns keeps its stored values: the table
hides it, nothing is deleted.

### 7.3 Where the columns show

- **Title block** revision table (019 §4): header and rows from the columns, in order, across the
  table's width (170 mm on A3; wider sheets stretch `description` as today).
- **Revisions window** (019 §7.2): one input per column for the pending row, read-only cells for
  issued rows.
- **Revision list** generated page (024 §5.2): the columns, then `Version`, across the page
  width.

### 7.4 Editing the columns

Project Properties ▸ Revisions group ▸ **Columns…** opens a small window:

```
┌ REVISION COLUMNS ───────────────────────────────── [x] ┐
│ Field         Header          Width                   │
│ rev           [Rev        ]   [12 ]          [↑][↓]    │
│ date          [Date       ]   [24 ]          [↑][↓][x] │
│ ecr           [ECR        ]   [20 ]          [↑][↓][x] │
│ description   [Description]   (rest)         [↑][↓]    │
│ …                                                      │
│ [Add field ▾]  (approved, a new field…)                │
│ Columns are narrowed to fit the 170 mm table on A3.   │
│                                         [OK] [Cancel]  │
└────────────────────────────────────────────────────────┘
```

`rev` and `description` have no remove button. OK writes `projectprops {revision_columns:
"…"}` (one transaction `Project properties`); Esc or Cancel writes nothing. Read-only project:
inputs read-only, OK hidden.

## 8. Tag style (brief scope 2a)

### 8.1 The setting

Two project properties (FP1):

| Key | Values | Absent means |
| --- | --- | --- |
| `tags.dash` | `yes`, `no` | `yes`: tags written with a leading `-` |
| `tags.case` | `upper`, `typed` | `upper`: tags written in upper case |

Shown in Project Properties as a **Tags** group: `[x] Leading - on tags` and `Case [Upper case ▾
| As typed]`, with a live example under them: `k5 is written -K05` / `k05` / `K05`.

### 8.2 What it changes

The tag style is a **writing** rule, applied where a tag is stored, not where it is shown.
`tag::normalise` and `tag::format` take a `tag::Style { padding, dash, case }` in place of the
padding alone. Everything that shows a tag (symbols, references, reports, BOM, terminal plan,
Properties panel, Checks) shows the stored text and needs no change. Identity is untouched:
`tag::key` already ignores case and an optional leading `-`, so `K01`, `-K01` and `k1` remain one
device, and every index keyed on `key` stays valid.

| Typed | dash yes, upper (today) | dash no, upper | dash no, typed | dash yes, typed |
| --- | --- | --- | --- | --- |
| `k5` (padding 2) | `-K05` | `K05` | `k05` | `-k05` |
| `M02a` | `-M02A` | `M02A` | `M02a` | `-M02a` |
| `N01 Slot02` | `-N01 SLOT02` | `N01 SLOT02` | `N01 Slot02` | `-N01 Slot02` |
| `-K1` | `-K01` | `K01` (the `-` dropped) | `K01` | `-K01` |
| `=PWR` | `=PWR` | `=PWR` | `=PWR` | `=PWR` |

With dash `no`, a typed leading `-` is dropped. `=` and `+` (function and location) are never
touched. Provisional tags follow the same rule (`-K?3` → `K?3`). Cable tags (`-W04`) and strip
tags (`-X01`) are tags and follow it too.

### 8.3 Tags written by ECAD

New tags from a prefix (place with automatic tag, renumber, finalise provisional, merge renames)
go through `tag::format(prefix, n, &style)`:

- **dash** as set;
- **case**: `upper` writes the prefix in upper case (today). `typed` keeps **each tag's own
  letters** when it renumbers a tag (`k05` → `k03`). A new tag uses the prefix as it is written in
  the project's prefix list (upper case unless the user typed it otherwise there).

Owner question Q5.

### 8.4 Changing the style of a project with tags

Changing `tags.dash` rewrites every existing component and cable tag **in the same transaction**
(`Project properties`): one `SetProperty(tag)` per tag whose stored text changes. The echo is
`Tag style: no leading -. 214 tags rewritten.` One undo puts the setting and every tag back. It
is O(tags), on an explicit command, like renumber.

Changing `tags.case` to `typed` rewrites nothing: the typed case of existing tags was not kept, so
they stay in upper case, and new or retyped tags keep their case. The echo says `Tags typed from
now on keep their case; existing tags are unchanged.` Changing it back to `upper` upper-cases
every tag in the same transaction, as above. Owner question Q4.

A rewrite that would make two tags equal is impossible, because `key` ignores what changes. The
transaction is checked anyway: a clash refuses the whole change with the two tags named.

### 8.5 Commands

`projectprops {…, tag_dash?: bool, tag_case?: "upper"|"typed"}`. No fields: the reply includes
`tag_dash`, `tag_case` and `tag_padding` (today's `tag_padding` stays).

## 9. Update maps (`ecad/CLAUDE.md`, "Derived views scale with what changed")

Each view below lists the ops that change it and what it does for each. **Every other op leaves

## 10. Format proposals (for the overseer)

All are project properties. They are additive, and older builds ignore them: older builds read
`properties` as a free map, and `revisions::list` skips fields it does not know, which was checked.

| FP | Key | Values | Old builds |
| --- | --- | --- | --- |
| FP1 | `tags.dash`, `tags.case` | `yes`/`no`; `upper`/`typed` | Ignore the setting. Tags are strings and read the same. `key` matches with or without `-` and in any case. An old build that re-types a tag writes it in its own style |
| FP2 | `revisions.columns`; custom fields `rev.<n>.<field>` | §7.1 grammar; field `a-z 0-9 _` 1–20 | Show the six built-ins. Custom fields are kept in the file and not shown |
| FP3 | `revisions.pending` | `star` (default when absent), `draft`, `off` | No marker |

Property keys with a dot are already used by commands (`numbering.provisional`,
`numbering.high.<P>`). The user's "Other properties" cannot type them (`a-z 0-9 _`), and the
`tags.` and `revisions.` prefixes join the reserved list (019 §7.1).

Continuation numbers, the contact table's position, the missing mark and culling are derived or
printing-only: no format change.

## 11. `table` on an ECAD page (brief scope 3)

### 11.1 Decision proposed: refuse it cleanly (owner question Q9)

Making it work would mean recording a CADCraft table entity as many ECAD items. That is one
entity to many items in `translate.rs`, which is on the tester's expensive list, and the result
would be lines and texts that can no longer be edited as a table. The pack's real need was a
fuse list, which is a generated report (roadmap 2.9). So `table` is refused before anything is
written:

> Tables can't be placed on ECAD pages yet. Draw it with lines and text, or add a generated page
> for lists (New Page ▸ Generated).

### 11.2 The refusal words for every kind

The broken plural is fixed for every kind: `convert::kind_name` gives the plural phrase directly
instead of adding `s`.

| Kind | Words |
| --- | --- |
| table | the §11.1 text |
| hatch | `Hatches can't be placed on ECAD pages yet. Draw the outline with lines.` |
| dimension | `Dimensions can't be placed on ECAD pages yet.` |
| multiline text | `Multiline text can't be placed on ECAD pages yet. Use single-line text.` |
| anything else | `Objects of this kind can't be placed on ECAD pages yet.` |

The "has properties ECAD pages do not record yet" message is lane T's (`justify`, Q2) and is not
touched here.

## 12. Questions for the owner, each with a recommendation

1. **Upstream patch for PDF culling.** The size problem is in CADCraft's plotter (§0.1): each
   page writes the whole book. No ECAD-only fix exists, because the plot hook takes one drawing
   and ECAD writes no PDF itself. Approve a small, generic patch in `crates/io/src/pdf.rs` (and,
   if the worker finds it cheaper, `crates/render`) that skips what lies outside a page's window,
   listed in `UPSTREAM-PATCHES.md`? **Recommend yes.** Offer it upstream to CADCraft too: it is not
   ECAD-specific.
2. **Missing-data mark:** `?` in a thin box; yellow on screen, black when printed in either colour
   mode (§3)? **Recommend yes.**
3. **Contact tables:** an automatic table that would hit the title block moves right of the coil,
   else lifts above the title block. A table the user placed stays where it is, with a Checks
   warning (§4.1)? **Recommend yes.**
4. **Tag style is a writing rule.** The style applies when a tag is stored, not when it is shown.
   Changing the dash rewrites existing tags in the same undoable transaction. "As typed" applies
   to tags typed from then on, because the typed case of existing tags was never kept (§8)?
   **Recommend yes.** A display-only style would mean changing every place that shows a tag, in
   four lanes' files, and still could not show the typed case.
5. **Case of tags ECAD writes under "as typed":** renumber keeps each tag's own letters; new tags
   use the prefix as written in the prefix list (§8.3)? **Recommend yes.**
6. **Custom revision fields** (§7): free fields such as `ecr`, `validated`, `verified`, with a header
   and width each, fixed after issue like the built-ins; widths scale down rather than refuse?
   **Recommend yes.**
7. **Pending marker** (§6): default `D*`; an edit is anything still on the undo stack after the
   issue except filling in the next revision's row; shown in the Rev box and on the cover, and
   noted when printing? **Recommend yes.**
8. **Continuation numbers** (§5): `400, 401, 402`, or `BOM, BOM2` without digits. They count as
   taken when a number is typed. A clash caused by a growing table is a Checks warning, not a
   refusal? **Recommend yes.**
9. **`table`:** refuse it in clean words with a way out, and leave placed tables to the report
   generator (2.9) (§11)? **Recommend yes.**

| AC2 | Pages look the same | 3-page book, each page rendered through the PNG device before and after culling: identical pixels |
| AC3 | Bench | `print25` before/after: bytes and time recorded in the worker's report (release build, 25 pages) |

| AC6 | Contact table, user placed | `mirrormove` into the title block: table stays (`"as placed"`); Checks lists `overlaps the title block` |
