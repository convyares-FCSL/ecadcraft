# Design 016: Project panel, one active page, read-only preview

Brief: `docs/briefs/016-project-tab.md` (Approved 2026-11-08, with its 2026-11-08 update: one
active page plus a read-only preview). Follows `docs/design/008.md` §2 (click-first, one commit =
one JSON-equivalent transaction, Esc writes nothing, feedback in words, never crash) and reuses
010's page commands and Go to Reference. Tokens: `docs/design/tokens.md` (this spec adds two, §9).
Open questions with recommendations: §13.

**No `.ecad` format change, no new op, no new engine command, no MCP change.** Everything the
panel writes goes through `newpage`, `renamepage` and `movepage` as they are. The panel and the
preview are trial UI (`apps/ecad-trial`), like the debugger.

## 0. What the code has today (checked)

- Page commands: `newpage {title}` (appends, then opens), `openpage {page}`, `renamepage {page,
  title}`, `movepage {page, index}` (`crates/ecad-cadcraft/src/commands.rs`).
- **No page-delete command.** `Op::RemovePage` exists (rename and move use it) but no command
  removes a page. Delete is **out of scope** (brief scope 2); the panel shows no Delete.
- Each open page is its own CADCraft document and file tab (`Project::open_page`); a commit
  redraws the page in front and marks other open pages `stale` (014, `Project::redraw_front`).
- Undo and redo (`Project::history`) work out `pages_touched` but never change the page in front:
  the brief's bug (an undo changed a page that wasn't visible).
- CADCraft lays out: file tabs on top (`cc_file_tabs`), Tool Sets on the left (with a 22 px strip
  when collapsed), palettes on the right (300 px); the trial adds its banner and, when open, the
  debugger on the right.

## 1. Goal

The user sees every page of the project in a list, makes any one of them the single editable page
with one click, and can glance at another page (the other end of a reference) without leaving it.

## 2. Placement and look

### 2.1 Where

A **left-docked panel** (`egui::Panel::left("ecad_project")`, laid out by the trial before
`cad.ui`, so it sits at the far left, below the banner and left of Tool Sets). No upstream change.

- Width: default **220 px**, resizable **160–360 px**. Shown by default whenever a project is open.
- **Collapse:** a `ChevronLeft` button in its header collapses it to a **22 px strip** like
  CADCraft's Tool Sets strip (fill `cad.chrome`, `ChevronRight` at the top, the whole strip
  expands it, hover text `Project`). Width and collapsed state last for the session only (the
  trial saves no window state).

Rejected: a tab in Tool Sets (a list does not fit its button groups, and switching tabs would hide
the ECAD tools); a right dock (the palettes and debugger are there).

### 2.2 Layout

```
┌ PROJECT ─────────────── [+][^][v][P][<] ┐  header 26 px, fill cad.chrome
│ demo  ·  12 pages                        │  sub-header, cad.text_dim
├──────────────────────────────────────────┤
│   1  Supply                              │  row 20 px
│ ▌ 2  Field                               │  active row
│   3  Motor control                   [P] │  previewed row (Preview icon)
│   4  Terminal strip X1 and X2 cabin…     │  long title cut with …, full title on hover
│                                          │
└──────────────────────────────────────────┘
```

- Header: label `PROJECT` (CADCraft section header text), then icon buttons, 18×18, as the file
  tabs draw them (`icons::paint`): **New page** (`Plus`), **Move up** (`ChevronUp`), **Move down**
  (`ChevronDown`), **Preview** (`Preview`), **Collapse** (`ChevronLeft`).
- Sub-header: project name, `·`, `<n> pages` (`1 page`), `cad.text_dim`, small text. Read-only
  project: `· read-only` appended.
- Rows: monospace. Number right-aligned in a 4-character column (`  1` … `500`), two spaces, the
  title, cut with `…` to fit; hover shows `Page 4: <full title>`.

### 2.3 Row states

| State | Look |
| --- | --- |
| Active (shown in the drawing tab) | fill `cad.tab_active`, text `cad.text`, a 3 px bar in `cad.accent` at the left edge |
| Not active | no fill, text `cad.text_dim`; hover fill `cad.chrome` |
| Keyboard cursor (panel armed, §3.3) | 1 px `cad.accent` outline around the row, on top of the above |
| Previewed (§5) | a `Preview` icon (12 px, `cad.text_dim`) at the right end of the row |
| Unavailable (its projection failed) | title followed by ` (unavailable)` in `ecad.orphan` red |
| Being renamed | the title replaced by a text field (§3.2) |
| Drag in progress | the dragged row at 50 % opacity; a 2 px `cad.accent` line where it will land |

"Open versus closed" from the brief collapses into **active or not**: with one active page there
are no other open tabs. When the project's drawing tab has been closed, no row is active.

### 2.4 Panel states

| State | Panel shows |
| --- | --- |
| No project | `No project open.` (`cad.text_dim`), header buttons hidden |
| Normal | as above |
| Read-only project | list, click, Preview work; New, Move up/down, rename and drag disabled (dimmed, hover `The project is read-only.`) |
| A command is running | a row click first cancels it as Esc would (nothing written, CADCraft's `*Cancel*` echo), then acts |

## 3. Interactions

All writes run the command's JSON form through the same path as the banner's Command field, so
each is exactly that command's transaction with one `u` (brief AC2).

### 3.1 Mouse

| User does | Result |
| --- | --- |
| Click a row | That page becomes the active page (§4.1), as `openpage {page}`. Already active: nothing. The panel becomes **armed** (§3.3); keyboard input otherwise still reaches the command line. |
| Double-click a row's title | Rename in place (§3.2). The first click of the double-click has already made it active. |
| Right-click a row | Menu: **Open**, **Preview**, **Rename** `F2`, **Move up** `Alt+Up`, **Move down** `Alt+Down` (writing items disabled when read-only). |
| Drag a row (more than 4 px) | Reorder: the insertion line follows the pointer; the list auto-scrolls within 24 px of its top or bottom. Release: `movepage {page, index}` with the 1-based landing index; same place: nothing. Esc or release outside the list: cancelled. |
| **New page** (`+`) | `newpage {"title": "<n+1>"}` (n = pages before), so its title is its number; the new last page becomes active, scrolls into view and enters rename with the title selected. Enter or Esc keeps the title: one transaction in total. |
| **Move up** / **Move down** | `movepage` of the cursor row (else the active row) by one place. Disabled at the ends. |
| **Preview** (header) | Previews the cursor row (else nothing is selected: `Click a page first.` in the hover). |

### 3.2 Rename in place

- A single-line text field over the title, monospace, full title selected.
- **Enter** or clicking elsewhere: `renamepage {page, title}` with the trimmed text. Unchanged:
  no transaction. Refused (empty, over 200 characters, control characters): the field stays open
  with a 1 px `ecad.orphan` outline and the command's message under it in `ecad.orphan`, small
  text.
- **Esc:** field closes, nothing written.
- The drawing tab's title and every reference text follow (010; renames do not change `/n.c`).

### 3.3 Keyboard

The panel never takes text focus, so typed commands keep reaching CADCraft's command line. After
a row click (or a header button) it is **armed** and handles only these keys, consuming them before
CADCraft sees them; any other key, or a click in the drawing, disarms it.

| Key | Action |
| --- | --- |
| Up / Down | Move the keyboard cursor (does not switch the page) |
| Home / End, PgUp / PgDn | Cursor to first / last, or by one visible page of rows |
| Enter | Make the cursor row active |
| F2 | Rename the cursor row |
| Space | Preview the cursor row (again: close the preview) |
| Alt+Up / Alt+Down | Move the cursor row up / down (`movepage`) |
| Esc | Disarm (and cancel a rename or drag in progress) |

### 3.4 Live (brief scope 3)

Per frame the panel compares the project's ledger head (one integer) with the head of its own copy
of `(page id, title)` in `page_order`. Only when it differs does it rebuild the copy, reading
`page_order` and page titles only: O(pages), never O(items), and never per frame. So undo, redo,
`newpage`/`renamepage`/`movepage` typed or run by command, and reopening a file all show at once
with no refresh button. The project is read under `try_lock`; busy means the previous copy stays.

## 4. One active page (brief scope 7)

### 4.1 The single drawing tab (recommended)

The project has **exactly one CADCraft document**, the **page window**, so exactly one file tab.
CADCraft's tab strip stays as it is (Start tab, `+`, other non-ECAD drawings); no upstream change.

- Tab title: `<project> - page <n>: <title>` (follows renames and moves), `*` when unsaved as now.
- **Switching** to page P: cancel a running command (as Esc); remember the old page's view (centre
  and zoom) for this session; project P into the **same** document (replace its drawing and handle
  map, `revision + 1`, clear selection and grips, as `refresh_page` already replaces a drawing);
  restore P's remembered view, or zoom to extents the first time P is shown; retitle the tab. The
  next frame shows P; no frame shows P's title over the old drawing.
- **Closing the tab** leaves the project open (banner) with no active page; the panel still lists
  every page and one click shows the clicked page again (brief AC5).
- The `stale` marking of 014 is removed: only the active page is ever drawn, and edits redraw only
  it.

Rejected alternative: removing CADCraft's tab strip for ECAD and letting the panel replace it
(needs an upstream seam in `chrome.rs`, and the strip still serves non-ECAD drawings). An
acceptable implementation variant is closing the old document and opening a new one per switch,
**only if** the user sees the same thing: one tab that never flickers and per-page views
remembered.

### 4.2 What switches the active page

| Trigger | Becomes active | Then |
| --- | --- | --- |
| Panel click / Enter / context **Open** | that page | view as §4.1 |
| `openpage {page}` (typed, Tool Sets template, MCP) | that page | as today's result `{page, document}`; `document` is the page window's uid |
| `newpage` | the new page | zoom extents (empty page: CADCraft's default view) |
| Go to Reference (`cablegoto`, 010 §4.5) | the other end's page | centred on the other end at the current zoom, its point selected (unchanged from 010) |
| Undo / redo (§4.3) | the page it changes | the change is visible |
| Preview's **Open page** (§5.3) | the previewed page | the preview's view becomes the page's view |

MCP (`ecad-mcp`) runs its own headless session with the same project code, so the same rule holds
there: `openpage`, `newpage` and `cablegoto` switch the session's one active page and every
active-page command acts on it. No tool is added. (The trial and an MCP session never edit one
project at once: the writer lock.)

### 4.3 Undo and redo bring their page to the front (brief AC8)

Before applying, `Project::history` already has `pages_touched(doc, ops)`. After applying:

1. A set that contains the active page: stay (the change is visible here).
2. A non-empty set without it: switch to the **first touched page in page order**, then redraw.
3. Page ops (`None` today): an undo or redo that **adds** a page makes it active; one that
   **removes the active page** makes the page before it in order active (else the first page);
   rename and move stay.
4. No active page (tab closed): open the page per rules 2–3.

Reference texts on other pages changing (derived) never switch the page. When the page switched,
the echo adds one line after CADCraft's undo echo: `Page 2 "Field" brought to the front.`

### 4.4 Tool Sets

The Pages group keeps **New Page**, **Open Page**, **Rename Page**, **Move Page** unchanged (they
remain the typed path). Wiring gains one button after **Go to Reference**:

| Element name (id) | Label | Does | Tooltip |
| --- | --- | --- | --- |
| `ecad.cablepreview` | Preview Reference | With a cable reference selected (its point or text), opens the preview on its other end (§5) | `Preview the other end of the selected cable reference without leaving this page` |

No selection, or not a reference: echo `Select a cable reference (its point or text), then click
Preview Reference.` Orphan: `This reference has no other end (orphan).` No command is started, no
transaction, works on a read-only project.

## 5. The read-only preview (brief scope 8)

### 5.1 Where and how it looks

A **floating window over the drawing area** (`ecad.preview`), one at a time. Default 480×320 px,
at the top-right of the drawing area, 12 px in from its edges; movable by its title bar, resizable
(min 240×160, max 80 % of the drawing area). Square corners, 1 px `cad.border`, no shadow.

```
┌ [lock] PREVIEW  page 2: Field   read-only  [Open page] [x] ┐  title bar 22 px, cad.chrome_dark
│                                                           │
│        (page 2 drawn on cad.canvas, no grid,              │
│         no grips, no hover lens)       ◯ /1.2             │  ring on the target reference
│                                                           │
└───────────────────────────────────────────────────────────┘
```

**Shows it can't be edited:** the `Lock` icon and the word `read-only` in the title bar; an arrow
pointer (never CADCraft's crosshair) over it; no selection, grips, snaps or hover lens; clicks
inside never reach the drawing or the command line.

### 5.2 Drawing it

ECAD projects the previewed page from the model (the projection already used for pages, including
the derived reference texts on `ECAD-CABLES`), builds a display list and rasterises it at the
window's pixel size with `cadcraft-render` (`pipeline::build`, `raster::render`), and shows the
image as an egui texture. A dependency of `ecad-trial` on the existing `cadcraft-render` crate is
not an upstream patch. Over the image the trial draws, for a reference preview, a ring of
`ecad.preview-ring` around the other end's point in `ecad.reference`. Terminal and wire-end marks
are not drawn in the preview (out of scope).

It is drawn **when shown** and again only on: a resize, a zoom or pan inside it (at most once per
frame), or a commit, undo or redo whose touched pages, or whose reference-text changes (010's
`Snapshot::pages_changed`), include the previewed page (Q4). Nothing else; never per frame.

### 5.3 Open, use, close

| User does | Result |
| --- | --- |
| **Preview Reference** with a reference selected | Preview of the other end's page, centred on the other end's point, spanning `ecad.preview-span` across; ring on it. |
| Panel: **Preview** button, Space, or context **Preview** on a row | Preview of that page at zoom extents. The active page itself: `This page is already shown.` (hover/echo), nothing opens. |
| Wheel inside it | Zoom about the pointer |
| Drag inside it (left or middle button) | Pan |
| **Open page** (`ecad.preview.open`) or double-click inside | That page becomes active with the preview's view (§4.2); preview closes |
| **×** (`ecad.preview.close`), Esc with the pointer over it, or Space on its row again | Preview closes |
| Opening another preview | Replaces this one |
| The previewed page becomes active by any route | Preview closes |
| The previewed page stops existing (undo of New page) | Preview closes; echo `The previewed page no longer exists.` |
| Project closed | Preview closes |

The preview never records a transaction and never changes the selection, view or history of the
active page (brief AC9).

## 6. Speed (brief AC7)

014's bench (`switch_pages`, native Windows 11, release): first view of a page ≈ 0.5 ms medium,
≈ 1.3 ms large (500 pages). With one page window, every switch reprojects, so every switch costs
about a first view. **Proposed targets**, median over the bench's spread pages, both histories:

| Bench column (replaces `1st view` and `back`) | What it times | Target, large | Target, medium |
| --- | --- | --- | --- |
| `switch ms` | `openpage` of another page in a headless session with one page active, until that page is the active page | **≤ 5 ms** | ≤ 2 ms |
| `preview ms` | Project, build and rasterise one page at 480×320 | **≤ 15 ms** | ≤ 8 ms |

Both are far below one 60 Hz frame (16.7 ms), so a switch shows on the next frame. The report
states pass or fail against these figures.

## 7. Scale: 500 pages (brief AC4)

- The list is virtualised: `ScrollArea::show_rows` with the fixed 20 px row height draws only the
  visible rows (about 30), whatever the page count.
- Per frame: one head comparison plus the visible rows. Rebuilding the copy is O(pages) and happens
  only when the head changed. No per-frame work touches items.
- Drag auto-scroll and PgUp/PgDn work over all 500. Making a row active scrolls it into view.
- Evidence: a test or bench figure on the large project (`--keep`) giving the panel's frame cost
  with 500 pages against without the panel (no measurable difference), and the rebuild time after
  one `renamepage`.

## 11. Quick start: section "5E. Project panel (by clicking)"

On `demo.ecad` (or after 5D, which leaves two pages):

1. **See the pages.** The **PROJECT** panel on the far left lists `1 Supply`, `2 Field`; the shown
   page is highlighted and named in the single drawing tab.
2. **Switch.** Click `Field`: it replaces `Supply` in the same tab. Click `Supply` again.
3. **New page.** Click **+**: page 3 appears, active, its title selected. Type `Spare`, Enter.
4. **Rename.** Double-click `Spare`, type `Spare 2`, Enter. Type `u`: back to `Spare`.
5. **Reorder.** Drag `Spare` above `Supply`: it becomes page 1, and the reference texts on the
   other pages change their page numbers. Click **▼** twice to put it back.
6. **Undo brings the page.** On `Field`, draw a wire. Click `Supply`. Type `u`: `Field` comes to
   the front with the wire gone.
7. **Preview.** On `Supply`, click the magenta reference point, then **Preview Reference** (ECAD
   tab, Wiring). A read-only window shows `Field` at the other end. Scroll to zoom, drag to pan;
   nothing in it can be selected. Click **×**. Click `Field`'s row, press Space: a preview of the
   whole page; **Open page** makes it active.
8. **Closed tab.** Close the drawing tab: the panel still lists every page; click one to show it.

§6 step 3 (pages as several tabs, reopening with an ID from `ecadinspect`) is replaced by a pointer
to 5E. §9 (limitations) gains: no Delete page; the preview shows no terminal marks; page views are
remembered for the session only.

## 12. Future (noted only, not built)

The panel is the natural home for project lists, each a derived view updated from the touched set:
cables (with their pages and references, orphans flagged), components by tag, cable references
and orphans, and search across titles. Also page folders or sections, page templates and title
blocks, a thumbnail per row, Delete page (needs a command and its rules), and a hover-to-preview on
references (needs a CADCraft click/hover seam, 010 Q6–Q7).

## 13. Open questions for the owner, each with a recommendation

1. **Tab strip:** keep CADCraft's tab strip with exactly one ECAD tab (the page window), or replace
   it with the panel? **Recommend one tab** (§4.1): no upstream change, the strip still serves other
   drawings, and the tab shows which page is active.
2. **Where the preview sits:** floating window over the drawing, a split of the drawing area, or a
   section of the Project panel? **Recommend the floating window** (§5.1): at 1280 px the panel,
   Tool Sets and palettes leave too little width for a split, and a 220 px panel section is too
   small to read a reference's surroundings.
3. **Opening a preview from a reference:** select it, then **Preview Reference** (and from the
   panel)? **Recommend yes for now**; opening it straight from the hover or a modifier-click needs
   a CADCraft seam (010 Q6–Q7), later.
4. **Preview after edits:** redraw it once when a commit, undo or redo touches its page or that
   page's reference texts (O(touched), never per frame), or freeze it until reopened? **Recommend
   redraw on touch**: AC9 asks it to stay correct after moves, renames, undo and redo, and it
   costs nothing when nothing touches it. Freezing it with an "out of date" bar is the alternative.
5. **Double-click on a row:** rename in place, or something else (zoom extents)? **Recommend
   rename** (single click already opens; a stray double-click is harmless: Enter on an unchanged
   title writes nothing).
6. **Up/Down:** move a cursor and switch on Enter, or switch on every arrow press? **Recommend cursor
   plus Enter**, so walking a 500-page list does not reproject 500 pages and leave view memories on
   each.
7. **Speed targets:** `switch ms` ≤ 5 ms and `preview ms` ≤ 15 ms on large (§6)? **Recommend
   approve**: four times the measured 1.3 ms leaves room for the view restore and the tab retitle,
   and both stay under one frame.
8. **New page title:** its number (`3`) with rename opened at once, or ask for a title first?
   **Recommend the number plus rename**: one click gives a page, and one transaction.
9. **Delete page:** no command exists; leave it out of 016 and write a brief for it (rules for a
   page with objects and references) later? **Recommend yes.**

## 14. Out of scope

Delete page; lists of cables, components or references; page templates, title blocks, folders and
thumbnails; terminal marks and editing in the preview; more than one preview; saving per-page
views or the panel's width to disk; multi-project tabs; any format change or new op.

## 15. Top bar removed (owner, 2026-11-08)

The trial's top banner (`apps/ecad-trial/src/lib.rs`, `fn banner`) is gone; the drawing area
gains its height. What it held moved as follows.

| Banner item | Now |
| --- | --- |
| Project status line (name, pages, file, unsaved changes) | Project panel header, under `PROJECT`, small text: `Project "demo": 2 pages, file …, 1 change not saved.` (pages now counts the project's pages, not open tabs) |
| Read-only and "last save not confirmed" warnings | Project panel header, under the status line, in the warning colour |
| New project / Open project… (no project open) | Project panel header: **New**, **Open…** (always shown; Open with a project open says to close it first) |
| Save / Save As… | Project panel header: **Save**, **Save As…** |
| — | Project panel header: **Close** (new: closing the drawing tab no longer closes the project, §4.1, so closing the project needs a button; it asks Save / Discard / Cancel as before) |
| Experiment warning (`ECAD TRIAL (experiment)…`) | Project panel header, one small line in the warning colour, `ECAD trial (experiment): keep .ecad files in a local folder.`; the full text on hover |
| Debugger / Hide debugger | Tool Sets > **ECAD Dev** > **Debugger** (toggles) |
| Export inspector snapshot (only with `--snapshots`) | Tool Sets > ECAD Dev > **Export Inspector Snapshot** (only with `--snapshots`) |
| `Command:` field with **Run**, and the template note under it | Tool Sets > ECAD Dev > **JSON Command** opens the **ECAD command window** (a small floating window: field, **Run**, the note, ×). The template buttons (Set Property, Add to Cable, Delete Electrical Object, New Page, Open Page, Rename Page, Move Page) open it with their template, as they filled the banner field. |

**Why the command field survived.** CADCraft's own command line can run `name {json}` (its
`cmdline` treats a line whose second word starts with `{` as a programmatic call), but its keyboard
handling turns a typed space into Enter. A JSON form with a space, or a page title such as
`Motor control`, cannot be typed there, and putting a template into its buffer would break at the
first space typed while editing it. Fixing that would be a CADCraft change, so the separate field
stays, in the ECAD command window.

## 16. Devices tab (owner request, 2026-11-08, after brief 018)

The Project panel has two tabs under its header: **Pages** (sections 2 to 7) and **Devices**: a
place to find, go to and edit components. No new op, command or format change: it reads brief
018's model and edits through `setprop`.

```
│ [Pages] [Devices]                        │
│ Filter: tag or text                      │  filter field
│ 3 devices                                │
│ -K  (2)                                  │  group: tag prefix, count
│ ▾ -K01    Contactor / relay coil         │  device row (selected: accent bar)
│     /1.1  Contactor / relay coil         │  its symbols: /page.column  name
│     /2.2  NO contact                     │
│ ▸ -K02    Contactor / relay coil         │
│ -Q  (1)                                  │
│ ▸ -Q01    MCB 1-pole                     │
├──────────────────────────────────────────┤
│ DEVICE -K01                              │  editor of the selected device
│ Tag          [-K01                    ]  │
│ Description  [Contactor / relay coil  ]  │
│ Maker / Part number / Location / Function│
```

| User does | Result |
| --- | --- |
| Type in the filter | The list narrows: a tag as Find Symbol matches it (`k1` finds `-K01`, `-K10`), other text matches the description, maker or part number |
| Click a device row | It is selected (accent bar), its symbols unfold, its properties show below |
| Click the ▸ / ▾ at its left | Unfold / fold only |
| Click a symbol row | Its page becomes the active page (the one page window, as `openpage` and Go to Reference), the view is centred on it at the current zoom (kept between 60 and 600 mm high) and the symbol is selected. Nothing is recorded |
| Edit a property, Enter or click elsewhere | `setprop {component, key, value}`: one transaction, one `u`, brief 018's value rules (`+` before a location, `=` before a function; empty clears). Esc puts the field back |
| A tag another device has | The refusal shows above the fields with **Make it the same device**, which runs `setprop` with `merge` (one transaction; refused with 018's reasons when the devices cannot be one) |

Accessible labels: tabs `Pages`, `Devices`; filter `Filter devices`; device row
`Device -K01: Contactor / relay coil`; symbol row `-K01 NO contact, page 2, column 2`; fields
`Tag field`, `Description field`, …; button `Make it the same device`.

**Cost (owner, 2026-11-08: act only on the ops that matter).** The list is built whole only on
open, on reload, when the tab is shown again and when the filter changes. After each commit, undo
and redo, the change log names what the ops could change in it (`device_list::devices_touched`):
`CreateComponent` / `DeleteComponent`, `SetProperty` on a component, `Link` / `Unlink` /
`ModifyRepresentation` of a component's representation and `ModifyItem` of one of its items
refresh that device only (its row is compared, so a move within the same column changes nothing;
the list is re-sorted only when a tag changed); `AddPage` / `RemovePage` (new, moved, renamed
pages) renumber the `/page.column` texts; every other op (wires, cables, plain lines, text)
changes nothing. `devupd ms` in the bench is one such refresh. The full build is a copy built from the tag index (`Document::tagged`, brief 018) and each
device's representations (the subject index), plus the components without a tag, only when the
project's change count or the filter changed, and only while the tab is shown. Rows are
virtualised (`show_rows`), so a frame lays out the visible rows only. `cargo xtask bench` reports
`devices ms` (one rebuild) and `goto ms` (show a symbol's page and select it).
