## 1. Goal

A designer places a change-over contact, RCBO, fuse bank, sensor, valve, connector or PLC card from
Find Symbol and gets a correctly numbered device with sensible connection points, the way the 21
starters work today.

## 2. Common rules

### 2.1 Geometry

As design 018 §4: millimetres, local frame, y up, rotation 0, symbol centre near (0,0), connection
points on the 5 mm grid, most symbols 20 mm tall (points at y = ±10). Mechanical links are dashed
(1.5 mm dashes, 1 mm gaps, the existing `dashed`); a vertical dashed link uses the same pattern
along y (a new helper beside `dashed`). **No arcs:** no starter has used `Primitive::Arc`, so curves
(socket cups, the RCD toroid) are short polylines. Fixed text inside a definition is graphics,
2.5 mm, and kept to a minimum; lane T's text sizes do not apply to it.

The shapes follow the forms of IEC 60617 named in each table, **drawn new for ECAD**. IEC is the
default, not the law: a project may draw its own symbols once the builder (1.1) exists. Nothing is
traced from the drawing pack or any vendor library.

### 2.2 Catalogue entries

Each new symbol is a `Starter` as today (key, name, aliases, prefix, kind, id), plus:

- `family: Family`, one of `Basic` (the 21 existing), `Contacts`, `Protection`, `Sensors`,
  `Actuators`, `Connectors`, `Plc`. `search` also matches the family word (`contacts`,
  `protection`, `sensors`, `actuators`, `connectors`, `plc`).
- `quiet: &[&str]`: connection points whose `Unconnected` check is not raised (§11, question 8).
  Empty for most.

Definition IDs are given in blocks so a family can grow without renumbering: contacts and
protection `def_id(0x100 + n)`, sensors and actuators `0x200 + n`, connectors `0x300 + n`, PLC card
bodies `0x400 + n`. An ID is never reused or changed once it has been on `dev`.

### 2.3 Kinds

| Kind | Used by | Labels when it makes a device | Labels when it joins one |
| --- | --- | --- | --- |
| `Contact { make }` (exists) | float, roller and interlock switches | `13`/`14` (NO), `11`/`12` (NC) | Next sequence digit, as 018 |
| **`ChangeOver`** (new) | `co`, `swco` | `11`, `12`, `14` | s = 1 + the highest sequence digit among the device's `s1`…`s4` labels: `s1`, `s2`, `s4`. After s = 9: `-K01 already has 9 contacts.` |
| `Fixed { exclusive: true }` (exists) | heads: RCBO, RCD, SSR input, fuse terminal, fuse bank, sensors, valves, thermocouple, heater, connector bodies, card bodies | The definition's | The definition's; refused when a label exists or the device already has a head (018 §3.1) |
| `Fixed { exclusive: false }` (exists) | `power4`, `ssrout` | The definition's | The definition's; refused when a label exists |

`symbols::changeover_labels(used, who)` holds the rule; `devices.rs` only calls it (§0). The labels
come back in definition order: common, NC, NO.

### 2.4 Properties

A device gets `description` = the symbol's name, as 018. New keys (ordinary component properties,
like 030's, so no format change):

| Key | On | Meaning | Example |
| --- | --- | --- | --- |
| `rating` | any device | Its rating as written on the drawing | `13A C 30mA`, `6.3A T`, `235W`, `K` |
| `rating.<n>` | a fuse bank | The rating of fuse output `<n>` | `rating.3 = 2A` |

### 2.5 Text

Definitions carry no text slots yet (that is 1.1, a format change). Anchors live in the catalogue,
keyed by origin like the kind and prefix, and lane T reads them (§10).

### 2.6 Words (glossary rows)

- **change-over contact**: a contact with a common, a normally-closed and a normally-open point
  (`11`/`12`/`14`).
- **fuse bank**: one device holding several fuses fed from one supply point, with a connection
  point and a rating per fuse.
- **fuse terminal**: a terminal-sized fuse holder; in v0.15 a device of its own (question 1).
- **connector half**: the plug or the socket side of a connector, drawn as a body with one
  connection point per pin. Mating the halves is M1 1.11.
- **bulkhead**: a connector through a panel wall; each pin is one connection point that wires
  reach from both sides.
- **card body**: the outline of a PLC card or CPU, with its supply points; channels join it as
  `di`/`do` symbols.

### 2.7 Defaults go through lane T's registry (owner principle, 2026-11-12)

Nothing this lane adds as a **default** is hard-coded where it is used. Each one is registered in
lane T's defaults registry (design 031 §3, append-only) and read back through it, so a later
Standards screen and the symbol editor (1.1) can manage them. The catalogue entries in §3–§6 are
the **built-in values** this lane registers, not constants the code reads directly.

| Default | Registered per | Built-in value | Read where |
| --- | --- | --- | --- |
| Tag prefix | symbol key | §3–§6's Prefix column (and the 21 starters' prefixes) | `devices::prefix_for` today reads `Starter.prefix`; it reads the registry instead, and a project's own `tag_prefixes` still wins over it |
| Connection-point labels | symbol key | §3–§6's labels (`11`/`12`/`14`, `N1`/`N2`, SSR `1`/`2`, `L+`/`M`…) | Placement and joining (§2.3) |
| Quiet points | symbol key | §3–§6's Quiet lists | `checks.rs`'s `is_quiet_point` (§0) |
| Ratings | symbol key | None: no symbol has a default rating; the registry lists `rating` and `rating.<n>` as known keys with an empty default, so the Standards screen can offer one | `setprop_rule` (§7.3) |
| Default description | symbol key | The symbol's name | Placement (018 §4) |
| Text anchors | symbol key | §10's rule and overrides | `anchors()` (§10) |

Rules:

- Registration is **append-only** in lane T's registry: one block of entries for this lane, added
  by the worker in `symbols.rs` (or wherever 031 says registrations live), never an edit of another
  lane's rows.
- **Labels and the definition.** A definition's terminal keys are part of its content hash and of
  its origin's meaning, so they stay fixed in the definition. A registered label is the default
  **label** a new device's connection point gets; the point's key stays the definition's key, which
  is how a symbol finds its points. Until the registry can change a label, label = key, exactly as
  today, so nothing changes in the file. Changing a built-in label later needs `devices.rs` (lane
  T) to write label and key separately at placement; that is the registry's work, not this lane's.
- **Kinds** (§2.3) and **geometry** are not defaults: they are what the symbol is.
- **Dependency.** At revision 2 of this design, 031 (`origin/feature/text-styles` `fe4fc5f1`) §3
  defines the text-style table and the `text_style` getter but not yet a registry for symbol
  defaults. Lane S's worker registers against the registry's API once 031 publishes it; until it is
  on the branch it builds from, the values sit in one table in `symbols.rs` behind one function per
  default (`symbols::default_prefix(key)`, `default_labels(key)`, `quiet_points(key)`), so moving
  them into the registry is one change in one place.

Notes:

- `co` puts the common on top, so a contact under a supply rail reads top-down like `no` and
  `nc`. Joined to `-K01` after a `no` (`13`/`14`) it is `21`/`22`/`24`.
- The fuse bank needs no bridge: the rail is inside the definition and `L+` is one point. Each fuse
  breaks the net, as a fuse does, because input and outputs are different points. A fault-signal
  contact is a `no` joined to the bank (`13`/`14`), as for any device. The bank's outputs do not
  count as contacts for the sequence digit, and a contact never takes an output's label: on a
  12-way bank an NC fault contact is `21`/`22`, since `11`/`12` are fuses.
- `fuseterm` is two points so it breaks the net (the pack's wire numbers change across it). It is
  not a strip position until 1.2 (question 1).

## 7. Interaction

Nothing new to learn: every symbol is placed as the 21 are.

### 7.1 Find Symbol and Place Symbol

1. The designer types in Find Symbol (`symbols`): a key, a word from the name or aliases, a prefix
   (`-Q`) or a family word (`protection`). The list shows ten rows and "n more" as today, each row
   `key  name  -prefix  labels  (symbol)`; for a fuse bank the labels read `L+/M/1/2/…`.
2. They pick a row; Place Symbol starts as today (018 §5.3): the preview follows the cursor, the
   prompt offers `Device` and `Tag`.
3. They click. A new device gets the prefix and next number (`-F01`), the definition's labels and
   its name as description; or, with `Device`, the symbol joins that device by §2.3's rules.
4. Refusals are 018's words, unchanged: `-K01 already has 9 contacts.`, `-Q01 already has a main
   symbol.`, `-K01 already has connection point 1.`

No new control, shortcut or element name. Find Symbol's empty state, read-only state and errors are
018's.

### 7.2 Setting a rating

- **Properties panel:** a device with a `rating` shows it in its property rows like any other
  property (as 030's strip keys show); a fuse bank lists `rating.1` … `rating.n`. Editing a row
  runs `setprop`.
- **JSON:** `setprop {component, key: "rating", value: "13A C 30mA"}`,
  `setprop {component, key: "rating.3", value: "2A"}`.
- The drawn rating text is lane T's (§10); until it draws `rating`, the value is stored, listed in
  Properties and searchable, and not drawn.

### 7.3 Rating rule (`symbols::setprop_rule`)

- `rating`: the 018 §6.1 value rules (at most 200 characters, no control characters, trimmed;
  empty or `null` clears).
- `rating.<n>`: the same, and only on a device whose head is a fuse bank, with `<n>` one of its
  fuse output labels. **Clearing** (`null` or empty) always works, whatever the device now is
  (review of PR #63, 2): a key left after the bank symbol is erased stays removable. Otherwise refused: `-F01 has no fuse 13.` or `rating.<n> is for a fuse
  bank's fuses; -Q01 is not a fuse bank.` `<n>` longer than 12 characters is refused the same way
  without parsing it.
- Any other key: no opinion (the call returns the value unchanged).

## 10. Text anchors (for lane T)

```text
pub enum TextRole { Tag, Description, Rating, RatingOf(String) }   // RatingOf: a fuse bank's fuse label
pub enum HAlign { Left, Centre, Right }
pub enum VAlign { Bottom, Middle, Top }
pub struct Anchor { pub role: TextRole, pub at: Pt, pub h: HAlign, pub v: VAlign, pub rotation: f64 } // local frame, degrees
pub fn anchors(s: &Starter) -> Vec<Anchor>
```

- An anchor is the **first place to try**: lane T may move text off wires and other text (Q2) and
  decides sizes, weights, visibility and whether rotated text stays upright. Anchors rotate and
  mirror with the symbol.
- **Default rule** from the box (lo, hi), mid = (lo.y + hi.y)/2: Tag at (lo.x − 2, mid), right,
  middle; Description at (lo.x − 2, mid − 4), right, top; Rating at (hi.x + 2, mid), left, middle.
- **Overrides:**
  - Fuse bank: `RatingOf(i)` at (x_i + 3, −8), left, middle, rotation 90; the bank's own Rating
    by the default rule.
  - RCBO and RCDs: Rating at (lo.x − 2, mid − 4), right, top, under the tag (Description then
    at mid − 8), as breakers carry their rating by the tag.
  - Card bodies: Tag at (lo.x, hi.y + 2), left, bottom; Description at (−13, 12), left, top,
    inside the body under the header.
  - Connector halves and bulkheads: Tag by the default rule; no Rating.
  - The 21 existing starters use the default rule (junction and continuation have none).
- Connection-point labels are not anchors: lane T places them by the point's position as today.

## 11. Limits and never crash

- The catalogue is static: about 70 new entries, each built and hashed once (`OnceLock`, as now).
  Building a definition never panics; a failed hash is an error, as today.
- `changeover_labels` reads only labels of the form `[1-9][1-4]`; it never overflows (s ≤ 9 or
  refused).
- `rating.<n>`: `<n>` capped at 12 characters before any lookup; values capped by 018's rule.
- Quiet points (question 8): `checks.rs` skips the `Unconnected` check for a point whose symbol
  marks it quiet; every other check on it still runs.
