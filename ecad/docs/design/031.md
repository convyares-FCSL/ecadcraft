### 0.2 The code today (`origin/dev` `6729c8f1`)

- **Derived texts.** `devices::texts_on_page(doc, page)` builds `DerivedText { rep, of: TextOf,
  value, at, height, halign, valign, aci }` for each symbol representation on the page: the tag
  (`TextOf::Tag`) and its connection point labels (`TextOf::Terminal(id)`); a continuation
  returns `wires::continuation_texts` instead (`TextOf::Name`, `TextOf::Places`). `project_page`
  draws them on `ECAD-TAGS` on every draw of the page, keyed by `(rep, of)` for stable handles.
- **Placement** (`texts_for`): a vertical symbol (rotation near 0° or 180°) gets its tag
  `TAG_GAP` (2 mm) left of its box, right-justified, middle; a horizontal one above, centred.
  Labels sit 1 mm beside their point. No avoidance.
- **Sizes**: `devices::TAG_HEIGHT` 3.5, `devices::LABEL_HEIGHT` 2.0, `locations::LABEL_HEIGHT`
  3.5, `look::LABEL_HEIGHT` 2.5 (cable look: core labels, wire numbers at the slash, label box,
  reference flags), `references::TEXT_HEIGHT_MM` 2.5, `xref::XREF_TEXT_MM`, frame literals 1.8 /
  2.5 / 3.0 / 3.5 / 5.0 / 7.0, generated-page literals 2.5 / 3.5, `wiring.label_height` 1.8
  (the only project setting, range 0.5–10 mm).
- **Style**: every text entity ECAD makes has `style: "Standard"`; CADCraft's `Standard` is
  `CADCraft Stroke`. CADCraft resolves a style's font through `cadcraft_fonts::TextFont::
  resolve_style` (TrueType/OpenType by family or file name, then SHX, then `FONTALT`, then
  stroke). craft-fonts faces are found by family name when the build embeds them
  (`CRAFT_FONTS_DIR`); **ECAD's builds do not set it today**.
- **craft-fonts** (manifest checked 2026-11-12): its Latin-capable faces are BIZ UDPGothic
  Regular and **Bold** (OFL-1.1; a proportional sans), BIZ UDMincho, Shippori Mincho and Noto Sans
  CJK SC (Regular only, and barred by `build.rs` as Adobe-derived). There is **no Latin-only sans**
  such as Noto Sans. The web build embeds BIZ UDPGothic Regular only.
- **Measuring**: `look::font_width` and `wires.rs` measure with `cadcraft_engine::fonts::
  line_width`, which is the stroke font's width.
- **Properties**: component keys are free text (dots allowed); project and page free keys are
  1–40 characters `a-z 0-9 _` through `projectprops` / `pageprops`; command-owned prefixes are
  reserved there (`numbering.`, `rev.`, `folder`).
- **Representations have no properties.** A symbol's own settings must live on its component,
  keyed by representation ID (§5.1), or need a format change (Q6).
- **Stale pages**: `project::pages_touched(doc, ops)` names the pages a transaction can change;
  `None` means any page.
- **`text` with `justify`** is refused by `convert::item_from` ("this text has properties ECAD
  pages do not record yet"), because `Primitive::Text { at, height, rotation, value }` cannot hold
  a justification.

## 1. Goal and words

**Goal:** a page that reads like a good printed schematic: sans font, bold tags, small sizes chosen
per project, no repeated or colliding tags, and texts that can be hidden or moved without losing
them as data.

Words (glossary): a **connection point label** is the `A1`, `13`, `1` beside a symbol's
connection point (code: `TextOf::Terminal`). A **text kind** is one row of the style table (§3.1).
A **run** is a row of adjacent symbols of one device on one page (§5.3). A **moved text** is a
derived text with a stored position (§6.3). "Derived" texts are the ones ECAD writes from data
(tags, labels, references); "free" text is text the user typed with `text`.

## 2. Fonts (Q1)

### 2.1 What the project stores

One project font family, stored as the project property `text.font` (FP1). Absent means the
built-in default `BIZ UDPGothic` (owner question Q1). Weights are the family's `Regular` and
`Bold` faces.

### 2.2 How a font is found and what falls back

1. The family's face of the wanted weight, found by CADCraft's resolver (embedded craft-fonts
   first, then the machine's fonts).
2. If the bold face is missing, the regular face (no synthetic bold on outlines).
3. If the family is missing, `BIZ UDPGothic` (the craft-fonts default).
4. If that is missing too (a build without craft-fonts and no such system font), CADCraft's
   stroke font. **Bold in the stroke font** is drawn with lineweight 0.35 mm instead of ByLayer
   (Q8), so tags still stand out on screen and in print.

The project opens anywhere (P8): a missing font never refuses anything, never changes the stored
value, and is reported, not hidden (§4.1 status line; `textstyle {}` returns `drawn_with`).

**Hostile values:** `text.font` longer than 64 characters, empty, or with control characters is
ignored (the default is used) and `textstyle` refuses it (§10.1).

### 2.3 Installing the styles into a drawing

`text_style::install(d: &mut cadcraft_engine::doc::Drawing, doc: &Document)` writes two text
styles into any drawing ECAD builds:

| Style | Font | Used by |
| --- | --- | --- |
| `Standard` | the project family, regular | free text and every regular ECAD text |
| `ECAD-BOLD` | the project family, bold (or as §2.2) | every bold ECAD text |

Setting `Standard` means free text and every existing `style: "Standard"` text (frame, generated
pages) turns sans at once, without lane P editing anything. The page projection calls `install`
(project.rs, §0.1); lane P calls it for generated pages and print drawings it builds (§7.2).

`translate.rs` already refuses user changes to the text-style table by comparing the last
projection with the edited drawing; the projection writes the same table into both, so ordinary
edits pass. The worker confirms that a `textstyle` font change, which re-projects the page,
does not reach `translate` as a user edit (tester covers it, §13 T12).

### 2.4 Measuring text

`text_style::text_width(doc, kind, value) -> f64` measures `value` at the kind's height in the
**resolved** font (`cadcraft_fonts::text_width`), falling back to the stroke font's
`line_width`; a non-finite or negative result counts as `chars × height × 0.8`. Placement (§6),
the cable look's boxes (`look.rs`) and location labels measure with it. Lane W may use it for
wire-label boxes (§7.1); it is not part of the shared contract.

### 3.3 The getter (the shared contract)

In `crates/ecad-cadcraft/src/text_style.rs`:

```rust
/// One row of the style table, resolved for this project.
#[derive(Debug, Clone, Copy, PartialEq)]
pub struct TextStyle {
    /// Height in drawing units (mm, or inches in an inch project); always finite and in range.
    pub height: f64,
    pub weight: Weight,
    /// The CADCraft text style an entity of this kind names: "Standard" or "ECAD-BOLD".
    pub style_name: &'static str,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Weight { Regular, Bold }

#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash)]
pub enum TextKind {
    Tag, PointLabel, Description, PartNumber, ContinuationName, Reference, WireLabel,
    CableText, LocationLabel, TitleValue, TitleCaption, TitleMain, Grid, Table, TableHeader, Free,
}

/// The style of `kind` in this project: the project's `text.<kind>.*` keys (and, for
/// `WireLabel`, `settings.wiring.label_height`), else the defaults of design 031 §3.2.
/// Never fails; a hostile stored value gives the default.
pub fn text_style(doc: &ecad_model::Document, kind: TextKind) -> TextStyle;
```

Rules the worker keeps, because lanes W and P rely on them:
- The name, signature and the three fields do not change in v0.15. New kinds may be added.
- It reads only `doc.properties` and `doc.settings`, through the defaults registry (§3.5): each
  kind's height, weight and font are registry entries, and `text_style` is a thin typed reader
  over `defaults::resolve`. It costs a few map lookups (it is called per text per draw).
- It lands in Q1's **first commit**, with the §3.2 defaults, before anything else in this lane, so
  lanes W and P can build on it from the branch (or from `dev` once merged). Until then they use
  their current constants.

**Styling an entity (the one entry point for other lanes, fix round of PR #67):**
`text_style::apply(doc, &mut Entity, kind)` sets a text entity's height, its style name (the
project font, or the kind's own `text.<kind>.font`, §3.5) and, for bold drawn in the stroke-font
fallback, the bold lineweight. A caller styling a whole page holds a `Look` and calls
`Look::apply` (one resolution per page). The drawing must hold the styles: `install`.

Also public (not part of the shared contract, may be used): `install` (§2.3), `text_width`
(§2.4; resolves only that kind; with a `Look` already held, `width_in`), `text_shown` (§5.2).

### 3.4 One wire-label height

The wire label height stays where it is stored today, `settings.wiring.label_height`; the getter
reads it for `WireLabel` (registry entry `text.wire_label.height` with `ProjectSource::Settings`,
§3.5), and the Text section and `textstyle` write it there (a `SetProjectSettings`). No
`text.wire_label.height` **property** is ever stored, so there is one value and one
way to set it from two places (`wiresettings` keeps working). Its default changes from 1.8 to 1.6
mm (Q3): files that never set it are written without the field, so they draw at 1.6.

### 3.5 The defaults registry (owner principle, 2026-11-12; all v0.15 lanes)

**Rule.** Every default a v0.15 lane adds (a size, a weight, a show rule, a gap, a tolerance, a
style word) is **one registry entry**. Code that needs the value asks the registry; it never
writes the number where it is used. A later Standards screen lists and overrides the entries;
this brief builds the registry and a read-only `defaults` command (§10.8), not the screen.

Not entries: **hostile-input bounds** (most candidates, most texts per page, most characters in a
key). They are guards, not preferences, stay constants beside the code they guard and say what
they prevent (house rule 12). Values that existed before v0.15 (tag padding, contact mirror,
reference style…) are not moved by this brief; a lane that changes one registers it then.

**Module.** `crates/ecad-cadcraft/src/defaults/` (L4; lanes W, P and S already live in this crate):

| File | Owner | Holds |
| --- | --- | --- |
| `mod.rs` | T | `Entry`, `Value`, `Kind`, `Level`, `Scope`, `resolve`, `all()`, the registry tests |
| `text.rs` | T | Lane T's entries |
| `wires.rs` | W | Lane W's entries (created empty by T) |
| `print.rs` | P | Lane P's entries (created empty by T) |
| `symbols.rs` | S | Lane S's entries (created empty by T) |

Append-only works by file: each lane adds `pub static` entries and appends them to the one slice in
its own file (`pub static ENTRIES: &[&Entry] = &[…]`). `mod.rs::all()` chains the four slices and
never changes again, so two lanes never edit one file. A later lane gets its own file the same way
(one line in `mod.rs`, by the lane that needs it).

**The entry.**

```rust
pub struct Entry {
    /// Stable key, also the stored property key: "text.tag.height". Lower case, dot-separated,
    /// first part the area ("text", "wire", "print", "symbol"). Never renamed once released.
    pub key: &'static str,
    /// Words for the Standards screen and `defaults`: "Tag height".
    pub label: &'static str,
    /// Group heading on the Standards screen: "Text", "Wire labels"…
    pub group: &'static str,
    /// The brief that added it: "031".
    pub brief: &'static str,
    pub kind: Kind,
    /// The built-in value; valid for `kind` (a test proves it).
    pub builtin: Value,
    /// The levels that may override it, narrowest last.
    pub levels: &'static [Level],
    /// Where the project level is stored, when it is not the project property `key`.
    pub project: ProjectSource,
}
pub enum Kind {
    /// A length in millimetres (divided by 25.4 in an inch project), in this range.
    Length { min: f64, max: f64 },
    /// A plain number (a factor), in this range.
    Number { min: f64, max: f64 },
    /// One of these words.
    Word(&'static [&'static str]),
    /// Free text of at most this many characters, no control characters.
    Text { max_chars: usize },
}
pub enum Value { Length(f64), Number(f64), Word(&'static str), Text(&'static str) }
pub enum Level { Standard, Project, Page, Object }
pub enum ProjectSource { Property, Settings(fn(&ecad_model::ProjectSettings) -> Option<f64>) }
```

Stored values are always text (properties); `Kind` parses and checks them in one place
(`Entry::parse(&self, &str) -> Option<Resolved>`). Anything that does not parse or is out of range
counts as **absent**, so resolution falls through to the next level: a hostile file never gives a
value outside the range.

**Resolution.** `defaults::resolve(doc: &Document, entry: &Entry, at: Scope) -> Resolved`,
narrowest level first, only the levels the entry allows:

| Level | Where it is read | Status |
| --- | --- | --- |
| Object | the object's property `key` (a component or conductor); for a symbol, the component's `text.<rep>.<rest of key>` (§5.1) | this brief |
| Page | the page's property `key` | this brief |
| Project | the project property `key`, or `ProjectSource::Settings` (wire label height reads `settings.wiring.label_height`) | this brief |
| Standard | a named drawing standard the project uses | **reserved**: no source until the Standards brief; `resolve` skips it |
| Built-in | `Entry::builtin` | this brief |

`Scope { page: Option<PageId>, component: Option<ComponentId>, rep: Option<RepresentationId>,
conductor: Option<ConductorId> }` says which objects to look at; `Scope::project()` looks at the
project only. `Resolved` carries the value and the level it came from (the Properties panel shows
"Default (…)" from it, §5.6). `resolve` never fails and allocates at most the symbol key string.

Callers get typed values through thin readers in their own module (lane T's `text_style` and
`text_shown`; lane W's and P's own); the entries are `pub static`, passed by reference, so there is
no lookup by name on the hot path.

**Lane T's entries** (`defaults/text.rs`; levels: S = standard, P = project, G = page, O = object):

| Key | Kind | Built-in | Levels |
| --- | --- | --- | --- |
| `text.font` | Text ≤ 64 | `BIZ UDPGothic` | S P |
| `text.<kind>.height`, one per §3.1 kind except `free` | Length 0.5–10 | §3.2 | S P |
| `text.wire_label.height` | Length 0.5–10 | `ecad_model::wiring::DEFAULT_LABEL_HEIGHT` (1.6) | S P (project from `settings.wiring.label_height`) |

| `text.<kind>.show`, the kinds of §5.1 | Word on, off (+ first for `tag`) | §3.2 | S P G O |

elsewhere (§5.3, §6.2–§6.3, §2.2) name these entries; the worker writes none of them as literals.
FP1's keys are exactly these keys, so nothing new is stored.

**Tests** (`defaults/mod.rs`): keys are unique across `all()`; every key matches the key rule;
every `builtin` parses as its own `kind`; every entry allows `Project`; a table of hostile stored
values (NaN, `1e308`, out of range, unknown word, 10,000 characters) resolves to the next level;
the narrowest allowed level wins. A test also checks that `text_style` returns each entry's
built-in on an empty project, so a reader and its entry cannot drift.

## 4. Setting styles (Q1)

### 4.1 Project settings ▸ Text

A new **Text** section in the Project settings popout (019's `ecad.projectsettings`), after
Numbering. One row per kind of §3.1 except `free`:

```
TEXT
Font  [BIZ UDPGothic          ]   drawn with BIZ UDPGothic
Kind               Height   Bold   Shown
Tag                [2.5 ]   [x]    [Once per run ▾]
Connection point   [1.5 ]   [ ]    [Shown        ▾]
Description        [1.6 ]   [ ]    [Hidden       ▾]
…
                                    [Defaults]
```

- **Font**: a text field with a drop-down of the families the build can find (craft-fonts first,
  then system families), any name allowed. The status line under it reads `drawn with <family>`,
  or `<name> is not available here; drawn with BIZ UDPGothic` / `…; drawn with the stroke font` in
  `ecad.check-warning`.
- **Height**: a number field, 0.5–10. Out of range: the field keeps the text and shows
  `A text height is 0.5 to 10 mm.` under it in `ecad.check-error`; OK is disabled.
- **Bold**: a check box.
- **Shown**: Shown / Hidden, plus **Once per run** for `tag`. Lane P's and W's kinds show
  `Shown` only and are disabled (their visibility is not in this brief).
- **Defaults** resets every row to §3.2 (fields only; nothing is written until OK).
- OK writes every changed field as **one** `textstyle` transaction ("Text styles"); Cancel or
  Esc writes nothing. Read-only (writes off, an issued revision reopened): fields disabled with
  019's read-only tooltip.

### 4.2 After a change

The page on screen redraws at once; other open pages are marked stale (§11). Text that no longer
fits where it was placed is placed again by §6 (moved texts keep their stored place).

| Level | Object | Key | Written by |
| --- | --- | --- | --- |
| Symbol | the symbol's component | `text.<rep>.<kind>.show` (`<rep>`: the representation ID, 32 hex digits) | `showtext {representation}`, Show/Hide Text tool, Properties (one symbol selected) |
| Device | the component | `text.<kind>.show` | `showtext {component}`, Properties (device) |
| Page | the page | `text.<kind>.show` | `showtext {page}`, Properties (page) |
| Project | the project | `text.<kind>.show` | `showtext {}`, `textstyle {kind, show}`, Project settings ▸ Text |
| Built-in | — | §3.2's column | — |

Kinds with visibility in this brief: `tag`, `point_label`, `description`, `part_number`,
`continuation_name`, and at page and project level also `reference` and `location`.
`wire_label` keys are stored by `showtext` at page and project level and on a conductor
(`text.wire_label.show`), and are **read by lane W** through `text_shown` (§7.1).

### 5.2 Which level wins

The narrowest level that has a value wins: symbol, then device, then page, then project, then the
built-in default. `text_style::text_shown(doc, target: TextTarget, kind) -> Shown` resolves it
(`Shown::On | Off | First`); `TextTarget` names the representation, its component and its page.
A hostile value (anything but the three words) counts as absent.

### 5.3 Runs: a tag once per run

A tag whose resolved value is `first` is drawn on the **first symbol of each run**, hidden on the
others. Built-in, `tag` is `first` for symbols whose starter kind is `Terminal` (strips) or `Plc`
(DI/DO channels); `on` for every other symbol.

A **run** is a maximal set of symbol representations of **one device**, on **one page**, of the
**same starter kind**, that follow each other along one line:
- their boxes' centres are within **1 mm** of each other on the axis across the line (the same y
  for a horizontal row, the same x for a vertical column);
- the gap between neighbouring boxes along the line is at most **15 mm** (Q5);
- no symbol of another device lies between them.

The first of a run is the leftmost (horizontal row) or topmost (vertical column); a single symbol
is a run of one. Rows are tried before columns. In the pack's page 100 the `TB01` terminals at
`1.L`, `1.N`, `1.PE` are one run and print `TB01` once; the separate group lower down is a second
run and prints it once more, as the pack does.

A symbol-level `on` or `off` overrides the run (a designer can show the tag on the last terminal
instead). A moved tag (§6.3) is shown wherever the run rule puts it only if it is the first; a
designer who wants a particular terminal to carry the tag sets that symbol `on` and the device
`off`.

PLC card tags "once per card" become once per card body when 1.3 adds card bodies; until then a
PLC device's channels follow the run rule.

### 5.4 Hidden text is still data

Hiding changes what is drawn and printed only. The tag, description and part number stay
component properties; `devices`, search, the Devices tab, BOM, wire list, strip plan, Checks and
hover show them as before. A hidden text has no entity on the page, so it cannot be picked; the
symbol can, and its hover lens lists the hidden texts as `Tag -X01 (hidden here)`.

### 5.5 The Show/Hide Text tool

ECAD tab ▸ **Text** group (new) ▸ **Show/Hide Text** (`ecad.tool.showtext`; command line
`showtext`; no shortcut).

1. Prompt: `Pick a text to hide, or a symbol to show its hidden texts [Device/Page/Project]
   <Symbol>:`. The keyword picks the level the next click writes (default Symbol); it stays for
   the rest of the command.
2. Hovering a derived text highlights it in `cad.hover`; a symbol with hidden texts shows them
   dimmed (`ecad.hidden-text`) while hovered.
3. Click a shown text: it is hidden at the chosen level (one transaction, `Hide tag -X01`). The
   echo says `Tag -X01 hidden on this symbol.` / `…for -X01.` / `…on page 100.` / `…in the
   project.` At Device level on a strip, the echo adds `Strip tags show once per run unless you
   set a symbol.`
4. Click a dimmed hidden text: it is shown at the chosen level (`Show tag -X01`).
5. The tool repeats until Esc or Enter. Esc writes nothing for the click in progress.
6. Errors, in words on the command line: a click on nothing derived: `Pick a tag, a label or a
   symbol.`; read-only: 019's sentence. Free text: `That is free text; erase it to remove it.`

### 5.6 Properties panel rows

- **Device** section (one device selected): a **Texts** group with a row per kind of §5.1's
  device level: `Tag  [Default (once per run) ▾]` with Default (the inherited value in brackets) /
  Shown / Hidden / Once per run (tag only). A change writes one `showtext {component}`.
- **One symbol** selected (a symbol pick, not the device row): the same group titled **Texts on
  this symbol**, writing `showtext {representation}`.
- **Page** section: the same group writing `showtext {page}`.

### 5.7 Show Hidden Text (view only)

ECAD tab ▸ Text ▸ **Show Hidden Text** (`ecad.view.hiddentext`), a toggle, off at start. On: the
page projection also draws every hidden derived text, in `ecad.hidden-text` (ACI 8) on the layer
`ECAD-HIDDEN-TEXT`. It is a session display state like the cable fan view: nothing is written, it
is not undoable, it is not in the file, and **print, PDF and release output never include it**
(they project with the flag off). Hidden texts drawn this way are pickable by Show/Hide Text and
Move Text only.

## 6. Placement (Q2)

### 6.1 What is placed

Each symbol's **tag block**: the tag line, then, when shown, the description line and the part
number line under it, all with the tag block's justification and a line pitch of 1.25 × each
line's height. A block with nothing shown is not placed. Connection point labels keep their
fixed rule (1 mm beside the point, their size from the getter) and are obstacles. Location labels
keep their place inside the box's top-left corner. Continuation texts keep lane W's positions
(§7.1).

### 6.2 Candidates by orientation

`gap` = 0.6 × the tag height (1.5 mm at 2.5 mm). Candidates are tried in order; text is always
upright (Q9).

| Symbol | 1 (preferred) | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- |
| **Vertical** (connection points top and bottom: rotation near 0° or 180°) | left of the box, top line level with the box top, right-justified | left, middle, right-justified | right of the box, top, left-justified | above, centred | below, centred |
| **Horizontal** (rotation near 90° or 270°) | above the box, centred, bottom-justified | above, left edge, left-justified | below, centred, top-justified | left, middle, right-justified | right, middle, left-justified |

Vertical candidate 1 matches the pack (tags at the top left of breakers and contacts); horizontal
candidate 1 matches today's rule, so a page with no collision keeps the same layout, smaller.

### 6.3 Obstacles and order

For each page draw, in this order:
1. **Obstacles that never move:** every symbol box on the page; every conductor route segment
   inflated by 0.3 mm; every junction dot; every connection point label (placed first by its
   fixed rule); the location box labels; the inside edge of the frame (text may not cross it).
2. **Moved texts** (§6.4) at their stored places; they become obstacles.
3. **Tag blocks**, symbols in reading order (box top, highest first; then box left; ties by
   representation ID), so the result does not depend on op order. For each, the first candidate
   whose box overlaps no obstacle is taken; if none is free, the candidate with the smallest
   overlap area (ties: the earlier one). The chosen box becomes an obstacle.

Bounds (hostile pages): at most 5 candidates; obstacles in a uniform grid of 20 mm cells built
once per draw; on a page with more than 5,000 tag blocks or 50,000 obstacles, blocks beyond the
bound take candidate 1 without a search. Non-finite boxes are skipped.

Placement never moves symbols, wires or stored text. `pagetexts {page}` (§10.4) reports
`overlaps: true` for a block that had no free candidate, so an agent or a test can see it; a
Checks row for it is later work.

### 6.4 Moved texts (FP3)

A moved text stores its place as the symbol's component property
`text.<rep>.<kind>.at = "x,y,J"`: `x,y` in millimetres in the **symbol's own frame** (the
definition's local frame, before the placement's rotation and offset), `J` its justification
(`L`/`C`/`R` then `T`/`M`/`B`, e.g. `RT`). Kinds that can be moved: `tag` (the whole tag block),
and `point_label` per connection point as `text.<rep>.point_label.<terminal key>.at`.

So a moved text follows its symbol when the symbol moves, rotates or mirrors (the text stays
upright), survives renumbering (the key names the representation, not the tag), survives
re-projection and reopening, and is merged like any property. A value that does not parse, or
whose page position is not finite, is ignored (the text is placed automatically).

Keys follow their symbol: `devicedelete` and the erase of a symbol remove that representation's
`text.<rep>.*` keys in the same transaction; a device merge (018's `plan_merge`) moves them to the
surviving component in the same transaction; copy carries them with the new representation ID.
Orphan keys (a representation no longer of that component) are ignored when drawing.

### 6.5 Move Text tool

ECAD tab ▸ Text ▸ **Move Text** (`ecad.tool.movetext`; command line `movetext`).

1. Prompt: `Pick a tag or label to move [Reset]:`. Derived texts highlight on hover.
2. Pick: the text (the whole tag block for a tag) follows the cursor with CADCraft's snaps and
   ortho; the prompt becomes `Place the text [Justify] <keep RT>:`. **Justify** asks for a
   two-letter code and keeps the point.
3. Click: one transaction `Move tag -K01`; the echo says `Tag -K01 moved. Reset puts it back.`
4. **Reset** then a pick: removes the stored place (`Reset tag -K01`), and §6.3 places it again.
5. Esc at any step writes nothing.
6. Errors: free text: `That is free text; use MOVE.`; a hidden text: `Show it first (Show/Hide
   Text, or Show Hidden Text).`; read-only: 019's sentence.

CADCraft's MOVE, grips and edits on a derived text stay refused; `TAG_DERIVED` becomes
`The tag text is derived: change the tag with Device Properties, or move it with Move Text.`

### 6.6 Justified and centred text (FP4)

`Primitive::Text` gains `halign` and `valign` (CADCraft's `HAlign` and `VAlign` words), both
optional and left out of the file when left/baseline, so every existing file reads and saves the
same. `convert::primitive_from` records a text entity's alignment and its alignment point;
`entity_for` gives it back, so the exact-round-trip check passes and `text {justify: "MC"}` is
recorded instead of refused. Free text takes `Standard` (the project font); its height stays the
user's.

## 7. Fit with the other lanes

### 7.1 Lane W (032, wires and nets)

- **Sizes:** `wires.rs` replaces `settings.wiring.label_height()` with `text_style(doc,
  TextKind::WireLabel).height` and sets the entity style to `style_name`. Same value, so this can
  land in either order.
- **Wire-label visibility:** Q4 calls `text_shown(doc, target, TextKind::WireLabel)` for the
  conductor's `text.wire_label.show`, then the page's, then the project's. Lane T only stores the
  keys (`showtext`).
- **Continuation texts:** lane T does not edit `continuation_texts`. In `texts_on_page` (T's) the
  returned texts are restyled by kind (`Name` → `ContinuationName`, `Places` → `Reference`) and
  filtered by visibility, so the name is hidden by default from Q3's first commit. When lane W
  next edits `continuation_texts`, it may call the getter itself; the restyle is then a no-op.
- **Wire labels avoiding tags** needs both lanes' work and is a follow-up after both land (brief:
  Later).

### 7.2 Lane P (033, print and project)

- `frame.rs`, `generated.rs` and `xref.rs` replace their literals with `text_style(doc, kind)`
  for the kinds of §3.1 and set the entity style to `style_name`; generated and print drawings
  call `install`. Defaults equal today's sizes (§3.2), so lane P chooses when to change the look.
- Q5's shared font resources in the PDF benefit from fewer, outline fonts: two faces per book
  instead of stroke outlines per glyph. Lane P measures it; this lane does not touch printing.
- Q7's tag display (leading `-`, case) changes the value `shown_tag` returns; placement measures
  whatever value it gets.

### 7.3 Lane S (034, component library)

Lane S's new definitions need nothing from this lane: placement works from the symbol's box and
orientation. Definition text slots (proposal §4.2) arrive with 1.1, when §6.2's candidate 1 may
come from the definition instead.

## 10. Commands, JSON forms and MCP

Every command is a `CommandSpec` with JSON `run`; programmatic calls never open dialogs.

### 10.1 `textstyle` (new; writes)

`{font?: string|null, kind?: word, height?: number|null, weight?: "regular"|"bold"|null,
show?: "on"|"off"|"first"|null}` → `{font, drawn_with, kinds: [{kind, height, weight, show,
default: bool}], changed: bool}`.

- No fields: reads only (works with writes off, records nothing).
- `font`: sets `text.font`; `null` removes it. `height`/`weight`/`show` need `kind`; `null`
  removes that key (back to default). `wire_label` height writes `wiring.label_height`.
- All given fields are one transaction ("Text styles"); a value equal to the current one writes
  nothing (`changed: false`).
- Refusals (nothing written): `A text height is 0.5 to 10 mm.`; `Unknown text kind "x". Kinds:
  tag, point_label, …`; `Weight is regular or bold.`; `Shown is on, off or first (first: tag
  only).`; `A font name is 1 to 64 characters with no control characters.`; `height, weight and
  show need a kind.`

### 10.2 `showtext` (new; writes)

`{kind: word, show: "on"|"off"|"first"|null, representation?: id | component?: id | page?: id}`
(at most one target; none = project) → `{level: "symbol"|"device"|"page"|"project", target,
kind, show, changed}`. One transaction. Refusals: an unknown kind or a kind not allowed at that
level (§5.1) names the allowed ones; `first` for a kind other than `tag`; `No representation
<id>.` (likewise component, page); a representation that is not a symbol of a component: `That
representation is not a symbol.`

### 10.3 `movetext` (new; writes)

`{representation: id, kind: "tag"|"point_label", terminal?: key, to: [x, y], justify?: "RT"…}`
or `{representation, kind, terminal?, reset: true}` → `{representation, kind, at: [x, y]|null,
justify, changed}`. `to` is a page point; it is stored in the symbol's frame (§6.4). One
transaction. Refusals: `A text position must be a finite point.`; `Justify is two letters: L, C
or R, then T, M or B.`; `point_label needs the connection point's key.`; unknown IDs as §10.2.

### 10.4 `pagetexts` (new; reads)

Named `pagetexts`, not `texts`: CADCraft already has a `texts` command, and a built-in command wins over an ECAD one of the same name (overseer, 2026-11-12).

`{page: id}` → `{texts: [{representation, component, kind, terminal?, value, at, justify,
height, weight, shown, moved, overlaps, box: [[x,y],[x,y]]}]}` for every derived text on the page
that lane T draws, hidden ones included with `shown: false`. At most 5,000 rows, then `more: n`.
Works with writes off.

### 10.5 `text` (CADCraft's; changed behaviour)

With `justify`, the text is recorded with its alignment (§6.6) instead of refused.

### 10.6 `projectprops`, `pageprops`, `setprop` (changed)

Keys starting `text.` are refused: `"text.…" is set with Text styles (textstyle, showtext,
movetext).` Nothing else changes.

### 10.7 MCP contract tests (brief 011 rule)

Through `ecad-mcp`'s `execute`, in `apps/ecad-mcp/tests/all/text_contracts.rs` (a new module of
the one test executable):
- `textstyle {kind: "tag", height: 3}`, `{font: "X"}`, `{kind: "wire_label", height: 2}`,
  `showtext` at each of the four levels, `movetext {to}` and `{reset}`, and `text {…, justify:
  "MC"}` each record one transaction with `Author::Agent(<client>)`, and each is refused with
  writes off.
- `textstyle {}` and `pagetexts {page}` work with writes off and record nothing.
- `projectprops {text.font: …}`, `pageprops`, `setprop` with a `text.` key are refused with §10.6's
  sentence and record nothing.
- `defaults {}` and `defaults {group: "Text", page: id}` work with writes off and record nothing.

### 10.8 `defaults` (new; reads)

`{group?: string, key?: string, page?: id, component?: id, representation?: id}` → `{defaults:
[{key, label, group, brief, kind, builtin, levels, value, from}]}`: every registry entry (§3.5), or
those of one group or one key, with the value resolved at the given scope (project when none) and
the level it came from (`builtin`, `project`, `page`, `object`). It is how an agent or the later
Standards screen sees every default and where it comes from. Works with writes off. Refusals:
`No default "x".`; unknown IDs as §10.2.

## 11. Update maps and cost

The page projection already rebuilds the derived texts of the **page on screen** on every draw
(018), and only that page (other pages are stale until shown). This brief keeps that and adds
what makes a page stale, in `project::pages_touched`:

| Op | Pages made stale |
| --- | --- |
| `SetProperty(Project, "text.*")` | every page (`None`): sizes, font and project visibility are everywhere |
| `SetProjectSettings` | every page (as today) |
| `SetProperty(Page p, "text.*")` | page `p` |
| `SetProperty(Component c, "text.*")` | the pages of `c`'s representations |
| `SetProperty(Component c, "description" or "part_number")` | the pages of `c`'s representations (they may be shown) |
| `SetProperty(Conductor, "text.*")` | the pages of that conductor's representations (lane W draws them) |
| anything else | as today; nothing new |

Runs (§5.3) and placement (§6) read only the page being drawn, so any op that touches a
symbol, wire or text on that page already marks it. Outputs, reports, strips, Checks and the
devices list read **none** of the `text.*` keys and nothing in this brief changes their update
maps: hiding is drawing only (§5.4).

`text_style`, `text_shown` and `defaults::resolve` are map lookups (no cache to keep in step);
the registry itself is static. The `defaults` command reads on request and is no view, so it has
no update map; the later Standards screen will need one (every `SetProperty` of a registry key,
and `SetProjectSettings`, change its rows). The font resolution is
cached by CADCraft's font table per family name; a font change only changes the name looked up.

Verify mode: the existing comparison of the page projection against a fresh projection covers the
new texts (same function, same inputs).

## 14. Format proposals (for the overseer)

Every addition except FP4 is an optional property, left out when unused, so an old file opens
unchanged and saves byte-identical. No new op.

- **FP1. Project keys** `text.font`, `text.<kind>.height`, `text.<kind>.weight` (`regular` /
  `bold`), `text.<kind>.show` (`on` / `off` / `first`) through `SetProperty(Project)`, reserved
  for `textstyle` and `showtext` (§10.6). `<kind>` is a §3.1 key word except `wire_label`'s
  height, which stays `settings.wiring.label_height` (default 1.8 → 1.6, Q3).
- **FP2. Page key** `text.<kind>.show` through `SetProperty(Page)`.
- **FP3. Component keys** `text.<kind>.show` (device) and `text.<rep>.<kind>.show`,
  `text.<rep>.tag.at`, `text.<rep>.point_label.<terminal key>.at` (symbol) through
  `SetProperty(Component)`; conductor `text.wire_label.show` through `SetProperty(Conductor)` (read
  by lane W).
- **FP4. `Primitive::Text` alignment:** optional `halign` and `valign`, omitted when left /
  baseline. This is a record field, not a property, because items have no properties. The worker
  confirms in its first Q2 commit what an older build does with a file that has them (ignores the
  fields and draws left-aligned, or refuses); if it refuses, the overseer decides before Q2's
  justify commit lands.
- **FP5 (ops recorded, not format).** `devicedelete`, erasing a symbol, a device merge and copy
  record the `SetProperty` moves of `text.<rep>.*` keys in their own transaction (§6.4).
- **FP6 (default change, not format).** `wiring.label_height`'s default 1.8 → 1.6; tags 3.5 →
  2.5 and the other §3.2 changes are drawing defaults, not stored values.

## 15. Questions for the owner

**Decided (owner, 2026-11-12): all nine "as recommended".** The owner added one principle for every
v0.15 lane: every new default is registered in one defaults registry, never hard-coded where it is
used (§3.5).

1. **The font.** craft-fonts has no Latin-only sans. Use **BIZ UDPGothic** Regular and Bold
   (already in craft-fonts, OFL-1.1, a clean proportional sans) as the default now, and add a
   Latin sans with bold (for example Noto Sans, OFL-1.1) to craft-fonts as a separate craft-fonts
   pull request later? **Recommend yes**: it needs no other repository to start, and the font is a
   project setting, so a later default changes nothing stored.
2. **ECAD builds embed craft-fonts.** Today ECAD's builds do not set `CRAFT_FONTS_DIR`, so they
   draw in the stroke font. Set it for the owner's local builds (documented in the quick start) and
   open a `storytold/craft-common-actions` issue so ECAD's CI release builds embed it (CI is not
   changed in this PR, house rule 11); tests pass without it? **Recommend yes.**
3. **Default sizes**: tags 2.5 mm bold, connection point labels 1.5, location labels,
   descriptions, part numbers, cable text and wire labels 1.6 (wire labels from 1.8),
   references and continuation names 2.0; lane P's kinds unchanged until lane P changes them?
   **Recommend yes** (the pack measures 2.8 / 1.6 / 1.5 / 1.5 / 2).
4. **Description and part number under the tag** are new texts. Hidden by default, switched on per
   device, page or project? **Recommend hidden by default**: existing pages do not grow new text,
   and the pack shows descriptions on only some devices.
5. **What counts as a run** (§5.3): one device, one page, one starter kind, aligned within 1 mm,
   gaps of at most 15 mm, nothing of another device between. **Recommend yes**; the 15 mm can
   become a project setting if a real pack needs it.
6. **Where a symbol's own settings live.** Component properties keyed by representation ID
   (`text.<rep>.tag.at`, FP3), cleaned up by delete, merge and copy; or a new `properties` map on
   representations (a record change to every representation). **Recommend component
   properties**: no record change, and merges per key already work.
7. **Moving derived texts** with a Move Text tool and `movetext`, while CADCraft's MOVE and grips on
   them stay refused (with a sentence pointing at Move Text)? **Recommend yes** for v0.15; grip
   dragging needs `translate.rs` to turn an engine move into a property, which is riskier and can
   come later.
8. **Bold in the stroke-font fallback** drawn with lineweight 0.35 mm? **Recommend yes**; without
   it a build without craft-fonts loses the bold tags entirely.
9. **Tags always upright** (horizontal), also on symbols rotated 90°, with per-text rotation later?
   **Recommend yes**: it reads best and matches most of the pack; the pack's few rotated tags can
   be matched later.
