bridges, the terminal plan and the BOM per terminal type), 024 (BOM, reports, generated pages,
Checks counts) and 026 (the planner that renumbers terminals). Follows `008.md` §2: click-first,

## 1. Goal and words

A strip is listed as it is built on the rail: end stop, end plate, terminals with partitions and
jumpers between them, end plate, end stop. The rule supplies what every strip needs; the user
places what only they can decide.

| Word | Means |
| --- | --- |
| **accessory** | A part on the rail that is not a terminal: end stop, end plate, partition plate, jumper, marker card, strip label |
| **end stop** | The clamp that holds a strip on the rail, one at each end (an "end clamp") |
| **end plate** | The cover on a terminal's open side, needed at the strip's open end and where the terminal family changes |
| **partition** | A partition plate between two positions: it separates groups (voltages, circuits) and stops a jumper |
| **gap** | Where accessories sit: `start` (before the first position), `after 4` (between 4 and the next position), `end` (after the last) |
| **jumper** | A plug-in or screw bridge: a bridge with its own part number and no wire to cut. A **wire bridge** is 028's bridge |
| **span** | The positions from a jumper's first terminal to its last, in plan order, spare positions included. A 3-way jumper spans 3 |
| **skip jumper** | A jumper whose span includes positions it does not connect (teeth removed) |
| **automatic / placed** | Made by the rule (§2) / written by the user (§3) |

The glossary gains a section "Terminal accessories (brief 030)" with these rows. **bridge** gains:
"A bridge is a wire bridge or a jumper (030)."

## 2. Automatic accessories (Q1, Q9)

### 2.1 The rule

For each strip, unless `strip_accessories` is `off` (project, FP4) or the gap has an override
(§2.2):

| Gap | Automatic items, inner first |
| --- | --- |
| `start` | `end plate` if the open side is `left`; `end stop` |
| `after p` (between positions p and q) | `end plate` when p and q are of different end-plate families (below) and no partition is placed there |
| `end` | `end plate` if the open side is `right` (default); `end stop` |

- **Open side** (strip property `open_side`, FP2): `right` (default), `left` or `none` (a family
  closed on both sides: no automatic end plate anywhere). Text other than these three is refused
  with `"up" is not a side. Write right, left or none.`
- **End-plate family:** a position's family is its end plate's part number, read for its terminal
  type: feed-through → `end_plate.part_number`, PE → `end_plate_pe.part_number`, else the
  feed-through one (§4). Two adjacent positions whose part numbers both exist and differ need an
  end plate between them. Unknown on either side → same family (no plate, no guess).
- **A partition replaces an automatic end plate** at its gap (a partition plate also covers the
  open side). Written explicitly, both are kept.
- A strip with no positions (only a tag) gets no accessories.

### 2.2 Overrides (FP1)

Strip properties, one per gap, value a comma list of `end_stop`, `end_plate`, `partition` in
order from the inner side, or `none`:

| Key | Gap | Example |
| --- | --- | --- |
| `acc.start` | before the first position | `end_stop` |
| `acc.end` | after the last position (follows the end when positions are added) | `partition, end_stop` |
| `acc.after.<label>` | after the position labelled `<label>` | `acc.after.4 = partition` |

- A written value **replaces** the rule at that gap; `none` means nothing there; absent means the
  rule. `acc.after.<last label>` and `acc.end` both apply at the last gap: `acc.end` wins, and
  `acc.after.<last>` is used again when positions are added after it.
- Spaces ignored, case-insensitive, stored canonical (`partition,end_stop`). At most 8 items per
  gap. A word not in the list is refused: `"plate" is not an accessory. Write end_stop, end_plate,
  partition or none.` Empty clears the key (back to the rule).
- `<label>` is any position label of the strip, drawn or spare (`4`, `PE1`, `10a`), at most 16
  characters. A key whose label names no position is kept and listed by Checks (§8,
  `accessory-orphan`); it never blocks anything.
- Why labels and not terminal IDs: spare positions have no terminal, and `acc.after.4` reads
  plainly in Properties, MCP and merges. Renumbering moves the keys (§6).

## 3. Placing accessories (brief scope 2)

### 3.1 The `accessory` command

`accessory {strip, after: "start"|"end"|<label>, items: [..] | null, add?: [..], remove?: [..]}`
or `{terminal, …}` (the terminal names its strip and its label as `after`). It writes one
`SetProperty` of the gap's key, in one transaction labelled `Accessory -X01 after 4`:

- `items` replaces the gap's list (`[]` writes `none`); `null` clears the key (rule again).
- `add` appends to the gap's **current** list (the override, else what the rule gives there), so
  "add a partition after 4" keeps an automatic end plate already there. `remove` takes items out
  of it (one occurrence each).
- Echo: `Partition after -X01:4.`, `-X01 after 4: rule restored (nothing automatic here).`
- Refused with a way forward: no such strip (`-X09 is not a terminal strip. Pick a terminal of the
  strip.`), a label not on the strip (`-X01 has no position 15; it has 1…12. Pick one of those, or
  start/end.`), more than 8 items.

### 3.2 Strip Accessory tool

ECAD tab, Components group, after Draw Bridge: **Strip Accessory** (`ecad.tool.accessory`,
command `accessory`). Prompts:

```
Select terminal (the accessory goes after it) [Start/End]:
Accessory after -X01:4 [Partition/Endplate/endStop/Remove/Rule] <Partition>:
```

The preview draws a short thick line across the terminal's inside side (§5.3 mark). Remove takes
the last item of that gap's list; Rule clears the key. Esc writes nothing.

### 3.3 From the terminal plan

Reports ▸ Terminals gains an **Accessory ▾** button (`ecad.reports.terminals.accessory`) acting on
the selected row: **Partition after**, **End plate after**, **End stop after**, **Remove here**,
**Restore rule here**. On an accessory row it acts on that row's gap. Each is one `accessory` call.
The tab's selection allows several rows (Ctrl, Shift) for jumpers (§4.3).

### 3.4 Properties panel (strip)

A section **Accessories** under 028's strip rows (`ecad.props.strip.acc`):

| Field | Editing |
| --- | --- |
| **Open side** | `Right ▾ / Left / None`, one `setprop open_side` |
| **Gaps** (read-only) | `start: end stop · after 4: partition · end: end plate, end stop` with **Show plan** |
| **Parts** | a small table, one row per item (End stop, End plate, End plate PE, Partition, Jumper 2…n, Marker card, Strip label): Part number and Maker text fields; the placeholder shows the project's value, `from project: ES-1`, or `e.g. ES-1` |

Each edit is one transaction. With several strips selected, a field writes to all of them in one
transaction (019's `components` form).

## 4. Part data (Q7, FP3, FP4)

Libraries (stage 3) are not built. Until they are, accessory part data are properties: on the
strip first, then the project's default, then unknown.

| Item | Strip keys | Project keys (default for every strip) |
| --- | --- | --- |
| End stop | `end_stop.part_number`, `.maker`, `.description` | `strip_end_stop_part_number`, `_maker`, `_description` |
| End plate | `end_plate.…` | `strip_end_plate_…` |
| End plate for PE terminals | `end_plate_pe.…` | `strip_end_plate_pe_…` |
| Partition | `partition.…` | `strip_partition_…` |
| Jumper, n-way (n = 2…50) | `jumper_<n>.…` (`jumper_3.part_number`) | `strip_jumper_<n>_…` |
| Marker card | `marker.…`, `marker.per_card` (1…100, default 10) | `strip_marker_…`, `strip_marker_per_card` |
| Strip label | `strip_label.…` | `strip_strip_label_…` |

- Project key = `strip_` + the strip key with `.` → `_`, so it passes the project key rule (all
  under 40 characters). `strip_accessories` = `auto` (default) | `off`.
- A strip's own value wins per key, including an empty-looking one: to stop inheriting, a strip
  sets its own value. Part numbers and makers go through `devices::property_value` (trimmed, the
  same limits as `part_number`).
- **Jumper sizes** are the n with a known `jumper_<n>.part_number` (strip or project). With none
  known, a jumper's size is its span and its part is `?`.
- **Later (stage 3):** a terminal part in a library carries the same fields; the lookup becomes
  strip → the terminal's library part → project. Nothing in the file changes.
- Descriptions default to words: `End stop`, `End plate`, `End plate (PE)`, `Partition plate`,
  `Jumper 3-way`, `Marker card ×10`, `Strip label`.

## 5. Jumpers (brief scope 3; Q3–Q6)

### 5.1 What a jumper is

A jumper is a **bridge** (028: a conductor whose two ends are on two terminals of one strip) with
conductor property `bridge = jumper` (FP5). Absent, or any other value, is a wire bridge, so every
028 bridge stays a wire bridge. Because it is still a conductor attached at both ends:

- **Nets and wire numbers** are unchanged: 022 joins the terminals; the jumper conductor keeps the
  net's `wire_number` like any member, so converting back loses nothing.
- **028's bridge derivation** is unchanged: `bridge_of` and `bridge_group` see it. The plan reads
  the kind per conductor.
- **Wire report:** a jumper is **not** a row (there is no wire to cut or mark). The wire report's
  footer count says `2 jumpers not listed`. A wire bridge stays `Bridge -X01`.
- **BOM:** a row per jumper part (§5.2). Wire bridges stay off the BOM (wire is not on the BOM,
  024).
- `bridge = jumper` on a conductor that is not a bridge (ends on two strips, a device, loose) is
  kept but means nothing: Properties shows it greyed with `Not a bridge: both ends must be on one
  strip.`, and the conductor stays an ordinary wire everywhere. No check (it becomes a jumper again
  if it is re-attached as a bridge).

### 5.2 Grouping, size and skip

- **One jumper** = the jumper conductors of one strip that are connected through shared terminals
  (union-find, as 028's `bridge_group` but over jumper conductors only). 3–4 and 4–5 are one
  3-way jumper; 3–4 and 6–7 are two 2-way jumpers.
- **Span** = last position index − first + 1 over its terminals, in plan order with spare positions
  counted and accessories not.
- **Size** = the smallest known jumper size ≥ span (§4). Longer than the largest known size: the
  jumper is built of chained pieces of the largest size that share their end terminals (the second
  jumper channel), `ceil((span − 1) / (largest − 1))` pieces, the last cut to fit; the plan
  shows piece breaks and the BOM counts them. No known size: size = span, part `?`.
- **Skip:** positions inside the span that the jumper does not connect are **skipped** (teeth
  removed). They are shown as `┆` in the plan's Bridge column; nothing else changes.
- Splitting one connected group into two jumpers by hand is out of scope (Q5).

### 5.3 How it is drawn

The route is the conductor's own stored polyline (028's staple); it is never recoloured. The
projection adds, for a jumper only, derived marks (not stored):

- a filled square `ecad.jumper-mark` at each end instead of 028's bridge dot;
- **no** wire-number or colour label on the jumper's route (022 labels skip it; display only).

So converting with `setprop bridge` changes the look of that one conductor on its pages only.

### 5.4 Draw Bridge (`bridge`), extended

Prompts gain the kind at the first prompt:

```
Select first terminal [Jumper/Wire] <Jumper>:
Select next terminal of -X01 (Enter ends) [New]:
```

- **Default kind** (Q4): `Jumper` when both terminals are on one strip and the span fits the
  largest known size (10 when none is known); else `Wire`. The prompt shows the default; typing
  `W` or `J` sets it until the command ends.
- Each pick in the chain is its own transaction, as built in 028. A chain 3 → 4 → 5 makes one
  3-way jumper because the grouping is derived.
- A jumper between terminals of two strips is drawn as a plain wire (028's rule) with `bridge`
  not set: `-X01:3 and -X02:1 are on different strips; drawn as a wire, not a jumper.`
- JSON: `bridge {from, to, kind?}` or `bridge {terminals: [t1, t2, …], kind?}` (2 to 50
  terminals of one page): conductors t1–t2, t2–t3… in **one** transaction, `Jumper -X01:3–5`.
  Skip jumpers name only the connected terminals (`[3, 5, 7]`). Pairs already bridged are skipped
  and listed in the reply (`already: [[3,4]]`); all already bridged writes nothing. `kind` omitted
  gives the default above. Result adds `kind` and `conductors: [..]`.

### 5.5 Converting

- Properties of a selected bridge conductor (`ecad.props.wire.bridge`): **Bridge** `Wire ▾ /
  Jumper`, one `setprop {conductor, key: "bridge", value: "jumper" | null}`.
- Reports ▸ Terminals: selected rows → **Make jumper** / **Make wire bridge**
  (`ecad.reports.terminals.jumper`, `…wire`): one `setprop` transaction per click over every bridge
  conductor among the selected rows (019's several-objects form, extended to conductors: FP5).
- With rows 3…5 selected and no bridge between them: **Jumper** (`ecad.reports.terminals.newjumper`)
  runs `bridge {terminals: [3, 4, 5], kind: "jumper"}`. Ctrl-selected rows 3, 5, 7 make a skip
  jumper.

### 5.6 Jumper across a partition (Q6)

A jumper whose span contains a gap with a `partition` is drawn and kept, never refused: real
partition plates with a jumper cut-out exist and house styles differ. Placing the partition, or
drawing the jumper, echoes `Jumper -X01:3–5 crosses the partition after 4 (see Checks).` and
Checks lists it (§8). Wire bridges may cross partitions freely (no check).

## 6. Renumbering (026, 028 §9.5; FP6)

When `renumber {kind: "terminals"}` changes a strip's labels, the same transaction moves every
`acc.after.<old>` key to `acc.after.<new>` (`SetProperty` to unset, `SetProperty` to set), so an
accessory stays after the terminal it followed. Moves are applied on the end state, so `4 ↔ 5`
swaps cleanly. A key on a spare position keeps its label (spare positions are not renumbered).
The Renumber preview adds a line per strip: `-X01: partition after 4 → after 6`.

Any other way a label disappears (erasing a terminal, lowering the offer) leaves the key where it
is; Checks lists it (`accessory-orphan`).

## 7. Terminal plan, BOM and the rest (brief scope 5)

### 7.1 Plan rows (028 §5.1, extended)

Rows in physical order: the `start` gap's items, then each position followed by its gap's items,
the `end` gap's items last. Accessory rows:

| Column | Accessory row |
| --- | --- |
| Inside target | the item in words, `end stop`, `end plate`, `partition`; ` (auto)` in `cad.text_dim` when the rule made it |
| Terminal | a mark (§7.3) |
| Place | the part number, `?` when unknown (flagged as 024 does) |
| others | blank |

Jumper marks in the Bridge column: wire bridges keep `● n`; a jumper shows `■ n` on each connected
row and `┆` on each skipped row, a piece break shows `■│`. The header gains the totals:
`-X01  +CP1  12 positions: 10 drawn, 2 spare · 2 end stops, 1 end plate, 1 partition, 2 jumpers`.

Reports ▸ Terminals gains a **Accessories** check box (`ecad.reports.terminals.acc`, on by
default) that hides accessory rows from the table (view only; the generated page always shows
them).

### 7.2 `stripplan` JSON (027 relies on it)

Rows keep 028's keys and gain:
- every row: `kind`: `"terminal"` | `"accessory"`;
- accessory rows: `{kind: "accessory", state: "accessory", accessory: "end_stop"|"end_plate"|
  "partition", gap: "start"|"end"|<label>, source: "auto"|"placed", part_number, maker,
  terminal: null, label: null}`;
- terminal rows: `bridge_kind`: `"wire"|"jumper"|null`, `jumper`: `{group, span, size, piece,
  skipped: bool}` or null;
- strip: `accessories: {end_stop, end_plate, partition, jumpers, marker_cards, strip_label}`
  (counts), `open_side`.
- New parameter `accessories` (default `true`); `false` gives 028's rows exactly.

`limit` and paging count accessory rows like terminal rows.

### 7.3 Generated `terminals` page (028 §5.3)

An accessory row is a full 5 mm row: the word written in the Inside target cell in
`ecad.xref-spare`, and across the Terminal cell a horizontal mark: end stop two 0.5 mm lines 1 mm
apart, end plate one 0.35 mm line, partition one 0.7 mm line extended over the Inside wire and
Outside wire cells. Jumpers: a 1 × 1 mm filled square per connected row, joined by a 0.5 mm
vertical line through skipped rows (drawn dashed there). 44 rows per sheet still counts every row.

### 7.4 BOM (024 §6.1, 028 §9.1)

Per strip, after its terminal rows, one row per accessory part with Qty:

| Row | Qty |
| --- | --- |
| End stop | end stops in all gaps |
| End plate, End plate (PE) | end plates, by the family of the position before the gap (PE when it is a PE position and `end_plate_pe` is known) |
| Partition plate | partitions |
| Jumper n-way | jumper pieces of size n |
| Marker card | `ceil(positions / per_card)`, only when a marker part number is known (Q10) |
| Strip label | 1 per strip, only when a strip label part number is known |

Tags = the strip's tag; Description, Maker, Part number from §4; a missing part number shows `?`
and is flagged, as 024 does for devices. **By part** grouping merges equal parts across strips
(`-X01, -X02`). **By location** uses the strip's location. Automatic items are counted the same as
placed ones (Q8).

### 7.5 Wire report and cable report

Wire report: jumpers are left out; its count and footer say how many (§5.1). `wirelist` JSON gains
`jumpers_omitted: n`. Cable report: unchanged.

### 7.6 Hover lens (028 §7.1)

- Terminal: `jumper to 4, 5 (3-way, ES…)` instead of `bridged to`, and `partition after` when its
  gap has one.
- Strip line: `-X01: 12 positions, 10 drawn, 2 spare · 1 partition, 2 jumpers`.

## 8. Checks (022 Checks tab; every row has a way out; nothing is refused)

| Kind | Severity | Row text | Go-to | Fix buttons |
| --- | --- | --- | --- | --- |
| `jumper-across-partition` | Warning ▲ | `-X01: jumper 3–5 crosses the partition after 4` | the jumper's first conductor | **Make wire bridge** (`setprop bridge` null on its conductors), **Remove partition** (`accessory remove [partition]` at that gap) |
| `jumper-overlap` | Warning ▲ | `-X01: jumpers 3–5 and 4–6 share positions 4–5` (two jumpers in one channel, from a skip jumper) | the second | **Make wire bridge** (the second) |
| `strip-end-open` | Warning ▲ | `-X01: the open end (after 12) has no end plate` / `-X01: the start has no end stop` (an override that leaves it out) | the end terminal | **Add end plate** / **Add end stop** (`accessory add`), **Restore rule** (`items: null`); for the end plate also **Closed family** (`setprop open_side none`) |
| `accessory-orphan` | Warning ▲ | `-X01: partition after 15, but -X01 has no position 15` | the strip's last terminal | **Move to end** (`acc.end` gets the items, key cleared, one transaction), **Remove** (key cleared) |
| `no-accessory-part` | Info, one count row | `14 strip accessories have no part number` | — | **Show** (Reports ▸ BOM, Only ? on), as 024's `NoPartNumber` |

`strip-end-open` is raised only when an end gap's override is a list that leaves the item out (a
likely slip, such as `acc.end = end_stop`). It is not raised for `none` (a deliberate choice), nor
for a missing end plate when `open_side` is `none` or the other side.

## 11. Update maps and cost

### 11.1 Strips (028 §11.1, extended)

`Strips` keeps per strip its gap lists (resolved: override or rule, with the source), its jumper
groups, accessory counts and BOM rows, and an index **`inherits: key → strips`** (strips reading a
project `strip_*` key because they have no value of their own). Built whole only where 028 builds
`Strips` (open, reload, branch switch, revision open, first show). After that, rows added to 028's
map; **every op not listed does nothing to accessories**:

| Op (kind, target) | Recomputed |
| --- | --- |
| `SetProperty(Component s, acc.* \| open_side)`, s a strip | s's gap lists, jumper-partition crossings, counts, BOM rows, checks |
| `SetProperty(Component s, <item>.part_number \| .maker \| .description \| marker.per_card)` | s's families (end-plate keys only: its family gaps), BOM rows, `inherits` entries of s |
| `SetProperty(Project, strip_<item>_<field>)` | the strips in `inherits[key]` only: their BOM rows (and family gaps for end-plate keys) |
| `SetProperty(Project, strip_accessories)` | every strip's automatic items (the switch is project-wide by meaning) |
| 028's strip rows: `AddTerminal`/`RemoveTerminal`, `SetProperty(s, terminals)`, `Link`/`Modify`/`UnlinkRepresentation` of s | s's positions changed, so its gaps (end gap, family gaps, orphans), jumper spans and counts |
| `SetProperty(Conductor w, bridge)` | if `bridge_of(w) = s`: s's jumper groups, crossings, BOM rows, checks; else nothing |
| `CreateConductor`/`DeleteConductor`/`AttachEnd` of w (028 already finds the strips at w's ends) | for those strips, also their jumper groups |
| `renumber`'s `SetProperty(s, acc.after.*)` moves | covered by the first row (one strip each) |
| anything else | nothing |

The Terminals tab and an open `terminals` page redraw only when a strip they show is in
`Strips::last_changed` (028 tester defect 2 rule, which this extends; and the reviewer's finding 2
applied to the tab).

### 11.2 Outputs (024 §9)

| Op | Recomputed |
| --- | --- |

## 14. Format proposals (for the overseer)

Every addition is an optional property, left out at its default, so an old file opens unchanged and
saves byte-identical when the feature is unused. No new op, record field or command-recorded kind.

- **FP1. Strip gap keys** `acc.start`, `acc.end`, `acc.after.<label>` (value: comma list of
  `end_stop`, `end_plate`, `partition`, or `none`), through `SetProperty(Component)`.
- **FP2. Strip property `open_side`** (`right` default, `left`, `none`).
- **FP3. Strip accessory part keys** `<item>.part_number`, `<item>.maker`, `<item>.description`
  for `end_stop`, `end_plate`, `end_plate_pe`, `partition`, `jumper_<2…50>`, `marker`,
  `strip_label`, and `marker.per_card`.
- **FP4. Project keys** `strip_<item>_<field>` (FP3's keys with `.` → `_`) and
  `strip_accessories` (`auto` default, `off`), through `projectprops`.
- **FP5. Conductor property `bridge`** (`jumper`; absent = wire bridge), and `setprop
  {conductors: [..]}` for that key only.
- **FP6 (ops recorded, not format).** `renumber {kind: "terminals"}` records `SetProperty` moves of
  `acc.after.*` in its transaction; the slow tests that pin its ops are updated.

**Code, not format:** the `accessory` command and Strip Accessory tool; `bridge`'s `kind` and
`terminals`; Checks kinds; plan, BOM and wire-report rows; the jumper marks.

## 15. Owner questions, each with a recommendation

1. **Automatic or placed:** end stops and end plates come from the rule with a per-gap override;
   partitions and jumpers are placed; marker cards and strip labels follow from part data?
   **Recommend yes**: every strip needs the first two, only the designer knows where groups split.
2. **Gap keys by position label** (`acc.after.4`), moved by Renumber, with an orphan check, rather
   than by terminal ID? **Recommend labels**: spare positions have no ID, and the key reads plainly
   in Properties, MCP and merges.
3. **A jumper is a bridge conductor with `bridge = jumper`:** same net and wire number, off the wire
   report, on the BOM, drawn with square marks and no wire label? **Recommend yes**: 028's
   derivation is untouched and converting is one property.
4. **Draw Bridge's default kind:** Jumper when both terminals are on one strip and the span fits the
   largest known jumper (10 if none), else Wire; existing 028 bridges stay wire bridges?
   **Recommend yes**: plug-in jumpers are the common case on a rail; nothing in an old file
   changes.
5. **Jumper grouping:** connected jumper conductors on one strip are one jumper, sized to the
   smallest known size ≥ span, chained in pieces when longer; splitting by hand later?
   **Recommend yes**: fewest parts, no extra data.
6. **Jumper across a partition:** allowed with a Checks warning and two fixes, never refused?
   **Recommend yes**: cut-out partitions exist, and 030 must not dead-end.
7. **Part data before libraries:** strip properties, falling back to project `strip_*` defaults;
   libraries later slot in between with the same fields? **Recommend yes**: one project usually uses
   one terminal family, and nothing in the file changes when libraries arrive.
8. **Automatic items on the BOM** even with no part number (`?`, flagged), including in 028 files,
   with `strip_accessories off` to turn the rule off project-wide? **Recommend yes**: a missing end
   stop on the order is worse than a `?` row.
9. **Open side and family changes:** end plate at the right end by default, wherever the end-plate
   part changes between positions, and replaced by a partition at its gap? **Recommend yes**.
10. **Marker cards and strip label:** counted only when a part number is known
    (`ceil(positions / per_card)`, one label per strip), no marker text? **Recommend yes**: optional,
    as Carl asked; printing markers comes with a marker export later.
11. **`stripplan` includes accessory rows by default** (`accessories: false` gives 028's rows), and
    027's CSV gains them? **Recommend yes**: the plan is the build list; tell 027's reviewer.
12. **028 review findings 1 and 2** (sheet counts and the Terminals tab re-copy on every edit) fixed
    in 028's fix round before 030 starts? **Recommend yes**: 030 adds rows to the same paths.

(stage 3); accessories on devices other than terminal strips.
