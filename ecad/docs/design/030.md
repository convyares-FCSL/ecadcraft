# Design 030: Terminal strip accessories

Brief: `docs/briefs/030-terminal-accessories.md` (Draft). Builds on design 028 (strips, offers,
bridges, the terminal plan and the BOM per terminal type), 024 (BOM, reports, generated pages,
Checks counts) and 026 (the planner that renumbers terminals). Follows `008.md` §2: click-first,
one commit = one JSON-equivalent transaction, Esc writes nothing, feedback in words, never crash.
Format proposals: §14 (**the overseer decides**). Update maps: §11. Questions: §15.

**Revision 2 (2026-11-12, owner answers to revision 1):** every accessory is **placed by the user**;
the automatic rule (open side, family-change end plates, `strip_accessories`) is removed and listed
as later work in the brief. The **jumper model is open** (§5): three options, owner to decide;
nothing else in this design depends on which is chosen, except where §5 says so. Q2, Q6, Q7, Q10
and Q11 of revision 1 are accepted as recommended; Q12 is being done in 028's fix round.

**Revision 3 (2026-11-12, owner and overseer answers to revision 2; decisions in §17):** jumpers
are **links owned by the strip** (model D, §5), drawn automatically on every page with a
continuation mark, made with a Jumper tool (the hybrid, confirmed by the owner), one link set per
strip (no internal/external rows), on whole positions (levels are a likely next brief), counted on
the BOM as bars per link (bar size per strip, project default, 10 if unset). FP1–FP4 approved;
strip label as a gap item approved.

## 1. Goal and words

A strip is listed as it is built on the rail, with the accessories the designer put there, in
position order, and they are counted on the BOM. Nothing is added that the designer did not place.

| Word | Means |
| --- | --- |
| **accessory** | A part on the rail that is not a terminal: end stop, end plate, partition plate, marker, strip label, jumper |
| **end stop** | The clamp that holds a strip on the rail (an "end clamp") |
| **end plate** | The cover on a terminal's open side |
| **partition** | A partition plate (divider) between two positions: separates groups and stops a jumper |
| **marker** | The label clipped onto one terminal, bought as cards of several |
| **strip label** | The marker that carries the strip's tag, usually on an end stop |
| **gap** | Where a plate or stop sits: `start` (before the first position), `after 4` (between 4 and the next position), `end` (after the last) |
| **jumper** | A plug-in or screw bridge between terminals of one strip: a part, not a wire |
| **link** | How ECAD stores a jumper: positions of one strip joined, owned by the strip, drawn as a dashed line through its terminals on every page (§5) |
| **bar** | One jumper bar as bought (10-way by default); a link needs `ceil(span / bar size)` of them |

The glossary gains a section "Terminal accessories (brief 030)" with these rows.

## 2. Placed accessories (brief scope 1)

### 2.1 Where they are stored (FP1)

Strip properties, one key per place, value a comma list of items in order from the inner side:

| Key | Place | Items allowed | Example |
| --- | --- | --- | --- |
| `acc.start` | before the first position | `end_stop`, `end_plate`, `partition`, `strip_label` | `end_stop, strip_label` |
| `acc.end` | after the last position; follows the end when positions are added | same | `end_plate, end_stop` |
| `acc.after.<label>` | after the position labelled `<label>` | same | `acc.after.4 = partition` |
| `acc.on.<label>` | on the position labelled `<label>` | `marker` | `acc.on.4 = marker` |

- Absent means nothing there. There is no rule: a strip with no keys has no accessories, and the
  plan and BOM show none. Old 028 files therefore show exactly what they showed before.
- Spaces ignored, case-insensitive, stored canonical (`end_plate,end_stop`). At most 8 items per
  key. A word not allowed at that place is refused: `"plate" is not an accessory. Write end_stop,
  end_plate, partition or strip_label.` (`… Only marker goes on a position.` for `acc.on`). Empty
  clears the key.
- `<label>` is any position label of the strip, drawn or spare (`4`, `PE1`, `10a`), at most 16
  characters. A key whose label names no position is kept and listed by Checks (§8,
  `accessory-orphan`); it never blocks anything.
- When the last position is `12`, `acc.after.12` and `acc.end` are both at the last gap: both are
  shown, `after.12` first. `acc.end` moves with the end when positions are added; `acc.after.12`
  stays after 12.
- Why labels and not terminal IDs (Q2 of revision 1, accepted): spare positions have no terminal,
  and `acc.after.4` reads plainly in Properties, MCP and merges. Renumbering moves the keys (§6).

### 2.2 The `accessory` command

`accessory {strip, at: "start"|"end"|<label>|[<label>…], on?: bool, items?: [..] | null, add?: [..],
remove?: [..]}`, or `{terminal, …}` (the terminal names its strip and its label). It writes one
`SetProperty` per key, all in one transaction labelled `Accessory -X01 after 4`:

- `on: true` addresses `acc.on.<label>` (markers); otherwise the gap key.
- `items` replaces the key's list (`[]` or `null` clears it). `add` appends to the current list;
  `remove` takes items out (one occurrence each).
- `at` as a list (at most 999 labels) writes the same change at each, so "markers on 1…12" is one
  call and one `u`.
- Echo: `Partition after -X01:4.`, `Markers on -X01:1…12.`
- Refused with a way forward: not a strip (`-X09 is not a terminal strip. Pick a terminal of the
  strip.`), a label not on the strip (`-X01 has no position 15; it has 1…12. Pick one of those, or
  start/end.`), more than 8 items, an item not allowed there (above).

### 2.3 Strip Accessory tool

ECAD tab, Components group, after Draw Bridge: **Strip Accessory** (`ecad.tool.accessory`,
command `accessory`). Prompts:

```
Select terminal [Start/End]:
Accessory at -X01:4 [Partition/Endplate/endStop/Marker/Label/Remove] <Partition>:
```

Partition, end plate, end stop and strip label go in the gap after the terminal (Start/End pick the
strip's ends); Marker goes on the terminal. Remove takes the last item of that place. The preview
draws the §7.3 mark beside the terminal. The tool repeats on the next terminal until Enter or Esc;
each pick is one transaction. Esc writes nothing.

### 2.4 From the terminal plan

Reports ▸ Terminals gains an **Accessory ▾** button (`ecad.reports.terminals.accessory`) acting on
the selected rows (Ctrl and Shift select several): **Partition after**, **End plate after**, **End
stop after**, **Strip label after**, **Marker on**, **Remove**. On an accessory row it acts on that
row's place. Several rows make one `accessory` call with `at` as a list. **At start** / **At end**
items act on the strip's ends.

A section **Accessories** under 028's strip rows (`ecad.props.strip.acc`):

| Field | Editing |
| --- | --- |
| **Placed** (read-only) | `start: end stop · after 4: partition · end: end plate, end stop · markers: 12` with **Show plan** |
| **Parts** | a table, one row per item (End stop, End plate, End plate PE, Partition, Marker, Strip label, and the jumper rows of §5): Part number, Maker and, for Marker, Per card; the placeholder shows the project's value, `from project: ES-1`, or `e.g. ES-1` |

## 4. Part data (Q7 of revision 1, accepted; FP2, FP3)

Libraries (stage 3) are not built. Until they are, accessory part data are properties: on the
strip first, then the project's default, then unknown (`?`).

| Item | Strip keys | Project keys (default for every strip) |
| --- | --- | --- |
| End stop | `end_stop.part_number`, `.maker`, `.description` | `strip_end_stop_part_number`, `_maker`, `_description` |
| End plate | `end_plate.…` | `strip_end_plate_…` |
| End plate on a PE position | `end_plate_pe.…` | `strip_end_plate_pe_…` |
| Partition | `partition.…` | `strip_partition_…` |
| Marker | `marker.…`, `marker.per_card` (1…100) | `strip_marker_…`, `strip_marker_per_card` |
| Strip label | `strip_label.…` | `strip_strip_label_…` |
| Jumper bar | `jumper.part_number`, `.maker`, `.description`, `jumper.bar` (bar size); a link may override the part with `link.<n>.part_number` (§5.6) | `strip_jumper_part_number`, `_maker`, `_description`, `strip_jumper_bar` |

- Project key = `strip_` + the strip key with `.` → `_`, so it passes the project key rule (all
  under 40 characters).
- A strip's own value wins per key. Part numbers and makers go through `devices::property_value`
  (trimmed, the same limits as `part_number`). `per_card` outside 1…100 is refused: `"0" is not a
  card size. Write 1 to 100.`
- An end plate in a gap uses `end_plate_pe` when the position before it is PE and `end_plate_pe`
  is known; otherwise `end_plate`.
- **Later (stage 3):** a terminal part in a library carries the same fields; the lookup becomes
  strip → the terminal's library part → project. Nothing in the file changes.
- Descriptions default to words: `End stop`, `End plate`, `End plate (PE)`, `Partition plate`,
  `Marker`, `Marker card ×10`, `Strip label`.

## 5. Jumpers: links owned by the strip (model D and the Jumper tool; owner decisions 2026-11-12)

Carl chose model D (revision 2's option C, refined against his reference drawings): a jumper is a
**link**, owned by the strip, never a conductor. Links are made with the hybrid below: a
Jumper tool creates or extends the link, and the line is drawn automatically wherever its
terminals appear (owner, 2026-11-12). §5.7 records the pure automatic alternative, rejected.
Revision 2's options A–C are withdrawn.

### 5.1 What a link is (FP5)

A **link** joins positions of one strip electrically: one net, one wire number, no wire. It is
stored as a strip property, one key per link:

| Key | Value | Example |
| --- | --- | --- |
| `link.<n>` | the positions, in plan order: ranges `a-b` (every position from a to b) and single labels, comma-separated | `link.1 = 1-4`, `link.2 = 7, 9, 11` (a skip link) |
| `link.<n>.part_number`, `.maker`, `.description` | optional, this link's own jumper part (a red bar for 24 V, a blue one for 0 V) | `link.2.part_number = JB-10-BU` |

- `<n>` is a whole number 1…999 given when the link is made (highest + 1 on the strip) and never
  reused while the key exists. It names the link in selection, MCP and merges; users see the
  positions, `link 1-4`.
- A link has at least 2 positions, at most 999. Labels as in §2.1 (at most 16 characters each).
  Spaces ignored; stored canonical (ranges collapsed: `1,2,3,4` → `1-4`). Unreadable text is
  refused: `"1–x" is not a link. Write positions like 1-4 or 7, 9, 11.`
- Spare positions may be in a link (the jumper is bought for them); only drawn terminals join nets.
- One link set per strip (no internal/external rows: owner, 2026-11-12). Links may overlap or skip;
  they are drawn in **lanes** (§5.3) so they never cross.
- **Levels:** a link joins whole positions. Multi-level terminals, and links per level, are a likely
  next brief after a status review (brief, Later).
- 028's wire bridges (a wire between two terminals of one strip) stay as they are, beside links.

### 5.2 Nets and wire numbers

022's connectivity gains a second bridge source beside `Definition::bridges`: the links of each
strip join the connection points of their drawn terminals (code, not format). A link edit is a
`SetProperty(strip, link.<n>)`; it counts as touching the nets of every terminal in the link
before and after, so 022's numbering pass merges or splits those nets' wire numbers **in the same
transaction**, with the rules 022's pass already applies when a wire joins two numbered nets (a
fixed number wins; two fixed numbers give 022's `two-fixed` Checks row, never a refusal). One `u`
undoes the link and its numbers.

### 5.3 How it is drawn: derived, on every page (owner decision)

On every page that shows terminals of a link, the page draws a **link line** (derived, never
stored, never editable as geometry):

- through the centres of that link's terminals shown on this page, in position order, a straight
  dashed line (`ecad.link`, linetype dashed 2 mm / 1 mm, `ecad.hairline`); between two shown
  terminals that are not in one horizontal or vertical row, an orthogonal dog-leg;
- **continuation:** where the link has positions beyond the first or last terminal shown on this
  page (drawn elsewhere, or spare), the line runs on past that terminal by `ecad.link-stub`
  (4 mm) in the line's direction, as the reference convention does; a page showing one terminal of a
  link draws only the stub (to the right, or up for a vertical row);
- **lanes:** links of one strip whose spans overlap get lanes 0, 1, 2… (greedy by first position,
  then link number, stable). Lane k is offset `k × 1.5 mm` perpendicular to the row (up, or left
  for a vertical row), so overlapping and skip links run side by side and never cross. Lane 0 goes
  through the terminal centres. The same lanes order the plan's link column (§7.1);
- skipped positions inside a skip link get no mark (the line passes them in its lane).

Moving a terminal redraws the line on that page only. Hover on a line: `-X01 link 1-4 (4 positions,
1 bar JB-10)`.

### 5.4 The Jumper tool (hybrid; decided)

ECAD tab, Components group, beside Draw Bridge: **Jumper** (`ecad.tool.jumper`, command `jumper`).
It feels like drawing a wire, but makes or extends a link, never a conductor.

```
Select first terminal:                        (a terminal, or a link line to extend it)
Next terminal of -X01 (Enter finishes) [Skip/Undo]:
```

- After the first pick a dashed rubber band follows the cursor. Each next pick (a click, or
  dragging across terminal symbols, each counted once) adds positions: by default **every position
  from the previous pick to this one** (a range); with **Skip** on, only the picked terminal (skip
  links). The preview draws the link line as it will be, with its lane.
- A first pick on a terminal already in a link, or on a link line, **extends that link**; otherwise
  Enter makes a new link. Undo removes the last pick. Esc writes nothing.
- A terminal of another strip: `-X02:1 is on another strip; a link stays on one strip. Pick a
  terminal of -X01, or Enter to finish.` (not added, the tool carries on).
- Enter writes **one transaction** (`Link -X01 1-4`, or `Extend link -X01 1-4 → 1-6`): one
  `SetProperty(strip, link.<n>)`, plus the numbering pass's wire-number ops.
- Positions shown on other pages can be added by typing their labels at the prompt (`5,6`), or from
  the terminal plan (§5.5).

### 5.5 Selecting and editing a link

A click on a link line selects **the link** (`cad.hover` highlight on every segment and stub of it
on this page; the Properties panel shows Link: positions, part, bars). Then:

| Action | Where | Writes |
| --- | --- | --- |
| **Extend** | context menu, or the Jumper tool with the link as first pick | `link.<n>` with more positions |
| **Shorten** | context menu ▸ Shorten, then pick the terminal(s) to remove; removing an inner position of a range splits it into a skip | `link.<n>` with fewer positions; fewer than 2 removes the key |
| **Split here** | context menu on a segment | `link.<n>` up to the segment, a new `link.<m>` after it (one transaction) |
| **Delete** | Delete key, or context menu | `link.<n>` (and its part keys) cleared |
| **Positions** | Properties ▸ Link ▸ Positions (text) | `link.<n>` as typed |
| **Part** | Properties ▸ Link ▸ Part number / Maker | `link.<n>.part_number` / `.maker` |

The line itself is never moved, trimmed or erased as geometry: CADCraft's own edit commands leave
it alone (it is derived drawing, like a cable's fan view), and Erase on a selected link deletes the
link, saying so (`Deleted link -X01 1-4.`). Every edit is one transaction and one `u`.

From the terminal plan: select rows and **Link** (`ecad.reports.terminals.link`) makes a link of
those positions (a range when contiguous, else a skip link); **Unlink** removes the selected
positions from their links.

### 5.6 BOM: bars per link (owner decision)

- Bar size: strip property `jumper.bar` (2…50), else project `strip_jumper_bar`, else **10**.
- Per link: `bars = ceil(span / bar)`, where span = last position index − first + 1 in plan order
  (spare positions counted, accessories not). `link 1-4` → 1 bar; a 12-position link → 2 bars.
- Part: the link's own `link.<n>.part_number`, else the strip's `jumper.part_number`, else the
  project's `strip_jumper_part_number`, else `?` (flagged). Colour is part of the part number, so a
  red and a blue jumper are two parts.
- BOM rows per strip per jumper part: `Jumper bar ×n` with Tags = the strip, Qty = Σ bars; **By
  part** merges strips as for other accessories.

### 5.7 Rejected alternative: pure automatic links

Considered and rejected by the owner (2026-11-12): no Jumper tool; links are written only in the terminal plan and
Properties (`Link`, positions text), and the lines appear on the pages automatically (§5.3). It is
simpler to build (no interactive tool, no line selection: about a third less work in §5) and keeps
the plan as the one place links are made, but the designer cannot make or see a link where they
draw, and extending one means leaving the page. The plan's Link and Unlink buttons (§5.5) stay as
a second way to make links.

## 6. Renumbering (026, 028 §9.5; FP4)

When `renumber {kind: "terminals"}` changes a strip's labels, the same transaction moves every
`acc.after.<old>` and `acc.on.<old>` key to the new label (`SetProperty` to unset, `SetProperty` to
set), so an accessory stays with the terminal it followed or sat on. Moves are applied on the end
state, so `4 ↔ 5` swaps cleanly. Keys on spare positions keep their labels (spare positions are not
renumbered). The Renumber preview adds a line per strip: `-X01: partition after 4 → after 6`.
The same pass rewrites the labels inside every `link.<n>` value (ranges re-collapsed in the new
order), so a link joins the same terminals after renumbering; the preview lists `-X01: link 1-4 →
3-6`.

Any other way a label disappears (erasing a terminal, lowering the offer) leaves the key where it
is; Checks lists it (`accessory-orphan`).

## 7. Terminal plan, BOM and the rest (brief scope 2)

### 7.1 Plan rows (028 §5.1, extended)

Rows in physical order: `acc.start`'s items, then each position followed by its `acc.after`
items, then `acc.end`'s items. Gap rows:

| Column | Gap row |
| --- | --- |
| Inside target | the item in words: `end stop`, `end plate`, `partition`, `strip label -X01` |
| Terminal | a mark (§7.3) |
| Place | the part number, `?` when unknown (flagged as 024 does) |
| others | blank |

A marker is not a row: a position with `acc.on.<label> = marker` shows `▭` after its label in the
Terminal cell. The Bridge column (028) also shows links: one narrow sub-column per lane (§5.3), a
dot on each linked position and a vertical line through the link's span (dashed past skipped
positions); 028's wire-bridge groups keep `● n`. The header gains totals:
`-X01  +CP1  12 positions: 10 drawn, 2 spare · 2 end stops, 1 end plate, 1 partition, 12 markers,
2 links (3 bars)`.

Reports ▸ Terminals gains an **Accessories** check box (`ecad.reports.terminals.acc`, on by
default) that hides gap rows from the table (view only; the generated page always shows them).

### 7.2 `stripplan` JSON (027 relies on it; Q11 of revision 1, accepted)

Rows keep 028's keys and gain:
- every row: `kind`: `"terminal"` | `"accessory"`;
- gap rows: `{kind: "accessory", state: "accessory", accessory: "end_stop"|"end_plate"|"partition"|
  "strip_label", gap: "start"|"end"|<label>, part_number, maker, terminal: null, label: null}`;
- terminal rows: `marker: bool`, `links: [{link: n, lane}]` (empty when none);
- strip: `accessories: {end_stop, end_plate, partition, strip_label, marker}` (counts), `links:
  [{link: n, positions: "1-4", span, lane, bars, part_number, maker}]`;
- 028's `bridge_group` is unchanged: it still names wire bridges only.
- New parameter `accessories` (default `true`); `false` gives 028's rows exactly.

`limit` and paging count gap rows like terminal rows.

### 7.3 Generated `terminals` page (028 §5.3)

A gap row is a full 5 mm row: the word in the Inside target cell in `ecad.xref-spare`, and across
the Terminal cell a horizontal mark: end stop two 0.5 mm lines 1 mm apart, end plate one 0.35 mm
line, partition one 0.7 mm line extended over the Inside wire and Outside wire cells, strip label a
4 × 2 mm box with the tag. A marker is a 1 mm open box after the terminal label. Links: in the
Bridge column, per lane a 1 mm filled dot on each linked row and a 0.35 mm vertical line through
the span, dashed past skipped rows. 44 rows per sheet counts every row.

### 7.4 BOM (024 §6.1, 028 §9.1)

Per strip, after its terminal rows, one row per accessory part, only for items that are placed:

| Row | Qty |
| --- | --- |
| End stop, Partition plate, Strip label | items placed |
| End plate, End plate (PE) | end plates placed, by the position before each (§4) |
| Marker | markers placed; with `per_card` known, the row is `Marker card ×n` with Qty `ceil(markers / per_card)` |
| Jumper bar | per link `ceil(span / bar size)`, summed per jumper part (§5.6) |

Tags = the strip's tag; Description, Maker, Part number from §4; a missing part number shows `?`
and is flagged, as 024 does for devices. Markers are listed only when a marker part number is known
(Q10 of revision 1, accepted); without one, placed markers show in the plan but not on the BOM, and
`no-accessory-part` counts them. **By part** grouping merges equal parts across strips
(`-X01, -X02`). **By location** uses the strip's location.

### 7.5 Hover lens (028 §7.1)

- Terminal: adds `partition after`, `end plate after`, `marker` when present, and `link 1-4`.
- Strip line: `-X01: 12 positions, 10 drawn, 2 spare · 1 partition, 12 markers, 2 links`.
- Link line: §5.3.

## 8. Checks (022 Checks tab; every row has a way out; nothing is refused)

| Kind | Severity | Row text | Go-to | Fix buttons |
| --- | --- | --- | --- | --- |
| `accessory-orphan` | Warning ▲ | `-X01: partition after 15, but -X01 has no position 15` | the strip's last terminal | **Move to end** (items appended to `acc.end`, key cleared, one transaction), **Remove** (key cleared) |
| `no-accessory-part` | Info, one count row | `14 strip accessories have no part number` | — | **Show** (Reports ▸ BOM, Only ? on), as 024's `NoPartNumber` |
| `link-across-partition` | Warning ▲ | `-X01: link 3-5 crosses the partition after 4` | the link (selected, its line ringed) | **Split link at 4** (two links, one transaction), **Remove partition** (`accessory remove [partition]`) |
| `link-orphan` | Warning ▲ | `-X01: link 3-15 names 13-15, which -X01 does not have` | the link | **Drop missing positions** (`link.<n>` rewritten; fewer than 2 left removes it), **Delete link** |

Overlapping and skip links are normal (drawn in lanes) and are no check. Checks that need a rule (a
strip with no end stop, an open end with no end plate) are later work, with the rule.

### 9.4 020 merge

Every addition is a property, so a branch merge compares and offers them like any property; two
branches placing different items at one place conflict on one key, the right granularity. Links are
one key each, so two branches adding different links never conflict, except when both drew a new
link with the same number on one strip: that conflicts on the key, and the merge offers **Keep
both** (the branch's link takes the next free number), as 026 does for tags.

     its terminals appear, with a continuation mark; editing the link updates every drawing; the
     line is never edited as geometry.
