Brief: `docs/briefs/030-terminal-accessories.md` (Draft). Builds on design 028 (strips, offers,
bridges, the terminal plan and the BOM per terminal type), 024 (BOM, reports, generated pages,
Checks counts) and 026 (the planner that renumbers terminals). Follows `008.md` §2: click-first,
one commit = one JSON-equivalent transaction, Esc writes nothing, feedback in words, never crash.
Format proposals: §14 (**the overseer decides**). Update maps: §11. Questions: §15.

**Revision 2 (2026-11-12, owner answers to revision 1):** every accessory is **placed by the user**;
the automatic rule (open side, family-change end plates, `strip_accessories`) is removed and listed
as later work in the brief. The **jumper model is open** (§5): three options, owner to decide;
nothing else in this design depends on which is chosen, except where §5 says so. Q2, Q6, Q7, Q10
and Q11 of revision 1 are accepted as recommended; Q12 is being done in 028's fix round.

## 0. What the code has today (checked on `origin/feature/terminal-strips` `81139aaf`)

  conductor whose two ends are on two terminals of one strip), the offer parser (`12+2PE`, at most

- `outputs.rs`: the wire report's Cable cell reads `Bridge -X01` for a bridge; the BOM gives a

## 1. Goal and words

A strip is listed as it is built on the rail, with the accessories the designer put there, in
position order, and they are counted on the BOM. Nothing is added that the designer did not place.

| Word | Means |
| --- | --- |
| **accessory** | A part on the rail that is not a terminal: end stop, end plate, partition plate, marker, strip label, jumper |
| **end stop** | The clamp that holds a strip on the rail (an "end clamp") |
| **end plate** | The cover on a terminal's open side |
| **partition** | A partition plate (divider) between two positions: separates groups and stops a jumper |
| **marker** | The label clipped onto one terminal, bought as cards of several |
| **strip label** | The marker that carries the strip's tag, usually on an end stop |
| **gap** | Where a plate or stop sits: `start` (before the first position), `after 4` (between 4 and the next position), `end` (after the last) |
| **jumper** | A plug-in or screw bridge between terminals of one strip: a part, not a wire. How it is modelled is open (§5) |

The glossary gains a section "Terminal accessories (brief 030)" with these rows.

## 2. Placed accessories (brief scope 1)

### 2.1 Where they are stored (FP1)

Strip properties, one key per place, value a comma list of items in order from the inner side:

| Key | Place | Items allowed | Example |
| --- | --- | --- | --- |
| `acc.start` | before the first position | `end_stop`, `end_plate`, `partition`, `strip_label` | `end_stop, strip_label` |
| `acc.end` | after the last position; follows the end when positions are added | same | `end_plate, end_stop` |
| `acc.after.<label>` | after the position labelled `<label>` | same | `acc.after.4 = partition` |
| `acc.on.<label>` | on the position labelled `<label>` | `marker` | `acc.on.4 = marker` |

- Absent means nothing there. There is no rule: a strip with no keys has no accessories, and the
  plan and BOM show none. Old 028 files therefore show exactly what they showed before.
- Spaces ignored, case-insensitive, stored canonical (`end_plate,end_stop`). At most 8 items per
  key. A word not allowed at that place is refused: `"plate" is not an accessory. Write end_stop,
  end_plate, partition or strip_label.` (`… Only marker goes on a position.` for `acc.on`). Empty
  clears the key.
- `<label>` is any position label of the strip, drawn or spare (`4`, `PE1`, `10a`), at most 16
  characters. A key whose label names no position is kept and listed by Checks (§8,
  `accessory-orphan`); it never blocks anything.
- When the last position is `12`, `acc.after.12` and `acc.end` are both at the last gap: both are
  shown, `after.12` first. `acc.end` moves with the end when positions are added; `acc.after.12`
  stays after 12.
- Why labels and not terminal IDs (Q2 of revision 1, accepted): spare positions have no terminal,
  and `acc.after.4` reads plainly in Properties, MCP and merges. Renumbering moves the keys (§6).

### 2.2 The `accessory` command

`accessory {strip, at: "start"|"end"|<label>|[<label>…], on?: bool, items?: [..] | null, add?: [..],
remove?: [..]}`, or `{terminal, …}` (the terminal names its strip and its label). It writes one
`SetProperty` per key, all in one transaction labelled `Accessory -X01 after 4`:

- `on: true` addresses `acc.on.<label>` (markers); otherwise the gap key.
- `items` replaces the key's list (`[]` or `null` clears it). `add` appends to the current list;
  `remove` takes items out (one occurrence each).
- `at` as a list (at most 999 labels) writes the same change at each, so "markers on 1…12" is one
  call and one `u`.
- Echo: `Partition after -X01:4.`, `Markers on -X01:1…12.`
- Refused with a way forward: not a strip (`-X09 is not a terminal strip. Pick a terminal of the
  strip.`), a label not on the strip (`-X01 has no position 15; it has 1…12. Pick one of those, or
  start/end.`), more than 8 items, an item not allowed there (above).

### 2.3 Strip Accessory tool

ECAD tab, Components group, after Draw Bridge: **Strip Accessory** (`ecad.tool.accessory`,
command `accessory`). Prompts:

```
Select terminal [Start/End]:
Accessory at -X01:4 [Partition/Endplate/endStop/Marker/Label/Remove] <Partition>:
```

Partition, end plate, end stop and strip label go in the gap after the terminal (Start/End pick the
strip's ends); Marker goes on the terminal. Remove takes the last item of that place. The preview
draws the §7.3 mark beside the terminal. The tool repeats on the next terminal until Enter or Esc;
each pick is one transaction. Esc writes nothing.

## 4. Part data (Q7 of revision 1, accepted; FP2, FP3)

Libraries (stage 3) are not built. Until they are, accessory part data are properties: on the
strip first, then the project's default, then unknown (`?`).

| Item | Strip keys | Project keys (default for every strip) |
| --- | --- | --- |
| End stop | `end_stop.part_number`, `.maker`, `.description` | `strip_end_stop_part_number`, `_maker`, `_description` |
| End plate | `end_plate.…` | `strip_end_plate_…` |
| End plate on a PE position | `end_plate_pe.…` | `strip_end_plate_pe_…` |
| Partition | `partition.…` | `strip_partition_…` |
| Marker | `marker.…`, `marker.per_card` (1…100) | `strip_marker_…`, `strip_marker_per_card` |
| Strip label | `strip_label.…` | `strip_strip_label_…` |
| Jumper | per §5's option | per §5's option |

- Project key = `strip_` + the strip key with `.` → `_`, so it passes the project key rule (all
  under 40 characters).
- A strip's own value wins per key. Part numbers and makers go through `devices::property_value`
  (trimmed, the same limits as `part_number`). `per_card` outside 1…100 is refused: `"0" is not a
  card size. Write 1 to 100.`
- An end plate in a gap uses `end_plate_pe` when the position before it is PE and `end_plate_pe`
  is known; otherwise `end_plate`.
- **Later (stage 3):** a terminal part in a library carries the same fields; the lookup becomes
  strip → the terminal's library part → project. Nothing in the file changes.
- Descriptions default to words: `End stop`, `End plate`, `End plate (PE)`, `Partition plate`,
  `Marker`, `Marker card ×10`, `Strip label`.

## 5. Jumpers: owner to decide

**Status: open.** The owner will compare these options with the drawing pack he gave earlier. The
designer could not find that pack in the feature checkout or in the main checkout's git-ignored `ecad/private/`
(which holds no terminal plans or schematics), so the
options below come from general practice and are **not yet checked against the pack**. No worker
builds §5 until the owner chooses; §2–§4, §6–§8 for the other accessories do not wait for it.

What every option shares:
- A jumper joins terminals of **one strip** electrically (one net, one wire number), adjacent or
  skipping positions (a skip jumper has teeth removed), in sizes such as 2-, 3- and 10-way.
- It is a **part** on the BOM, by size, with part data from §4's lookup (`jumper_<n>.part_number`,
  n = 2…50, project `strip_jumper_<n>_…`). Its size is the smallest known size ≥ its **span**
  (first to last position, spare positions counted); no size known → size = span, part `?`.
- It appears in the terminal plan's Bridge column (`■ n` on connected rows, `┆` on skipped rows),
  and a jumper across a partition gives a Checks warning, never a refusal (Q6, accepted).
- 028's wire bridges stay as they are: a wire between terminals of one strip, listed as
  `Bridge -X01` on the wire report, not on the BOM.

### Option A: a bridge conductor marked `bridge = jumper`

The jumper is a conductor between two terminals, as 028's Draw Bridge makes, with conductor property
`bridge = jumper`. Connected jumper conductors on one strip form one jumper.

- **Looks:** drawn on the schematic as the staple 028 draws, with filled squares at its ends and no
  wire-number label. A 3-way jumper is two staples (3–4, 4–5).
- **Wire report:** left out (footer `2 jumpers not listed`). **BOM:** one row per jumper by size.
- **Nets:** unchanged; 022 already joins the terminals through the conductor.
- **Cost:** low. One conductor property; plan, BOM and wire-report filters; Draw Bridge gains
  Jumper/Wire and a terminal list; converting is one `setprop`. Grouping is derived, so two
  separate jumpers on 3–4 and 4–5 cannot be told from one 3-way jumper without more data.
- **Fits** a house style that draws every jumper on the schematic as a link between terminals.

### Option B: a strip property, shown only in the terminal plan

The jumper belongs to the strip, not the drawing: strip property `jumpers` lists the groups by
position label, `3-5, 7+9` (3 to 5 joined; 7 and 9 joined, 8 skipped). Nothing is drawn on the
schematic; the terminals' wires on the schematic do not show the link.

- **Looks:** only the terminal plan (Reports ▸ Terminals and the `terminals` page) shows the jumper,
  as a bar down the Bridge column. Hover on a terminal says `jumper to 4, 5`.
- **Wire report:** nothing to leave out (no conductor). **BOM:** one row per group by size, each
  group exactly as written (two groups `3-4, 4-5` are two 2-way jumpers).
- **Nets:** 022 must join the terminals from the strip property: `connectivity::bridged` gains a
  per-strip source beside `Definition::bridges`, and a `SetProperty(strip, jumpers)` must count as
  touching the nets of those terminals so the numbering pass merges or splits their wire numbers in
  the same transaction. Renumber rewrites the labels in `jumpers` (as §6 does for `acc.*`).
- **Cost:** medium. New net source and its update map (022's net index, wire-number pass), a parser,
  a plan editor (select rows → **Jumper**), the renumber rewrite. The schematic gives no sign that
  two terminals are linked, which a reader of the schematic may miss.
- **Fits** a house style where jumpers are a terminal-strip matter, set in the strip editor, and
  the schematic shows terminals and their field and panel wires only.

### Option C: B's model, also drawn on the schematic as derived marks

As B (strip property, nets from the strip), and in addition the page draws a derived link (not
stored, never selectable as a wire) between terminals of one jumper that are shown on the same
page: a short bar beside the terminals on the inside side, `ecad.jumper-mark`.

- **Looks:** the schematic shows a jumper wherever its terminals are drawn together; terminals on
  different pages show a small `▪` mark with the hover `jumper to -X01:5 (page 105)`.
- **Wire report and BOM:** as B.
- **Cost:** B's cost plus a derived drawing layer for the strip's pages (its update map: a jumper or
  terminal change redraws the strip's pages only). Moving a terminal redraws the bar.
- **Fits** a house style that draws jumpers on the schematic but manages them in the strip.

### Comparison and recommendation

| | A: conductor | B: strip, plan only | C: strip, plus derived marks |
| --- | --- | --- | --- |
| Schematic | staple with square ends | nothing | derived bar |
| Grouping | derived, connected = one | as written | as written |
| Nets | unchanged | new per-strip source | new per-strip source |
| Wire report | filter out | nothing to do | nothing to do |
| Worker size | S | M | M+ |
| Change later | A → B/C: a converter turns marked conductors into groups | B → C: drawing only | — |

**Recommendation, provisional until the owner has checked the pack: C** if the pack draws jumpers
on the schematic as links between terminals while the strip owns them, **B** if the pack shows
them only on terminal plans. A is the cheapest but ties a part to a drawn wire, which is the
pattern the owner suspects is not real practice. The owner question is §15 Q1.

## 6. Renumbering (026, 028 §9.5; FP4)

When `renumber {kind: "terminals"}` changes a strip's labels, the same transaction moves every
`acc.after.<old>` and `acc.on.<old>` key to the new label (`SetProperty` to unset, `SetProperty` to
set), so an accessory stays with the terminal it followed or sat on. Moves are applied on the end
state, so `4 ↔ 5` swaps cleanly. Keys on spare positions keep their labels (spare positions are not
renumbered). The Renumber preview adds a line per strip: `-X01: partition after 4 → after 6`.
(Under jumper option B or C, the same pass rewrites `jumpers`.)

Any other way a label disappears (erasing a terminal, lowering the offer) leaves the key where it
is; Checks lists it (`accessory-orphan`).

items, then `acc.end`'s items. Gap rows:

| Column | Gap row |
| --- | --- |

| others | blank |

A marker is not a row: a position with `acc.on.<label> = marker` shows `▭` after its label in the

Reports ▸ Terminals gains an **Accessories** check box (`ecad.reports.terminals.acc`, on by

### 7.2 `stripplan` JSON (027 relies on it; Q11 of revision 1, accepted)

Rows keep 028's keys and gain:
- every row: `kind`: `"terminal"` | `"accessory"`;
- gap rows: `{kind: "accessory", state: "accessory", accessory: "end_stop"|"end_plate"|"partition"|
  "strip_label", gap: "start"|"end"|<label>, part_number, maker, terminal: null, label: null}`;
- terminal rows: `marker: bool`; jumper fields per §5's option (none until it is chosen);
- strip: `accessories: {end_stop, end_plate, partition, strip_label, marker}` (counts).
- New parameter `accessories` (default `true`); `false` gives 028's rows exactly.

`limit` and paging count gap rows like terminal rows.

### 7.3 Generated `terminals` page (028 §5.3)

A gap row is a full 5 mm row: the word in the Inside target cell in `ecad.xref-spare`, and across
the Terminal cell a horizontal mark: end stop two 0.5 mm lines 1 mm apart, end plate one 0.35 mm
line, partition one 0.7 mm line extended over the Inside wire and Outside wire cells, strip label a
4 × 2 mm box with the tag. A marker is a 1 mm open box after the terminal label. 44 rows per sheet
counts every row.

### 7.4 BOM (024 §6.1, 028 §9.1)

Per strip, after its terminal rows, one row per accessory part, only for items that are placed:

| Row | Qty |
| --- | --- |
| End stop, Partition plate, Strip label | items placed |
| End plate, End plate (PE) | end plates placed, by the position before each (§4) |
| Marker | markers placed; with `per_card` known, the row is `Marker card ×n` with Qty `ceil(markers / per_card)` |
| Jumper n-way | per §5's option |

Tags = the strip's tag; Description, Maker, Part number from §4; a missing part number shows `?`

`no-accessory-part` counts them. **By part** grouping merges equal parts across strips
(`-X01, -X02`). **By location** uses the strip's location.

### 7.5 Hover lens (028 §7.1)

- Terminal: adds `partition after`, `end plate after`, `marker` when present.

## 11. Update maps and cost

### 11.1 Strips (028 §11.1, extended)

`Strips` keeps per strip its placed lists (keys parsed, labels resolved to places), counts, BOM
rows and orphans, and an index **`inherits: key → strips`** (strips reading a project `strip_*`
key because they have no value of their own). Built whole only where 028 builds `Strips` (open,
reload, branch switch, revision open, first show). After that, rows added to 028's map; **every op
not listed does nothing to accessories**:

| Op (kind, target) | Recomputed |
| --- | --- |
| `SetProperty(Component s, acc.*)`, s a strip | s's places, counts, BOM rows, orphans, checks |
| `SetProperty(Component s, <item>.part_number \| .maker \| .description \| marker.per_card)` | s's BOM rows and `inherits` entries |
| `SetProperty(Project, strip_<item>_<field>)` | the strips in `inherits[key]` only: their BOM rows |
| 028's strip rows: `AddTerminal`/`RemoveTerminal`, `SetProperty(s, terminals)`, `Link`/`Modify`/`UnlinkRepresentation` of s | s's positions changed, so its places (the end gap, orphans, PE end plates) and counts |
| `renumber`'s `SetProperty(s, acc.*)` moves | covered by the first row (one strip each) |
| anything else | nothing |

Jumper rows are added to this map with §5's option (A: `SetProperty(Conductor w, bridge)` and
028's conductor rows; B/C: `SetProperty(s, jumpers)` plus 022's net map).

The Terminals tab and an open `terminals` page redraw only when a strip they show is in
`Strips::last_changed` (028's rule, with the reviewer's finding 2 applied to the tab).

### 11.3 Cost and bench (`cargo xtask bench`, large tier)

The bench step that adds 028's 250 strips also sets project defaults for every item, places end
stops and end plates at both ends of every strip, a partition after every 5th terminal on 50
strips, and markers on every position of 50 strips. Build adds O(positions + keys), about 7 000
visits.

| Row | Measures | Target |
| --- | --- | --- |
| `stripbuild ms` | first build of strips with accessories | no more than 10 % over 028's |
| `accset ms` | `accessory` partition after 4, commit, update | < 2 ms beyond `edit` |
| `accmany ms` | `accessory` markers on 20 positions in one call, commit, update | < 16 ms |
| `accproj ms` | change `strip_end_plate_part_number` (250 strips inherit), commit, update | < 16 ms |
| `trenum ms` | 028's row with 4 `acc.*` keys on the strip | < 16 ms |

`stripupd`, `netupd`, `xref`, `draw_window` and 024/028 rows must not get noticeably worse (more
than 10 %). The verify-mode comparison of kept and rebuilt `Strips` covers the accessory fields; a

## 14. Format proposals (for the overseer)

Every addition is an optional property, left out when unused, so an old file opens unchanged and
saves byte-identical. No new op or record field.

- **FP1. Strip placement keys** `acc.start`, `acc.end`, `acc.after.<label>` (comma list of
  `end_stop`, `end_plate`, `partition`, `strip_label`) and `acc.on.<label>` (`marker`), through
  `SetProperty(Component)`.
- **FP2. Strip accessory part keys** `<item>.part_number`, `<item>.maker`, `<item>.description`
  for `end_stop`, `end_plate`, `end_plate_pe`, `partition`, `marker`, `strip_label`, and
  `marker.per_card`.
- **FP3. Project keys** `strip_<item>_<field>` (FP2's keys with `.` → `_`), through `projectprops`.
- **FP4 (ops recorded, not format).** `renumber {kind: "terminals"}` records `SetProperty` moves of
  `acc.after.*` and `acc.on.*` in its transaction; the slow tests that pin its ops are updated.
- **Jumper FPs wait for §5:** option A adds conductor property `bridge` and `jumper_<n>` part keys;
  B and C add strip property `jumpers`, the `jumper_<n>` part keys and a per-strip source in 022's
  connectivity (code, not format).

Revision 1's `open_side` and `strip_accessories` are withdrawn.

**Code, not format:** the `accessory` command and Strip Accessory tool; Checks kinds; plan and BOM
rows.
