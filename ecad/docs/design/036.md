## 1. Goal and words

A strip is listed and bought as it is built: each position is one part, with the levels its type
has, each level labelled and linked on its own, and each level drawn where its circuit is.

| Word | Means |
| --- | --- |
| **position** | One terminal block on the rail: the strip terminals that share one **position label** (`1`, `2.1`) |
| **level** | One deck of a position: one connection point (feed-through level), or two (fuse and disconnect: in and out). Numbered 1… from the top deck |
| **terminal type** | What a position is: feed-through, PE, 2-level, 3-level, L/N/PE, sensor, disconnect, fuse, 2-level bridged (§2.2) |
| **level name** | The level's short name, shown in its label: `L`, `N`, `PE`; `S`, `+`, `−`; `1`, `2`, `3`. A registry default |
| **terminal label** | What the page and the plan show for one level: `1.L`, or a per-level override (§4) |
| **internal bridge** | Levels of one position joined inside the block by its type |
| **free level** | A level of a drawn position that no symbol draws yet |

The glossary gains a section "Multi-level terminals (brief 036)" with these rows.

## 2. Model: positions, levels and types

### 2.1 No new object

A strip stays one device (028 Q1). Each **level point** is one `Terminal` of the strip:

| Field | Value |
| --- | --- |
| `label` | the **position label**, shared by every level of the position (`3`) |
| `key` | the **level key** of the definition point it was drawn from: `.1`, `.2`, `.3` for one-point levels; `.1i`, `.1o` for the in and out points of a two-point level (FP2) |

Old terminals keep their keys (`1`, or their first label); a terminal whose key does not start with
`.` is **level 1** of a one-level position, exactly as today. So nothing in an old file changes
meaning (roadmap question 5).

Why the position label on every level, not `1.L` as the label: renumbering, accessories (`acc.*`),
links, spares and the BOM already work by position label (028, 030); keeping it there makes them
work per position unchanged, and the shown label is derived (§4). Why the dot in the key: it lets
`ecad-model` tell a level key from an old key without knowing the catalogue (§5, §6).

A position's **type** is read from the starter of the symbols that draw its levels (as 028 reads
feed-through and PE today). Spare positions get their type from the offer (§7.1). Levels of one
position drawn by symbols of different types give a Checks row (§8, `position-mixed`); the first
drawn level's type is used.

### 2.2 The terminal type catalogue (`terminal_types.rs`, code)

| Type key | Name | Offer code | Levels (key: default name) | Internal bridges | Breaks the net |
| --- | --- | --- | --- | --- | --- |
| `terminal` (exists) | Feed-through terminal | (none) | `1`: — | — | no |
| `terminalpe` (exists) | PE terminal | `PE` | `1`: — (PE mark) | — | no |
| `term2` | Two-level terminal (double-deck) | `x2` | `.1`: `1`, `.2`: `2` | — | no |
| `term2b` | Two-level terminal, bridged | `x2B` | `.1`: `1`, `.2`: `2` | `.1`+`.2` | no |
| `term3` | Three-level terminal | `x3` | `.1`: `1`, `.2`: `2`, `.3`: `3` | — | no |
| `termlnpe` | Installation terminal L/N/PE | `LNPE` | `.1`: `L`, `.2`: `N`, `.3`: `PE` (PE mark) | — | no |
| `termsensor` | Sensor terminal, 3-level | `SEN` | `.1`: `S`, `.2`: `+`, `.3`: `−` | — | no |
| `termdisc` | Disconnect terminal | `DIS` | `.1i`/`.1o`: — (one level, in and out) | — | **yes** |
| `termfuse` | Fuse terminal (strip position) | `FUSE` | `.1i`/`.1o`: — | — | **yes** |

- Level names, BOM descriptions and the level separator are **registry entries** (§12); the
  catalogue holds keys, codes, level counts, bridges and geometry only, which are what the part
  is, not defaults (031 §3.5).
- The `−` of the sensor terminal is typed and stored as `-`; it is drawn as a minus.
- Disconnect and fuse levels **break the net** (roadmap 1.2): in and out are two terminals, so they
  are two nets with two wire numbers and nothing joins them. A link or internal bridge never
  crosses in → out.
- Adding a type later is a row here and its starters; no file change.

## 3. Drawing levels

### 3.1 Starters (appended to `symbols.rs`, `Kind::Terminal`, prefix `X`)

Per multi-level type: one **level symbol** per level, and one **whole-terminal** symbol.

| Starter key | Points (key at) | Graphics (drawn new for ECAD, 028's style) |
| --- | --- | --- |
| `<type>.<n>`, e.g. `termlnpe.2` | one: `.n` at (0,0) | 028's terminal circle r 1.5; a level tick: n short strokes 0.8 mm long above the circle, 0.6 mm apart, so a level reads without its label; the PE level adds 028's earth mark |
| `<type>` (whole terminal), e.g. `termlnpe` | `.1` (0,0), `.2` (0,−5), `.3` (0,−10) | the circles of every level on the 5 mm grid, inside one body rectangle 5 mm wide, levels separated by a 0.25 mm line; internal bridges as a 0.5 mm bar between the bridged circles |
| `termdisc` | `.1i` (0,10), `.1o` (0,−10) | body (−3.5,−7.5)–(3.5,7.5); a knife: line (0,10)–(0,3), blade (0,3)–(2.5,−3), stop (0,−3)–(0,−10) |
| `termfuse` | `.1i` (0,10), `.1o` (0,−10) | **`fuseterm`'s drawing function** (034): the same graphics and the same points, so a `fuseterm` symbol can become a `termfuse` symbol without its wires moving (§3.5) |

Search finds them by type name and level name (`L/N/PE terminal, level N`; aliases `installation
terminal`, `sensor terminal`, `double-deck`, `two-level`, `three-level`, `stacked`, `disconnect`,
`knife`, `fuse terminal`). Each definition carries its type's internal bridges in
`Definition::bridges` (`term2b.1` and `term2b.2` both hold `[[".1", ".2"]]`).

### 3.2 Place Terminals (`terminals`, 028 §3.2, extended)

```
Terminal strip [New] <-X01>:
Type [Feedthrough/PE/x2/x2B/x3/LNPE/SEN/DIS/FUSE] <last used>:
Level [L/N/PE/All] <L>:                    (multi-level types only; All = whole-terminal symbols)
First point of the line across the wires:
Second point:                              preview: a ring and the shown label at each crossing
```

Every wire the fence crosses gets one level symbol, filling positions by §3.3's rule. Echo:
`Placed -X01:1.N…4.N on 4 wires (positions 1–4, level N).` One transaction. All other behaviour,
limits and refusals are 028's.

### 3.3 Which position a level joins (Q3)

When a level symbol of type T, level n, is placed on strip S (Place Symbol on a wire, or the fence):

1. **Free level first:** the lowest position (plan order) of type T on S whose level n is free.
2. Else a **new position**: label = 1 + the highest whole-number position label of S (028's rule),
   type T, level n drawn, its other levels free.
3. The prompt offers `Position <3>:` before the insertion point (Place Symbol) or the first point
   (fence), so the user can name a position; a named position must be of type T (or new) and its
   level n free, else refused: `-X01:3 is an L/N/PE terminal and its level N is drawn on 101-C-3.
   Pick another position, or Enter for the next free one.`

So drawing the L row across three wires and then the N row across three others fills positions
1–3 with L and N. Whole-terminal symbols always make a new position.

Ops (one transaction, labelled `Place terminal level`): 028's split ops, and `AddTerminal { label:
position, key: ".n" }` (`.ni` and `.no` for a two-point level), `AddItem`, `LinkRepresentation`
with explicit `connection_points` (**always** explicit for level symbols, also the first symbol of
a new strip; §10.3 relies on it).

### 3.4 Placing a level on a wire (028 §3.1)

Unchanged for one-point levels. For a two-point level (`termdisc`, `termfuse`) on a wire: the
wire is split as 028 does, and the half towards the first point of the symbol after rotation lands
on `.1i`, the other on `.1o`; the two halves are **two nets** (the net breaks, as for a fuse), so
the second half's stored wire number is dropped and the numbering pass gives it its own. Echo:
`Placed fuse -X01:7 on wire 24V-07: in 24V-07, out 24V-12.`

### 3.5 Turning 034's fuse terminals into strip positions (`toposition`)

034's `fuseterm` is a device of its own (`-F05`). This brief offers, never forces, turning it into
a fuse position of a strip:

- **Command** `toposition {device, strip?, position?}`: strip absent = the strip nearest on the
  page among strips with a terminal on that page, else refused `Name a strip: there is none on this
  page.` Position absent = §3.3's new position.
- **From the page:** context menu on a `fuseterm` symbol ▸ **Make strip position…** (prompt
  `Terminal strip <-X01>:`). **From Checks:** the Info row `fuse-device` (§8).
- **One transaction**, labelled `-F05 → -X01:7`:
  `ModifyItem` (the symbol's definition becomes `termfuse`; same points, so nothing moves),
  `UnlinkRepresentation` and `LinkRepresentation` (subject the strip, explicit points),
  `AddTerminal` `.1i` and `.1o` on the strip, `AttachEnd` of each wire end from `-F05:1` to `.1i`
  and from `-F05:2` to `.1o`, `RemoveTerminal` of `-F05:1`/`:2`, `SetProperty(strip,
  rating.<pos>)` from `-F05`'s `rating`, and `DeleteComponent -F05`. The nets do not change.
- **Preview** (and the result's `lost`): what goes with the device: its tag (references to `-F05`
  in 025's index disappear), and any property other than `rating`, `part_number` and `maker`.
  When `-F05`'s part number differs from the strip's fuse part (§7.2), the echo says so: `-F05's
  part FT-4 differs from -X01's fuse terminal part FT-6; set -X01's part if FT-4 is right.`
- A `fuseterm` with more than one representation, or joined by other symbols, is refused: `-F05 has
  other symbols (-F05:13); move them first.`

## 4. Labels per level, and relabelling

### 4.1 The shown label

For a level n of position p of type T:

1. the strip property `term_label.<p>.<n>` when set (FP4), else
2. for a one-level type: `p`;
3. else `p` + **separator** + the level name (`1.L`, `2.1.S`).

Separator and level names are registry entries (§12), resolved strip → project → built-in, so a
project or one strip can write `2.1S` (separator empty) or rename levels. The shown label is what
the page draws as the connection-point label (031's kind and its visibility rules), what the plan,
hover, Checks and MCP show, and what a user may type after the tag (`-X01:1.L`). Typed names are
also accepted as `p.n` (`-X01:1.2`) and `p.<level name>`.

### 4.2 `termlabel` (new)

`termlabel {terminal | strip + position, position?: "1.L", text?: "2.1S" | null}`:

- `position` relabels the **position**: every level terminal of it, by `RemoveTerminal` +
  `AddTerminal` of the same ID with the same key (028 Q7's precedent), and in the same transaction
  moves its `acc.after.<p>`, `acc.on.<p>`, `term_label.<p>.*` and `rating.<p>` keys and rewrites
  the labels inside every `link.<n>` value (030 FP4/FP7's rule). A position label is 1–16
  characters, no spaces or control characters, unique among the strip's positions. Dotted labels
  such as `2.1` are allowed (§5.1 says how links name them). Refused with the way out: `-X01
  already has a position 4. Pick another label, or swap them with Renumber.`
- `text` sets one level's shown label (`term_label.<p>.<n>`), 1–24 characters; `null` clears it.
  Works for a one-level position too: that is how a single terminal reads `1.L`.
- Echo: `-X01:3 is now -X01:1.L (3 levels).`, `-X01:2.1 level S shows 2.1S.`

**UI:** Properties ▸ Terminal: **Position** (text, `ecad.props.terminal.position`) and **Label**
(text, placeholder the derived label, `ecad.props.terminal.label`); the Terminals tab's Position
and Label cells edit in place (§9). Each edit is one transaction.

## 5. Links per level (030 §5, extended)

### 5.1 Values (FP3)

An item of `link.<n>` names a position and optionally a level:

| Written | Means |
| --- | --- |
| `4` | position 4, level 1 (roadmap question 5) |
| `4.2` | position 4, level 2 |
| `1-4` | positions 1 to 4 (plan order), level 1: exactly 030's meaning |
| `1.2-8.2` | positions 1 to 8, level 2 (a position without level 2 is skipped) |
| `1.1-1.3` | position 1, levels 1 to 3 (a **cross-level link**: an external bridge between decks) |
| `7.1i`, `7.1o` | the in or out point of a two-point level; `7` or `7.1` alone is the in point |

**Parsing rule (in `ecad-model`, catalogue-free):** an endpoint whose text ends in `.` + digits
(+ optional `i`/`o`) carries a level; the rest is the position. A range is a **level range** when
both ends have the same position text, else a **position range**, whose ends must have the same
level (or none). Mixed ranges are refused: `"1.1-4.2" joins different levels at different
positions. Write 1.1-4.1, or 1.1-1.2 for levels of one position.`

Because the last `.digits` is always a level, a position labelled `2.1` is written with its level
(`2.1.1`, `2.1.2`) by every ECAD writer (the Jumper tool, the plan, renumber), and a typed `2.1`
means position 2, level 1; the echo says so (`Link -X01 2.1 (position 2, level 1)`), and the
preview shows it before anything is written. Old files are unaffected: positions were whole numbers
until this brief (no command could write another terminal label). Level names are accepted when
typed (`1.N-3.N`) and stored as numbers, so renaming a level never breaks a link.

### 5.2 Nets

022's connectivity reads link edges per level: `links::linked(doc, t)` matches terminal t (label
p, level n from its key, point i/o) against each item (FP8b). Wire numbering, `two-fixed` and the
transaction rules are 030 §5.2's, unchanged.

### 5.3 The Jumper tool (030 §5.4)

- The first pick fixes the strip and the **level**. Each next pick on the same level adds the range
  between picks (Skip: only the pick), as in 030.
- A next pick on **another level of the same position** makes a cross-level link (`1.1-1.3`) and
  ends the tool's range mode for this link: `Link levels 1–3 of -X01:1. Enter to finish.`
- A pick on another level of another position is not added: `-X01:4.N is on level N; this link is
  on level L. Pick level L terminals, or Enter to finish.`
- Typed positions at the prompt accept §5.1's grammar.

### 5.4 Link lines (030 §5.3)

- A position link on level n is drawn through the centres of the level-n symbols shown on the page;
  lanes are computed **per level** (links on different levels run through different symbols, so
  they never share a lane). Stubs as 030.
- A cross-level link is drawn on a page that shows two or more of its levels **of that position**
  as an orthogonal dog-leg between them, in lane 0, else as a 4 mm stub on each shown level.
- Hover on a line: `-X01 link 1.2-8.2 (level N, 8 positions, 1 bar JB-10)`.

### 5.5 BOM

Bars per link as 030 §5.6, per level: span = last − first position index + 1 on that level. A
cross-level link counts as **one bridge** (a part per cross-level link, part key `link.<n>.part_number`,
else the strip's `jumper.part_number`, else `?`).

## 6. Internal bridges (FP8a)

A bridged type (`term2b`) joins its levels inside each position. Stored: nothing new; each level
symbol's definition carries `bridges: [[".1", ".2"]]` (§3.1).

**`ecad_model::connectivity::bridged(t)`**, changed (code, not format):

- When t's key starts with `.`: the bridge groups are those of **the definitions of the
  representations that show t** (its level symbol; a whole-terminal symbol), and the terminals
  joined are those of the same component with **the same label** and a key in t's group. A free
  partner level (no terminal yet) joins nothing.
- Otherwise: today's rule, unchanged (the component's own definition, the whole device).

So two positions of one bridged type stay two nets, and old devices behave exactly as before. The
connectivity update scope adds: `LinkRepresentation`, `UnlinkRepresentation` and a `ModifyItem`
that changes a symbol's definition, when that definition has bridges, touch the nets of the
terminals with the same label in that component.

## 7. Plan, BOM and offers

### 7.1 Offers by type (FP1)

The strip's `terminals` offer gains type codes: a `+`-separated list of `<count><code>`, codes from
§2.2, case-insensitive, no code = feed-through. `12+2PE+4x3` is 18 positions: 12 feed-through, 2
PE, 4 three-level. At most 999 positions. Spare positions are numbered after the drawn ones in the
order the offer lists the types, each with its type's levels. 028's `12` and `12+2PE` read the
same. Refusal: `"6Q3" is not a terminal count. Write 12, 12+2PE or 12+4x3 (types: PE, x2, x2B, x3,
LNPE, SEN, DIS, FUSE).` More drawn of a type than offered: 028's `too-many-terminals` per type
(`-X01: 5 L/N/PE terminals drawn, strip offers 4`), fix **Offer 5**.

### 7.2 BOM (028 §9.1, generalised; FP6)

One row per strip per **type**, Qty = drawn + spare **positions** of that type (a 3-level terminal
is one part, never three). Part data per type: strip `part_number.<code>`, `maker.<code>`,
`description.<code>` (lower-case code: `part_number.lnpe`; 028's `part_number.pe` is this rule for
`pe`; feed-through keeps `part_number`), then project `strip_<code>_part_number`, `_maker`,
`_description` (030's pattern), else `?` flagged. The default description is the registry's
`terminal.<code>.description` (§12). Fuse inserts are 1.12's.

### 7.3 Plan rows (028 §5.1, 030 §7.1, extended)

One row per **level** (one row also for a two-point level), grouped by position in plan order,
levels in level order. Columns, mirrored around the strip (§9 names them):

| Inside target | Inside wire | **Position** | **Level** | Label | Bridge / links | Outside wire | Cable | Core | Outside target | Place |

- **Position** is written once per position, in a box spanning its level rows (`ecad.level-box`);
  **Level** is the level name; **Label** the shown label (§4.1), with `*` after it when it is an
  override.
- A **free level** row: `—` in every target and wire cell, Place blank, state `free`; a **spare**
  position: every level row says `spare` (028).
- **Two-point levels:** inside cells come from the in point, outside cells from the out point
  (fixed by the type, Q6), and the Bridge column shows a break mark `≠`.
- **Internal bridges:** a vertical bar joining the bridged levels inside the position box.
- **Links** per level as 030 (lanes per level); a cross-level link: a bar inside the position box,
  dashed.
- Header: `-X01  +CP1  18 positions (12 feed-through, 2 PE, 4 three-level): 10 drawn, 8 spare ·
  …030's totals`.
- 028's side rule (cable core, location, geometry) applies **per level**, unchanged for one-point
  levels.

Generated `terminals` page: columns Position 12 and Level 10 mm replace 028's Terminal 16 (Label
shows in the Position box when the position has one level, else under Level as `L 1.L`); a position
is never split across sheets (its rows move to the next sheet together); 44 rows per sheet count
level rows. Reports ▸ Terminals: the same columns, with §9's edit cells.

### 7.4 Accessories (030)

Gap accessories (`acc.after.<p>`, `acc.start`, `acc.end`) are per position, unchanged. Markers
(`acc.on.<p>`): one marker per **level** of the position on the BOM (Q10); the plan shows `▭` on
each level row.

### 7.5 Tokens (appended to `tokens.md`)

The owner's direction for the terminal manager: **inside | strip | outside**, mirrored, with

| Strip | `level` (number), `level_name` | derived (type, registry) | — |
| Strip | `label` | **editable** (override) / derived | `termlabel {text}` (`term_label.<p>.<n>`) |
| Strip | `type` (code), `type_name` | derived (symbol; offer for spares) | — (Place, offer) |
| Strip | `state`: `drawn` / `free` / `spare` | derived | — |

## 11. Update maps and cost

### 11.1 Strips (028 §11.1 and 030 §11.1, extended)

`Strips` keeps per strip its positions (label → type, levels, terminals per level), and two new

`terminal.<code>.levels` from the project or built-in). Every op not listed does nothing to levels:

| Op (kind, target) | Recomputed |
| --- | --- |

## 14. Format proposals (for the overseer)

Pre-v1: no compatibility work is needed, but every item below reads old files the same at no cost,
so it is kept. No new op and no new record field.

- **FP1. Offer type codes** in the existing strip property `terminals`: `<count><code>` items
  (§7.1).
- **FP2. Level keys** in the existing `Terminal.key`: `.n` for one-point levels, `.ni` / `.no` for
  two-point levels; new starter definitions embedded with origins as usual (§2.1, §3.1).
- **FP3. Link values with levels** in the existing `link.<n>` (§5.1): `p.n`, `p.ni|no`, level and
  position ranges; the last `.digits` is always a level.
- **FP4. Strip property `term_label.<p>.<n>`**: one level's shown label (§4).
- **FP5. Strip property `rating.<p>`**: a fuse position's rating, 034's `rating.<n>` grammar.
- **FP6. BOM part keys per type:** strip `part_number.<code>`, `maker.<code>`,
  `description.<code>`; project `strip_<code>_part_number`, `_maker`, `_description` (§7.2).
- **FP7 (ops recorded, not format).** Renumber and `termlabel` move `term_label.*` and `rating.*`
  with `acc.*` and rewrite `link.*` canonically; `toposition`'s transaction (§3.5).
- **FP8 (code in `ecad-model`, not format; listed because it changes `ecad-model` semantics):**
  (a) `connectivity::bridged` per position for level keys (§6) and its update scope; (b)
  `links` items with levels (§5.1–§5.2); (c) `numbering::Request.positions` and the first-match fix
  of the empty-points branch (§10.3).

**Code, not format:** `terminal_types.rs`; the new starters; `termlabel` and `toposition`;
Checks kinds; plan, BOM and page columns; `defaults/terminals.rs`.

**Decision (overseer, 2026-11-12):** FP1–FP8 are approved. They are properties and existing fields,
with no new op. FP8's `ecad-model` semantic changes (bridges per position, link matching by level,
the planner's position groups and its first-match fix) are approved together with their update
scope (§6, §11.2). The owner questions (§15) are with the owner.

## 15. Owner questions, each with a recommendation

1. **Position label shared by all levels**, the level read from the symbol, the shown label
   derived (`1.L`) with a per-level override? **Recommend yes**: renumbering, accessories, links,
   spares and the BOM keep working per position, and any house label (`2.1S`) is still possible.
2. **One symbol per level** (drawn where its circuit is) **plus a whole-terminal symbol** per type?
   **Recommend yes**: schematics draw levels on different rows or pages; the whole symbol suits
   compact overviews.
3. **A placed level fills the next position of its type that lacks that level** (so the L row then
   the N row fill positions 1…n), with `Position` at the prompt to choose? **Recommend yes**.
4. **The type list and level names** of §2.2 (2-level, bridged 2-level, 3-level, L/N/PE, sensor
   `S`/`+`/`−`, disconnect, fuse), level 1 the top deck, names changeable per project or strip?
   **Recommend yes**; tell us any type your panels use that is missing.
5. **In link values the last `.digits` is always a level**, so a position labelled `2.1` is linked
   as `2.1.1`, and a typed `2.1` means position 2, level 1 (the preview says so)? **Recommend yes**:
   one rule, no guessing; ECAD writes the full form for you.
6. **Fuse and disconnect positions: the in point is inside, the out point outside**, fixed by the
   type rather than 028's side rule? **Recommend yes**: the part has a supply side; a later
   Checks row can flag a reversed one if you want it.
7. **Offer codes** `x2`, `x2B`, `x3`, `LNPE`, `SEN`, `DIS`, `FUSE` (`12+2PE+4x3`)? **Recommend
   yes**; `x3` follows the roadmap's `12x2` idea while keeping `+` between types.
8. **BOM: one row per strip per type, Qty in positions** (a 3-level terminal is one part)?
   **Recommend yes**.
9. **034's fuse terminals become strip positions only when you ask** (`toposition`, offered from a
   Checks Info row and the context menu), the device tag disappearing? **Recommend yes**: an
   automatic change would remove tags you may have referenced.
10. **Markers on a multi-level position count one per level** on the BOM? **Recommend yes**: each
    deck carries its own marker.
11. **Relabelling:** `termlabel` renames a position (all levels, unique on the strip, keys moved)
    or sets one level's text (`2.1S`, also `1.L` on a single terminal)? **Recommend yes**.
12. **A cross-level link (`1.1-1.3`) counts as one bridge part** on the BOM, with the link's or the
    strip's jumper part number? **Recommend yes**.
