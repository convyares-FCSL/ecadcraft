# Design 029: The inspector protocol and `ecadinspect serve`

Brief: `docs/briefs/029-inspector.md` (Draft). Revised twice on 2026-11-12 after the owner's
decisions. The second revision brings a correct, fast full Verify into this brief (§3, §7). The first:
the inspector is a developer and test tool that never ships. The wasm route is dropped. The tool
is now a versioned JSON protocol in `ecad-inspect`, served locally by `ecadinspect serve`, in the
manner of rosbridge, with the existing page as a thin client. The page keeps the existing
inspector's rules (read-only, static, every value escaped, light and dark) and the owner decision
of 2026-10-12 on HTML and JavaScript under `ecad/tools/`. The Rust is product-grade: never-crash
rules, errors in words, table-driven tests. Owner questions: §11. Format: none (§10).

## 0. What the code has today (checked on `dev` `dc2472c6`)

- **`ecad-inspect`**: Core, depends on `ecad-model`, `serde`, `serde_json`, and is listed in
  `xtask`'s `WASM_CRATES`. It writes `ecad-inspect/2` snapshots (`SNAPSHOT_FORMAT`). Used by
  `ecad-cadcraft` and `ecad-trial`.
- **`ecad-cli`** (class Ui): the `ecad` and `ecadinspect` binaries over `ecad-file`.
  `ecadinspect <file> tables|branches|log|versions|chunk|verify|export-jsonl` prints text.
- **`ecad-file` v2**: `Store::open(path, false)` reads beside a running writer (redb
  `SingleWriter`, decision 2026-11-08); `Store::from_bytes` reads a buffer. `ProjectV2::open`
  loads from the latest snapshot, or read-only at the last good state when damaged.
  `v2::inspect::*` returns text; `v2::verify::verify` returns a `VerifyReport`.
- **Model data without the engine:** `derive::nets`, `wiring::{net_number, net_potential,
  net_place, label}`, `book::{FUNCTION_KEY, LOCATION_KEY}`, `tag::TAG_KEY`, `Document::check`
  (the first violation of I1–I18) and `derive::mismatches`. The drawing Checks (022, 025, 026),
  derived locations (024) and reports live in `ecad-cadcraft` and stay out (owner, Q3 accepted).
- **The page** `tools/inspector/index.html` (13 KB): file input for snapshots, search, tabs,
  `esc()` on every value.

## 1. What the spike found (2026-11-12, deleted)

A throwaway wasm build was used to answer the original question. The figures that still matter:

| Large bench file `large-lean.v2.ecad` (67 MB, 500 pages, 5 000 devices, 25 000 wires, 33 998 tx), native release | Time |
| --- | --- |
| `Store::from_bytes` | 54 ms |
| `tables`, and `tx_count` over 33 998 rows | 45 ms, 18 ms |
| `ProjectV2::open` (wasm figure; native is faster) | 957 ms |
| `v2::verify::verify` | **not finished after 25 min** (stopped) |

Verify first decodes every row and checks the chain, which is linear and fast. It then replays
with `Ledger::replay_verified_from`, which checks every invariant after every transaction. That
replay is the cost, and the app's **Verify file** and the check before a revision is issued pay
it too. The owner's correction (2026-11-12) is to fix Verify in this brief (§3.2–§3.3). On the demo (`demo.v2.ecad`: 323 KB, 3 branches, 90 tx), full Verify takes
about 0.1 s.

## 2. The protocol: `ecad_inspect::protocol`

### 2.1 Envelope

```json
{"v": 1, "id": "7", "op": "devices", "from": 0, "count": 200, "q": "-K1"}
{"v": 1, "id": "7", "ok": {"total": 5000, "from": 0, "rows": [ ... ]}}
{"v": 1, "id": "7", "error": {"what": "not-open", "why": "No file is open.", "way_out": "Drop a .ecad file on the page, or start with: ecadinspect serve <file>"}}
```

- `v` is the protocol version, starting at **1**, as a constant `PROTOCOL_VERSION`. A request
  with a higher `v` gets `error.what = "protocol"` (§6 row 13). Fields a v1 server does not know
  are ignored, so later clients can add optional fields. Removing or changing a field raises `v`.
- `id` is echoed back as given (any string up to 64 characters), so a later transport can
  multiplex or stream.
- `op` names the operation (§2.2). An unknown op gets `error.what = "unknown-op"`, with the list
  of known ops in `why`.
- Every error has a stable `what` (kebab-case, tested), a sentence `why`, and a `way_out`.
- Paging: `from` (default 0) and `count` (default 200, at most 1 000). Replies carry `total`.
  Optional `q` filters rows by substring over the row's text columns, case-insensitive.
- The reply is plain JSON values only. The protocol never sends HTML.

### 2.2 Ops

| op | Needs | Reply |
| --- | --- | --- |
| `hello` | | `{protocol: 1, server: "ecadinspect 0.1.0-dev", source: {kind: "file"\|"bytes", name, size}\|null, ops: [...], capabilities: ["store", "model", "verify"]}` |
| `summary` | | file facts (`meta`: container, schema, codec, writer, created), open report (clean, damaged at *n*, repaired in memory), counts, chain-check status |
| `project` | model | project properties (with `rev.*` grouped), reference style, counts |
| `pages` | model | paged: number, folder, title, properties, counts of items, devices and wires |
| `devices` | model | paged: tag, `duplicate`, stored `function` and `location`, definition, pages, connection points with wire numbers, all properties on request (`detail: true`) |
| `nets` | model | paged: number, `fixed`, potential, place, connection points, wire count |
| `wires` | model | paged: number, ends (`-K1:A1 → -X1:3`), cross-section, colour, cable and core |
| `cables` | model | paged: tag, members, ends |
| `branches` | store | name, id, status, release line, head, fork point, row count |
| `log` | store | `branch`, paged newest first: seq, time (UTC), author, kind, op count, stored size, compression; `detail: true` adds the decoded record |
| `versions` | store | user versions, revisions (with release fields), auto snapshots, merges |
| `tables` | store | the six tables: rows, stored bytes, metadata, fragmented; and `meta` |
| `rows` | store | `table`, paged: key (hex and decoded), size, compression |
| `row` | store | `table`, `key` (hex), `form: "readable"\|"raw"`. Readable is the decoded JSON. Raw is the stored bytes as hex, at most 64 KiB, with `size` and `truncated` |
| `check_chain` | store | the `VerifyReport` of `verify_chain` (§3.2), computed on load |
| `invariants` | model | `Document::check` result and `derive::mismatches` |
| `verify` | store | `{state: "running"\|"done"\|"failed", elapsed_ms, report?}`: the result of the Verify started on load (§3.4) |
| `export_jsonl` | store | `branch`, `with_raw`; transport-level download (§5.1) of `export_jsonl`'s output |

"Needs" is a capability of the source (§4). An op whose capability is missing gets
`error.what = "unavailable"`, with a reason, for example a file whose full open failed (§6).

### 2.3 Where it lives

`ecad_inspect::protocol` holds the types (`Request`, `Reply`, `ErrorReply`) and
`fn handle(source: &dyn Source, request: &str) -> String`. It is pure: no I/O, no threads. It
needs `ecad-inspect` to depend on `ecad-file` (Core on Core; `ecad-file` does not depend on
`ecad-inspect`, so there is no cycle). `ecad-inspect` stays in `WASM_CRATES` and still builds
for wasm, because the protocol has no platform code.

## 3. Sources and checks

### 3.1 `Source`

```text
trait Source {
    fn describe(&self) -> SourceInfo;              // kind, name, size
    fn store(&self) -> Option<&Store>;              // raw views, history, chain, Verify
    fn opened(&self) -> Result<&OpenedV2, &OpenFailure>;  // model views
    fn chain(&self) -> &VerifyReport;               // computed once, on load
    fn verify(&self) -> VerifyState;                // running, or its report (§3.4)
}
```

- **`FileSource`** (029): built from `Store::open(path, false)` or `Store::from_bytes`. On load
  it runs `check_chain` and `ProjectV2::open` and keeps both results, then starts Verify (§3.4). If the full open fails,
  the store ops still work and the model ops answer `unavailable` with the open error. One
  source at a time (owner, Q5 accepted): a new file replaces the old one.
- **`SessionSource`** (later, not built, §4).

### 3.2 Verify, part (a): `verify_chain`

Verify's first phase on its own, for every branch:
- decode every row;
- check its chain value against the previous one;
- check that the head matches the last row;
- check that every version's chunks are present and hash to their keys;
- check the merge rows' chain values.

There is no replay, and it is linear in the file. `verify` calls it first, so the two cannot
drift. It returns a `VerifyReport` (`snapshots` = 0). Bench target: at most 3 s on the large tier.

### 3.3 Verify, parts (b) and (c): replay as at commit, full check at snapshots

The owner's definition (2026-11-12). For each branch, parents before children:

- **(b) Replay** every transaction from the root, or from the parent's state at the fork point,
  with **only the touched-object check**: `Document::check_touched`, exactly what
  `Ledger::commit` runs (`validate` with verify off). A failure names the transaction:
  *main: transaction 3 412: <the invariant's own message>*.
- **(c) Full check** (`Document::check` and `check_index`) only at each stored snapshot point
  (user, revision and automatic versions, in seq order) and at the branch's end. At a snapshot,
  the replayed state is also compared with the assembled snapshot, as today. A mismatch names
  the snapshot and the first difference (*main: snapshot "00000000000000002000" at 2 000
  differs from the replay: component 4 711, property `tag`*).
- **Never brief 013's verify mode.** The full check after every transaction stays a test-only
  safety net: `cargo test` turns it on through the `verify-invariants` feature. Verify must not
  get it, either through that feature or through `replay_verified_from`. `ecad-model` therefore
  gains one replay entry, `Ledger::replay_checked_from(doc, log, seed, Check::Commit)`: it runs the
  commit-time check whatever the build's verify mode, so Verify behaves and costs the same in
  tests and in release. `replay_verified(_from)` stays for the debugger's **Verify replay** (Q2)
  and the tests.
- **Fork states once.** A branch starts from its parent's state at the fork point. Verify keeps
  each parent's document at the fork seqs its children need, a clone per fork point, instead of
  replaying the parent again for every child.
- **Who uses it.** `v2::verify::verify` keeps its signature and report, so the app's **Verify
  file** (`ecad-cadcraft/src/debug.rs`), `ecadinspect verify` and the check before a revision is
  issued all get the new path with no change of their own.

**Cost.** Part (b) is what version 1 did on every open: a full replay with the commit check, 2.4
to 8.5 s on the large tier (brief 021's v1 numbers). Part (c) is one full check per stored
snapshot; there are few, since automatic snapshots are kept sparse. Part (a) is linear. **Bench
target, large tier (`large-lean.v2.ecad`, 33 998 tx), native release: at most 10 s, goal 5 s.**
The bench report gains the `verify_chain` and `verify` rows. If (b) alone is over 5 s, the worker
reports where before tuning, rather than relaxing a check.

**What it catches.** It catches everything the old Verify caught. A broken invariant can only
come from a transaction, and the transaction that breaks it touches the broken object (the
013 contract that `verify-invariants` tests on every `cargo test`), so (b) finds it at that
transaction. A row that decodes and applies but gives a different state (rewritten ops with
recomputed chains) is not an invariant break. Both the old and the new Verify catch it only when
the state is compared with a snapshot, and (c) still does that at every snapshot. §8 proves both.

### 3.4 Verify on load

Decision (the owner left it to the designer): **full Verify runs on load**, on a background
thread, and nothing waits for it.
- At load: `verify_chain` (at most 3 s on the large tier) and `ProjectV2::open` (under 1 s). Then
  the first view shows with the pill **chain PASS · verifying…**.
- Verify then runs on its own thread over the same read-only `Store`, behind an `Arc`. The server
  keeps answering requests. The page asks `verify` every second until it is done, then shows
  **verified** or **Verify FAIL**, with the lines on the Checks tab and the time.
- If the file is replaced (`/open`, **Reload**), the running Verify's result is dropped, because
  the source has a generation number. A Verify cannot be started twice for one source.
- There is no Stop button and no warning. With the 10 s target, a load fully verifies in about
  the time it takes to read the first view. If the large-tier bench misses the target, the brief
  is not done.

## 4. Live inspection later: the seam

Two things are kept open; neither is built in 029.

- A **source** is a trait. A later `SessionSource` reads through `ProjectHandle` under
  `try_lock`, copying what it needs, as the debugger does (`ecad/CLAUDE.md`). It can offer
  `model` always and `store` when the project has a v2 file. `capabilities` in `hello` tells the
  page which tabs to show.
- A **transport** is separate from `handle`. A later one (in the app, or a WebSocket beside
  `serve`) feeds the same request strings. For live updates the protocol will add
  `{"op":"subscribe","topic":"commits"}`, replied to with `{"v":1,"id":…,"event":{...}}` messages
  carrying the transaction's seq and touched objects. 029 reserves the `event` key and the
  `subscribe` op name (a v1 server answers `unknown-op`). Nothing else.

## 5. Transport: `ecadinspect serve`

### 5.1 Behaviour

```text
ecadinspect serve [file.ecad] [--port N]
  ecadinspect: serving demo.v2.ecad (323 KB) read-only
  open http://127.0.0.1:51734/?t=4f9c2a7e1b3d (Ctrl+C to stop)
```

- **Plain HTTP/1.1 on std `TcpListener`**, with **no new dependency**. One connection at a time,
  `Connection: close`, `Content-Length` required, headers at most 16 KiB, a request body at most
  1 MiB for `/api` and 1 GiB for `/open`. Anything else gets `400` with a JSON `error`. This is
  about 200 lines in `ecad-cli`. Verify runs on its own thread (§3.4), so the single-threaded
  request loop never waits for it.
- Bound to **`127.0.0.1`** only. `--port 0` (the default) takes a free port. The port is printed.
- Routes:

  | Route | |
  | --- | --- |
  | `GET /` | the page (`tools/inspector/index.html`, embedded with `include_str!`) |
  | `POST /api` | one protocol request, one reply |
  | `POST /open?name=<file name>` | the body is a `.ecad` file's bytes; it replaces the source, and replies `summary` |
  | `GET /export?branch=…&with_raw=…` | `export_jsonl` as a download (`Content-Disposition`) |

- Ctrl+C or closing the terminal stops it. A dropped file is held in memory only, never written
  to disk.
- Without `file`, it starts with no source. The page shows the drop box, and every op except
  `hello` answers `not-open`.

### 5.2 Safety on a developer machine

Read-only, but a local server can still be reached by other pages in the same browser, so:
- a random 96-bit **token** per run is in the printed address. It is SHA-256 of the time, the
  process id, the port and a stack address. `sha2 0.10` is already in the lock through
  `ecad-file`, so `ecad-cli` takes it as a direct dependency and no new crate is added. It is not cryptographically strong, and a local developer tool does not need it to be. Every request must carry it
  (`?t=` on `GET /`; the page then sends `X-Inspector-Token`). Without it the server answers 403;
- the `Host` header must be `127.0.0.1:<port>` or `localhost:<port>`, which blocks DNS
  rebinding;
- an `Origin` header, when present, must be the same origin;
- no CORS headers are sent, so the page works only when served by `serve` itself;
- the server never takes a path from the page. It reads only the file named on the command line,
  or bytes the user dropped.

### 5.3 The page

`tools/inspector/index.html` has two modes, chosen automatically:
- **Server mode**, when served by `ecadinspect serve`: the header shows the file name, size,
  `container 2 · schema 1 · json/1`, the writer, and pills `read-only`, `local only` and
  **chain PASS** / **chain FAIL** / **raw tables only** / **damaged: read-only at n**. Six tabs:
  Project (with Pages), Devices, Wires and nets (nets, wires, cables), History (branches, log,
  versions, export), Tables (rows, with a **Readable / Raw** toggle per row) and Checks (open
  report, chain, invariants, and the Verify result with its time). Lists are paged 200 at a time, with a
  search box per tab that sends `q`. Times are shown in UTC, labelled UTC. Drop a `.ecad` anywhere
  to replace the file (`POST /open`).
- **Snapshots mode**, opened from disk (`file://`) or by choosing **Open snapshots…**: exactly
  as today, for `ecad-inspect/1` and `/2`. Dropping a `.ecad` here says: *Reading a .ecad needs
  the inspector server: run `ecadinspect serve <file>` and open the address it prints.*

Every value goes through `esc()`. The page has no control that writes, and the protocol has no
op that writes. Export downloads a new file.

## 7. Verify in the app

No UI change. **Verify file** in the debugger, `ecadinspect verify` and the check before a
revision is issued call `v2::verify::verify` and get the new path (§3.3). Their existing tests
must pass unchanged. On the large tier, **Verify file** goes from not finishing in 25 minutes to
at most 10 s. A revision issued on a large project stops waiting on a replay that checks
everything after every transaction.

## 8. Tests

- **Protocol contracts** (`crates/ecad-inspect/tests/all/protocol_contracts.rs`, table-driven).
  The fixtures are built in the test with `ecad-file`'s helpers, as `container_v2.rs` does: two
  branches, a revision, a cable, a net, a duplicate tag. The tests cover each op's reply shape and
  counts, paging and `q`, unknown ops and fields, the `v` handling, and `row` raw against the
  stored bytes. Readable is checked against `pack::unpack`. `export_jsonl` output is checked
  byte for byte against `v2::inspect::export_jsonl`.
- **Mismatches:** rows 1–14 of §6, one table row each.
- **Hostile input:**
  - every truncation of the small fixture;
  - a flipped byte in one row of each table;
  - random bytes (fixed seed);
  - malformed JSON requests, oversized fields, `count` of `u64::MAX`.
  Each must give a reply and never a panic. Larger cases go in the slow set.
- **Verify** (`ecad-file/tests/all/verify_contracts.rs`, table-driven; the store is a risky
  area, so the tester covers this file):
  - **Same detection as before.** For each case, the old path (replay with the full check after
    every transaction, kept in the test as the reference) and the new `verify` both fail. They
    name the same transaction, or the same snapshot, and both pass on the clean fixture. The
    cases:
    - chain tamper: a flipped byte in a row, a missing row, a wrong head;
    - an invariant break at a mid-history transaction, written as a crafted row with a correct
      chain;
    - a snapshot that differs from the replay;
    - a missing chunk, and a chunk whose bytes do not hash to its key;
    - a merge row whose chain value differs from the log.
  - **A corruption between snapshots is caught at the next snapshot.** A transaction between two
    snapshots is rewritten with ops that apply cleanly but change a property, and every later
    chain value and the head are recomputed. Chain: PASS. Replay: PASS. The report fails at the
    next snapshot, naming its seq and the first difference.
  - **Verify mode stays out.** With the `verify-invariants` feature on (every `cargo test`),
    `verify` still runs only the commit check per transaction. `VerifyReport` gains
    `full_checks`, and it equals the number of snapshots plus branch ends, never the number of
    transactions.
  - `verify_chain` alone: passes on clean fixtures and finds each chain case above.
- **Bench**: `verify_chain` and `verify` rows on the large tier, with targets of 3 s and 10 s
  (goal 5 s), native release.
- **Server** (`ecad-cli/tests/all/serve_contracts.rs`): starts on port 0 in a thread and sends
  raw HTTP. It checks the token, `Host` and `Origin` refusals, the body limits, malformed HTTP,
  `/open` replacing the source (a running Verify's result for the old source is dropped),
  `/export`, and that it listens on 127.0.0.1 only.
- **Never writes:** the file's bytes and modified time are unchanged after a session of every op.
- **Escaping:** a fixture with `<img src=x onerror=alert(1)>` in a tag, a page title and a
  property. The tester opens it in a browser (screenshot `029-escape.png`).
- **Screenshots** for the owner: `029-empty.png`, `029-project.png`, `029-devices.png`,
  `029-history.png`, `029-tables-raw.png`, `029-checks-verify.png`, `029-mismatch-v1.png`.

## 11. Remaining owner questions, each with a recommendation

Accepted on 2026-11-12: Q3 (no drawing checks or derived locations), Q4 (v1: a message and
`ecad upgrade`) and Q5 (one file at a time). Replaced by the protocol and server shape: Q1, Q2
and Q6. Replaced by the owner's correction: Q7 (Verify is fixed here, not worked around), the
child process with Stop, and the proposed brief 030.

1. **HTTP or WebSocket.** **Recommend plain HTTP/1.1 on std**, with no new dependency.
   Request/response is all 029 needs, and the server stays about 200 lines that we own. When live
   inspection arrives, its push channel can be server-sent events on the same std server, or
   `tungstenite` then. The `event` key is reserved either way (§4).
2. **The debugger's Verify replay.** It uses `Ledger::replay_verified` (the full check after every
   transaction) on the in-memory log, and is not Verify. **Recommend leaving it as is in 029**:
   it is a developer check of the 013 scoped-versus-full contract and runs only on request.
   Moving it to the commit check would remove the one place that exercises that contract
   outside `cargo test`.
3. **The page served by the server only.** **Recommend yes**, with no CORS. Server mode works at
   `http://127.0.0.1:<port>/?t=…`, and `file://` keeps Snapshots mode. Opening the page from disk
   and pointing it at a server would need CORS headers and a weaker token story.
