# Design 029: The HTML inspector opens `.ecad` v2 through wasm

Brief: `docs/briefs/029-inspector.md` (Draft). The page follows the existing inspector
(`tools/inspector/index.html`: read-only, static, every value escaped, light and dark) and the
owner decision of 2026-10-12: developer tools under `ecad/tools/` may be HTML, CSS and
JavaScript, ship with no product, and run no server. The Rust in this brief is product-grade:
never-crash rules, errors in words, table-driven tests. Owner questions: §11. Format: none (§10).

## 0. What the code has today (checked on `dev` `dc2472c6`)

- **The page.** `tools/inspector/index.html` (13 KB) loads `ecad-inspect/1` and `/2` JSON
  snapshots through a file input. It has search and a light and dark theme, and it escapes
  everything through one `esc()`.
- **The reader.** `ecad_file::v2::Store::from_bytes(Vec<u8>)` opens a redb database held in
  redb's `InMemoryBackend` (decision 2026-11-08: "wasm reads through redb's in-memory backend").
  `ProjectV2::open(store, seed, writer)` loads from the latest snapshot. Damage opens read-only
  with a `ReportV2`. The facts are checked first, as `OpenErrorV2::Unsupported` (format,
  container version, schema version, codec) or `Damaged`.
- **Readable views.** `v2::inspect::{tables, branches, log, versions, chunk, export_jsonl}` and
  `v2::verify::verify` back `ecadinspect` (`ecad-cli`). They return text. The page needs data,
  so the new crate builds JSON from the same `Reader` calls (§2).
- **Wasm today.** `cargo xtask wasm` builds `ecad-model`, `ecad-store`, `ecad-file`,
  `ecad-inspect` and `ecad-cadcraft` for `wasm32-unknown-unknown`, in debug and as libraries
  only. Nothing runs them. Threads are already off on wasm (`par_map`, `Index::build`), and
  `ruzstd` decodes on wasm.
- **Derived data available without the engine:** `ecad_model::derive::nets`,
  `wiring::{net_number, net_potential, net_place, label}`, `book::{FUNCTION_KEY, LOCATION_KEY}`,
  `tag::TAG_KEY`, `Document::check` (invariants) and `derive::mismatches`. Device locations
  from location boxes (024), the BOM and wire reports, and the drawing Checks tab (022, 025, 026)
  live in `ecad-cadcraft`. The inspector does not link that crate (§6.2).

## 1. The spike (2026-11-12, thrown away, not committed)

Under `C:\dev\ecad-features\_tmp\designer029-wasm-spike`: a cdylib over `ecad-file` and
`ecad-model` (path dependencies, release, `opt-level = "s"`, LTO, one codegen unit,
`panic = "abort"`, stripped), with three raw exports. The input bytes go into a buffer that Rust
owns, `run(mode)` runs, and the output is read back. Node 26 drove it. Results:

| File | What ran | Time in wasm | Memory |
| --- | --- | --- | --- |
| `demo.v2.ecad`, 323 KB (owner's demo copy: 3 branches, 90 tx, 3 pages) | tables, branches, versions, full open | 46 ms | 1.9 MiB |
| same | Verify (every branch replayed, 3 snapshots compared): "everything verifies" | 114 ms | 2.4 MiB |
| large bench `large-lean.v2.ecad`, 67 MB (500 pages, 5 000 devices, 25 000 wires, 33 998 tx) | tables, branches, versions | 69 ms | 130 MiB |
| same | full open from the snapshot | 957 ms | 156 MiB |
| same | Verify | not finished after 25 min **natively** (stopped); wasm not attempted | |

1. **It builds and runs.** `ecad-file` with redb `=4.5.0` and `ruzstd` builds for
   `wasm32-unknown-unknown` in release. It opens from an in-memory buffer with no change to
   `ecad-file`: no clock, thread or file call is reached on open, raw views or Verify.
2. **Size.** The module is **1.97 MB**, **570 KB gzipped**. `wasm-opt` was not available; it
   usually takes off a further 10–20 %.
3. **Verify on the large file does not finish.** `v2::verify::verify` first decodes every row
   and checks the hash chain (linear), then replays with `Ledger::replay_verified_from`, which
   checks invariants on every transaction. On the large tier the native release build ran over
   25 minutes and was stopped (the demo takes 114 ms). This is not caused by wasm: the app's
   **Verify file** has the same cost (a follow-up for `ecad-file`, not this brief). The page
   therefore offers a cheap **Check chain** by default and the full replay only on request, with
   a warning and **Stop** (§4.6, Q7).
4. **Two findings for the worker.** (a) `cargo build --target wasm32-unknown-unknown` warns that
   `store.rs`'s `Db::ReadOnly` is never constructed (it is used only by native `Store::open`).
   `xtask wasm` does not deny warnings, so nobody saw it. Gate it with `cfg`. (b)
   `#[unsafe(no_mangle)]`, which raw exports need, is refused by the workspace's
   `unsafe_code = "forbid"`. `wasm-bindgen` 0.2.100 compiles under `forbid` but needs its own
   CLI to generate the glue (Q1).
5. **Opening never writes the source.** The browser hands over a copy of the bytes. redb may
   repair the copy in memory (a file copied mid-save), and that is reported, not hidden (§5).

## 2. The crate: `crates/ecad-inspector`

- `crate-type = ["cdylib", "rlib"]`. It depends only on `ecad-file`, `ecad-model`, `serde` and
  `serde_json` (`ecad-file` and its dependencies must never depend on a `cadcraft-*` crate). It
  is added to `xtask`'s `WASM_CRATES` and to the layers table as a tool crate.
- **One entry point**, safe Rust, tested natively:

  ```text
  Session::load(bytes: Vec<u8>) -> LoadReply        // detect, open, keep the result
  Session::request(&self, req: &str) -> String     // JSON in, JSON out
  ```

  A request is `{"view": "...", ...}`. Every reply is either `{"ok": {...}}` or `{"error":
  {"what": "...", "why": "...", "way_out": "..."}}`, in words (§5). Large lists are paged:
  `{"from": n, "count": ≤ 500}` with a `total` in the reply, so nothing builds a 25 000-row JSON
  unless asked.
- **Load keeps two things:** the `Store` (for raw views, history and Verify) and, when the full
  open succeeds, the `OpenedV2` (for the model views). If the full open fails, the raw views
  still work and every model view answers with the open error and a way forward.
- **The wasm boundary** (`src/wasm.rs`, `cfg(target_arch = "wasm32")`, about 30 lines):
  `input_reserve(len) -> ptr`, `load() -> reply_len`, `request_reserve(len) -> ptr`,
  `request() -> reply_len` and `reply_ptr() -> ptr`. The buffers are `Mutex<Vec<u8>>` statics
  (wasm has one thread), so the Rust side needs no `unsafe` code beyond the export attribute
  itself (Q1).
- **Never crash.** `panic = "abort"` on wasm (no unwinding there). If something still traps, the
  page catches `WebAssembly.RuntimeError` and shows §5 row 12. Input-sized work is capped (§5
  row 10), and loops are bounded by the store's own counts.

## 3. Opening a file

The built file is `target/inspector/ecad-inspector.html`: one self-contained page.

- **Drop or pick.** The whole window is a drop target. The header has **Open file…**
  (`accept=".ecad,.json"`). A `.ecad` file goes to the wasm reader, and `.json` files go to the
  existing snapshot loader, unchanged. Several `.json` files may be dropped at once, but only one
  `.ecad` (Q5).
- **Empty state:** a dashed box, *Drop a `.ecad` project file or inspector snapshots here.
  Nothing leaves this computer and the file is never changed.*
- **Loading:** *Reading `demo.v2.ecad` (323 KB)…* For a file over 20 MB the line adds *large
  file, this may take a few seconds*. The page stays responsive: the wasm runs in a Web Worker
  built from a `Blob` URL, which `file://` allows.
- **The header after loading:** file name, size, `container 2 · schema 1 · json/1`, the writer
  string (`ecad 0.1.0-dev (cadcraft 00c7613)`), and a status pill: **chain checked** /
  **verified** / **read-only: damage found** / **raw tables only**. The pills `read-only`
  and `nothing is sent` stay.
- **No server, from `file://`.** `fetch()` of a sibling `.wasm` fails on `file://` in Chromium,
  so the module is **inlined**: gzipped, base64 in a `<script type="application/octet-stream"
  id="ecad-wasm">`, then decoded with `DecompressionStream("gzip")` and
  `WebAssembly.instantiate`. These are standard in current Chrome, Edge, Firefox and Safari, and
  need no library.
- **The un-built page.** `tools/inspector/index.html` opened directly (the committed template,
  with no module inside) still opens snapshots. Dropping a `.ecad` there says: *This copy of the
  inspector has no file reader built in. Build it with `cargo xtask inspector` and open
  `target/inspector/ecad-inspector.html`, or run `ecadinspect <file> tables` on the command
  line.*

## 4. What it shows

Six tabs, the same tab strip as the snapshot views. Each has a search box that filters its rows
(tags, names, numbers, IDs). Tables are plain HTML tables, 500 rows a page, with **Next** and
**Previous** and `1–500 of 25 000`. Every value goes through `esc()`. Times are UTC, labelled
**UTC** (decision 2026-11-10: wasm cannot read the time zone).

### 4.1 Project

Title, drawing number, customer, status and every other project property (`rev.*` grouped
under **Revisions**), the reference style, and counts: pages, devices, wires, cables, nets,
definitions. Below them, **Pages** in book order with folder, number, title, page properties
and counts of items, devices and wires on each.

### 4.2 Devices

One row per component: tag (or *untagged*), stored `function` and `location` (`=` and `+`,
shown as stored; 024's location derived from location boxes is an engine view and is not
shown, Q3), definition name, the pages its symbols are on, and connection points with the wire
number on each. A row expands to every property. Duplicate tags are marked **duplicate** (counted
by the inspector from the stored tags).

### 4.3 Wires and nets

**Nets**, from `derive::nets` and `wiring`: number (and *fixed*), potential, place, connection
points, wire count. **Wires**: number, the two ends (`-K1:A1 → -X1:3`), cross-section and
colour as stored, cable and core when in a cable. **Cables**: tag, members, ends.

### 4.4 History

- **Branches**: name, status, release line, head seq, fork point, row count.
- **Transactions** of the chosen branch, newest first and paged: seq, time (UTC), author, kind,
  op count and summary, stored size and compression. Expanding a row shows its ops as JSON.
- **Versions and revisions**: user versions, revisions (with release fields), automatic
  snapshots and merges, each with its point and chunk count.
- **Export** gives the same JSONL as `export-jsonl`, as a download (a `Blob` link). It saves a
  new file and never touches the source.

### 4.5 Tables

The six redb tables (`meta`, `branches`, `transactions`, `versions`, `chunks`, `assets`):
rows, stored bytes, metadata, fragmentation, as `ecadinspect tables` shows them. Picking a table
lists its rows (key, size, compression), paged. Each row has the **Readable / Raw** toggle from
brief 021's "Later": readable is the decoded JSON, pretty-printed; raw is the stored bytes as
hex with an offset column, the first 4 KiB, then *4 KiB of 18 233 shown*. An asset row shows its
media type and size, never the asset itself.

### 4.6 Checks

- **Open report**: what `ProjectV2::open` found. Clean; or damage at seq *n*, opened read-only
  at *n − 1*; or a repair of the copy in memory (§5 row 9).
- **Model invariants**: `Document::check()` on the opened document (it names the first
  violation of I1–I18), and `derive::mismatches` (one row each), in words.
- **Check chain** (runs on load, and on files over 20 MB from a button): every row of every
  branch is decoded and its chain value checked, every head matches its last row, and every
  version's chunks are present and hash correctly. This is linear in the file and needs no
  replay. It is `verify`'s first phase, split out by the worker as
  `v2::verify::verify_chain(&Store) -> VerifyReport` (code, not format, Q7). The result is
  **chain PASS** or a row per failure.
- **Full Verify** (a button, run on request as in the app): replay every branch from the root and
  compare every snapshot. Before it starts on a file of over 2 000 transactions it says
  *This replays every transaction (33 998) with every check; on large projects this can take a
  long time.* While it runs it shows **Stop**, which terminates the Worker and reloads the module
  with the same bytes, so the views stay. After it: the `VerifyReport` lines, **PASS** or
  **FAIL**, and the time.
- The drawing Checks (022, 025, 026) are not here (Q3).

## 5. Mismatches: always a message and a way forward

The page shows as much as it can. Detection order: size, magic bytes, redb, `meta` facts,
full open.

Rows 1–8 and 10–11 are tested natively. Row 9 has a native test (a file cut mid-commit), and
row 12 is tested by the Node smoke check with a debug-only trap request.

## 6. Packaging and size budget

### 6.1 Build

`cargo xtask inspector [--check]`:

1. `cargo build -p ecad-inspector --release --target wasm32-unknown-unknown`, with a profile
   override for this crate only (`opt-level = "s"`, `lto`, `codegen-units = 1`,
   `panic = "abort"`, `strip`). No new tool: `wasm-opt` is used if it is on `PATH`, and skipped
   with a note if not.
2. Gzip the module (`flate2` in `xtask` only, Q2), base64 it, and replace the empty
   `<script id="ecad-wasm" type="application/octet-stream"></script>` in the template.
3. Write `target/inspector/ecad-inspector.html` and print *`ecad-inspector.html`: 0.78 MB
   (module 1.97 MB, gzipped 0.57 MB); budget 1.5 MB.*
4. `--check` also runs `tools/inspector/smoke.mjs` under `node` when it is on `PATH`
   (otherwise *node not found: smoke check skipped*), against the fixtures of §7.

### 6.2 Budget

| | Spike | Budget (xtask fails above) |
| --- | --- | --- |
| Module, gzipped | 0.57 MB | 0.9 MB |
| Built page | ≈ 0.78 MB (base64 of 0.57 MB, plus 20 KB of page) | **1.5 MB** |
| Open, demo | 46 ms | under 1 s, page included |
| Open, large tier | 0.96 s | under 3 s, page included |
| Check chain, large tier | not measured (linear; native `tables` 45 ms, open 0.96 s) | under 5 s |

Linking `ecad-cadcraft` (the engine, for the drawing checks or derived locations) would pull in
CADCraft's engine, render and I/O, several megabytes more. That is why §4.2 and §4.6 stop where
they do.

### 6.3 Shipping

- **Nothing built is committed.** The template, `smoke.mjs` and the crate are committed;
  `target/` is ignored.
- **CI is not changed** in this brief (root `CLAUDE.md`). `cargo xtask ci`, which the QA gate's
  full suite runs, gains the `inspector --check` step, so the size budget and smoke check run
  there with no workflow edit (Q6). Publishing the page as a CI artifact or release asset is a
  follow-up through `craft-common-actions`.
- To give someone the inspector, send the one HTML file. It runs offline.

## 7. Tests

- **Native contracts** (`crates/ecad-inspector/tests/all/inspector_contracts.rs`,
  table-driven). Fixtures are built in the test with `ecad-file`'s own helpers (as
  `container_v2.rs` does): a small project with two branches, a revision, a cable and a net. Then:
  - each view's reply: keys, counts and paging (`from`, `count`, `total`);
  - every row of §5 (except 12): the error's `what`, `way_out` and what is still shown;
  - the raw toggle: the hex of a row equals the stored bytes, and readable equals `pack::unpack`;
  - Export output equals `export_jsonl`'s byte for byte.
- **Hostile input** (in the same file): every truncation of the small fixture, a flipped byte in
  one row of each table, random bytes of 0–64 KiB (fixed seed). Each must give a reply, never a
  panic. Larger cases are in the slow set.
- **Never writes:** after `load`, the input `Vec` is gone (moved), and the test's own copy of the
  file is byte-identical to before. The page has no write path, which the reviewer checks.
- **Node smoke** (`tools/inspector/smoke.mjs`, from `cargo xtask inspector --check`): it loads
  the built module from the built page (proving the inlining) and runs `load` and every view on
  the demo fixture, a damaged fixture and a schema-2 fixture, asserting `ok` or the expected
  `error.what`.
- **Escaping:** a fixture whose tag, page title and a property hold `<img src=x
  onerror=alert(1)>`. The tester opens it in a browser and checks that the text shows and nothing
  runs (screenshot `029-escape.png`).
- **Screenshots** for the owner: `029-empty.png`, `029-project.png`, `029-devices.png`,
  `029-history.png`, `029-tables-raw.png`, `029-checks.png`, `029-mismatch-v1.png`.
- No MCP contract test: the brief adds no command (the 011 rule applies to commands).

## 10. Format

None. The inspector reads the brief 021 format through `ecad-file`'s own reader and changes
nothing. **No FP items.** If a later format change (a schema 2, a new table) lands, the
inspector shows it raw (§5 rows 6–7) until it is rebuilt.

## 11. Owner questions, each with a recommendation

1. **How the module is exported, given `unsafe_code = "forbid"`.** (a) Raw exports:
   `ecad-inspector` alone sets `unsafe_code = "deny"` and allows it on `src/wasm.rs` only, for
   the `#[unsafe(no_mangle)]` attribute (five functions, no `unsafe` blocks). It needs no new
   dependency or tool, and the loader is about 40 lines of page JavaScript. `xtask layers` checks
   that no other crate relaxes the lint. (b) `wasm-bindgen`: keeps `forbid` (checked, 0.2.100
   compiles under it), but adds a dependency, the `wasm-bindgen-cli` tool pinned to the same
   version on every machine that builds, and its generated glue. **Recommend (a).** The attribute
   is unsafe only because of symbol clashes, which a cdylib with five uniquely prefixed names
   cannot have. The exception is one file, visible and checked.
2. **A gzip crate in `xtask`.** Inlining 1.97 MB raw makes a 2.6 MB page; gzipped it is about
   0.78 MB. **Recommend** `flate2` with its default pure-Rust backend (`miniz_oxide`; MIT OR
   Apache-2.0, both already in `Cargo.lock` through CADCraft), in `xtask` only, never in a
   product crate. Without
   it the budget becomes 3 MB.
3. **Drawing checks and derived locations.** They need `ecad-cadcraft`, which is several MB
   more, plus engine code on wasm. **Recommend not in 029:** show file integrity, model
   invariants and stored `=`/`+` only. If the owner wants them, the follow-up moves those rules
   into `ecad-model` (where they belong if they need no geometry), not the engine into the page.
4. **Version 1 files.** `ecad_file::open_project` already reads v1 from bytes and would build
   for wasm, so adding it is cheap. But v1 is being replaced, and the way forward
   (`ecad upgrade`) is one command. **Recommend:** message and way forward only (§5 row 3), and
   no `.jsonl` reading either. Revisit if the owner wants to inspect old files in a browser.
5. **One project at a time.** Comparing two `.ecad` files side by side doubles memory (156 MiB
   for the large tier each). **Recommend one at a time.** Dropping a second replaces the first,
   with *Replaced `a.ecad` with `b.ecad`* shown.
6. **Where the size budget and smoke check run.** **Recommend in `cargo xtask ci`** (the QA
   gate's full suite, already run by CI on PRs into `main`). This adds about a minute for one
   release wasm build and no workflow edit. Quick PR checks into `dev` stay as they are.
7. **Check chain as the default check, and full Verify on request.** Full Verify did not finish
   in 25 minutes on the large tier (native, §1.3). **Recommend:** the worker splits `verify`'s
   first phase into `verify_chain` (decode, hash chain, heads, chunk hashes; no replay; code in
   `ecad-file`, no format change), and the page runs it on load. Full Verify stays a button
   with a warning and **Stop**. Separately, propose a follow-up for `ecad-file` to make full
   Verify scale (check invariants on the touched set per transaction, as brief 013 does, and in
   full only at snapshots). It belongs to the store and the app's **Verify file**, not here.
