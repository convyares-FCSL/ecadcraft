# Design 019: Sheets, title block, project and page properties, folders, revisions

Brief: `docs/briefs/019-sheets-and-properties.md` (Approved 2026-11-08). Follows `008.md` §2
(click-first, one commit = one JSON-equivalent transaction, Esc writes nothing, feedback in words,
never crash), the Project panel of `016.md`, the device properties of `018.md` and the references
of `010.md`. Tokens: `tokens.md` (this spec adds the rows in §11). Format and ops proposals: §2
(**the overseer decides**). Owner questions with recommendations: §14.

## 0. What the code has today (checked)

- `Page { title }` only; `page_order: Vec<PageId>`. `renamepage` and `movepage` are a
  `RemovePage` + `AddPage` pair (016 §0).
- `SetProperty { object: ObjectRef, key, before, after }`, but **`ObjectRef` is only
  `Component | Conductor | Cable`**: it cannot target a page or the project. The document has no
  project-level properties map.
- `ProjectSettings { length_unit, tag_padding, tag_prefixes }`, `#[serde(default)]`, changed by
  `SetProjectSettings { before, after }`: typed fields can be added there with defaults.
- `NameVersion { name, at }` adds `name → at` to `Document::versions`; the ledger requires
  `at < seq` of the naming transaction (`check_bookmarks`), so a version names a point **before**
  the transaction that names it. `Ledger::state_at(seq)` rebuilds the document at that point
  (replay from 0, on a scratch copy). No command names a version yet.
- References: `derive::column_of(x, 40 mm)` from x = 0, numbered 1..999; the text is
  `/<page position>.<column>` (010). The Devices tab shows the same `/page.column`.
- Indexes: `page_reps` (page → representations), `subject_reps`, `tags`. The ledger reports touched
  pages, cables and devices per commit (`pages_touched`, `cables_touched`, `devices_touched`).
- CADCraft's Properties palette (`crates/ui-egui/src/palettes.rs`, `properties_section`) has no
  hook for an embedding application.

## 1. Goal

Every page is a real A3 sheet at true size with a lettered grid and a filled title block, and the
project, page and revision facts it shows are edited in one place, the Properties panel.

## 2. Format and ops proposals (for the overseer)

All are additive: every new field is optional and left out of the file at its default, so an old
file opens with defaults (brief AC6) and an old file saved again without using a new feature is
unchanged. `ecad-file`'s `v1` mirror types gain the same fields.

**FP1. `SetProperty` on pages and the project (required).** Add `ObjectRef::Page(PageId)` and
`ObjectRef::Project`, `Page.properties: Properties` and `Document.properties: Properties` (both
omitted when empty). Page number, `=`/`+` override, sheet override and folder membership are page
properties; title, drawing number, customer, status, defaults and revisions are project
properties. *Why:* SetProperty cannot target either today. *Rejected:* (a) new typed `Page` fields
changed by the `RemovePage` + `AddPage` pair: every number or folder edit would look like a page
removed and re-added, so every view would treat it as a whole-page change (against the update
maps, §9); (b) putting title or customer in `ProjectSettings`: they are free text, not settings.

**FP2. Sheet settings in `ProjectSettings` (no new op).** Add `sheet: SheetSpec` (default A3
landscape, 8 columns lettered, 6 rows numbered; §3) and `page_number_step: u32` (default 1),
both through the existing `SetProjectSettings`. A page's override is the page property `sheet`
holding the same spec as text (`A2`, `A3 10x6`, `594x420 12x8 numbers letters`); unreadable text
is ignored with a warning (§6.1).

**FP3. Folders.** Two options:
- **A (recommended):** typed folders with IDs, mirroring pages: `FolderId`, `Folder { name,
  parent: Option<FolderId> }`, `Document.folders` and `folder_order: Vec<FolderId>` (sibling order is
  the relative order there), ops `AddFolder { id, folder, index }`, `RemoveFolder { id, folder,
  index }` and `ModifyFolder { id, before, after }` (rename, re-parent). A page's folder is its page
  property `folder` (the folder's hex ID; absent = top level), set by `SetProperty`. New invariants:
  a page's `folder` names an existing folder; parents exist and form no cycle; depth ≤ 8.
  *Why:* folders are structure referenced by pages, and DOC-02 says references use IDs while names
  are properties; a rename is one op, whatever the folder holds.
- **B (no new op):** folders as project properties (`folder.<n>` = name and parent, `folder_order`
  = a list) and the page property `folder = <n>`. Works with FP1 only, but structure lives in strings
  that the model cannot check (cycles, dangling parents).

**FP4. Revisions (no new op beyond FP1).** Recommended: project properties `rev.<n>.<field>`,
`n` = 1, 2… in issue order, fields `rev`, `date`, `description`, `drawn`, `checked`, `approved`,
and `issued` (the version name, set only by Issue). The row with the highest `n` and no `issued`
is the **pending** revision. Issue writes the fields and `NameVersion { name: "Rev <rev>", at:
head }` in one transaction (§7). *Alternative:* typed `Document.revisions: Vec<Revision>` with
`AddRevision`/`ModifyRevision`: cleaner types, two more ops. A flat list of text fields does not
need them.

**Key rules (commands enforce them, the model stores strings):** values are trimmed, at most 200
characters, no control characters, empty or `null` clears (P7), as 018 §6.1. `location` and
`function` are stored with their leading `+` / `=`, added if missing.

## 3. The sheet frame (brief scope 1)

### 3.1 Geometry, A3 default, millimetres

*Revised in the fix round of 2026-11-08 (owner):* the model origin is the **page's bottom-left
corner**, the paper edge. A title block or a bottom margin is not always full width, so nothing
assumes one. Sheet W × H, columns C, rows R:

| Part | Rectangle (x0, y0) – (x1, y1) | A3 (420 × 297, 8 × 6) |
| --- | --- | --- |
| Sheet edge (paper) | (0, 0) – (W, H) | (0, 0) – (420, 297) |
| Frame (the grid) | (10, 10) – (W − 10, H − 7) | (10, 10) – (410, 290) |
| Title block (built-in layout) | (10, 10) – (W − 10, 50) | (10, 10) – (410, 50) |

Margins: 10 left, right and bottom, 7 top (parameters of the grid, not constants: a later project
setting). The zones span the **whole frame**, title-block area included: column width = (W − 20) / C
(A3: 50), row height = (H − 17) / R (A3: 46.67). Counted from the **top-left** (the starting corner
is a parameter too): columns left to right, **row 1 is the top row**; on A3 the title block lies in
row 6.

- Column labels (default `A`…, then `AA`…; or `1`…) centred in each column in the top margin
  (y = H − 3.5) and the bottom margin (y = 5), text height 3.0.
- Row labels (default `1`…; or `A`…) centred in each row at x = 5 and at x = W − 5, height 3.5.
- Ticks: a 3 mm line outward from the frame at every column boundary (top and bottom) and row
  boundary (both sides).

Presets (landscape): A3 420 × 297 (8 × 6), A2 594 × 420 (12 × 8), A1 841 × 594 (16 × 12), A0 1189 ×
841 (24 × 16). Custom: W 420–2400, H 250–2400, C 1–26, R 1–26 (smaller sheets cannot hold the title
block, §4; Q10). Inch projects divide every value by 25.4, as 010 does.

### 3.2 How it is drawn

Derived, never stored: projected into the page window on the reserved layer **`ECAD-FRAME`**
(ACI 7, locked), like `ECAD-CABLES`. Selecting or editing it is refused with
`The sheet frame is derived; change it in Project settings or the page's Sheet.` Object snap
ignores it. It plots and exports with the page. Weights: frame `ecad.frame-weight` (0.50 mm);
grid ticks, title-block lines and the sheet edge `ecad.wire-weight` (0.25 mm); sheet edge in ACI 8
(`ecad.sheet-edge`) so the paper reads as paper. Zoom extents (and the first view of a page) fit
the sheet edge (brief AC1).

### 3.3 References use the frame (brief AC3)

A point's column is `clamp(floor((x − 10) / column width) + 1, 1, C)`, its row
`clamp(floor((H − 7 − y) / row height) + 1, 1, R)` (zones over the whole frame, so the title-block
area is row R; a point outside the frame is clamped), on **its own page's** sheet. Reference texts
are `<page number>-<column label>-<row label>`, e.g. `105-C-4` (owner answer Q1; the style is a
project setting, `/105.C` the other). The Devices tab's symbol rows read the same way. `ecad.column-width` (40 mm) is retired.

page and project, §8).

## 5. Folders in the Project panel (brief scope 5)

### 5.1 Book order

Within the top level and within each folder, **pages come first** (in `page_order` order), then
sub-folders (in `folder_order` order). The book order is that tree read depth-first. It gives
"Next", positional numbers (§6.1) and the order of the Pages list. With no folders it is
`page_order`, as today.

### 5.2 Look

The Pages tab (016 §2) becomes a tree. Rows stay 20 px, monospace, virtualised (`show_rows` over
the flattened visible rows).

```
┌ PROJECT ─────────── [+][F][^][v][P][<] ┐
│ [Pages] [Devices]                       │
│     1  Cover                            │  top-level page
│ ▾ Schematic layouts (3)                 │  folder: chevron, name, page count
│     100  Supply                         │  indent 12 px per level
│ ▌   105  Motor control                  │  active page (016 states)
│   ▸ Spare circuits (2)                  │  folded sub-folder
│ ▾ Terminal strips (0)                   │
│       (empty)                           │  drop target, cad.text_faint
```

- Page row: number right-aligned in a 5-character column, two spaces, title (016 rules). Hover:
  `Page 105: Motor control`. Duplicate numbers (only possible from old data) show the number in
  `ecad.orphan` with hover `Two pages are numbered 105.`
- Folder row: `ChevronDown`/`ChevronRight`, name in `cad.text`, `(n)` = pages inside, all levels,
  in `cad.text_dim`. Fold state is per session.
- Header gains **New folder** (`ecad.project.newfolder`, an existing folder-like glyph from
  `icons.rs`; no new icon).

### 5.3 Interactions

All are one transaction and one `u`.

| User does | Result |
| --- | --- |
| Click a folder row / its chevron | Fold or unfold (nothing recorded) |
| **New folder** | `newfolder {name: "New folder", parent}`: inside the cursor row's folder (or the active page's), at the end; opens rename with the name selected |
| Double-click a folder name, F2 | Rename in place (016 §3.2 rules): `renamefolder {folder, name}` |
| Double-click a page number | Edit the number in place: `pageprops {page, number}` (§6.1 refusals under the field) |
| Double-click a page title | Rename (016) |
| Drag a page onto a folder row | Into that folder, at its end: `movepage {page, folder, index}` |
| Drag a page between rows | Insertion line where it lands, in that row's folder: same command |
| Drag a folder | Moves it with all its contents (`movefolder {folder, parent, index}`); onto itself or a descendant: no-drop pointer, hover `A folder cannot go inside itself.` |
| **+** (New page) | `newpage` in the cursor row's folder (else the active page's), at its end (016 §3.1 otherwise) |
| Right-click a folder | **New page here**, **New folder inside**, **Rename** F2, **Delete folder** |
| **Delete folder** | `deletefolder {folder}`: its pages and sub-folders move to its parent, in place; one transaction. Echo `Folder "Spare circuits" deleted; its 2 pages moved to "Schematic layouts".` |

A folder name is 1–100 characters; sibling folders may not share a name (case-insensitive):
`There is already a folder "Spare circuits" here.` Depth beyond 8: `Folders nest at most 8 deep.`

## 6. Page properties (brief scope 4)

### 6.1 Fields

| Field | Stored as (FP1) | Rules |
| --- | --- | --- |
| Internal ID | `PageId` | Never shown in the panel (the debugger shows it) |
| Number | page property `number` | 1–12 characters `0-9 A-Z a-z _`, no spaces, `.`, `-` or `/` (they separate reference parts). Unique, case-insensitive, against every page's **shown** number: `Page 105 already exists ("Supply").` |
| Title | `Page.title` (`renamepage`) | 016 rules |
| Function | page property `function` | 018 value rules; absent = the project's |
| Location | page property `location` | 018 value rules; absent = the project's |
| Sheet | page property `sheet` | absent = the project's sheet (§3.1); text spec, refused if unreadable: `Sheet "A5" is not known. Use A3, A2, A1, A0 or WxH, then columns x rows.` |
| Folder | page property `folder` | set by drag (§5.3) |

**Shown number:** the stored `number`, else the page's 1-based position in book order (old files,
brief AC6). **New page default:** take the page it follows in book order (the last page of the
target folder; for an empty folder, the page before the folder); its number's leading digits +
`page_number_step`; skip numbers in use; no digits or no page before: its book position. `newpage`
stores it, so later inserts never shift it. `newpage {title, number?, folder?}` accepts an explicit
number.

### 6.2 Where they are edited

The Properties panel with nothing selected (§8), the number column in the panel (§5.3), and
`pageprops {page, number?, title?, function?, location?, sheet?}` (each `null` clears; one
transaction for all given fields; no fields: returns the current values, writes nothing).

## 7. Project properties and revisions (brief scopes 3 and 6)

### 7.1 Project Properties dialog

Opened by **Project Properties** (`ecad.project.props`, an existing settings-like glyph) in the
Project panel header, or **More…** in the Properties panel. A floating window, 420 px wide, square
corners, `cad.panel`; Esc or **Cancel** closes and writes nothing; **OK** writes every changed
field as **one** transaction `Project properties` (several `SetProperty` and at most one
`SetProjectSettings`); unchanged: nothing.

```
┌ PROJECT PROPERTIES ───────────────────────────── [x] ┐
│ Title           [Panel 7 extension                 ] │
│ Drawing no.     [FCS-1708-E-001                    ] │
│ Customer        [                                  ] │
│ Status          [Draft                          ▾  ] │  editable combo
│ Function        [=PWR      ]  Location [+09-02     ] │  defaults for pages
│ ── Sheet ─────────────────────────────────────────── │
│ Size [A3 420×297 ▾]  Columns [8 ] [Letters ▾]        │
│                      Rows    [6 ] [Numbers ▾]        │
│ Page number step [1  ]                               │
│ ── Other properties ──────────────────────────────── │
│ [site_contact   ] [J. Smith               ] [x]      │
│ [Add property]                                       │
│ ── Revisions ─────────────────────── [Revisions…]    │
│ Current: A, 2026-11-08 "First issue"                 │
│                                       [OK] [Cancel]  │
└──────────────────────────────────────────────────────┘
```

- Keys: `title`, `drawing_number`, `customer`, `status`, `function`, `location`. Status suggestions:
  `Draft`, `For review`, `For construction`, `As built`; any text is allowed (Q9).
- Other properties: key 1–40 characters `a-z 0-9 _`, not a reserved key (`title` … `location`,
  `rev.*`, `folder*`): `"title" is set above.` They are stored and shown, not drawn (custom title
  blocks later).
- Size combo: A3, A2, A1, A0, **Custom…** (width and height fields appear). Choosing a preset
  fills its default columns and rows. Out-of-range values: red outline and §3.1's limits under the
  field; OK is disabled.
- A grid change shows, under the Sheet group, `Changing the grid changes reference texts on every
  page.` (it is the one edit that legitimately does, §9).
- Read-only project: every field read-only, OK hidden.

Commands: `projectprops {title?, drawing_number?, customer?, status?, function?, location?,
sheet?, page_number_step?, props?: {key: value|null}}`; no fields: returns everything, writes
nothing.

### 7.2 Revisions dialog and issuing

**Revisions…** opens a floating window listing all revisions, newest first:

```
┌ REVISIONS ──────────────────────────────────────────────────────── [x] ┐
│ Rev  Date        Description            Drawn  Checked  Approved       │
│ [B ] [         ] [Terminals added     ] [CVA ] [JS   ] [      ]  pending│
│  A   2026-11-08  First issue             CVA                 [Open]    │
│                                   [Issue Rev B…]           [Close]     │
└────────────────────────────────────────────────────────────────────────┘
```

- **Pending row** (always one, editable): the next rev suggested from the newest issued (`A`→`B`,
  `Z`→`AA`, `0`→`1`, `P3`→`P4`; none: `A`). Editing a field and leaving it writes
  `revision {rev?, date?, description?, drawn?, checked?, approved?}` (one transaction, creating
  the pending `rev.<n>` keys on first edit). Rev text: 1–8 characters `0-9 A-Z a-z`, not used
  before.
- **Issued rows** are read-only (the commands refuse edits: `Rev A is issued and cannot change.`).
- **Issue Rev B…** asks `Issue Rev B? The project as it is now is kept as "Rev B" and can be
  opened read-only. [Issue] [Cancel]`. Needed: rev, description and drawn (else the button is
  disabled with hover `Fill in Rev, Description and Drawn first.`); empty date becomes today
  (local, `YYYY-MM-DD`). A project with no transactions: `Nothing to issue yet.`
- **Issue** = `issuerevision {}`: one transaction `Issue Rev B` holding the remaining field writes,
  `rev.<n>.issued = "Rev B"` and `NameVersion { name: "Rev B", at: head }` (head = the last
  transaction before it). Echo `Rev B issued (transaction 812). Save to keep it.` The title block's
  Rev box and table follow. `u` undoes the issue (removes the name and the `issued` key); that is
  the only way an issued row changes.

### 7.3 Opening an issued revision read-only (brief AC5)

**Open** on an issued row (or `openrevision {rev}`) builds the document once with
`Ledger::state_at(at)` (on request, on a copy, as the debugger's replay), then:

- The Project panel shows a bar under its header in `ecad.revision-bar` fill: `Rev A,
  2026-11-08: read-only` and **Back to current** (`ecad.project.revision.back`). The Pages tree
  shows Rev A's pages and folders, all writing controls disabled.
- Clicking a page opens it in 016's read-only **preview window**, titled `Rev A · page 105: Motor
  control  read-only`, drawn with its frame and title block **as at Rev A**: since `at` precedes
  the issue transaction, the revision table is the live project's issued rows up to and including
  Rev A (issued rows never change, so this is exact).
- The live page window stays as it was and stays editable. Back to current, closing the project or
  opening another revision drops the copy. Nothing is recorded.

## 8. The Properties panel (brief scope 7)

### 8.1 Seam

An upstream patch in `crates/ui-egui/src/palettes.rs`: an **owner section** drawn at the top of
`properties_section`, under the header, when the front document has an owner
(`// ECAD-SEAM(owner): owner section in Properties`, listed in `UPSTREAM-PATCHES.md`; Q8). ECAD
draws it; CADCraft's own rows follow unchanged. Rows use CADCraft's `prop_row` look (label column
and value box).

### 8.2 What it shows

Section headers: `ECAD · <KIND>` in CADCraft section-header text.

| Selection | Section | Fields (editable unless marked) |
| --- | --- | --- |
| Nothing | `ECAD · PAGE 105`, then `ECAD · PROJECT` | Page: Number, Title, Folder (read-only: path), Function, Location, Sheet (combo: `Project (A3, 8×6)` and the presets). Project: Title, Drawing no., Customer, Status, Revision (read-only `A, 2026-11-08`) with **Revisions…**, and **More…** (the dialog) |
| One device: any item of a symbol, its tag text or a terminal label | `ECAD · DEVICE -K01` | Tag, Description, Maker, Part number, Location, Function (018 §6.1 rules, merge offer as in 016 §16); This symbol (read-only `NO contact 13/14`); Where (read-only `105.C`) |
| Several items of devices | `ECAD · 3 DEVICES` (symbols of one device count once) | As one device; differing values show `*varies*` in `cad.text_faint`; a value typed is written to all in one transaction. Tag is read-only (`Tags are one per device.`) |
| One wire | `ECAD · WIRE` | From, To (read-only `-K01:A1`, `not connected`); Cables (read-only); its stored properties as key/value rows (`setprop`) |
| One cable (slash, label box, fan view part) | `ECAD · CABLE W01` | Tag, then stored properties; Cores (read-only count) |
| One cable reference (point or text) | `ECAD · CABLE REFERENCE` | All read-only: Cable, This end `/105.C`, Other ends (`/110.B`, …), with **Go to** (`cablegoto`) |
| Mixed kinds | `ECAD · 5 OBJECTS` | `3 devices, 2 wires. Select one kind to edit.` |
| Plain CADCraft geometry only | none | CADCraft's rows as today |

Inherited values (page Function or Location from the project) show as the project's value in
`cad.text_faint` with ` (project)`; typing replaces it, clearing returns to inherited.

### 8.3 Editing

Text fields commit on Enter or focus loss, Esc puts the value back (CADCraft's `edit_field`). A
refusal keeps the field open with a 1 px `ecad.orphan` outline and the message under it. Each
commit runs the command's JSON form (`setprop`, `pageprops`, `projectprops`, `revision`): one
transaction, one `u`, and the title block follows on the next frame (brief AC2). Read-only
project: every value is a read-only box. **Device Properties** (018) stays as the command-line
shortcut.

## 9. Update maps (brief scope 8)

Only the active page window is drawn (016). "Refresh" below means recompute that part only. Every
op not listed changes nothing in that view. A full build happens only on open, reload, switching
the active page (frame and title block of the new page) or first show of a panel.

| View | Op (kind, target) | Does |
| --- | --- | --- |
| **Frame** of the active page A | `SetProjectSettings` with `sheet` changed, A has no `sheet` | redraw frame and title block geometry; refresh A's reference texts |
| | `SetProperty(Page A, sheet)` | same |
| **Title block** of A | `SetProperty(Project, title / customer / drawing_number / status)` | that one box |
| | `SetProperty(Project, function / location)` with A not overriding; `SetProperty(Page A, function / location)` | that box |
| | `SetProperty(Page A, number)`; `RemovePage`+`AddPage` of A (rename) | Page or Page title box |
| | `SetProperty(Page N, number)` where N is A's next page | Next box |

| | `SetProperty(Project, rev.*)`, `NameVersion` / `UnnameVersion` | revision table and Rev box (issued rows only change on issue and its undo) |

| | `AddPage` / `RemovePage` / folder ops | only partners on pages **without** a stored number whose position changed |

| **Properties panel** | a selection change | rebuild its copy (O(selected)) |
| | ops whose touched set (`pages_touched`, `devices_touched`, `cables_touched`) meets the selection; with no selection: the Page A / Project rows above | refresh the copy |
| **Revisions dialog** (open) | `SetProperty(Project, rev.*)`, `NameVersion` / `UnnameVersion` | rebuild its rows (O(revisions)) |
| **Revision view** (§7.3) | none: a frozen copy | — |

Book-order positions (for "Next", positional numbers and the tree) are kept as an index updated
from the change point on `AddPage`, `RemovePage`, folder ops and `SetProperty(Page, folder)` only.
*As built (review M5, kept for later):* book order is worked out from the pages and folders when
one of those ops arrives or a view is built (O(pages + folders), never items), as the page order
was before 019; a kept index is a later step.

**Bench (`cargo xtask bench`, large project):** `pnum ms` (renumber a page with references on 50
pages: commit and refresh), `frame ms` (first view of a page with frame and title block),
`tbupd ms` (a project-title edit), `gridchange ms`, `revopen ms` (open Rev A on the large log). No
row may scan all pages' items on an ordinary edit (brief AC7).

## 13. Quick start: section "5H. Sheets and properties (by clicking)"

On `demo.ecad`, after 5E:

1. **The sheet.** Each page now sits on an A3 sheet with columns `A`–`H` and rows `1`–`6`. Type
   `z` Enter `e` Enter (zoom extents): the whole sheet fits. The reference texts read
   `/<page>.<column letter>`.
2. **Number a page.** With nothing selected, open the **Properties** palette: under `ECAD · PAGE 1`
   set **Number** to `100`, Enter. The title block's Page box says `100`; the reference on the other
   page now says `/100.…`. Type `u`: back to `1`. Set it again.
3. **Project facts.** Click **Project Properties** in the Project panel header. Fill Title,
   Drawing no. and Customer, choose Status `Draft`, OK. The title block fills in.
4. **Folders.** Click **New folder**, type `Schematic layouts`, Enter. Drag `Supply` and `Field`
   onto it. Make another folder `Terminal strips`: it shows `(empty)`. Fold and unfold
   `Schematic layouts`.
5. **Revision A.** In Project Properties click **Revisions…**. In the pending row type
   Description `First issue`, Drawn your initials. Click **Issue Rev A…**, then **Issue**. The title
   block shows Rev `A` and the row. Save.
6. **Look back.** Draw a wire on `Supply`. In Revisions click **Open** on Rev A, then click
   `Supply` in the panel: the preview shows the page without the wire. Click **Back to current**.
7. **Device properties.** Click a contact's symbol: Properties shows `ECAD · DEVICE -K01`; change
   its Description. Type `u`.

§9 (limitations) gains: one built-in title block; landscape A3–A0 and custom sizes only; references
show page and column, not yet the row; the revision list page, cover and contents are F6.

## 14. Owner questions, each with a recommendation

1. **Reference text:** `/105.C` (page number, column letter) now, `105-C-4` with the row later?
   **Recommend yes**: the brief puts `page-column-row` later; the row is already computed and
   listed by `cablerefs`, so the switch is a small follow-up once you see the frame.
2. **Existing references change:** the 40 mm numbered columns become 50 mm lettered ones, so texts
   in existing projects change (`/1.2` → `/1.B` or `/1.C`). **Recommend accept**: what the reference
   says must be what the frame shows (AC3).
3. **Origin:** model (0,0) at the lower-left of the drawing area, title block below it.
   **Recommend yes**: existing drawings stay inside the frame with no migration.
4. **Folder storage (FP3):** typed folders with IDs and three ops, or folders encoded in project
   properties? **Recommend typed (A)**: folders are structure referenced by pages (DOC-02), and the
   model can then check cycles and dangling parents.
5. **Revision storage (FP4):** project properties `rev.<n>.*` (no new op), or typed revisions?
   **Recommend properties**: a flat list of text fields; the commands lock issued rows.
6. **Pages before sub-folders** inside a folder (§5.1)? **Recommend yes**: one simple book order;
   a page that must come after a sub-folder goes in a folder of its own.
7. **Issuing:** require Rev, Description and Drawn; Checked and Approved may be empty; `u` can
   undo an issue. **Recommend yes**: sign-off often comes after the drawing is issued for review;
   undo keeps a mistaken click cheap, and the log still shows it.
8. **Properties panel seam** in `crates/ui-egui/src/palettes.rs` (§8.1): is this upstream patch
   approved under the brief's scope 7? **Recommend approve**: it is the only way into CADCraft's
   Properties tab and is a small hook like the Tool Sets seam.
9. **Status:** free text with suggestions (`Draft`, `For review`, `For construction`, `As built`),
   or a fixed list? **Recommend free text with suggestions** (IEC default, never the law).
10. **Sheet sizes:** landscape A3–A0 and custom (≥ 420 × 250) only; A4 and portrait later, when
    the title block has a compact variant? **Recommend yes.**
11. **Page number step:** project setting, default 1 (you would set 5 for `100`, `105`, `110`)?
    **Recommend yes.**
12. **Revision table on the sheet:** the newest 7 issued revisions, the full list on the
    revision-list page (F6)? **Recommend yes.**
