# Design 026: Numbering

Brief: `docs/briefs/026-numbering.md` (Draft), lane C, branch `feature/numbering`. Builds on 018
(tags, high-water mark, duplicate rule, "make it the same device"), 022 (wire numbers, fixed
numbers, `wirenumber` conflicts, `renumberwires`, `?` labels, Checks), 019 (sheet grid, book
order, folders, Properties panel, Issue Revision), 020 §5.3 (merge conflicts) and 010 (cable tags).
Words: `docs/glossary.md`; §1 proposes three rows. Tokens: `docs/design/tokens.md` (§10 adds two).
Format proposals: §12. Owner questions: §15. Stays off `references.rs` (025) and outputs (024).

## 0. What the code has today (checked on `dev` `af2d41eb`)

- **Device tags.** Component property `tag`. `ecad_model::tag` parses the usual form (letters, then
  1–9 digits, `-` optional) and compares by key (`-K1` = `k01`). Other tags are kept as typed and
  compared whole. Padding is `ProjectSettings.tag_padding` (2). Prefix overrides per starter
  symbol are in `tag_prefixes`. The next automatic number is the prefix's **high-water mark** + 1:
  `tag::note_ops` counts every `tag` a `CreateComponent`, `DeleteComponent` or **any**
  `SetProperty` (component, conductor or cable) writes or removes, so a number is never given
  twice. Version 2 snapshots carry it (021).
- **Duplicate tag.** `setprop {component, key: "tag"}` with a held tag is refused, naming the holder
  and the next free; `merge: true` runs `devices::plan_merge` (one transaction). Device Properties
  asks `-K03 exists: … Make this the same device? [Yes/Choose another]`; the Devices tab (016 §16)
  and Properties panel (019 §8) show **Make it the same device**.
- **Wire numbers.** `wire_number` and `wire_number_fixed` on every conductor of a net. `wirenumber`
  already offers `conflict: "swap" | "another" | "merge"`. `wiring::renumber(doc, all)` sorts nets
  by page order, then top to bottom, then left to right of the first conductor's route start. A net
  with no number shows `?`. Checks has the Info row `N nets have no number` with **Number them**.
- **Cables.** `Cable.properties["tag"]` is set only when `slash` is given `tag`. There is no
  automatic tag and no duplicate rule. `note_ops` counts a cable tag changed by `SetProperty` but
  not one in `CreateCable`.
- **Merge.** `Choice::{RenumberSource, RenumberTarget}` for a tag conflict; `merge.rs` says "make
  them one device" is excluded.
- `SetProperty` targets components, conductors, cables, pages and the project. Ops
  `AddCableMember` and `RemoveCableMember` exist.
- **Bench large tier** (`ecad-bench`, `TIERS`): 500 pages, **5,000** devices, 25,000 wires,
  2,500 cables. The brief's "10,000 devices or more" is not today's tier; §11 gives both.

## 1. Goal and words

The designer draws first, then numbers everything in drawing order in one undoable step, with a
preview. A clash always offers Swap, Make them one, or the next free number.

Proposed glossary rows (Q12):

| Word | Means |
| --- | --- |
| **drawing order** | Page in book order, then column, then row of the sheet grid, then top to bottom and left to right inside a cell. |
| **fixed** | A tag or wire number chosen by hand that Renumber and Finalise never change. |
| **provisional tag** | A placeholder tag (`-K?3`, `-W?1`, wire `24V-?`) that Finalise numbering replaces. Not issued. |

## 2. One mechanism

A pure planner in `ecad-model`, `numbering::plan(doc, &Request) -> Plan`, serves Renumber,
Finalise, Swap's next-free and the merge's renumber choices. Wires call it through
`wiring::renumber`, which keeps its own net rules (022 §5) but takes the planner's order and
start.

```
Request { kind: Devices | Cables | Wires | All, scope, start: Option<u64>, digits: Option<u8> }
Plan    { rows: [Row { object, kind, old, new, at, fixed, change }], skipped: [(object, tag, why)],
          ops: Vec<Op>, change_count }
```

### 2.1 Which items (scope)

| Scope | Devices and cables | Wires (nets) |
| --- | --- | --- |
| `all` | every tagged item in the usual form, provisional included | every net with an automatic number or none |
| `selection` | the devices of the selected symbols, tag texts or labels; selected cables | the nets of the selected wires |
| `prefix` | tags with these letters (`-K`) | nets of this potential (`24V`) |
| `folder` | items whose **anchor** (§2.2) is on a page in the folder or its subfolders | nets whose first conductor's route starts there |
| `provisional` | provisional tags only (§5) | nets with no number |

Always left alone, listed under **Skipped** in the preview with the reason:
- **fixed** items (`fixed`);
- tags not in the usual form (`-K1A`: `not a letter code and a number`);
- devices with no tag;
- junctions and continuations, which are not listed at all.

### 2.2 Drawing order

Each item has an **anchor**:
- a device: its `main` representation, else its first representation in book order;
- a cable: its first representation (the slash) in book order, at the slash's midpoint;
- a net: as 022, the first conductor's route start.

The sort key is (page index in book order (019 §5.1), column index, row index, −y, x, ID), with
column and row from that page's frame grid (019 §3, page override included). An item with no
representation sorts last, by its old number. This replaces 022's (page, −y, x) for wires too, so
all three kinds share one order (Q2).

### 2.3 Numbers

Per prefix (devices, cables) or per numbering scope of 022 §5.3 (wires), the planner hands out
`start`, `start + 1`, … in drawing order. It skips every number **taken** by an item not being
renumbered: fixed items, items out of scope, and the other kind in the shared namespace (§6). It
never produces a duplicate.

- **Start:** 1 for every scope except `provisional`, where it is the next free number (highest in
  use or high-water mark, + 1), so finalised items follow the issued ones.
- **Digits:** the project's `tag_padding` (devices, cables) or `wiring.digits` (wires). A value
  typed in the dialog applies to this run only. Ticking **Also for new tags** writes it to the
  project setting in the same transaction (`SetProjectSettings`).
- **Ops:** one `SetProperty` per item whose tag changes; for wires, 022's `write_ops` per net.
  Exchanges such as `-K01 ↔ -K02` are fine, because the duplicate rule is checked on the
  transaction's end state, not op by op (FP6).
- **High-water reset:** last in the transaction, one `SetProperty(Project, "numbering.high.<P>",
  "<n>")` per prefix the run covered, `n` = the highest number now in use. New devices then
  continue after the renumbered set, not after the old top (FP4, Q3).

## 3. The Renumber dialog

Opened by:
- **Renumber…** (`ecad.renumber`) in the ECAD tab's new **Numbering** group;
- **Renumber…** in the Devices tab header (016 §16);
- a folder row's menu: **Renumber in this folder…** (scope folder preset);
- **Renumber Wires** (022), which opens it with Wires chosen;
- typing `renumber`.

```
┌ Renumber ─────────────────────────────────────────────────────────┐
│ What   (•) Dev  ( ) Cbl  ( ) Wire  ( ) All                         │
│ Which  (•) All  ( ) Sel (3)  ( ) Prefix [-K ▾]  ( ) Folder [Ctrl ▾]│
│        ( ) Prov (5)                                                │
│ Order  page · col · row                                            │
│ Start  [1    ]   Digits [2]   [ ] Also for new tags                │
├───────────────────────────────────────────────────────────────────┤
│ 42 to change · 3 fixed · 7 same · 1 skipped                        │
│ Old      New      At        Desc                                   │
│ -K07  →  -K01     101-A-2   Contactor / relay coil                 │
│ -K01  →  -K02     101-C-1   Contactor / relay coil                 │
│ -K03  F  -K03     102-B-4   Motor contactor                        │
│ -K?2  →  -K04     102-D-3   NO contact                             │
│ -K1A  –           103-A-1   not a letter code and a number         │
├───────────────────────────────────────────────────────────────────┤
│                                   [Apply 42]   [Cancel]            │
└───────────────────────────────────────────────────────────────────┘
```

| Element | Does |
| --- | --- |
| `ecad.renumber.dialog` | CADCraft window, square corners, `cad.panel`; one at a time; Esc = Cancel |
| `ecad.renumber.kind.devices` / `.cables` / `.wires` / `.all` | Radio. Changing it recomputes the preview |
| `ecad.renumber.scope.all` / `.selection` / `.prefix` / `.folder` / `.provisional` | Radio with a count. **Sel** is disabled with `(0)` when nothing is selected; **Prov** shows `(0)` and still works (an empty plan) |
| `ecad.renumber.prefix` | Combo of the prefixes in use (`-K`, `-Q`…), or the potentials for wires |
| `ecad.renumber.folder` | Combo of the folder paths (`Control / Motors`) |
| `ecad.renumber.start`, `ecad.renumber.digits` | Integer fields (start 1–999 999 999, digits 1–6). Bad input: 1 px `ecad.orphan` outline, `Start is a whole number from 1.`, no preview |
| `ecad.renumber.newtags` | Check box **Also for new tags** (digits) |
| `ecad.renumber.rows`, `.row.<i>` | Virtualised list. Clicking a row goes to the anchor as Checks does (022 §8), dialog stays open |
| `ecad.renumber.apply` | `Apply <n>`; disabled at 0 (`Nothing to change.`) |
| `ecad.renumber.cancel` | Closes, writes nothing |

**Row marks** (§10): `→` changes, `F` fixed (kept), `=` unchanged, `–` skipped. Rows that change
come first, then fixed, then same, then skipped, each group in drawing order. For **All** kinds,
rows are grouped `Dev`, `Cbl`, `Wire`.

**Preview and apply.** The preview is computed when the dialog opens and when an option changes,
never on commits. It records the project's change count. **Apply** runs `renumber {…, based_on:
<change count>}`. If the project changed meanwhile (an MCP edit, another window), the command
refuses with `The project changed since the preview; check the new list and Apply again.`, and the
dialog recomputes. Apply closes the dialog and echoes `Renumbered 42 devices (3 fixed kept). U
undoes it.` Undo label: `Renumber devices` / `Renumber cables` / `Renumber wires` / `Renumber`.

**States.** Read-only project, revision or version view: the dialog opens as a preview with Apply
hidden and the line `Read-only: preview only.` Busy (another command running): **Renumber…** is
disabled, as other ECAD tools are.

## 4. Fixed

| Kind | Stored as | Set by |
| --- | --- | --- |
| Device | component property `tag_fixed = "yes"` (absent = not fixed) | the **Fixed** box beside Tag (Properties panel, Devices tab); `setprop {component, key: "tag_fixed", value: "yes" \| null}` |
| Cable | cable property `tag_fixed = "yes"` | the same, `ECAD · CABLE` section; `setprop {cable, …}` |
| Wire | 022's `wire_number_fixed` (unchanged) | 022 |

- **Typing a tag fixes it** (Q4), as typing a wire number does (022). The tag and the flag are one
  transaction (`Set tag`). Automatic tags, copies and Finalise never fix.
- A provisional tag cannot be fixed: `A provisional tag can't be fixed; give it a number first.`
- Fixed is shown as a small `F` after the tag in the Devices tab and in the Properties panel's Tag
  row (`cad.text_dim`). It is **not drawn** on the sheet, so prints stay clean.
- Unticking releases the flag. The tag stays.
- In a merge, `tag_fixed` is an ordinary property (020 §5.1).

## 5. Provisional tags

### 5.1 Setting

**Project Settings → Numbering**: a check box **Provisional tags until Finalise**
(`ecad.settings.provisional`), off by default (Q5). Stored as project property
`numbering.provisional = "yes"` (FP2), written by `numbering {provisional: true}` (one
transaction, `Set numbering`). Switching it changes no existing tag.

### 5.2 Form and placement

| Kind | Provisional form | When given |
| --- | --- | --- |
| Device | `-K?3`: prefix, `?`, the next provisional number of that prefix (highest provisional in use + 1, unpadded) | `place` of a new device, copy, `tag: "-K?"` typed |
| Cable | `-W?1` | a new cable (`slash`) without a typed tag |
| Wire | no `wire_number` stored; label `24V-?` (prefix and `?`; `?` alone with no potential) | the numbering pass does not number **new** nets. A wire joining a numbered net still takes its number, and merges and splits keep 022's rules |

A provisional tag is an ordinary `tag` value (`tag::parse` refuses it, so it is compared whole). The
duplicate rule applies to it. It is stored canonical (`-K?3`, upper case, no padding). Typed
`-K?` takes the next provisional; typed `-K?7`, if free, is kept.

**Drawn** like any tag (018 §2.4), in `ecad.provisional`. The same colour is used in the Devices
tab, the Properties panel and the wire label of a provisional net. The `?` is the part that
survives a monochrome print.

### 5.3 Finalise numbering

**Finalise numbering** (`ecad.finalise`, Numbering group; and the Checks rows' button) opens the
Renumber dialog with **All** kinds and **Prov** scope. Start shows `next` (read-only, per prefix),
because each prefix continues after its highest number in use. One transaction, `Finalise
numbering`: the provisional devices and cables get real tags in drawing order, skipping fixed and
taken numbers, and the unnumbered nets are numbered by 022's rules in drawing order. JSON:
`finalise {preview?, based_on?}` = `renumber {kind: "all", scope: "provisional", …}`.

### 5.4 Checks (022 §8)

| Kind | Severity | Row |
| --- | --- | --- |
| Provisional tag (device or cable) | Warning ▲ | `▲ Provisional tag   102-D-3  -K?2` with **Finalise** |
| Unnumbered nets | Warning ▲ when the setting is on, else Info · (022) | `▲ 12 wire numbers provisional` with **Finalise**. One row, not one per net (Q6) |

**Finalise** on a row opens §5.3's dialog, not a direct write. The Show filter gains
`Provisional`.

### 5.5 Issue Revision

`issuerevision` (019 §7.2; the History tab's Issue, 020 §2.5.2) with provisional items present
shows, before the usual confirmation:

```
┌ Issue Rev B ───────────────────────────────────────────┐
│ 3 provisional tags and 12 wire numbers are not final:  │
│ -K?1  -K?2  -W?1   · 12 nets (24V ×8, 0V ×4)           │
│                                                        │
│ [Finalise numbering now]  [Issue anyway]  [Cancel]     │
└────────────────────────────────────────────────────────┘
```

- **Finalise numbering now** (`ecad.issue.finalise`) opens §5.3's dialog. Applying it is its own
  transaction; the Issue confirmation then follows (two transactions, two `u`).
- **Issue anyway** (`ecad.issue.anyway`) goes straight to the confirmation. The issue echo adds
  `(3 provisional tags issued)`.
- JSON: `issuerevision {…, provisional?: "finalise" | "issue"}`. Without it, and with provisional
  items present, the command refuses with the ways forward, as `wirenumber` does: `3 provisional
  tags and 12 wire numbers are not final. Give provisional: "finalise" (number them first, in
  one transaction before the issue) or "issue" (issue as they are).` `"finalise"` writes two
  transactions, Finalise then Issue.

## 6. Cable tags

- A new cable gets `-W<next>` (padded) or `-W?n`. The prefix is `tag_prefixes["cable"]`, else
  `W`. A tag given to `slash` is used as typed, normalised as device tags are.
- **One namespace:** device and cable tags share the high-water mark and the duplicate rule. A
  device `-W01` and a cable `-W01` clash (Q7). `note_ops` must also count `CreateCable` and
  `DeleteCable`.
- Old projects' cable tags (`W0`, `C1`) are kept. A pair of duplicates already present is a Checks
  error, `Two cables share W1`, not a refusal at open.

## 7. Swap: a tag that is taken

Applies when a device's or cable's tag is set to one another object holds, in every place a tag is
typed: Properties panel, Devices tab, Device Properties, `setprop`.

### 7.1 Choices, in this order

| # | Choice | Writes (one transaction) | Echo |
| --- | --- | --- | --- |
| 1 | **Swap** (`ecad.tagclash.swap`) | `SetProperty` tag on both objects; `tag_fixed` on the one typed (§4); the other keeps its own flag | `Swapped: this is -K03, the other is now -K05.` |
| 2 | **Make it the same device** (`ecad.tagclash.merge`) / **…cable** | 018's `plan_merge`; for cables, `RemoveCableMember` / `AddCableMember` per member, then `DeleteCable` | `-K05 is now part of -K03 (3 symbols on 101, 102).` |
| 3 | **Use -K08** (`ecad.tagclash.next`) | `SetProperty` tag = next free, fixed | `-K05 is now -K08.` |

- **Panel and tab:** the refusal box under the field shows the line
  `-K03 is used by -K03 (Contactor / relay coil, 101-C-1).` and the three buttons in a row, Swap
  first and in `cad.accent`. Esc puts the field back; nothing is written until a button is
  clicked.
- **Command line:** `-K03 is used by -K03 (Contactor / relay coil, 101-C-1). [Swap/Merge/Next]
  <Swap>:`
- **JSON:** `setprop {…, key: "tag", value, conflict?: "swap" | "merge" | "next"}`. Without
  `conflict`, it refuses naming all three (022's wording pattern). `merge: true` stays accepted as
  `conflict: "merge"`.

### 7.2 Edge cases

| Situation | Behaviour |
| --- | --- |
| The holder is fixed | Swap still offered, labelled `Swap (-K03 is fixed)`; the holder keeps its flag on its new tag |
| The typed object is provisional | Swap gives the holder `-K?2`; echo says `the other is now provisional -K?2` |
| Holder is the other kind (device vs cable) | Swap and Merge disabled with the reason `-W01 is a cable`; **Use -K08** remains |
| Merge refused (018 §3.1 label clash) | Merge disabled, its reason under it (`-K03 already has a coil.`); Swap and Next remain |
| Wires | Unchanged: 022's swap / another / merge in `wirenumber` |

## 8. Merge: Make them one device (020 §5.3)

The tag-conflict row gains a third choice:

| Row | Choices |
| --- | --- |
| `-K05 · main and the branch each added a device -K05` | **Renumber the branch's to -K07** · **Renumber main's to -K07** · **Make them one device** (`ecad.merge.conflict.<i>.one`) |
| `-W03 · main and the branch each added a cable -W03` | the same, with **Make them one cable** |

- **Make them one device:** in the merge transaction, 018's `plan_merge` joins the branch's device
  into main's. Its symbols and connection points move to main's device, and wire ends follow their
  points. Where a property differs, main's value is kept. The row lists the differences:
  `description: main keeps "Motor contactor" (branch "Contactor")`. The choice is refused, and
  greyed with the reason, when the devices cannot be one (a label clash, two coils); the renumber
  choices remain. **Keep … for all** never picks it.
- **Provisional duplicates are not conflicts:** two sides each adding `-K?1` give the branch's the
  next provisional number silently. The "After the merge" line counts them: `2 provisional tags
  renumbered`.
- JSON: the merge `choices` accept `"one"` for a tag row (`Choice::MakeOne`, FP5).

## 10. Labels: electrical shorthand, small, spaced

The owner's rule, applied to everything this spec adds (Q11):
- **Words:** shorthand a panel builder reads at a glance: `Dev`, `Cbl`, `Wire`, `Sel`, `Prov`,
  `Desc`, `At` (in the project's reference style, `101-C-1`), `F`, `→`, `-K?3`, `24V-?`. No

- **Small:** CADCraft's small text size in the dialog and rows; monospace for tags and positions.
- **Spaced:** 8 px between controls, 12 px between groups. Columns of the preview align (Old 8,

## 11. Cost and update maps

**Renumber cost (estimates for the worker to measure).** The planner reads the tag index (018),
one anchor per item (subject index) and the page's grid. It sorts O(n log n) and writes one op per
changed item. No document clone, no scan beyond the items in scope.

| Bench row (`cargo xtask bench`) | Large tier today (5,000 dev, 2,500 cbl, 25,000 wires) | At 10,000 devices | Target |
| --- | --- | --- | --- |
| `renumprev ms`: preview, devices, all | ≈ 10 ms | ≈ 20 ms | ≤ 50 ms |
| `renum ms`: apply, devices, all (≈ 5,000 `SetProperty`) | ≈ 40 ms | ≈ 80 ms | ≤ 150 ms; linear in n |
| `renumw ms`: apply, wires, all (25,000 conductor writes) | ≈ 150 ms | — | ≤ 400 ms |
| `renumu ms`: undo of `renum` | ≈ `renum` | | ≤ `renum` × 1.5 |
| `swap ms` | ≈ a tag rename (about 1 ms) | | ≤ 2 ms |
| `finalise ms`: 50 provisional devices | ≈ 2 ms | | ≤ 5 ms |

A whole-project renumber adds about 100 bytes of log per changed tag: about 0.5 MB on the large
tier, and 2.5 MB for all wires. The saving cost is reported by the bench row as written.

**Update maps.** Each view batches per transaction: a 5,000-op renumber is one refresh of each
view, not 5,000.

| Op | Tags on sheet | Devices tab | Properties panel | Checks (provisional rows) | References, mirrors (025) |
| --- | --- | --- | --- | --- | --- |
| `SetProperty` component or cable `tag` | that object's representations on the page on screen; other pages marked stale | that row; one re-sort per transaction | if selected | that object's row | 025's map for a tag change (not changed here) |
| `SetProperty` `tag_fixed` | none | that row's `F` | if selected | none | none |
| `SetProperty` project `numbering.provisional` | none | none | none | the wire summary row's severity | none |
| `SetProperty` project `numbering.high.*` | none | none | none | none | none |
| `CreateComponent` / `DeleteComponent` / `CreateCable` / `DeleteCable` | as 018 / 004 | as 016 | — | that object's row | 025 |
| `Link` / `Unlink` / `ModifyRepresentation`, `ModifyItem` of a provisional item's anchor | as today | as 016 | — | that row's `At` | 025 |
| `AddPage` / `RemovePage`, page number, folder | as 019 | `At` texts | — | `At` texts of rows on that page | 025 |
| Wire number writes | 022 | none | 022 | the summary row's count | none |
| Everything else | none | none | none | none | none |

The Renumber preview is built on request only (open, option change, Apply check); it follows no
commits.

## 12. Format and ops proposals (the overseer decides)

**No new op.** Everything is `SetProperty`, `SetProjectSettings` and existing component and cable
ops.

- **FP1. Fixed flag:** component and cable property `tag_fixed = "yes"`, absent when not fixed.
  Same pattern as `wire_number_fixed`. No format change.
- **FP2. Provisional setting:** project property `numbering.provisional = "yes"` (019 FP1),
  absent = off. *Alternative:* a `ProjectSettings.numbering { provisional }` field through
  `SetProjectSettings`, additive and omitted at default, with an `ecad-file` mirror change. The
  project property needs no type change.
- **FP3. Provisional forms:** a provisional tag is a `tag` value `-<P>?<n>`. A provisional net has
  no `wire_number`, as 022's unnumbered nets. Adds `tag::provisional(t) -> Option<(prefix, n)>`.
  No format change.
- **FP4. High-water reset (needs a ruling).** Renumber and Finalise write project property
  `numbering.high.<P> = "<n>"` last in their transaction. `tag::note_ops` treats it as "set
  high[P] = n" (overwrite, not max), so the next automatic tag follows the renumbered set. Undo
  re-applies the old tags, which raise the mark again. Old builds ignore the key and give higher
  numbers, which is harmless. Snapshots (021) carry the resulting mark as today. *Without it,*
  after renumbering `-K01…-K40` in a project whose top was `-K300`, the next device is `-K301`.
- **FP5. Merge choice `one`:** `Choice::MakeOne` in `ecad-model::merge` and `"one"` in the merge
  command's JSON. Not stored: the merge transaction records ops (020b `TxKind::Merge`).
- **FP6. Tag uniqueness on the end state:** the command layer checks duplicates on the
  transaction's result (permutations such as `-K01 ↔ -K02` are legal mid-transaction). If any
  check runs per op, the worker orders the ops through a free placeholder instead. No format
  change either way.
- **FP7. Cable tags in `note_ops`:** count `CreateCable` and `DeleteCable` tags. Behaviour only.

## 17. Decisions (2026-11-11)

- **Owner:** every §15 recommendation is accepted, Q1–Q13. For Q11 the labels point means §10 as
  written (dialog and list words, small text, 8/12 px spacing, nothing new drawn for fixed); the
  drawn tag and wire-number texts belong to the look-and-feel pass.
- **Overseer:** FP1–FP7 approved as written:
  - FP1 `tag_fixed = "yes"` on components and cables;
  - FP2 the project property `numbering.provisional = "yes"`;
  - FP3 the provisional form `-K?n`;
  - FP4 the high-water reset through project property `numbering.high.<P>`;
  - FP5 `Choice::MakeOne` (`"one"` in the merge JSON);
  - FP6 tag uniqueness checked on the transaction's end state;
  - FP7 cable tags counted by `tag::note_ops` (`CreateCable`, `DeleteCable`).
- **Tester 026 fixes (2026-11-11):**
  - FP4's value is `"<n>;<was>;<generation>"` (`tag::reset_value`): the new mark, the mark it
    replaced, and one more than the generation it overwrites. A write to a newer generation is a
    reset (mark = n); a write back to an older one or to nothing is an undo, and the mark becomes
    at least `was`, so no number held before or since the reset is given again. Every renumber
    that changes tags writes it, even when `n` is the stored number. A plain number (earlier
    builds of this branch) still reads as a reset.
  - Overseer ruling: a provisional tag never counts as fixed. Finalise numbers it and drops the
    flag; a merge that would leave a provisional tag fixed drops the flag.
  - The MCP gate takes an issue back with `undoissue`, also for a plain `issuerevision` (019).
- **Reviewer 026 fixes (PR #52, 2026-11-11):**
  - In a merge's tag row, the source's holder is always the one whose tag the merge brought from
    the source, also an object both sides have that the source renamed: `renumber_branch`
    renumbers it, and `one` joins it into the target's.
  - Make them one cable moves the cable's slash drawings (one join, `merge::join_cables`, used by
    the merge and by `setprop`'s merge choice).
  - MCP: two transactions only when the call is the line's first write and it recorded exactly
    Finalise, then the issue.
  - `numbering.high.<P>` is internal: never merged, no conflict row; the target's value stays.
