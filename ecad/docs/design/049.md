**Words.** *Continuation arrow* (or *arrow*): 022's tagless component, `kind = continuation`, that
joins its net to every arrow with the same name. *Other end*: another arrow with the same name.
*Caption*: a short text shared by arrows that go to the same place. *Caption run*: the arrows on
one page drawn under one bracket. Not to be confused with 033's **continuation sheets** (a
generated report's pages 400, 401): this design never calls those anything but "continuation
sheets", and never calls an arrow a sheet.

## 1. Goal

Every continuation arrow shows where its other ends are, worked out live from the reference index
and never typed, and arrows that go to the same place are grouped under one caption.

## 2. What an arrow shows

### 2.1 Direction and tip

The arrow points from its connection point (local (0, 0)) to its tip (local (0, −5)); its
**direction** is that vector after the placement's rotation and mirror, snapped to one of four
(down, up, left, right; 022 allows only quarter turns). The **tip** is the placed (0, −5).

### 2.2 The other ends

The other ends of arrow `a` are the other members of its name group (§6), each located by 025's
`Places::text` at its symbol's insertion point (`anchor`), in the project's reference style
(`102-C-2`, or `/102.C` in the 010 style). They are sorted by **book position, then column, then
row**, then component ID (so the order is total). An end whose page is not in the book, or that
cannot be located, shows `?` (025's unlocated text) and sorts last. An end on the **same page**
is listed like any other (the pack does this).

Up to `continuation.places.max` (default 3) are shown, then `+n` for the rest. The sorted list of
a group is worked out **once per group per derivation** (one `Places` per derivation, which builds
the book at most once) and each member's text is that list minus itself: O(m log m) for a group of
m, not O(m²), and never O(pages) per arrow.

### 2.3 Where the text goes (owner question Q1)

One text, kind `Reference` (031's size, weight and font), colour `ecad.reference` (ACI 6, as
today), placed **past the tip, reading along the wire**:

| Direction | Anchor | Rotation | Alignment |
| --- | --- | --- | --- |
| down | tip + (0, −g) | 90° | right-aligned (its end at the anchor, so it reads upward towards the tip), middle |
| up | tip + (0, +g) | 90° | left-aligned, middle |
| right | tip + (+g, 0) | 0° | left-aligned, middle |
| left | tip + (−g, 0) | 0° | right-aligned, middle |

`g` = `continuation.reference.gap` (default 1.0 mm). Text is never upside down. This replaces
022's horizontal text under the name: with the name hidden (031's default) the reference stands
alone at the tip, as in the pack, and ten arrows 5 mm apart no longer overlap. The name, when shown,
stays where 022 put it.

The text is a reference part (`xref::Part`, `Shape::Text` with `rotation`, FP3): it is hit,
hovered and refused like 025's contact texts. An arrow with no other end shows nothing (022's rule;
Checks has `lonely-continuation`).

## 3. Captions

### 3.1 The property (FP1)

`caption` on a continuation component: trimmed, 1–80 characters, no control characters (a typed
line break is refused; wrapping is automatic, §3.2). Empty or `null` removes the property. Refusals:

- `A caption is 1 to 80 characters on one line.`
- `Only continuation arrows have a caption; -K01 is a device.` (any other component).

A caption is display only: it joins nothing, changes no net and is not compared across pages.
Each end has its own caption (the pack writes `TO CONTROL SUPPLY` at one end and a different text at
the other); nothing is derived from the other end's caption (Q9).

### 3.2 Caption runs and the bracket

On each page, the arrows with a caption are grouped into **runs**: same caption (exact, after
trimming), same direction, ordered along the axis across the direction (x for up and down arrows,
y for left and right), and a new run starts where the gap between two neighbouring tips along that
axis is more than `continuation.caption.run_gap` (default 20 mm). A run may be one arrow.

For each run, drawn as reference parts of its lowest-ID member's representation:

- **Bracket:** a line across the direction, at the distance past the tips where the farthest
  reference text of the run ends (measured with 031's text measure), plus
  `continuation.caption.gap` (default 1.5 mm). It spans from the first arrow to the last, plus
  1.5 mm each side, with an end tick of `continuation.caption.tick` (default 1.5 mm) at each end,
  pointing back towards the arrows. Line `ecad.continuation-bracket` (ByLayer on `ECAD-TAGS`, thin,
  as the arrow).
- **Caption text:** kind `ContinuationCaption` (FP2; default 2.5 mm, regular), colour ByLayer,
  **always horizontal**, centred on the bracket and past it (under it for down arrows, above it
  for up arrows; beside it, middle-aligned, for left and right). It wraps at word breaks to the
  bracket's length or 25 mm, whichever is longer, at most 3 lines; beyond that the last line ends
  with `…` (hover shows the whole caption).

Arrows without a caption are never in a run. The bracket and caption are derived, never stored,
and refused as edits like every reference text.

## 4. On the page

`xref::parts_on_page(doc, page)` (already the source of contact texts, tables and connector texts)
adds `continuations::parts_on_page(doc, places, page)`: for each arrow on the page its reference
text, then for each run its bracket and caption. `wires::continuation_texts` keeps only the name.
States:

| State | What shows |
| --- | --- |
| Arrow with other ends | Reference text past the tip; bracket and caption if captioned |
| Lonely arrow | No reference text; bracket and caption if captioned; Checks Info as today |
| Other end not locatable | `?` in its sorted place, `ecad.reference` colour (Q12) |
| Name hidden (031 default) | Only the reference text and the caption |
| Read-only project or revision | Same drawing; `contcaption` and the Caption row refused/disabled with 042's read-only words |

## 5. Commands and reading

### 5.1 `contcaption` (new; writes)

- **JSON:** `{continuations: [<component hex>, …] (1–2000), caption: "<text>" | null}` →
  `{changed: n, unchanged: n, caption}`. One transaction of `SetProperty` ops (only for arrows whose
  caption changes), label `Caption <text>` or `Remove caption`. Refusals: any ID that is not a
  continuation (named), an empty list, more than 2000, §3.1's text rules.
- **Interactive** (label `Caption Continuations`, command line `contcaption`; ECAD specs carry no
  menu path, and 049 adds no wheel slot, so `actions.rs` is untouched):
  1. `Select continuation arrows:` (pick, window or crossing, Enter to finish). Non-arrows in the
     selection are ignored and counted: `3 arrows selected (2 other objects ignored).` None:
     `No continuation arrows selected.` and the prompt repeats.
  2. `Caption <TO CONTROL SUPPLY> or [Remove]:` with the session's last caption as default (none the
     first time: `Caption or [Remove]:`). Enter accepts the default; `R` removes.
  3. Commits; the line says `Captioned 3 arrows "TO CONTROL SUPPLY".` Esc at any step writes nothing.
- `place {symbol: "continuation", …, caption?}` and `setprop {object, key: "caption", value}` take
  the same rules. The interactive Place asks only for the name, as today (Q5).

### 5.2 Properties and inspector (019 §8, 042)

A continuation selected shows, under 022's **Name** row:

| Row | Editing |
| --- | --- |
| **Caption** | text, placeholder `e.g. TO CONTROL SUPPLY`; one `setprop`, one `u`; refusals under the field |
| **Other ends** (read-only) | every other end, sorted (§2.2), `102-C-2  page 102 "Supply"`, each with **Go to** |

A multiple selection of arrows shows **Caption** once (blank when they differ); an edit is one
`contcaption`.

### 5.3 Go to Reference (`refgoto`, 025 §5.3)

Source: an arrow, its reference text, or its bracket or caption (the run's arrows). Without
`target`, goes to the **first** other end; invoked again on the same source within the session it
goes to the next, wrapping. With `target` (a member of the group), goes there. The wheel's Go to
target slot works on the reference text, which maps to `ObjectKind::Reference` like 025's texts
(the worker confirms in `interact/kind.rs`; no `actions.rs` edit expected). Records nothing.

### 5.4 Hover lens

On an arrow or its text: `Continuation 24V: 3 other ends`, then up to 6 lines `102-C-2  page 102
"Supply"`, then `+N more`. With a caption, a first line `Caption: TO CONTROL SUPPLY`. On a
lonely arrow: `Continuation 24V: no other end`.

### 5.5 `xrefs` (025 §5.4)

Rows of kind `continuation`: `{source, source_page, target, target_page, kind: "continuation",
text}`, one per (arrow, other end), filtered by `page` and `component` like the others, paged by
`limit`/`after`. `xrefs {component: <arrow>}` lists that arrow's other ends.

## 6. On the reference index (FP4)

- **Group:** `Group::Continuation(ComponentId)`, keyed by the **lowest component ID** among the
  name's arrows (from `continuations_named`, already in ID order). The key is `Copy` and equal in a
  rebuild, so `verify` still compares whole indexes. When that arrow is deleted or renamed, the
  group is remade under the next lowest ID (§8).
- **Member:** each arrow's symbol representation, class `Class::Arrow`. An arrow drawn twice (a
  hostile file) has both representations as members.
- **Edges: implicit.** `targets(s)` of an arrow is `members(group) − s`, and `sources(t)` the same;
  nothing is stored per edge. A name with 10 000 arrows costs 10 000 members, not 10⁸ edges.
  `sizes()` counts implicit edges as m(m−1) for the edges figure, computed, not stored.
- **Build** on open, reload, branch switch and revision open: one pass over `continuation_names`
  (O(arrows)). Kept per commit by §8.

## 8. Update maps (`ecad/CLAUDE.md`, "Derived views scale with what changed")

### 8.1 The index and the texts (joins 025 §6)

**Refresh a group** means deriving its members' texts and its runs again and comparing them per
page with before (the `Watch` way); pages whose parts differ are redrawn if on screen, otherwise
nothing (other pages project when shown). **Runs of a page** means the caption runs on that page
only.

| Op (kind, target) | Index | Refreshed |
| --- | --- | --- |
| `CreateComponent` / `DeleteComponent` of a continuation | its name's group remade (key may change) | that group, before and after |
| `SetProperty` component `name` or `kind` | old and new name groups remade | both groups (their members' texts), and the runs of the arrow's page |
| `SetProperty` component `caption` | nothing | the runs of the arrow's pages only |
| `LinkRepresentation` / `UnlinkRepresentation` / `ModifyRepresentation` of an arrow | member added, removed or moved; group remade | the group; runs of the old and new pages |
| `ModifyItem` / `RemoveItem` of an arrow's symbol item | nothing | the group when the arrow's place or page changed (F1); runs of the old and new pages; the arrow's own text when its direction changed |
| `SetProperty` page `number` or `sheet` | nothing | every group with a member on that page (members on the page through the page index ∩ `member`) |
| `SetProperty` page folder, `AddPage`, `RemovePage`, folder ops | nothing | as above, for the pages in `book::positions_changed` |
| `SetProjectSettings` changing `reference_style`, `sheet` or `length_unit` | nothing | the wide case, as 025: every page with an arrow (from the index, no item scan) |
| `SetProperty` project `continuation.*`, or `text.reference.*` / `text.continuation_caption.*` | nothing | every page with an arrow (`places.max`, `reference.gap`) or with a captioned arrow (the `caption.*` keys and the caption text kind) |
| `EmbedDefinition` / `RemoveDefinition` of the continuation starter | classes of its components again | their groups |
| `AttachEnd`, conductor ops, wire numbers, cables, devices, terminals, layers, versions | nothing | nothing: an arrow's text does not depend on its wires |
| every other op | nothing | nothing |

### 8.2 `pages_touched` (project.rs)

The three continuation arms stop returning `None`: a created or deleted arrow touches its own
page(s) (its representation ops name them already), and `name`/`kind` touch the arrow's pages. The
other ends' pages come from `Watch`'s outcome (§8.1), as 025's device pages do. After 049 no
continuation op makes a commit "any page".

### 8.3 Other views

- **Checks:** unchanged (022's per-name scope already covers `lonely-continuation`).
- **Properties and hover:** copies built on show, refreshed when the touched set meets the

- **Devices tab, wire list, terminal plan, strip pages, BOM:** unchanged; none shows other ends.

## 12. Format proposals (for the overseer)

- **FP1. Component property `caption`** on a continuation (§3.1). No op, no record field; free-form
  properties already carry `name` and `kind`. Validated where `name` is.
- **FP2. Registry area `continuation`** (§7) and the text kind **`continuation_caption`** in lane
  T's `defaults/text.rs` and `text_style.rs` (one variant). The `defaults/mod.rs` chain line meets
  044's and 047's (047's FP6 asks how to order them).
- **FP3. `xref::Shape::Text` gains `rotation: f64`** (radians, 0 for every existing part). Every
  `Shape::Text` constructor gets `rotation: 0.0`; 044's connector texts and 045's (if any) are
  touched by one field each. Needed for §2.3.
- **FP4. `Group::Continuation(ComponentId)` with implicit edges** (§6). Keyed by the lowest member
  ID so `Group` stays `Copy` and rebuild-equal. Alternative: drop `Copy` and key by the name string,
  which touches every `Group` user; not recommended.
