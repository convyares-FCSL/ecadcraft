## 1. Goal and words

The owner opens the trial, asks Claude to draw, and watches it appear, with every agent step
recorded as the agent's and nothing of theirs ever recorded as the agent's.

- **Agent access**: the trial's preference (Off, Read only, Read and change; port).
- **Bridge session**: one `ecad-mcp` process connected to the trial, from `ecad.hello` to
  `ecad.bye` (or 10 minutes without a call). It has a random 64-bit id chosen by `ecad-mcp`, the
  agent name, whether the server allows writes (`--write`), and the list of transactions it
  recorded (`seq`s on their branch).
- **Call**: one MCP tool call. A **request line** (a JSON-RPC message or batch) is one call for the
  transaction cap, as in 011.
- **Writer**: the one bridge session allowed to change the project at a time (§5.5).

## 2. The pieces

```
Claude Code ──stdio JSON-RPC──▶ ecad-mcp --connect 47823
                                  │ Mode::Undecided → probe 127.0.0.1:47823
                                  ├─ nothing answers → Headless (011, unchanged behaviour)
                                  └─ answers → Bridged: Remote (token, caps, reconnect)
                                          │ JSON lines: ecad.hello / ecad.execute / ecad.tool /
                                          │ ecad.bye + allowlisted reads
                                          ▼
ecad-trial  listener thread (upstream control_server.rs, included)
            └─ bounded queue (64) ─▶ Trial::logic, top of every frame:
                 author check → drain → busy rule → route:
                   ecad.*            → gate.rs (same code as headless) on cad.session + project
                   allowlisted reads → CadApp's own control channel (screenshot, render, inspect)
                   anything else     → refused, not-run
                 → banner state updated → repaint
```

`gate.rs` is the single place where the policy, the caps and the author live. The headless server
and the trial call the same functions; only the session and project they pass differ.

## 3. Agent access preference (brief scope 1; owner question 18)

### 3.1 Stored

`agent-access.json` in the ECAD settings folder (the folder `cable-views.json` uses), format
`ecad-agent-access/1`:

```json
{"format": "ecad-agent-access/1", "mode": "off", "port": 47823}
```

`mode`: `off` | `read` | `write`. `port`: 1024–65535. Missing, unreadable, over 4 KiB, or an
unknown format or mode reads as **off** with one line in the command history
(*"Agent access settings could not be read; agent access is off."*). Written atomically
(write-then-rename) like `cable-views.json`.

`--control PORT` on the trial's command line turns access on for that run only, as **Read and
change** on `PORT`, and writes nothing. `--control` with the preference on and a different port
uses the flag's port. `ECAD_CONTROL_PORT` is **not** read (an environment variable is too easy to
inherit unnoticed; upstream's `CADCRAFT_CONTROL_PORT` is ignored by the trial too).

### 3.2 Where it is set

A row at the top of the **ECAD Dev** tab of Tool Sets (until the UI shell, item 1.5, gives settings
a home; Carl's redesign decides its final place):

```
Agent access  [ Off            ▾]  Port [47823]   ● Listening on 127.0.0.1:47823
```

- **Mode** combo: `Off`, `Read only`, `Read and change`. Element `agent.access.mode`.
- **Port** field: digits only, applied on Enter or focus loss; invalid shows *"1024–65535"* in
  `ecad.check-warning` under the field and keeps the old port. Element `agent.access.port`.
- **Status** text, element `agent.access.status`, `cad.text_dim`:
  - `Off` — nothing listens.
  - `● Listening on 127.0.0.1:47823` — dot in `cad.accent`.
  - `● Port 47823 is in use by another program; agent access is off in this window` — dot in
    `ecad.check-warning`. (The listener could not bind; detected because its receiver is
    disconnected at the first drain.)
  - `● Listening on 127.0.0.1:47823 (this run only, --control)` — when the flag turned it on; the
    combo shows the run's mode and is disabled, tooltip *"Set by --control for this run."*

Changing the mode takes effect at once: Off → On starts the listener (§4.1); On → Off makes the
drain refuse everything (*"agent access was turned off in the ECAD window"*, `not-run`), ends every
bridge session (banner goes), and the listener keeps its socket until the trial exits (upstream's
server has no stop; nothing is answered). Changing the port while on asks for a restart:
*"The new port is used the next time ECAD starts."* Read and change → Read only takes effect at the
next call.

### 3.3 The `agentaccess` command

Everything is a command: `agentaccess {mode?, port?}` reads (no fields) or sets the preference and
replies `{mode, port, listening, status}`. Menu path: none (ECAD Dev only). It is in
`policy::NEVER_COMMANDS`: an agent can never turn its own access on, widen it, or move the port,
headless or bridged; the refusal says *"Agent access is set by the person in the ECAD window."*

## 4. The port (brief scope 2)

### 4.1 Transport

The trial uses **upstream's own control server file unchanged**, included by path (§0, Q2):
same bounds (16 connections, 256 MiB line, 64 queued, 10 min idle, 60 s reply wait), same token
file `cadcraft-control-<port>.token` (owner-only; `Remote` reads it), same `not-run` /
`may-have-run` replies. Bound to `127.0.0.1` only. Started once per trial process, the first time
access is on. The token file is revoked (`control_token::revoke`) when the trial exits.

The trial never calls `CadApp::with_control` with the listener's receiver: CadApp's own channel is
fed only by the trial's drain, with the allowlisted methods (§4.3), so `cmdline.*`, `ui.click` and
the rest can never reach CadApp from the port.

### 4.2 ECAD methods (documented in `docs/control-protocol-ecad.md`)

Every `ecad.*` request carries `session` (16 hex digits) and the agent `name`; `ecad-mcp` sends
them on every call, so authorship never depends on connection state.

| Method | Params | Reply `result` |
|---|---|---|
| `ecad.hello` | `{session, name, write, client_version}` | `{writes: bool, why?: text, project: {name, file}, writer: bool, app_version}` |
| `ecad.execute` | `{session, name, line, command, params}` | 011's `execute` result with `ecadTransactions` |
| `ecad.tool` | `{session, name, line, tool, arguments}` | the tool's MCP result (`ecad_project`, `ecad_history`, `ecad_inspect`, `save`, `ecad_connection`) |
| `ecad.bye` | `{session}` | `{}` |

`line` is a counter per request line in `ecad-mcp`; the gate counts transactions per
`(session, line)` and forgets the previous line when a new one starts. An `ecad.execute` or
`ecad.tool` whose `session` never said hello is refused (*"say ecad.hello first"*, `not-run`).
`name` is passed through `agent_name` (011) on the trial side as well; a name that differs from the
hello's is refused.

### 4.3 Allowlist of upstream methods

Forwarded unchanged to CadApp's own channel, then answered by upstream's `control::handle`:
`drawing.inspect`, `engine.commands`, `ui.render` (without `path`: a `path` is refused as in 011),
`ui.screenshot` (without `path`: the reply is the PNG inline; a `path` is refused), `ping`,
`control.methods` (answered by the trial with this table only).

Everything else is refused with `{"ok": false, "error": "not offered over ECAD's port: <why>",
"state": "not-run"}`; `<why>` reuses 011's `not_offered` text (`cmdline.*`: *"ECAD changes go
through execute only"*; `app.open`/`app.save`: *"files stay with the person"*; `ui.*` input: *"the
agent does not use the person's mouse and keyboard"*).

## 5. The app-side write gate (brief scope 3)

### 5.1 One gate, two hosts

`gate.rs` holds what `State` holds today minus the session and project, and takes them per call:

```
Gate::execute(&mut self, s: &mut Session, p: &ProjectHandle, call: &Call, command, params)
Gate::tool(&mut self, s, p, call, tool, arguments)
Call { agent: String, write_allowed: bool, line: u64, owned: &mut OwnedSteps }
```

Headless: one `Gate`, one `Call` per request line, `write_allowed = --write`, the session is the
headless one. Bridged: the trial keeps one `Gate` and, per bridge session, its `OwnedSteps`;
`write_allowed = preference is write ∧ hello.write ∧ this session is the writer ∧ not paused`.
The result is that every refusal text, cap and roll-back over the bridge is byte-identical to
headless for the same project state; the contract tests compare the two (§12).

The command runs through `Session::execute`, not `CadApp::run`, so UI-only commands (`UI_COMMANDS`)
are unknown to the agent as they are headless. The trial then echoes one line in the command
history: `Agent claude-code: WIRE  #57 "Wire W12"` (or `… refused: <first line>`), `cad.text_dim`.

### 5.2 Author per call

```
let scope = AuthorScope::enter(p, Author::Agent(name))?;   // sets project.author, tx_budget
let r = catch_unwind(AssertUnwindSafe(|| gate.run(...)));
drop(scope);                                               // restores Author::User, tx_budget None
```

- `AuthorScope::enter` fails closed: if `configure` fails, the call is refused (`UNREADABLE`) and
  nothing runs.
- `Drop` restores `Author::User` and `tx_budget = None`; it runs on success, refusal, error and
  unwind. If restoring fails, the trial turns agent access **off for this run**, shows the banner
  in its error state (§7.2) and logs *"Agent access stopped: the author could not be reset."*
- **Frame invariant:** at the top of every `Trial::logic`, before any input of the frame is
  handled, the trial checks `project.author == Author::User` and `tx_budget == None`; if not, it
  restores them and records a diagnostic (one command-history line, and a counter the tests read).
  The person's input can only arrive inside `logic`/`ui`, after this check.
- Headless keeps setting the author once (only the agent edits there), through the same scope.

### 5.3 Caps

Unchanged numbers: `MAX_REQUEST_BYTES` and `MAX_BATCH` apply in `ecad-mcp` (the stdio side, before
anything is sent), `MAX_TRANSACTIONS_PER_CALL` and `transactions_allowed` in the gate per
`(session, line)`, with 011's roll-back and wording. The port's own bounds are upstream's (§4.1).
Additionally the trial answers at most **8 agent requests per frame** (`MAX_AGENT_CALLS_PER_FRAME`)
so a burst cannot freeze the window; the rest wait for the next frame (the window requests a
repaint while any are queued).

### 5.4 Read-only and writes off

Refusals, in the order checked: access off; read-only preference (*"Agent access in the ECAD window
is Read only."*); server without `--write` (011's `WRITES_OFF`); not the writer (§5.5); paused
(§7.3); project read-only (011's `project_read_only`). Each is `not-run` on the wire and the
history is unchanged.

### 5.5 One writer

The first session whose hello has `write: true`, while access is Read and change, becomes the
**writer**. Others are served as read-only with *"another agent (<name>) is changing this project;
this session can read"* in `ecad.hello.why` and in each refused write. The writer role is released
by `ecad.bye`, 10 minutes without a call, access turned off, or **Disconnect** on the banner (§7.3);
the next session to write after that takes it. (Q4.)

## 6. Calls on the UI thread (brief scope 4)

### 6.1 Where

`Trial::logic`, first thing, before `self.cad.logic(ctx)`:

1. Frame invariant (§5.2).
2. Take up to `MAX_AGENT_CALLS_PER_FRAME` requests from the listener (`try_recv`); skip any whose
   `begin()` is false (the client was told `not-run`).
3. For each: route (§4.2, §4.3). `ecad.*` run the gate synchronously, so the whole call (author
   set, command, cap check, roll-back, author restored) completes inside this frame, before the
   person's input of this frame is processed.
4. Repaint requested. The listener thread calls `ctx.request_repaint()` when it queues, so a
   minimised or occluded window (logic-only frames) still answers.

### 6.2 The busy rule

A **write-capable** request (`ecad.execute`, `ecad.tool` `save`) is held while the person is busy:

| Busy when | Said |
|---|---|
| `session.running` or `session.suspended` is `Some` | *the designer is in the middle of WIRE* (the running id, upper case) |
| a trial dialog is open (Save As, Open, close prompt, merge, renumber, release, page properties) or CadApp's closing/save-loss prompt | *the designer has the <dialog title> dialog open* |
| a pointer button is held over the canvas (drag, grip, window selection) | *the designer is dragging on the drawing* |
| the ECAD command field or command line has unsent text | *the designer is typing a command* |

Held requests stay queued in order (they are not `begin()`-ed, so the client's 60 s wait still
applies) and are re-checked each frame. After **5 s** held (`AGENT_HOLD`), the request is
answered `{"ok": false, "error": "Refused: <said>; nothing was changed. Try again when they
finish.", "state": "not-run"}`. All `execute` calls are held, also reads like `nets`, because
starting any command would cancel the person's. `ecad.tool` reads (`ecad_project`, `ecad_history`,
`ecad_inspect`, `ecad_connection`) and the allowlisted upstream reads are answered at once.
Later requests of the same session wait behind a held one (order is kept per session).

## 7. The agent banner (brief scope 5)

### 7.1 Data contract (what the UI redesign places)

The banner is drawn from one value the trial keeps up to date; the redesign may move or restyle
the strip, but keeps these fields, controls and element names:

```
AgentBanner {
  agent: String,                 // "claude-code"
  state: Connected | Writing | Held | Paused | ReadOnly | Finished | Error,
  writes: On | ReadOnly(reason),
  last_change: Option<{seq, label, time, branch}>,
  steps: usize,                  // this session's transactions still on the log
  last_refusal: Option<String>,  // first line, cleared by the next accepted call
  others: usize,                 // other connected sessions (read-only)
}
```

### 7.2 Look and placement (until the redesign)

A strip 24 px high across the top of the drawing area, under the page tabs, `cad.chrome_dark`
fill, 3 px left bar (colour by state), monospace `cad.text`, square corners, no animation other
than the bar colour. Shown from `ecad.hello` until dismissed after the session ends.

```
▌ Agent claude-code · changing · last: #57 Wire W12 · 14:02:11 · 12 steps   [Undo session] [Pause] [Disconnect]
```

| State | Bar | Middle text |
|---|---|---|
| Connected | `ecad.agent` | `changing` (or `reading` when writes are off, with the reason on hover) |
| Writing (1 s after each accepted write) | `ecad.agent-write` | `changing` |
| Held | `ecad.check-warning` | `waiting for you to finish WIRE` |
| Paused | `ecad.check-warning` | `paused — agent changes are refused` |
| ReadOnly | `cad.text_dim` | `reading only: <reason>` |
| Finished (bye or idle) | `cad.text_faint` | `finished · 12 steps`; buttons: Undo session, Dismiss |
| Error | `ecad.check-error` | `agent access stopped: <reason>`; button: Dismiss |

`last_refusal`, when set, follows in `ecad.check-warning`: `· refused: one call may record at most
1 transaction`. `+1 reading` is appended when `others > 0`.

### 7.3 Controls

| Control | Element | Does |
|---|---|---|
| Last change text | `agent.banner.last` | Opens History with `#seq` selected (020's panel) |
| **Undo session** | `agent.banner.undo` | §8.2. Disabled with tooltip *"Nothing of this session is left to undo"* when `steps == 0` |
| **Pause** / **Resume** | `agent.banner.pause` | Pause: agent writes refused (*"paused by the designer"*, `not-run`); reads continue. Shortcut none |
| **Disconnect** | `agent.banner.disconnect` | Ends this bridge session: its further calls are refused (*"the designer disconnected this agent; restart the MCP server to connect again"*); the writer role is released |
| **Dismiss** | `agent.banner.dismiss` | Finished/Error only: hides the banner |

The banner element is `agent.banner`; its state text is `agent.banner.state`.

### 7.4 Tokens (rows to add to `tokens.md`)

| Token | Value | Used for |
|---|---|---|
| `ecad.agent` | `cad.accent` | Banner left bar, connected |
| `ecad.agent-write` | ACI 3 green `#00FF00` (same as `ecad.attached`) | Banner left bar for 1 s after an accepted agent write |
| `ecad.agent-bar` | `cad.chrome_dark` fill, 3 px left bar, 24 px high | The banner strip (the revision/branch bar pattern) |

### 7.5 Update map

The banner changes only on: `ecad.hello`, an accepted or refused agent call, the 1 s write timer,
hold start and end, Pause/Resume, Disconnect, `ecad.bye`, the 10-minute idle mark, access mode
change, Undo session. `steps` is recomputed only on those events and on an undo, redo or branch
switch by anyone (an `O(steps)` check of the session's `seq`s against the log, at most a few
thousand). A person's ordinary edit changes nothing in the banner. No per-frame work beyond
drawing the strip.

## 8. Agent undo (brief scope 6)

### 8.1 The agent's `u` and `redo`

Over the bridge the gate allows the agent's `u` only when the step it would take back is one this
session recorded (its `seq` in `OwnedSteps`), and `redo` only when the undo it would redo was
recorded by this session. Otherwise: *"Refused: the last step (#41 "Move") is the designer's; an
agent undoes only its own steps."* Headless is unchanged (only the agent edits there). The cap's
own roll-back is unaffected (it only takes back what the call itself just recorded, within the
frame).

### 8.2 Undo session (the banner button)

Recorded as the **person's** action (`Author::User`): they clicked it.

1. Collect, on the branch shown, the session's steps still on the log, newest first.
2. If the newest step on the log is the session's and every step down to the session's oldest is
   the session's: take them back one by one (011's step mapping: `u`, `undomerge`, `undoissue`, a
   `redo` for an undo). History gets one undo per step. Command history: *"Undid 12 agent steps
   (#46–#57)."*
3. If the person (or anyone else) recorded steps among or after them: a small dialog,
   element `agent.undo.confirm`, title **Undo agent session**:
   *"3 of your own steps come after the agent's: #58 Move, #59 Text, #61 Wire. Undoing the agent's
   session also undoes them."* Buttons **Undo all 15** (`agent.undo.all`), **Undo the agent's
   steps after my last one (4)** (`agent.undo.after`, only when that number is above 0), **Cancel**
   (`agent.undo.cancel`, Esc).
4. Steps on another branch than the one shown are not touched: *"6 agent steps are on branch
   `try-a`; switch to it to undo them."*
5. A step that fails to undo stops the run and says where: *"Stopped after 7 of 12: <reason>. The
   project is as after #50."*

Undo session is held by the busy rule's own conditions too (the person cannot click it mid-command
anyway; the button is disabled while `session.running`).

## 9. `ecad-mcp --connect` (brief scope 7)

### 9.1 Command line

```
ecad-mcp [--write] [--agent <name>] [--connect <port>] [--launch] [--create] [<project.ecad>]
```

- `--connect <port>`: one server, headless or bridged (§9.2). `<project.ecad>` (optional) is what
  headless opens; bridged works on whatever the trial has open.
- `--launch` (needs `--connect`): open the trial when nothing answers (§9.3). Never headless.
- `--write`: the server's upper bound in both modes (bridged: `hello.write`).

### 9.2 Modes

`Mode::Undecided` at start; `initialize` answers at once (no probe), `serverInfo.title` "ECAD".

- Each call while Undecided probes `127.0.0.1:<port>` (connect, 300 ms; a refused loopback connect
  returns at once). It answers → `ecad.hello` → **Bridged**. Nothing → the call runs **headless**
  (011's server, opened lazily on the first headless call, same as today).
- Headless sticks once it has recorded a transaction or saved (*work would otherwise be split
  between two places*). Until then a later call probes again, so opening the app after Claude
  started still bridges, as SolidCraft does.
- Bridged sticks. If the app goes away, calls answer *"The ECAD window at 127.0.0.1:47823 is not
  answering (closed?). Reopen ECAD with agent access on; nothing was changed."* and `Remote`
  reconnects on the next call when it is back (a new hello is sent; same session id).
- `ecad_connection` (new tool, read): `{mode, port, app: {project, file, writes, why}, agent,
  session, writer}`. The server's `instructions` say: *"ECAD may be headless (no window) or live
  (the person watches). Call ecad_connection to know which."*
- `screenshot` is always listed; headless answers *"No ECAD window is connected; use render."*
- Remote errors are reworded: the prefix `CADCraft at <addr>` becomes `The ECAD window at <addr>`;
  `may or may not have been applied` keeps its advice and adds *"check ecad_history"*.
- On stdin closing, `ecad-mcp` sends `ecad.bye` (best effort, 1 s).

### 9.3 Launch on Windows and Linux

Only with `--launch`, when the probe finds nothing:

1. Find the trial: `ECAD_TRIAL` (a full path), else `ecad-trial(.exe)` beside the running
   `ecad-mcp` executable, else on `PATH`. None → *"--launch could not find ecad-trial; set
   ECAD_TRIAL to its path."*
2. Start it with `--control <port>` and the project if one was given, stdin/stdout/stderr to null
   (never the MCP stream), detached: Windows `CREATE_NEW_PROCESS_GROUP | DETACHED_PROCESS`
   (`std::os::windows::process::CommandExt::creation_flags`); Linux `process_group(0)`
   (`std::os::unix::process::CommandExt`). No `unsafe`.
3. Linux without `DISPLAY` or `WAYLAND_DISPLAY`: not started; *"No display for the ECAD window
   (DISPLAY/WAYLAND_DISPLAY unset); running headless is not possible with --launch."*
4. Wait up to 30 s, probing every 500 ms; then `ecad.hello`. Timeout: *"ECAD was started but its
   port <port> did not answer within 30 s; if ECAD was already open without agent access, turn it
   on in ECAD Dev."*

macOS keeps upstream's `open -a` semantics only if a later brief packages the trial as an app; not
designed now.

## 10. Registration and quick start 7B (brief scope 8)

Section **7B. Watch an agent draw (live)**, after 7A:

1. Build once: `cargo build --release -p ecad-mcp -p ecad-trial`.
2. Open the trial; ECAD Dev ▸ **Agent access** ▸ **Read and change** (port 47823). Status says
   *Listening on 127.0.0.1:47823*. Once only: it is remembered.
3. Register for every folder (user scope), Windows:

   ```powershell
   claude mcp add --scope user ecad -- C:\dev\ecadcraft\ecad\target\release\ecad-mcp.exe --connect 47823 --write
   ```

   Linux or WSL:

   ```sh
   claude mcp add --scope user ecad -- ~/ecadcraft/ecad/target/release/ecad-mcp --connect 47823 --write
   ```

   Add `--launch` to have Claude open ECAD when it is closed; leave out `--write` for read-only.
   Add a project path at the end to choose what headless opens when ECAD is closed (without one,
   headless works on an unsaved project).
4. Ask: *"With the ecad tools, draw three wires from 0,0 to 60,0, 0,5 to 60,5, 0,10 to 60,10."*
   Expected: the wires appear one by one; the banner reads `Agent claude-code · changing · last:
   #3 Wire …`; History shows each by `agent claude-code`.
5. Start `wire` yourself and leave it half done; ask for another wire. Expected: banner `waiting
   for you to finish WIRE`, then after 5 s the agent reports the refusal; finish or Esc, ask again.
6. Click **Undo session**: the agent's wires go; History has the undos by `user`.
7. Close ECAD and ask again: the agent says the window is not answering (bridged sticks).

Section 9 (limitations) loses "bridged mode is a later brief" and gains: one agent changes the
project at a time; the port is loopback only; WSL needs WSLg for `--launch`.

## 12. Acceptance checks the tester can run from outside

**Contract tests over the bridge** (`apps/ecad-mcp/tests/all/bridge_contracts.rs`). Harness: a
`Trial` built headless with an isolated settings folder (`ECAD_SETTINGS_DIR` via
`use_process_settings_dir`) and access on at a free port (bind 0, read the port, release, start);
an `EcadMcp` in `--connect` mode on a second thread; the test thread pumps `Trial::logic` frames
until each reply arrives (with a 10 s guard). Token files are revoked at the end.

1. **Transaction and author**: `execute wire` → one transaction, `ecadTransactions[0].author ==
   "agent <client>"`, the wire on the trial's page; the same call headless on an equal project
   gives the same reply text (refusals too, for the 011 refusal table).
2. **Person between agent calls**: agent wire, person wire (through the trial's ECAD command
   field), agent wire → authors agent, user, agent.
3. **Restored on failure**: an agent call refused by policy, one failing in the engine, and one
   panicking (the `fault-injection` dev command), each followed by a person edit → `user`. The
   frame-invariant counter stays 0.
4. **Caps**: a call recording two transactions is rolled back with 011's text; a batch of two
   `execute`s on one line records at most one.
5. **Writes off**: preference Read only; then preference write but server without `--write`:
   every change and `save` refused; `ecad_history` unchanged; reads work.
6. **Busy**: start interactive `wire` in the trial; agent `execute` is answered after ≥5 s with the
   WIRE text and `state: not-run`, history unchanged; `ecad_project` answered in the same frame.
7. **Raw methods** sent as raw JSON lines with a valid token: `cmdline.input`, `cmdline.script`,
   `app.open`, `app.save`, `ui.click`, `ui.key`, `engine.execute {command: "agentaccess"}`: all
   refused, nothing changes. Without a token: `unauthorized` (upstream).
8. **Agent undo rule**: person edit last → agent `u` refused; agent edit last → agent `u` undoes it.
9. **One writer**: two sessions with `--write`: the second's write refused with the first's name;
   after the first's `bye`, the second writes.
10. **Mode**: no listener → `ecad_connection.mode == "headless"`; start the trial before any
    write → next call `bridged`; a fresh server that wrote headless, then the trial started →
    stays `headless`.
11. **Off by default**: a trial with no preference and no `--control`: connecting to 47823 and to
    the test port is refused.
12. **Launch args** (unit, `launch.rs`): the path order (`ECAD_TRIAL`, beside, `PATH`), the
    arguments, null stdio, the Linux no-display refusal. The real spawn is an `#[ignore]` manual
    test.

**Trial UI tests** (`apps/ecad-trial/tests/all/agent_ui.rs`, `egui_kittest`, by element name):
the ECAD Dev row's three modes and the status texts (listening, in use, this run only); the
banner's states of §7.2 after scripted bridge calls; Pause refuses, Resume accepts; Disconnect;
Undo session without and with person steps on top (both dialog choices and Cancel); the settings
file written and read back, and an unreadable one reading as Off.

**By hand:** quick start 7B on Windows with Claude Code (owner), and on Linux/WSLg by the tester
with any MCP client.

## 15. Questions (recommendations first)

1. **Default port 47823**, distinct from CADCraft's examples and the other crafts' usual ports?
   **Recommend yes**; it is changeable in ECAD Dev and in the registration line.
2. **Upstream's `control_server.rs` included by `#[path]`** from the trial (no copy, no upstream
   patch, follows every upstream sync), rather than (b) an upstream seam exposing it from a library,
   or (c) an ECAD copy? **Recommend the include.** It keeps the security-sensitive transport
   identical to CADCraft's; the cost is that a sync which renames or splits that file breaks the
   trial's build loudly, which the sync brief then fixes.
3. **Busy rule: hold 5 s, then refuse** (`not-run`), rather than refusing at once or holding until
   the person finishes? **Recommend 5 s.** Short pauses (a click between prompts) pass; a long one
   gives the agent a clear reason within its 60 s wait, and it can retry.
4. **One writer at a time**; other agents read? **Recommend yes.** Several Claude sessions run at
   once on this machine; two writers on one open project would interleave steps and make Undo
   session ambiguous. Several writers is listed as later work.
5. **Agent `u`/`redo` limited to its own steps over the bridge?** **Recommend yes**: an agent's
   undo must never take back the person's work.
6. **Undo session as N ordinary undos by the person**, with the confirmation of §8.2 when the
   person's steps are on top? **Recommend yes**: no format change; History shows exactly what
   happened. A single "undo to point" step would need a new op (FP), not worth it now.
7. **Headless sticks after its first change; bridged sticks once connected** (§9.2)? **Recommend
   yes**, as SolidCraft: work is never split between a file and the window without the agent being
   told.
8. **Pause and Disconnect on the banner** (beyond the roadmap's "last write" and "Undo session")?
   **Recommend yes**: they are the person's brakes and cost little. The redesign may move them into
   a menu on the banner.
9. **`save` allowed over the bridge** with Read and change (the project's own file only; Save As and
   a never-saved project refused, as 011)? **Recommend yes**, so an agent's long job is not lost if
   the window crashes; the person can turn it off with Read only.
10. **Agent page switches follow on screen** (an agent's `openpage` changes the page the person
    sees)? **Recommend yes for 035** (watching is the point); a "don't follow" toggle can come with
    the UI shell.

## 16. Out of scope

Several writers at once; agent changes held as proposals or on their own branch; any non-loopback
transport, remote machines, or a second window per process; macOS launch; a settings window (the
row lives in ECAD Dev until 1.5); CADCraft's raw `command_line`, `script`, `cancel`, `open`,
`new_drawing`, `ui_click` and other UI-input tools; changing upstream's control server or token;
agent access to libraries (stage 3).
