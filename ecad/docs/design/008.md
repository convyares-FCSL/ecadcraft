# Design 008: ECAD tools by mouse

Brief: `docs/briefs/008-usability-mouse-tools.md` (Approved 2026-11-01).
Tokens: `docs/design/tokens.md`. Status: design for the worker; open points in §11 and questions
for the architect in §12 must be answered (or explicitly deferred) before the parts they touch are
built.

## 1. Goal

The owner builds the quick-start example (a rectangle made a component, two terminals on it, a
rotated coil, a wire from terminal to terminal) by clicking and pressing Enter/Esc only, and sees
on the drawing, before each click, what the click will do.

## 2. Principles for every ECAD interactive form

1. **CADCraft's prompt machine, nothing new.** Each command gets an `interactive` factory on its
   existing `CommandSpec` (same id). Prompts, keywords, typed coordinates (`40,10`, `@30,0`),
   object snaps, ortho/polar, Dynamic Input, the pick box, Enter, Space-as-Enter, Esc and
   right-click behave exactly as in CADCraft's own commands (LINE, INSERT, MOVE).
2. **The JSON form is untouched.** `engine.execute`, the control channel, MCP, scripts and a
   typed `name {json}` line run the JSON form and never prompt. A bare name (`addterminal`, `wire`
   …) typed in either command field, a menu item, or an ECAD Tool Sets button starts the
   interactive form.
3. **One click = one JSON-equivalent transaction.** Every time the interactive form commits, it
   commits exactly the transaction the JSON form would record for the resolved values (brief AC1):
   it builds those values and goes through the same code path. "Repeat until Enter" commands
   commit once per placed object (see Q1).
4. **Esc never changes anything that was not already committed.** Esc at any prompt drops the
   pending, uncommitted input; the document, head and selection stay as they were before that
   input. Objects committed earlier in the same repeating command stay (as in CADCraft, where Esc
   in LINE keeps the segments drawn). Undo then removes the last committed object in one step.
5. **Click-first.** Every prompt can be answered by one click; typing is optional. No prompt asks
   for an ID or a handle.
6. **Capture, not guess.** Where a click means "this terminal" or "this wire end", the cursor is
   captured when it is within `ecad.aperture` of it, and the capture is drawn before the click
   (§4). Outside the aperture nothing is captured, and nothing is drawn to suggest it.
7. **Feedback after every commit** is one line at the command line, in words (no JSON), naming
   what was created, for example `Terminal 1 added to component 3f9c…`. IDs are given in full
   hex as the debugger shows them, so they can still be copied into a JSON line.
8. **Never crash.** Typed values are parsed by CADCraft's grammar; non-finite or out-of-range
   values are rejected at the prompt with a message and the same prompt again (§9).

## 3. Starting the tools

### 3.1 ECAD tab in Tool Sets

Same tab, groups, order, labels and ids as today. What changes is what five buttons do and their
tooltips. Clicking any ECAD button first cancels a running command (as today and as CADCraft's own
Tool Sets buttons do).

| Element name (id) | Label | Group | Does now | Tooltip (new text) |
| --- | --- | --- | --- | --- |
| `ecad.convertcomponent` | Convert to Component | Components | Starts `convertcomponent` interactively: runs at once on the current selection, else asks to select objects | `Make drawing objects one component (uses the selection, or asks you to select)` |
| `ecad.addterminal` | Add Terminal | Components | Starts `addterminal` interactively | `Click on a component's outline to add terminals; Enter to finish` |
| `ecad.place` | Place Symbol | Components | Starts `place` interactively | `Place coil symbols by clicking; R rotates, M mirrors; Enter to finish` |
| `ecad.wire` | Wire | Wiring | Starts `wire` interactively | `Click points to draw a wire; ends on terminals attach; Enter to finish` |
| `ecad.connect` | Connect | Wiring | Starts `connect` interactively | `Click a wire near its end, then a terminal` |
| `ecad.disconnect` | Disconnect | Wiring | Starts `disconnect` interactively | `Click a wire near an attached end to detach it` |
| `ecad.cableadd`, `ecad.setprop`, `ecad.delete`, `ecad.newpage`, `ecad.openpage` | unchanged | unchanged | Template, as today | unchanged |
| `ecad.inspect` | Inspect Project | Inspect | Runs now, as today | unchanged |

Starting a button never leaves anything in the banner's Command field and shows no template note.
The command's first prompt appears at CADCraft's command line (bottom of the drawing area), and the
keyboard focus goes to the drawing so the next key press answers the prompt.

### 3.2 Typed names

- CADCraft's command line or the banner's Command field: a bare `convertcomponent`, `addterminal`,
  `place`, `wire`, `connect` or `disconnect` starts the interactive form.
- `name {json}` in the banner runs the JSON form, exactly as today.
- No new aliases in this brief (see Q6).

### 3.3 Menus

An **ECAD** menu is wanted (brief scope "a menu") only if extension commands' `menu` paths appear
in CADCraft's menu bar without an upstream change. See open point O5. If it is possible:
`ECAD > Convert to Component`, `ECAD > Add Terminal`, `ECAD > Place Symbol`, separator,
`ECAD > Wire`, `ECAD > Connect`, `ECAD > Disconnect`. Otherwise no menu in this brief.

### 3.4 When a tool cannot start

Checked before the first prompt; the message is echoed at the command line and nothing runs.

| Situation | Message (existing wording where it exists) |
| --- | --- |
| The active drawing is not an ECAD page | `this page is not owned by an ECAD project` |
| The page is unavailable | `this page is unavailable (its drawing could not be rebuilt); close and reopen it` |
| The project is open read-only (second window) | the existing read-only refusal, unchanged |
| The project is busy (re-entrant) | the existing `busy` refusal, unchanged |

## 4. What the drawing shows

### 4.1 Always (no command running)

Visible at every zoom, constant screen size (tokens in `tokens.md`):

| Thing | Glyph | Token |
| --- | --- | --- |
| Terminal (any component, drawn or symbol) | open circle, `ecad.terminal-size`, `ecad.hairline`, centred on the terminal point | `ecad.terminal` |
| Wire end attached to a terminal | filled dot, `ecad.dot-size`, centred on the terminal point (inside the circle) | `ecad.attached` |
| Wire end attached to nothing | open square, `ecad.loose-size`, `ecad.hairline`, centred on the end | `ecad.loose` |

So a free terminal is a cyan ring; a connected terminal is a cyan ring with a green dot; a wire end
that is not connected has a red square. The wire line itself keeps its layer colour.

Glyphs are display only: they are not objects, cannot be selected, gripped, snapped to by CADCraft's
own snaps or plotted, and do not change the document. Terminal markers remain the existing POINT
objects on layer `ECAD-TERMINALS` underneath; how the glyphs are drawn is open point O2.

### 4.2 Capture preview (while an ECAD command runs)

When the cursor is within `ecad.aperture` of a terminal at a prompt that accepts a terminal:

- the cursor point jumps to the terminal point exactly (the crosshair centre and rubber band end
  there);
- an **attach ring** (`ecad.ring-size`, `ecad.bold`, `ecad.attach-preview`) is drawn around the
  terminal;
- the terminal's name is written beside the ring, offset 10 px right and 10 px up, in
  `ecad.preview-text`: `→ A1` (terminal label), or `→ terminal 3f9c…` (first 8 hex digits) when it
  has no label.

Outside the aperture: no ring, no name, the cursor is where the mouse (or CADCraft's own snap) puts
it. That difference is what brief AC4 checks.

Several terminals within the aperture: the nearest to the cursor is captured; at equal distance,
the one the JSON form's `terminal_at` would resolve for that point (so preview and transaction
agree).

CADCraft's own object-snap marker may show at the same time (for example an Endpoint square at a
rectangle corner). An ECAD capture takes precedence over CADCraft's snap for the cursor point at
ECAD prompts that accept a terminal; see O1.

### 4.3 Hover information

With no command running (CADCraft's rollover highlight active, PICKFIRST on), hovering over an
ECAD object for 500 ms shows a tooltip next to the pointer (16 px right, 16 px below; kept inside
the window). It disappears as soon as the pointer leaves the object, a button is pressed, or a
command starts. Hovering never writes to the document, the selection or the history (AC5).

Element name: `ecad.hover` (egui id), first label line as below. Panel: `ecad.tooltip-bg`,
`ecad.tooltip-border`, `ecad.tooltip-text`, square corners, at most 12 lines; longer lists end in
`… and N more`.

| Hovered | Lines |
| --- | --- |
| Item of a component (drawn outline or placed symbol) | `Component <tag or (no tag)>` / `id <full hex>` / `Terminals: <n>` / one line per terminal: `  <label> — <k> wire end(s)` |
| Terminal marker | `Terminal <label or (no label)>` / `of component <tag or id>` / `id <full hex>` / `Wires: none` or one line per attached end: `  wire <first 8 hex>… end A` |
| Wire | `Wire <tag or (no tag)>` / `id <full hex>` / `End A: terminal <label> of <tag or 8-hex id>` or `End A: not connected` / same for End B |
| Plain geometry | no tooltip (CADCraft's own behaviour) |

`<tag>` is the `tag` property when set. Nothing else from the model is shown (no new semantics).
During ECAD commands the capture preview (§4.2) replaces the tooltip. The existing debugger panel
is unchanged.

## 5. Add Terminal (`addterminal`)

Goal: click on a component's outline to put a terminal there; repeat; Enter to finish.

| Step | User does | Prompt shown / what they see |
| --- | --- | --- |
| 1 | Clicks **Add Terminal** | `Specify point for terminal <name> on a component or [Name]:` where `<name>` is the default name (see Q2), for example `Specify point for terminal 1 on a component or [Name]:`. The pick box shows; hovering a drawn component's outline highlights the whole component (CADCraft hover colour). |
| 2 | Clicks on the outline (or on an object snap on it, or types `40,10`) | The point is resolved (below). A terminal is committed at once (one `addterminal` transaction with `handle` = the picked object, `at` = the point, `label` = the name). The cyan ring appears there. Echo: `Terminal 1 added to component <id>.` The prompt repeats with the next default name. |
| 2a | Types `N` (or clicks `Name`) | `Enter terminal name <1>:` — typed text (trimmed, 1–64 characters) becomes the name for the **next** terminal; Enter keeps the default. Back to the point prompt, showing the chosen name. |
| 3 | Presses Enter (or Space, or right-click Enter) at the point prompt | Command ends. |
| — | Presses Esc | Command ends; terminals already added stay; a pending Name entry is dropped. |

Point resolution:
- The object under the pick box at the click (or at the typed point) must be an item of a
  **drawn** component. If a CADCraft object snap was in effect (Endpoint, Midpoint, Nearest …, or a
  typed `mid` override) or the point was typed, the terminal goes exactly at that point. Otherwise
  the point is moved to the nearest point on the picked object's outline, so a click a few pixels
  off the line still lands on it.
- The quick-start's terminal at the middle of an edge (40,10) is reached with Midpoint snap (`mid`
  typed at the prompt, Shift+right-click > Midpoint, or Midpoint on in the snap settings), or by
  typing `40,10`.

Errors (echoed, prompt repeats, nothing committed):

| Click on | Message |
| --- | --- |
| Empty space | `No component outline there. Click on a component's outline.` |
| Plain geometry | `That object is not part of a component. Convert it to a component first.` |
| A placed symbol | `terminals of placed symbols come from their definition` (existing wording) |
| A wire or a terminal marker | `That is not a component outline.` |

Default name: see Q2. Until answered, the worker builds the rule in Q2 option (a) behind one
function so it is easy to change.

## 6. Place Symbol (`place`)

Goal: place the built-in coil by clicking, rotated or mirrored as wanted.

| Step | User does | Prompt / what they see |
| --- | --- | --- |
| 1 | Clicks **Place Symbol** | `Specify insertion point (rotation 0, not mirrored) or [Rotate/Mirror]:`. The coil follows the cursor in `ecad.preview` style with its terminal rings (`ecad.terminal`) at their would-be positions. The insertion point is the symbol's origin (the coil's centre). |
| 2 | Types `R` then Enter/Space, or clicks `Rotate` | Rotation steps +90° counter-clockwise (0 → 90 → 180 → 270 → 0). The preview turns at once; the prompt shows the new rotation. |
| 2b | Types `M` then Enter/Space, or clicks `Mirror` | Mirror toggles (`mirrored` / `not mirrored`); the preview flips. |
| 3 | Clicks (or types a point) | One `place` transaction: `at` = point, `rotation` = degrees shown, `mirror` = shown, no `definition` (the built-in coil, as the JSON default). The coil and its terminal rings are drawn. Echo: `Coil placed: component <id>, terminals A1, A2.` The prompt repeats with the same rotation and mirror. |
| 4 | Enter | Command ends. |
| — | Esc | Command ends; coils already placed stay. |

Rotation and mirror persist only within the running command; the next Place Symbol starts at 0,
not mirrored. A single key press without Enter (R alone) is open point O3. Any rotation angle other
than multiples of 90 stays available through the JSON form only.

The quick-start's coil (at 100,0, terminals at 90,0 and 110,0): Place Symbol, `R` Enter, type
`100,0` Enter (or click with grid snap), Enter.

## 7. Wire (`wire`)

Goal: draw a wire by clicking; ends on terminals attach, and you see that before you click.

| Step | User does | Prompt / what they see |
| --- | --- | --- |
| 1 | Clicks **Wire** | `Specify first point of wire:`. Capture preview (§4.2) active. |
| 2 | Clicks (on a terminal: captured) | First point fixed. Prompt: `Specify next point or [Undo]:`. Rubber band from the last point to the cursor (CADCraft ortho/polar apply). If the first point is captured, a small `ecad.attach-preview` dot stays on it. |
| 3 | Clicks elsewhere | A bend point is added; the fixed part of the wire is drawn in `ecad.preview` style; prompt repeats. |
| 4a | Clicks while a terminal is captured (not the first point) | That point is the last point and the wire is **committed and the command ends** (one click finishes on a terminal, as the brief asks). |
| 4b | Presses Enter | Commits the wire with the points so far (needs ≥ 2), command ends. |
| — | `U` / `Undo` / Ctrl+Z | Removes the last point; at the first point, back to step 1. |
| — | Esc | Command ends, nothing written (the wire is not committed until 4a/4b). |

Commit: one `wire` transaction with `points` = the clicked/captured points in order. Captured
points are the terminals' exact coordinates, so the JSON form's own end resolution attaches them
(AC1, AC4). Echo:
- `Wire <id> drawn; end A attached to A1, end B attached to 1.` or
- `Wire <id> drawn; end B not attached.` (one sentence naming each end's outcome).

After commit, attached ends show the green dot, loose ends the red square (§4.1).

Rules and errors:
- A click on the same point as the last one is ignored (no zero-length segment), with no message.
- Enter with one point: `A wire needs at least two points; nothing was drawn.` Command ends with
  no change. Enter with none: command ends.
- At 10 000 points (the JSON limit): `A wire has at most 10000 points; press Enter to finish.` and
  further points are refused.
- Captures only terminals **shown on this page**. A captured terminal mid-wire always finishes the
  wire; to pass close to a terminal without attaching, click outside the aperture or type the point
  (typed points are also captured if they equal a terminal point: see Q4).

## 8. Connect, Disconnect, Convert to Component

### 8.1 Connect (`connect`)

| Step | User does | Prompt / what they see |
| --- | --- | --- |
| 1 | Clicks **Connect** | `Select wire near the end to connect:` (pick box). Hovering a wire highlights it and marks the nearer end with the attach ring. |
| 2 | Clicks a wire | The end nearer the click (straight distance to the route's first and last point; A wins a tie) is chosen; a rubber band runs from that end to the cursor. Prompt: `Select terminal for end <A or B>:`. Capture preview active. |
| 3 | Clicks with a terminal captured | One `connect` transaction (`conductor`, `end`, `terminal`), as the JSON form, which also moves the end onto the terminal. Echo: `End A of wire <id> connected to A1.` Back to step 1. |
| 3x | Clicks with nothing captured | `No terminal there. Move onto a terminal until the green ring shows.` Prompt repeats. |
| — | Enter at step 1 | Command ends. Enter at step 2: back to step 1. |
| — | Esc | Command ends; nothing pending is written. |

Step 1 click on something that is not a wire: `That is not a wire.` Prompt repeats.

### 8.2 Disconnect (`disconnect`)

| Step | User does | Prompt / what they see |
| --- | --- | --- |
| 1 | Clicks **Disconnect** | `Select wire near the end to disconnect:`. Hovering a wire marks the nearer end with a ring in `ecad.loose` colour if attached. |
| 2 | Clicks a wire | Nearer end chosen as for Connect; one `disconnect` transaction. Echo: `End B of wire <id> disconnected.` The end shows the red square. Prompt repeats. |
| 2x | The nearer end is not attached | `that end is not connected` (existing wording). Prompt repeats. |
| — | Enter / Esc | Command ends. |

### 8.3 Convert to Component (`convertcomponent`)

- With a selection (pickfirst): runs at once on it, as today (no prompt).
- With no selection: `Select objects to convert to a component:` — CADCraft's standard object
  selection (click, window, crossing, Shift to remove, keywords as in CADCraft). Enter ends the
  selection and runs one `convertcomponent` transaction with the selected handles. Echo:
  `Component <id> created from <n> objects.`
- Enter with nothing selected: `Nothing selected; nothing converted.` Command ends.
- Esc: command ends; nothing written; the selection is as before.
- Refusals use the existing wording (`only plain geometry can be converted; …`). The command ends
  (no retry loop), because the selection itself is wrong.

## 9. Keyboard, cancel and hostile input

| Key | At a point prompt | At a select prompt | At the Name prompt |
| --- | --- | --- | --- |
| Enter / Space / right-click Enter | Ends the command (Wire: commits, §7) | Ends selection | Accepts the default |
| Esc | Ends the command; uncommitted input dropped | Same | Ends the command (as CADCraft); terminals already added stay |
| `U`, Ctrl+Z | Wire: undo last point. Others: CADCraft's normal undo of the last committed object (one step) | — | — |
| `R`, `M` | Place Symbol keywords | — | text |
| `N` | Add Terminal keyword | — | text |
| F3, F8, F9, F10, typed snap overrides | As CADCraft | As CADCraft | — |

Hostile input (AC7). Each rejected value prints a message and repeats the prompt; nothing panics,
nothing is committed:
- Typed coordinates that are not finite, or beyond ±1e12: `Point out of range.`
- Name text longer than 64 characters, or containing control characters: `Names are 1 to 64
  printable characters.`
- Wire point count capped at 10 000 (§7). Selection for Convert is capped at the JSON limit
  (100 000 handles): `At most 100000 objects can be converted at once.`
- A cursor at a non-finite position (off-screen, extreme zoom) captures nothing and draws no
  preview.

## 10. Acceptance checks the tester can run from outside

Run with the trial app headless (egui_kittest, elements by name), plus the public session API
(`current_prompt()`, `preview()`/`preview_objects()`, the project snapshot from `ecadinspect`).

**A. Each tool starts its interactive form.** For each of the six buttons in §3.1: click it on an
ECAD page; `current_prompt().display()` equals the first prompt text in §5–§8 exactly; the Command
field is empty and no template note is shown.

**B. JSON forms unchanged.** Every JSON line from today's quick-start test runs and produces the
same snapshot as before this branch; `engine.execute` with each command never leaves a prompt
running.

**C. Same transaction (AC1).** For each command: run the interactive form by clicks; run the JSON
form with the resolved values on a fresh identical project; the two transactions are equal apart
from fresh IDs (same op kinds, order, positions, labels, rotation, mirror, attached ends).

**D. Esc and undo (AC2).** At every prompt of every command, press Esc: the snapshot head,
document and selection equal the ones before that prompt's pending input. After a finished
command, one `u` removes exactly the last committed object.

**E. Quick-start by clicks (AC3).** In a 1280×800 window: draw the rectangle
(`line 0,0 40,0 40,20 0,20 c`), window-select it, **Convert to Component**; **Add Terminal**,
type `40,10` Enter, `0,10` Enter, Enter; **Place Symbol**, `R` Enter, `100,0` Enter, Enter;
**Wire**, click at the screen position of 40,10 (captured), click at 70,10 and 70,0, click within
5 px of 90,0 (captured, finishes). The final snapshot equals today's quick-start test result
(same structure; IDs aside), with both wire ends attached.

**F. Capture aperture (AC4).** With `APERTURE` = 10 and a known zoom: cursor 5 px from a terminal
→ `preview_objects` contains the attach ring and name, and a click attaches; cursor 20 px away →
no ring, and the click leaves that end unattached (red square after commit).

**G. Hover (AC5).** With no command running, move the pointer onto the coil, a terminal ring and
the wire in turn: a widget `ecad.hover` appears with the first lines in §4.3; the snapshot head and
selection are unchanged after hovering.

**H. Glyphs at every zoom.** Zoom to extents, then ×0.01 and ×100: the terminal ring, attached dot
and loose square are drawn at their token sizes in each screenshot.

**I. Errors.** Each error row in §5–§8 shows its message and repeats (or ends) as stated.

**J. Hostile input (AC7).** Type `nan,0`, `1e309,0`, `@1e300<0`, a 10 000-character name, and
click 10 001 wire points by script: messages as in §9, no panic, no commit.

**K. Reference screenshots (AC6)** for owner approval, saved under the tester's report folder,
dark theme, 1280×800, after **E**'s drawing then `zoom e`:
1. `008-terminals.png`: the finished example (rings, green dots, no red squares), plus one loose
   wire `wire {"points":[[0,30],[20,30]]}` to show two red squares.
2. `008-wire-snap.png`: Wire started at 40,10, cursor within the aperture of the coil's A1 at
   90,0: ring and `→ A1` visible.
3. `008-place-preview.png`: Place Symbol after one `R`, cursor at 100,0 before the click.

**Needs owner check (native Windows):** the owner repeats **E** by mouse only, following the
updated quick-start, and says whether it is easy enough.

## 11. Open points for CADCraft machinery (may need a seam; owner approval)

- **O1. Terminal capture vs CADCraft object snap.** CADCraft's object snap knows only drawing
  entities; terminal markers are POINT entities, so Node snap would find them, but Node is off by
  default (`OSMODE` 4133) and is a user setting. Proposed without a seam: the ECAD interactive
  command does its own capture from the cursor it receives (`Session::cursor`, `pixel_size()` ×
  `settings.aperture`), and draws the ring through `preview_objects`. Limits: the cursor it
  receives may already be moved by a CADCraft snap; CADCraft's own snap marker may show beside the
  ring; Tab-cycling does not include terminals. If those prove confusing in the owner trial, the
  clean fix is a seam letting a document owner add snap candidates (owner approval needed).
- **O2. Constant-size glyphs (§4.1).** Terminal markers are POINT entities whose look depends on the
  drawing-wide `PDMODE`/`PDSIZE`; one style for every point, and no way to tell connected from
  free terminals, nor to mark loose wire ends. Options: (a) set `PDMODE`/`PDSIZE` on ECAD page
  drawings from the projection (ECAD-side only; affects every point on the page; gives rings only,
  no green/red end marks); (b) a CADCraft seam for an owner-drawn canvas overlay in world
  coordinates with screen-sized glyphs (gives §4.1 in full). Recommendation: (b); (a) is a
  fallback that meets only "terminals visible at every zoom". Owner decides.
- **O3. Single-key rotate/mirror.** CADCraft keywords need Enter/Space after the letter (`R`
  Enter). A bare key press while the preview follows the cursor would need a UI-level shortcut
  hook. Proposed: keywords with Enter in this brief; single key only with an approved seam.
- **O4. Hover tooltip.** CADCraft computes the rollover object (`CanvasState::hover`, public) but
  shows no tooltip. The trial can read it and draw an egui tooltip at the pointer without an
  upstream change; confirm the trial can draw above the canvas. If not, the fallback is a "Hover"
  line at the top of the existing debugger panel (no seam).
- **O5. ECAD menu.** Whether extension commands' `menu` paths show in CADCraft's menu bar
  unchanged. If not, no menu in this brief (Tool Sets and typed names cover it).
- **O6. Committing from an interactive command on an owned page.** The JSON run path commits
  through `Project::apply_edit` and then CADCraft's owner commit hook. The interactive forms must
  commit the same way, possibly several times within one running command (repeat until Enter).
  The worker confirms the session's commit pass handles a commit per input; if it only commits at
  command end, a seam or a different repeat model (Q1) is needed.

## 12. Questions for the architect

- **Q1. Repeat and undo granularity.** The brief asks for "repeat until Enter" and "undo after a
  finished interactive command undoes it in one step", and also "exactly the same transaction as
  its JSON form". The JSON forms add one object per transaction. This design commits one
  transaction per placed object (undo removes the last one; Esc keeps earlier ones). Alternative:
  one transaction for the whole run, which needs batch JSON forms (a format/transaction-model
  question, out of this brief's scope). Confirm per-object.
- **Q2. Default terminal name.** Options: (a) the smallest positive integer not already used as a
  label among that component's terminals (`1`, `2`, `3` …); (b) no label unless typed (Enter =
  none). Is a default label "numbering", which the brief puts out of scope?
- **Q3. Loose-end and connected marks.** Is showing unattached wire ends in red, and attached ends
  in green, wanted, or is a dangling end sometimes intended (e.g. a wire continued on another page)
  and should not look like an error?
- **Q4. Typed points on a terminal.** A typed point equal to a terminal's position attaches (that
  is what the JSON form does). Should a typed point within the aperture but not exact also be
  captured? This design says no: only the cursor is captured; typed points are taken literally.
- **Q5. Terminals on symbol components in Connect/Wire.** Capture offers every terminal shown on
  the page, both drawn and symbol terminals. Confirm no terminal kind should be excluded.
- **Q6. Command aliases** (`TERM`, `W`…)? None proposed; `W` is WBLOCK in CADCraft.

## 13. Out of scope

New electrical semantics (numbering, cables by slash, brief 004), symbol libraries or a symbol
picker beyond the built-in coil, arbitrary rotation angles by mouse, changes to the file format or
transaction model, interactive forms for Set Property, Add to Cable, Delete, New Page and Open Page
(they keep templates), editing terminal names after creation, the light theme's contrast, and any
change to the debugger beyond the O4 fallback.

## 14. Quick-start update (for the worker, brief item 8)

§4 replaces the "Every other button … fills in the Command field" bullet for the six interactive
tools with one line per tool from §3.1. §5–§7 follow check **E** step by step, with the expected
sight after each step (ring appears, coil follows the cursor, green ring before the last click,
green dots after). A native Windows variant uses the same steps (only paths and the start command
differ). §9 drops "no interactive ECAD prompts" and lists O1–O3's limits as they end up.
