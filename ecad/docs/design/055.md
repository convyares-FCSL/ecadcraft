# Design 055: Library ▸ Title blocks, a simple title block and frame editor

Brief: [`055-title-blocks.md`](../briefs/055-title-blocks.md). UI rev 4 spec, "Library workspace ▸
Title blocks", and board 3.05. Release 0.2.2.

The user's goal in one sentence: **make the sheet look like the company's drawings (border, zones,
title block, logo) once, and have every page fill itself in.**

## 0. What exists today, and the files this brief touches

### 0.1 Today (`origin/dev` `8b6c2ccd`)

- **Frame and title block** (019, 033): `ecad-cadcraft/src/frame.rs` draws both as derived parts on
  the locked layer `ECAD-FRAME`. `FrameInput` holds a fixed set of values (project title, customer,
  drawing number, status, page title, function, location, page, rev, next, total, the newest seven
  issued revisions). `built_in` is one hand-coded layout. The `FrameLayout` trait was left for "users
  will define their own borders and title blocks" (owner note of 2026-11-08). `touches` is the
  frame's update map.
- **Style model** (050a, merged): the `frame` catalogue (`styles/frame.rs`) has the fields
  `border_weight`, `inner_weight`, `line_colour`, `grid_labels` and `title_block` (a choice with one
  word, `standard`), and one built-in style, `sheet`. The choice is `print.frame.style`, levels
  Standard, Project and Page. A `StyleRecord` is a name plus at most 64 text fields of at most 256
  characters (`ecad-model/src/style.rs`). Standards ▸ Frames lists the catalogue.
- **Sheet** (019): `SheetSpec` (paper size, landscape only, 420 × 250 mm at least, zone counts and
  labels) per page (`sheet` property) or project (`settings.sheet`). `Grid` already takes margins
  and a start corner as parameters, but `Grid::of` always uses the constants `MARGIN_MM` and
  `TOP_MARGIN_MM`. `TITLE_BLOCK_MM` (40) is a constant read in `frame.rs`, `generated.rs`,
  `plc/page.rs`, `plc/sheets.rs` and `xref.rs` as the strip that content keeps out of.
- **Revisions** (033): the project's revision columns (`revisions.columns`) with custom fields such
  as `ecr`; the Rev box with the pending marker (`D*`).
- **Library workspace** (038, 048): the tab `Title blocks` exists as a placeholder
  (`library.tab.title_blocks`, "They come later"). The symbol builder (048) keeps a temporary draft
  in eframe storage, edits it with its own undo, and writes one transaction on Save.
- **CADCraft images**: an `Image` entity references a file path, and the PDF writer skips raster
  images ("not written to PDF yet"). A raster logo would show on screen and vanish on paper, and has
  no path on wasm. This is why logos are vector in 0.2.2 (§6, Q3).

### 0.2 The words

| Word | Meaning |
| --- | --- |
| **frame** | One style of the `frame` catalogue: the border, the zones, the margins, the line weights and its **title block**. The Library list calls a frame a "title block", because that is what people pick it by. |
| **title block** | The layout inside a frame's block area: lines, static texts, fields, a revision table and a logo. Stored in the frame style's **body** (FP1). |
| **field** | A box on the block that shows one value read from the project, the page, the revision or the print, never typed on a page. Dashed in the editor, never printed as a box. |
| **binding** | What a field shows: a source and a key, such as `project:drawing_number`, `page:number`, `revision:ecr`. |
| **built-in frame** | A frame in code. Its block is computed for the page's sheet size, so it fits any sheet. |
| **own frame** | A frame a project or standard made. It is drawn for one sheet size ("one frame per sheet size"). |

## 1. Model

### 1.1 One model: the frame style carries its block

The editor writes **`frame` style records**, the same records Standards ▸ Frames lists and
`print.frame.style` chooses. There is no second store. A frame style is one row in the Library list.
Its fields hold the border and zones. Its body holds the block. Making, renaming, deleting with a
replacement, promoting to the standard and choosing per project or page are 050a's commands and
rules, unchanged.

Why not two catalogues (a frame picking a block)? The spec says one frame per sheet size, and the
board's list shows one row per block with its sheet. A block shared by an A3 and an A2 frame is
done by **Duplicate for A2** (§4.6). Two catalogues would double the choices and the Used by counts
for no case the owner named (Q1).

### 1.2 The body (FP1)

```rust
// ecad-model/src/style.rs
pub struct StyleRecord {
    pub name: String,
    pub fields: Properties,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub body: Option<StyleBody>,             // FP1; only on `frame` records
}
pub enum StyleBody { TitleBlock(TitleBlockLayout) }   // serde tag "title_block"; unknown tags kept as raw and ignored
pub struct TitleBlockLayout {
    pub size: (f64, f64),                    // block width × height, mm
    pub items: Vec<Item>,                    // drawing order
}
pub enum Item {
    Line   { a: (f64, f64), b: (f64, f64), weight: LineWeight },        // Thin | Thick
    Text   { at: Rect, text: String, look: TextLook },
    Field  { at: Rect, bind: Binding, label: Option<String>, look: TextLook, if_empty: IfEmpty },
    RevTable { at: Rect, rows: u8, header: bool, newest: Newest },     // Top | Bottom
    Logo   { at: Rect, name: String, prims: Vec<Primitive> },          // vector, fitted to `at`
}
pub struct Rect { pub x: f64, pub y: f64, pub w: f64, pub h: f64 }   // mm from the block's bottom-left
pub struct TextLook { pub size: f64, pub bold: bool, pub align: Align, pub colour: Ink }  // Ink | Red
pub enum IfEmpty { Blank, Dash, Missing, Text(String) }              // Missing: 033's "?" mark
pub struct Binding { pub source: Source, pub key: String }           // Source: Project | Page | Revision | Print
```

`Primitive` is the model's own (lines, arcs, circles, polylines, solid fills, text), as symbols use.
Coordinates are millimetres in the block, so a project in inches draws the same paper.

### 1.3 Bounds (guards, house rule 12; each says what it prevents)

| Bound | Value | Prevents |
| --- | --- | --- |
| `MAX_ITEMS` | 512 | An unbounded block from a hostile file; the editor's per-frame cost |
| `MAX_LOGO_PRIMS` | 2 000 per logo, 4 000 in a body | A logo that slows every page's frame |
| `MAX_BODY_TEXT` | 256 characters per text, label, binding key | Unbounded records |
| Coordinates | finite, 0 ≤ x, y ≤ 2 400 mm; sizes ≥ 0.5 mm | NaN or huge geometry (`MAX_WIDTH_MM`) |
| `size` | 1–2 400 mm by 1–400 mm | A block taller than any sheet |
| `rows` of a revision table | 1–20 | An unbounded table |

A file that breaches a bound opens. The excess items are dropped when drawing and counted in a
Checks row (`title-binding-unknown`'s family, §8). Commands refuse a breach in words.

### 1.4 Frame fields (FP2, FP3)

| Field | Kind | Built-in `sheet` | Meaning |
| --- | --- | --- | --- |
| `sheet` | `SheetSpec` text (`A3 8x6`, `594x420 12x8 letters numbers`), or empty | empty | Empty: the page's own sheet (019). Set: this frame is drawn for that sheet, and its pages use it (§2) |
| `margins` | Four lengths `l,r,b,t`, 0–50 mm, or empty | empty (10,10,10,7) | The frame's distance from the paper edge |
| `centre_marks` | `on`, `off` | `on` | A short mark at the middle of each side (house style) |
| `block` | Choice `bottom_right`, `bottom_full` | `bottom_full` | Where the block sits. `bottom_full` stretches the block's left part to the frame's left edge (built-ins only; own frames are one sheet size, so their block is drawn as made) |
| `border_weight`, `inner_weight`, `line_colour`, `grid_labels` | as 050a | as 050a | |
| `title_block` | **retired** | — | 050a's one-word choice. A stored value is ignored and listed as unknown by `styles` (050a's rule for unknown fields) |

## 2. Where a page's sheet comes from (FP4)

The spec moves sheet size, margins and zones into **Frame…**. The rule, in one place
(`sheets::sheet_of`):

1. The page's frame (resolved `print.frame.style`) has `sheet` set → that sheet.
2. Else the page's `sheet` property (019) → that sheet.
3. Else the project's `settings.sheet` → that sheet.
4. Else A3 8 × 6.

Margins: the frame's `margins`, else 019's. The keep-out strip at the bottom of the frame is the
block's height (built-in: 40 mm, so nothing moves), replacing `TITLE_BLOCK_MM` at its call sites.

So an own frame decides its pages' paper, and built-ins keep today's behaviour. When a page has its
own `sheet` property and its frame sets another, the frame wins and Checks says so
(`frame-sheet-differs`). Settings and the inspector show the sheet as grey text "A3, from the frame
A3 Northfield" (grey text is read from the drawing). 054 decides whether a page type sets the frame
or the sheet. Either way this function is the one place it lands (Q2).

## 3. The built-in house block

The drawing review set the house style: a revision grid (rev, ECR, drawn, date, checked,
approved); a status field in red that must not stay on a draft word at issue; the function and
location; sheet, next sheet and total counters; the drawing title and the drawing number. The best
sets also had a logo with a short property line. The look is a thin frame with zones on all four
sides and centre marks. Nothing below copies any drawing: it is our own arrangement of those
contents, and it carries no company name or wording. It will be the border of the public examples.

The built-in `sheet` frame takes this look (FP3; the old 019 layout goes, pre-v1, as 051 FP3).
Block height 40 mm, as today, so no device, reference or table moves. On A3 (frame 400 mm wide),
from the right edge (widths in mm; rows from the top):

| Column | Width | Rows (height) | Field (binding) · look |
| --- | --- | --- | --- |
| Sheet counters | 30 | Page (15): `page:number` 7 bold centre · Next (12.5): `page:next` 2.5 centre · Of (12.5): `page:total` 2.5 centre | |
| Drawing | 90 | Page title (15): `page:title` 3.5 bold · Drawing no. (12.5, 70 wide): `project:drawing_number` 3.5 bold, Rev (12.5, 20 wide): `revision:rev` 5 bold centre (with 033's pending marker) · Function (12.5, 35): `page:function` 2.5, Location (12.5, 35): `page:location` 2.5, Size (12.5, 20): `print:sheet` 2.5 centre | |
| Project | 80 | Logo and owner line (15): an empty logo box, `project:company` 1.8 under it · Project (12.5): `project:title` 3.5 bold · Customer (12.5, 45): `project:customer` 2.5, Status (12.5, 35): `project:status` 2.5 bold **red** | |
| Revisions | the rest (200 on A3) | A revision table: header + 7 rows of 5 mm, newest at top; columns from the project's revision columns (033) | |

Captions are 1.8 mm in `ecad.frame-label`. Values read the frame's text styles (Standards ▸ Text
styles still changes them on built-ins). The sizes above are the built-in text styles' sizes today.
On a larger sheet only the revision table widens (`block: bottom_full`). Zones stay the project's
(8 × 6 on A3, columns numbered, rows lettered, as the owner chose in round 2), labelled on all four
sides, with centre marks on.

Duplicating the built-in (§4.6) writes this layout, computed for the chosen sheet, as an own frame,
so the user starts from the house block rather than from nothing.

### 4.2 Draft and Save

The editor edits a **draft** of the record (048's pattern): nothing is written while editing, the
editor has its own undo (Ctrl+Z, Ctrl+Y), and the draft is kept in eframe storage under
`title_block_drafts` (per project, at most 8) so a crash loses nothing. **Save** writes one
transaction (`SetStyle`). The right panel header shows the consequence before Save: "Saving changes
10 pages." (050's consequence line). **Discard** asks only when the draft changed: "Discard the
changes to A3 Northfield?" Discard / Keep. Leaving the tab keeps the draft and marks the row with a
dot (Q4: live writes instead).

### 4.4 The right panel per selection (board 3.05)

Header: the item's name in `ui_type.object` ("Drawing number") and a grey line ("Field · A3

**Value** (fields only)
- *Filled from*: a drop-down grouped Project / Page / Revision / People / Print, then "Project

- *Shows*: grey text, the value on the sample page, with "on page 2" at the right. With Sample off:
  "—".
- *If empty*: Leave blank · Dash · Missing mark (033's "?" box) · Text… (≤ 32 characters).

**Look** (fields and texts)
- *Label*: a toggle and its text (fields; on by default with the row's name).
- *Size*: segmented 1.8 · 2.5 · 3.5 · 5 · 7 mm (cap height). The board shows four; 7 is the page
  number's.
- *Bold*: toggle. *Align*: Left · Centre · Right. *Colour*: Ink · Red.
- Text items have *Text* (≤ 256 characters) above Size.

**Box** (every item; mm, from the block's bottom-left)
- *Position* x, y and *Size* w × h. Typed values snap to 0.1 mm; out of the block refused in place:
  "Keep it inside the block (180 × 40 mm)."
- Lines show *From*, *To* and *Weight* (Thin · Thick: the frame's inner and border weights).
- Revision tables add *Rows* (1–20), *Header* toggle, *Newest* Top · Bottom, and grey "Columns from

### 4.5 Tools

| Tool | Key | Does |
| --- | --- | --- |
| Select | V | Click picks the top item; Shift adds; drag on empty space picks by window. Drag moves (snapped); handles resize boxes. Arrows nudge 1 mm (Shift: 5 mm). Delete removes. Ctrl+D duplicates 5 mm down-right. Esc clears the selection |

**Snap** (on by default): points snap to 1 mm, and to item edges and line ends within 1.5 mm, shown
by a `sheet.connection_point` dot. **Sample** (on by default): fields show this project's values on

binding name in `sheet.ink_2` ("Drawing number").

The canvas: paper `sheet.sheet`, items in `sheet.ink`, field boxes dashed 1 px `shell.accent`
(selected: solid 2 px with handles), the selected item's name tag above it ("Drawing number ·

with "…" (019's `fit`), and the box gets a `sheet.warning` corner mark.

### 4.6 The list's actions

- **+ Title block**: a menu "From the built-in, for A3 / A2 / A1 / A0 / this project's sheet" and
  "Blank, for …". Makes an own frame in the project layer named "A3 title block" (unique by suffix),
  selects it, opens the editor. One transaction (`titleblock` new).
- **Import DXF**: pick a DXF, then a sheet size. Lines, polylines, arcs, circles, solids and texts
  become items; blocks are exploded (depth ≤ 8); everything else is skipped and counted. Texts stay
  static: the user turns one into a field with **Make field** (right panel of a text), which keeps
  its box and look. The import fits the drawing's extents into the frame's block area at 1:1 when it
  fits, else refuses: "The drawing is 260 × 60 mm; the block area of A3 is 400 × 40 mm. Scale it in
  the DXF first." One transaction (Q5).
- Row context menu: Rename, Duplicate for…, Promote to standard, Use for this project, Delete…
- Built-in rows are read-only: the right panel says "Built-in. Duplicate it to make your own." with
  **Duplicate for…**.

## 6. Logos

0.2.2 logos are **vector**: a DXF drawing (the company's logo exported from any drawing program),
stored in the block as primitives, so it prints in every output today and works on wasm. Refused in
words: "The DXF has no drawing in it.", "The logo has 3 400 shapes; 2 000 at most. Simplify it
first.", "This file is not a DXF we can read: <reason>." Texts in a logo use the sheet font.

Raster logos (PNG, JPEG) need two upstream changes to CADCraft (images from bytes rather than a
path, and images written to PDF) and the container's `assets` table, which exists and is unused. That
is a follow-up with its own owner approval (Q3).

| `print` | `sheet` (A3, or W × H) | The page's sheet |

A key not in the list for its source, or a source word not known (a newer file), draws as empty
and gives one `title-binding-unknown` Info row per frame. `print:date` (the day of printing) is out
of scope: it would change every frame each day (§13).

**Project info**: the fields that bound blocks in use read (`project:<key>` that are not the four
built-ins) are the "title block fields" the spec puts in Settings ▸ Project info. That screen's
brief lists them from `titleblocks`' `keys` (§9); this brief adds no Settings UI.

## 14. Format proposals (overseer)

- **FP1** `StyleRecord.body: Option<StyleBody>` with `StyleBody::TitleBlock(TitleBlockLayout)` (§1.2):
  additive, omitted when `None`, so older files are unchanged; an unknown body tag is kept raw and
  ignored. Arms: apply (none new: `SetStyle` writes the whole record), diff, merge (whole record, as
  050a), invariant (body only on `frame`), file (v1 and v2), bounds (§1.3). No new op, no new
  `ObjectRef`. Considered and rejected: items as text fields (64 fields × 256 characters is too small
  and untyped); a separate `Document.title_blocks` map (a second model).
- **FP2** `frame` fields `sheet`, `margins`, `centre_marks`, `block` (§1.4). Fields are strings, so
  no format change; listed because `sheet` changes where pages get their paper (FP4).
- **FP3** The built-in `sheet` frame is redrawn to the house block (§3), and 050a's `title_block`
  field is retired. Every existing drawing changes look; nothing moves. Pre-v1, as 051 FP3.
- **FP4** `sheets::sheet_of` / `grid_of` / `keep_out` resolve a page's sheet, margins and keep-out
  strip through its frame (§2), replacing `Grid::of`, `ecad_model::sheet::sheet_of` and
  `TITLE_BLOCK_MM` at their ten call sites. `ecad-model`'s functions stay for the model's own use.
- **FP5** The built-in revision columns gain `ecr` ("ECR", 18 mm) after `rev` (Q6). A registry
  default change; projects that set `revisions.columns` keep theirs.

No raster asset, no op, no `ObjectRef`, no `.ecad` table change.

**Overseer rulings (2026-11-14): FP1–FP5 approved as written.** FP3: redrawing the built-in frame to
the house block is accepted before v1.

## 15. Owner questions, each with a recommendation

**Owner answers (Carl, 2026-11-14): all as recommended.** Q3: DXF logos only in 0.2.2; PNG/JPEG
image support comes in 0.4.0.

1. **One catalogue or two?** A frame style holds its block (one row per block and sheet), or blocks
   are their own catalogue picked by frames. **Recommend one** (§1.1): the spec says one frame per
   sheet size, and Duplicate for A2 covers reuse.
2. **Sheet from the frame.** When an own frame sets a sheet, it decides its pages' paper, over a
   page's own `sheet` (with a Checks row). Portrait and A4 are left to 054. **Recommend yes**, and
   ask 054 to land portrait/A4 in `SheetSpec`, since the board's "A4 portrait" row needs it.
3. **Logos in 0.2.2 are DXF vectors**; PNG/JPEG follow with an upstream CADCraft change (images from
   bytes, images in PDF) and the container's `assets` table. **Recommend yes**: a raster logo
   today would vanish from every PDF.
4. **Draft and Save, or live?** Edits go to a draft and Save writes once with "Saving changes 10
   pages." first, or each edit writes at once. **Recommend draft and Save** (048's pattern; one
   undo step per save; no page rebuilds while nudging).
5. **Import DXF** for a whole title block in 0.2.2 (board 3.05 shows the button). **Recommend
   yes**, in part c, geometry and texts only, at 1:1.
6. **ECR column by default.** The house style's revision grid has ECR. Add it to the built-in
   revision columns. **Recommend yes**; projects that set their columns keep them.
7. **Status left on a draft word at issue.** The review says a released set must not still carry a draft status.
   **Recommend no check here**: which words count is the company's rule; Issue (033) can ask later.
8. **Red** as the only colour besides ink in Look. **Recommend yes** (house style: red status);
   more colours later if asked.
9. **The built-in replaces 019's look** (FP3) rather than sitting beside it as a second built-in.
   **Recommend replace**: one built-in to maintain, and the public examples get the house border.
10. **Size 7 mm** added to the four sizes on the board, for the page number. **Recommend yes**.
