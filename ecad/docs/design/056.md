## 1. Goal and words

Goal: **the PLC list is the signal list of the project: every channel has a PLC tag, a safe state
and what it drives, and the list stays in step with the PLC programming project through a tag
table that goes out and comes back.**

| Word | Meaning |
| --- | --- |
| Signal | A channel of a card, with its tag. One row of the list. |
| Tag | The channel's name in the PLC program (`Valve_Inlet`). Stored on the card as `plc.ch.<i>.tag`. Not the device tag (`-A03`): in the UI the column is **Tag** inside the PLC tab only, and the right panel says **PLC tag**. |
| Tag table | A file of PLC tags: name, address, data type, comment. What PLC tools import and export. |
| Snapshot | The last tag table imported, kept in the project (FP2). The PLC column compares against it. |
| Sync state | Per channel: in sync, differs, not in PLC, only in PLC, or nothing to compare (§6.3). |
| Safe state | What an output does when the PLC stops or the bus is lost: Off, On, Hold, or a value. |

## 4. The channel table

### 4.1 Card header (over the table)

One line, `ecad.plc.cardhead`:

- Left: `<tag> · <kind> · slot <n>` (`ui_type.title`), then `<count> channels, <in use> in use,
  drawn on page <p>` (`pages 4, 5`; `not drawn yet`) in `ui_type.small`, `shell.text_2`.
- Right, in this order:
  - **Sync chip** (`ecad.plc.syncchip`, §6.4).
  - **Compare** (`ecad.plc.compare`): opens Compare for this card (§6.5). Greyed when no snapshot

  - **Export tags** (`ecad.plc.exporttags`): §6.6, scope this card's rack.
  - **→ Page 5** (`ecad.plc.gopage`): goes to the card's first run (051's link). Absent when not

`All cards` scope: the header reads `All cards · <n> cards, <channels> channels, <in use> in use`
and the chip counts the project.

Footer of the table (039's footer row): `input` chip `you set it here`, `grey text read from the
drawing` (rev 3's legend), and at the right §8's sentence.

### 4.3 Tag (new channel property)

- Key `plc.ch.<i>.tag` on the card (FP1), ≤ 128 characters, trimmed. Allowed: letters, digits, `_`,
  and anything the tag table formats accept (§7.3); a tag with characters a format refuses gets a
  Check, not a refusal (§9), so typing is never blocked by a target the user may not use.
- Unique per PLC (a rack and its cards; cards in no rack are one PLC together): a second channel
  with the same tag is refused with `Tag "Valve_Inlet" is already -A03 channel 2 (%Q2.2).` (case
  insensitive, as PLC tools compare).
- Empty: the channel has no tag. Export leaves it out (§6.6) unless **Make tags** fills it (Q8).
- **Make tags** (`ecad.plc.maketags`, in the card header's `…` menu; `plcmaketags {card | rack}`):
  fills empty tags of used and reserved channels from their descriptions (`Inlet valve open` →
  `Inlet_valve_open`, spaces and dashes to `_`, other characters dropped, a digit first gets `_`
  before it, duplicates get `_2`, `_3`), one transaction. Echo `Made 7 tags on -A03.`

### 4.4 Safe state (new channel property)

- Key `plc.ch.<i>.safe` (FP1). Outputs only (DQ, AO, IO-Link outputs). Inputs show `—` (read).
- DQ values: `off`, `on`, `hold` (words in the choice: `Off`, `On`, `Hold`).
- AO values: `hold`, `min`, `max`, or a value in the channel's units as text ≤ 16 (`4 mA`).
- Unset: the default from the registry (`plc.safe.dq` `off`, `plc.safe.ao` `hold`, §11), shown in
  `shell.text_2` with the origin badge (042) `default`. Setting the default's value writes it (the
  row is then set here; the badge goes).
- Not exported to the TIA tag table (no column for it, §7.3); exported in the generic CSV and the
  release CSV; printed on the I/O sheet (Q9). The Tests brief (0.2.3) reads it for the stop tests.

### 4.5 Drives (from the drawing)

The device and pin the channel connects to, following the net **through** pass-through devices:

1. Take 045's targets (tagged devices on the channel's nets).
2. Drop targets that are pass-through: terminal strip positions, connector halves (plug, socket),
   cable cores, link bars. Keep the rest (coils, valves, lamps, sensors, other cards).
3. If a pass-through device's two sides are on different nets (a terminal's outside on another net
   than its inside), follow to the other side's net once per pass-through, at most 8 hops, and
   repeat 1–2 there. Cycle-safe (visited set).
4. Show the first kept target as `-K03:A1`, more as `-K03:A1 +1` (tooltip lists all, with places).
   No kept target but pass-throughs: show the last pass-through (`-X10:3`) in `shell.text_3`.
   Nothing: empty.

The worker confirms in the code whether terminal sides share a net (`ecad_model::wiring`) and
writes the rule against what is there (house rule 3). For inputs the header still reads
**Drives**; tooltip on the header: `For outputs, what the channel switches. For inputs, what feeds
it.` (Q7 offers *Wired to* instead.) Click: goes to that device's point.

### 4.6 Test column (designed here, filled by the Tests brief, 0.2.3)

Read-only. Values, from a provider the Tests brief supplies (`plc::signals::TestState`, an enum
056 defines with only `None` produced):

| Value | Looks | Meaning |
| --- | --- | --- |
| `✓ C` | `shell.ok`, revision letter `ui_type.small` | Passed at revision C |
| `↻ retest` | `shell.provisional`, dotted underline | Passed, then something it depends on changed |
| `⊘ failed` | `shell.error` | Last result failed |
| `⊘ blocked` | `shell.warning` | Cannot run yet (not in PLC; duplicate address) |
| `—` | `shell.text_3` | No test yet |

In 056 every row shows `—`; the column is shown (board) with the header tooltip `Tests come with
the Tests tab.` Q11 offers hiding it until then. Blocked uses §6.3's state: the Tests brief marks a
test blocked when the channel is *not in PLC*.

## 6. PLC sync

### 6.1 The loop

```
 ECADCraft ──Export tags──▶ tag table file ──(user imports it in the PLC tool)──▶ PLC project
     ▲                                                                                │
     └────────────Import tags◀──── tag table file ◀──(user exports from the PLC tool)─┘
```

ECADCraft never talks to the PLC tool directly; the file is the interface (Q1). Export changes no
data. Import records a snapshot (and, if asked, takes names), in one transaction.

### 6.2 The snapshot (FP2)

- Project property `plc.sync.table`: the imported tags as our canonical CSV text (§7.2's generic
  columns: `name,address,type,comment`), sorted by normalised address then name. Only tags with an
  I/O address (`I`, `Q`, `IW`, `QW`, `ID`, `QD`, `IB`, `QB` and the German mnemonics `E`, `A`,
  `EW`, `AW`…, with or without `%`, `P` periphery prefix, `:P` suffix); memory, data-block and
  timer tags are counted in the echo and not kept.
- `plc.sync.source`: the file name (no directory, house rule 10) and the format.
- `plc.sync.at`: the import time as RFC 3339 UTC (`chrono`), shown in local time.
- Caps (hostile input): 20 000 tags, names ≤ 128, comments ≤ 256, file ≤ 16 MB; more is refused
  with words (`The file has 31 204 I/O tags; at most 20 000 are read.`). The worker checks the
  property value size limit in `ecad-model` and stops to ask if 20 000 rows do not fit (house
  rule 3).
- One snapshot per project (one PLC program). A project with several PLCs: Q2.

### 6.3 Matching and states

Addresses are normalised before comparing: strip `%`, spaces and `:P`; `E`→`I`, `A`→`Q`, `PE`→`I`,
`PA`→`Q`; drop the IEC size letter `X` on bits (`%IX0.0` → `I0.0`); upper case. ECAD's own address
(045 style, typed or live) is normalised the same way, so every 045 style except `slot` and `none`
matches. Names compare exactly (case sensitive; the uniqueness rule of §4.3 is case insensitive).

Per channel, in this order:

| State | When | PLC column | Counted |
| --- | --- | --- | --- |
| nothing to compare | no snapshot yet | `—`, tooltip `No tag table imported yet.` | no |
| no address | the channel has no address (style `none`, `slot`, overflow) | `no address` `shell.text_3` | no |
| in sync | a PLC tag at the address, same name | `✓ in sync` `shell.ok` | no |
| differs | a PLC tag at the address, other name | `⚠ <PLC name>` `shell.warning` | yes |
| moved | no tag at the address, but the channel's tag is in the PLC at another address | `⚠ at <PLC address>` `shell.warning` | yes |
| not in PLC | used or tagged channel, nothing at its address, its tag nowhere | `ⓘ not in PLC` `shell.error` | yes |
| only in PLC | a free channel (no tag, not used) with a PLC tag at its address | `⚠ only in PLC: <name>` `shell.warning` | yes |
| free | free channel, nothing in the PLC | empty | no |

Data type mismatch (a `Bool` at a word address, `Int` on a DI) and comment differences are shown
in Compare but not counted (Q4). PLC tags at addresses no card has are **not on any card**: counted
on the project total and listed in Compare's last group; they have no row in the channel table.

### 6.4 The chip

`ecad.plc.syncchip`, a pill (037) in the card header:

| Case | Words | Tone |
| --- | --- | --- |
| no snapshot | `PLC: not imported` | `shell.text_3` |
| this card counts 0 | `PLC: in sync` | `shell.ok` |
| n > 0 | `⚠ PLC: n differences` (1: `difference`) | `shell.warning` |

Tooltip: `Compared with <source>, imported <local time>. Project: <m> differences.` Click: opens
Compare for this card. In `All cards` the chip counts the project, *not on any card* included.

### 6.5 Compare

Opens in place of the channel table (the strip stays; `Esc` or **Back to the list** returns),
`ecad.plc.compare.view`. Not a dialog: the table area changes its column set (039), like Reports'
preview. Two sides with the address between them:

  %I8.0. Place a card or change the PLC.`
- Writes off: Take buttons greyed with `Writes are off.`; Export works.

### 6.6 Export tags

**Export tags** (card header) and **Export ▸ Tag table…** (tab bar Export menu, which also keeps
`Copy as CSV`, today's behaviour):

1. The app's path dialog (`FileDialog`) with a format choice: **TIA Portal tags (.xlsx)** and
   **Tag table (.csv)** (Q3), the last used format and folder remembered per project while the app
   runs, the file name `<project> PLC tags.<ext>`.
2. Scope: the rack of the selected card (`rack`), or **All racks** (a toggle in the dialog row).
3. Rows: used and reserved channels with a tag and an address; one row each (IO-Link: one per
   direction). Data type from the card type: DI, DQ → `Bool`; AI, AO, RTD → `Int`; IO-Link →
   `Word` (Q4 asks about per-channel types). Comment = the description.
4. Left out, counted in the echo: channels without a tag (`3 without a tag — Make tags fills
   them`), without an address, and tags a format refuses (§7.3).
5. Echo: `Wrote 38 tags of rack -A01 to Pump station PLC tags.xlsx; left out 3 without a tag.`
6. Writes no project data; allowed with writes off. MCP: `plcexport` (§10).

### 6.7 Import tags

The tab bar's **Import an I/O list** becomes **Import tags** (`ecad.plc.import`; the board's
words are kept if the owner prefers, Q13):

1. Path dialog; the format is guessed from the extension and content (§7.1), shown, changeable.
2. **Preview**, not yet written (`plcimport {path, dry_run: true}`), in Compare's layout against
   the new file, with a summary line `412 tags read; 96 with an I/O address; 2 differences on
   -A03, 1 not on any card. 316 memory and data-block tags skipped.` and a choice:
   - **Keep the snapshot only** (default): compare, change nothing else.
   - **Also take the PLC's names** where they differ (as Use PLC's on every *differs* and *only in
     PLC* row).
3. **Import** writes one transaction `Import PLC tags` (snapshot property, source, time, and any
   taken names). **Cancel** / `Esc` writes nothing.
4. Refusals in words: unreadable file, unknown format, too many tags (§6.2), a header the format
   needs missing (`The file has no "Logical Address" column.`), a row with a bad address is
   skipped and counted (`4 rows with an address that is not I/O were skipped.`).
5. Writes off: refused with the brief 011 sentence.

Import never adds cards, channels, or addresses (rev 3 calls this tab's importer "Import an I/O
list"; building cards from a PLC hardware configuration is out of scope, §15).

## 7. Formats

### 7.1 Which first, and why

| Order | Format | Why |
| --- | --- | --- |
| 1 | **Generic CSV** (`name,address,type,comment`, UTF-8, comma, header row) | No dependency, works in wasm, opens in any spreadsheet, every PLC tool can be mapped to it by a user in a spreadsheet. The release already writes CSV (027). Tests and agents use it. |
| 2 | **TIA Portal PLC tags (.xlsx)** | Siemens is the most common PLC in the UK process and water work this project targets, and the board's addresses (`%Q2.0`, `%IW64`) are Siemens-shaped. TIA Portal imports and exports PLC tag tables as `.xlsx`, so the file round-trips without the user editing it. Needs an XLSX reader and writer (§7.4). |
| later | Rockwell Studio 5000 tag CSV; CODESYS / TwinCAT (PLCopen XML); Siemens STEP 7 Classic symbol table | Each is a mapping onto §7.2's rows; added when an owner project needs it. Q3 asks which comes next. |

Detection on import: `.xlsx` → TIA reader; `.csv` with the generic header → generic; a `.csv`
with TIA's column names (TIA can also be saved as CSV by a user) → TIA mapping; anything else →
refused with the list of known formats.

### 7.2 Generic CSV

Columns, in order: `name, address, type, comment`, then, on export only, `card, channel, safe,
drives, page` (ignored on import). Addresses written in the project's style normalised to `%`
form (`%Q2.2`). Fields quoted per RFC 4180. Import accepts `;` as separator when the header uses
it (spreadsheets in some locales), and a UTF-8 BOM.

The release's ` I/O list.csv` (045c) gains `tag`, `safe` and `plc` (the sync state word)
columns at the end.

### 7.3 TIA Portal PLC tags

Sheet **PLC Tags**, header row with the columns TIA Portal writes for a tag table: `Name`, `Path`
(the tag table name), `Data Type`, `Logical Address`, `Comment`, and the HMI flags. 056 writes
`Name`, `Path` = `plc.tia.table` (§11, built-in `ECADCraft`), `Data Type`, `Logical Address`
(`%Q2.2`, `%IW64`), `Comment`; HMI flags `True`. On import it reads `Name`, `Data Type`, `Logical
Address`, `Comment` by header name (column order not assumed), from every sheet named `PLC Tags`.

Name rules applied on export: TIA refuses some characters and duplicate names; a tag containing
`"` or a control character, or longer than 128, is left out and counted (Check `plc-tag-chars`).

**Clean room.** The column names are the user-visible interface of the file, not code or text
copied from Siemens. The worker builds the reader and writer from a synthetic file the owner
exports from TIA Portal with a dummy project (Q15) and from public documentation of the tag table
import; nothing from a Siemens installation goes in the repository except that synthetic file
(owner's own work, CC0, recorded in `ATTRIBUTION.md` if kept here).

### 7.4 Dependencies (only if Q3's XLSX is yes)

Two pure-Rust crates, to be checked by the worker before adding (house rule: licence allowlist,
wasm build):

- an XLSX writer, e.g. `rust_xlsxwriter` (MIT OR Apache-2.0);
- an XLSX reader, e.g. `calamine` (MIT).

Both must build for wasm (`cargo xtask wasm`) or sit behind a native-only feature with the wasm
build saying `Only CSV tag tables are available in the web version.` The worker reports the
licences and transitive dependencies in the PR. This is **Stop and ask** territory only if a
licence is outside the allowlist.

### 12.2 Sync states

A kept index `Sync { by_address: HashMap<Addr, TagRow>, by_name: HashMap<NameKey, Addr>, states:
BTreeMap<(Card, u32), State>, no_card: Vec<Addr> }`, built once from `plc.sync.table` when it
changes. A channel's state is recomputed when its tag, its address (a card move, a style change: 045
already reports which cards' addresses moved) or the snapshot changes. *Not on any card* is
recomputed when a card's address block changes or the snapshot changes. Counts are kept per card
and patched.

### 12.3 Pages

`plcrack` redraws on 051's triggers plus a change of a tile's kind words or description. The I/O
sheet adds Tag and Safe (Q9) and redraws on their keys. No other page changes.

## 14. Format proposals (for the overseer)

Pre-v1: no compatibility work. No new op, no record field, nothing in `ecad-model`.

- **FP1. Channel keys** `plc.ch.<i>.tag` and `plc.ch.<i>.safe` on cards (045's FP3 pattern),
  with `setprop_rule` value checks (§4.3 uniqueness and length, §4.4 values).
- **FP2. Project properties** `plc.sync.table` (the snapshot as canonical CSV text, ≤ 20 000 rows),
  `plc.sync.source`, `plc.sync.at`. The first project property that holds a table. Merge (020)
  treats it as one value: a conflict keeps one side whole (newer import wins on "take theirs"). The
  worker confirms the property value size limit first.
- **FP3. Import is ops.** `plcimport` records `SetProperty` ops (project snapshot keys, and with
  `take: names` the channel tag keys) in one transaction labelled `Import PLC tags`; undo restores
  the previous snapshot and names. `plctake` and `plcmaketags` likewise.
- **FP4. Registry entries** of §11, and the address style value `percent` (Q5).
- **FP5. Dependencies** (Q3): an XLSX writer and reader, licences in the allowlist, wasm build kept.
