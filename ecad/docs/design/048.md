## 1. Goal and words

A designer draws a symbol once, in the project, with connection points, text slots and
defaults, places it like a built-in, and edits it later knowing exactly what each placed copy
will do.

| Word | Meaning (glossary) |
| --- | --- |
| **Symbol** | An embedded definition people can place. *Built-in* (a starter), *project* (made here) or, later, *library* |
| **Project symbol** | A symbol made or edited in this project. Its source reads "Project" |
| **Version** | One saved content of a symbol. Versions of one symbol share a **lineage**; the newest is what Place uses |
| **Placed copy** | One symbol representation showing a version of the symbol |
| **Text slot** | Where a device text (tag, description, rating…) of a placed copy goes, in the symbol's frame |
| **Origin** (tool) | The symbol's base point, (0, 0) of its frame: the point the cursor holds when placing |
| **Update available** | A placed copy whose symbol has a newer version in the project |
| **Clash** | A change an update cannot make to a placed copy without losing a connection (§6.2) |

The tool is called **Origin**, as in the spec. Where a person sees provenance it is called
**Source** (Built-in, Project, a library's name), never "origin", so the two do not meet.

## 2. Model

### 2.1 No new object

A project symbol is an `EmbeddedDefinition` like a starter: the builder writes the same record a
library will hold (question 2 of the roadmap review: "the definitions it makes are the same ones a
library will hold"). What a starter keeps in catalogue code, a project symbol keeps in its
definition (`defaults`, FP2), because nothing else in the file can hold it.

### 2.2 Lineage and version (FP3)

| | Starter | Project symbol | Edited starter |
| --- | --- | --- | --- |
| `origin.library` | `STARTER_LIBRARY` | `PROJECT_SYMBOLS` (fixed) | `PROJECT_SYMBOLS` |
| `origin.definition` (the lineage) | the starter's fixed ID | allocated at the first save, kept by every later version | allocated when the copy is first saved |
| `origin.library_seq` (the version) | 1, or 2 (044) | 1, 2, 3… | 1, 2, 3… |
| `origin.content_hash` | content hash | content hash | content hash |
| `derived_from` | none | none | the starter's origin at the time (FP4) |

- **Lineage** = (`origin.library`, `origin.definition`). Each version is its own `DefinitionId`
  (§20.3: versions coexist; LIB-01).
- **Newest** version of a lineage = highest `library_seq` embedded. Place uses it.
- A save whose content hash equals the newest version's is refused: `Nothing changed.`
- Because `origin` is always set on a project symbol, the file reader's content-hash check
  (`check_content_hash`) covers it with no new code.
- `PROJECT_SYMBOLS` is one fixed `LibraryId`, not the project's ID: a project symbol pasted into
  another project (today's copy rules) stays a project symbol there; 2.1 adds "promote to
  library", which gives it a library origin and keeps the old one in `derived_from`.

### 2.3 Text slots (FP1)

```
TextSlot { text: String, at: Pt, h: Left|Centre|Right, v: Bottom|Middle|Top, rotation: f64 }
```

- `text` names the device text the slot places: `tag`, `description`, `rating`,
  `rating.<label>`, `part_number`, `maker`, `article_number`, `function`, `location`. Any other
  word is refused (Q5 asks about free properties). One slot per text.
- `at` is in the symbol frame; `rotation` in radians, counter-clockwise (proposal §4.2's units
  rule: the builder takes degrees and converts once).
- A slot carries **no size or style**: lane T's text styles decide (031). It is an anchor, as
  034's `Anchor` is.
- `symbols::anchors_of(doc, def)` gives a placed copy's anchors: the definition's slots if it has
  any, else the starter rule of 034 §10. Every reader of anchors calls it (one call in
  `devices.rs`; lane T's placement later).
- A text the user moved on the page keeps its stored offset from its slot (Q2's rule), so a slot
  moved by an edit moves every text that was not moved by hand.
- Fixed words drawn inside a symbol ("POWER", "DI", a pin group heading) are plain `Text`
  graphics, not slots.

### 2.4 The symbol's defaults (FP2)

`Definition.defaults` holds the values a starter keeps in the catalogue. Keys (all optional
except `key` on a project symbol, and `prefix` when `join` is `device`):

| Key | Value | Used for |
| --- | --- | --- |
| `key` | 1–16 characters, letters, digits, `-`, `_`; unique among starters and the project's lineages (FP7) | `place {symbol}` and Find Symbol |
| `prefix` | a tag prefix (`devices::valid_prefix`) | the built-in of `symbol.<key>.prefix` |
| `description` | text, 1–200 characters | the built-in of `symbol.<key>.description`; written on a new device |
| `rating` | text, 1–40 characters | the built-in of `symbol.<key>.rating`; written on a new device |
| `join` | `device` or `part` | how a placement joins a device (§5.2) |
| `aliases` | comma-separated words, at most 8 | Find Symbol |
| `family` | one of 034's family words, or `project` | the Library tree and Find Symbol grouping |

Connection-point default labels stay in `TerminalDef.label`; bridges stay in `bridges`. Nothing in
`defaults` is read for an edited **starter** except what its copy changed: the copy writes every
key, so it is self-describing.

### 2.5 Connection-point keys are stable

The builder gives a new point the next free key (`1`, `2`, … in drawing order) and never reuses a
key within a lineage, even after the point is deleted (the index knows every key any version
used). A point keeps its key when moved or relabelled. So an update maps old to new **by key**,
with no guessing. A promoted or copied starter keeps the starter's keys.

## 3. The builder (Library workspace, part b)

### 3.1 Where it lives

No new panel and no dialog. The Library workspace's main view is either the **browser** (today's
symbol search, later 2.2's viewer) or the **builder**. In builder mode:

| Region | Contents |
| --- | --- |
| Tool strip (48 px) | Select (V), Draw (D: Line, Polyline, Rectangle, Circle, Arc), Text (T), Connection point (C), Text slot (S), Origin (O) |
| Main view | The symbol on an empty grid at print size, `sheet.sheet` ground, `sheet.grid` dots every 2.5 mm, a heavier dot every 5 mm; the Origin as a `sheet.ink_2` cross, 4 mm arms; a breadcrumb "Library ▸ New symbol" or "Library ▸ <name> v<n>" |
| Right panel (380 px) | **Details**: name, key, source, version; defaults (§2.4) with origin badges; connection points (key, label) as rows; text slots as rows; **Missing** list with a button per item; Save, Save as new, Cancel |
| Drawer | Closed while drawing. On Save of an edit: "Before saving" (§6) |
| Left panel | Unchanged (navigation) |

Element names: `library.builder`, `library.builder.canvas`, `library.builder.tool.select|draw|
text|point|slot|origin`, `library.details`, `library.details.name|key|prefix|description|rating|
join`, `library.details.points.row.<key>`, `library.details.slots.row.<text>`,
`library.details.missing.<item>`, `library.details.save|saveas|cancel`.

### 3.2 The draft is temporary state

The builder draws on a **scratch drawing** that is not a project page: no transaction, no
history, nothing in the file (P5). The Draw tools are the Draw group's (CADCraft's line,
polyline, rectangle, circle, arc on the scratch session); Text writes plain `Text` graphics.
Undo and redo inside the builder (Ctrl+Z, Ctrl+Y) act on the draft only. The draft is kept in
eframe storage under `symbol_drafts` (per project ID, at most 8 drafts), so leaving the workspace
or a crash does not lose it (Q3). **Save** is the only write, one transaction.

### 3.3 New symbol (screen g)

1. Library ▸ **New symbol** (button in the browser header, `library.browser.new`; Ctrl+K "New
   symbol"). The builder opens empty; Details shows name `New symbol`, key empty, join `device`,
   and Missing: *Name*, *Key*, *A connection point*, *A tag slot*.
2. Draw with the Draw tools. Snaps: grid, ends, midpoints, centres (CADCraft's object snaps).
3. **Connection point** (C): click on the grid. The point is drawn as a `sheet.connection_point`
   ring (8 px) with its key above in `ui_type.small`; the intent line says "Adds point 3. Label?"
   and a typed label (Enter keeps none) is its default label, shown in ink at
   `sheet_type.label` beside it. Points snap to the point grid (`symbol.point-grid`, built-in
   5 mm, Q6); a click off it or on another point is refused at the cursor (`A point goes on the
   5 mm grid.`, `Point 2 is already here.`).
4. **Text slot** (S): pick which text (chips: Tag, Description, Rating, Part number, Maker,
   Article number, Function, Location; the used ones greyed), then click where. The slot shows a
   sample in `sheet.ink_2` (`-K01`, `Description`, `10 A`…) at the text style's size, with a
   dashed `sheet.placement_preview` box and a 2 px anchor dot. Drag to move; R turns it 90°;
   H/V step the alignment.
5. **Origin** (O): click to set the base point; the symbol's geometry is shifted so the point is
   (0, 0). Default: the first connection point.
6. Details: type name, key (checked as typed: `-K` style is refused, a used key says whose),
   prefix, description, rating, join (`A device of its own` / `Part of a device`).
7. **Save** is enabled when Missing is empty. Save embeds version 1 and returns to the browser
   with the new tile selected and the Place panel ready: "Placed next: <name>".

Esc in a tool ends the tool; Esc in Select with nothing selected does nothing (the draft stays).
Cancel asks only if the draft changed: `Discard the draft of <name>?` Discard / Keep.

### 3.4 States

| State | Looks like |
| --- | --- |
| Empty | Grid, Origin cross, hint in `shell.text_3` centred: "Draw the symbol, then add connection points and a tag slot" |
| Normal | Ink geometry, rings, slot samples; Missing list empty; Save enabled |
| Invalid | Missing list rows in `shell.warning` with a button each (Add a point → picks the C tool; Add a tag slot → picks S with Tag chosen; Name/Key → focuses the field); Save disabled with the reason as its tooltip |
| Read-only (writes off, or an agent session paused writes) | Builder opens; Save disabled: "Writes are off for this project." Drafts still kept |
| Editing a built-in | Banner row at the top of Details: "Built-in symbol. Saving makes a project copy; the built-in stays as it is." |

### 3.5 Validation (shared by builder and commands)

Refused with these words (the builder shows them in Missing or at the cursor):

| Rule | Message |
| --- | --- |
| Name 1–64 characters, no control characters | `A symbol needs a name.` / `The name is too long (64 characters at most).` |
| Key per §2.4, not a starter's, not another lineage's | `The key coil is a built-in symbol's; choose another.` / `The key valve2 is used by Valve, dual; choose another.` |
| A tag prefix when `join` is `device` | `A symbol of its own device needs a tag prefix (for example B).` |
| At least one connection point | `A symbol needs at least one connection point.` |
| A tag slot (unless `join: part`, whose texts are its device's) | `A symbol needs a tag slot.` |
| Points on the point grid, distinct | as §3.3 |
| Limits: 4 000 primitives, 512 points, 16 slots, coordinates within ±1 000 mm, finite | `The symbol is too large (4000 shapes at most).` … |
| Content equal to the newest version | `Nothing changed.` |

## 4. Make symbol (part c)

### 4.1 From plain geometry (screen j)

1. Select lines, polylines, arcs, circles and texts on a page (no meaning). The selection wheel's
   Right slot reads **Make symbol** (also Ctrl+K).
2. The Library workspace opens in the builder with the geometry moved so its bounding-box centre
   is on the nearest grid point at (0, 0) (Back returns to the page).
3. **Offers**, drawn dashed in `sheet.placement_preview`, nothing applied: a connection point at
   every free line end that is on the point grid and is not on another line; a slot for a text
   that looks like a tag (`-` + letters + digits) as Tag; other texts stay graphics. Each offer
   has Accept / Skip on hover; "Accept all" in Details.
4. Save shows one choice above the buttons: **Replace the drawing on page <n> with this symbol**
   (on by default, Q7). Saved with it on, the transaction also removes the selected items and
   places a new device of the symbol at the same spot (new component, next tag).

### 4.2 Promote a drawn component

A drawn-form component (from Convert to Component) is a Device on the wheel; its TopLeft slot
reads **Make symbol** instead of Edit symbol (§9.4). The builder opens with its items as
geometry and its connection points as points: **keys** are the component's terminal keys if set,
else their labels, else `1…n`; labels are their labels. Save replaces the drawn representation
with a symbol representation of the **same component**: component, terminal and wire IDs stay;
every wire stays attached (§5.4). If the component has other drawn representations, only the one
picked is promoted; the others stay drawn.

## 5. Placing and updating

### 5.1 Place

`place {symbol: <key>}` and Find Symbol accept a project key; it resolves to the lineage's newest
version. The placement is 018's: `EmbedDefinition` is never needed (the version is embedded),
`CreateComponent` with `definition` set, `AddTerminal` per key with the default label,
`LinkRepresentation`. The device gets `description` and `rating` from the registry (§7) when they
resolve to a value, and the prefix from `symbol.<key>.prefix`.

### 5.2 Joining

`kind_of_definition` returns, for a project symbol: `join: device` → `Kind::Fixed { exclusive:
true }`; `join: part` → `Kind::Fixed { exclusive: false }` (it joins a named device, like 034's
SSR output; labels fixed by the definition; a label already on the device is refused as for
starters). An edited starter keeps its starter's kind (contact numbering, channels…) because its
`derived_from` names the starter (§2.4: kind follows the source, Q4).

### 5.3 What an update writes, per placed copy (one transaction for all)

| Change | Ops |
| --- | --- |
| The copy shows the new version | `ModifyItem` (the `SymbolInstance.definition`) |
| The component's own definition was the old version | `SetComponentDefinition { before: old, after: new }` (FP5) |
| A point kept (same key) | nothing; if its default label changed and the terminal's label is still the old default, `RemoveTerminal` + `AddTerminal` of one ID with the new label |
| A point added | `AddTerminal` (new ID, the key, default label) |
| A point removed, unwired | `RemoveTerminal` |
| A point moved, wired | the wire end follows: `ModifyItem` of the route's end vertex (as a move does in `translate.rs`); the route's other vertices stay |
| The representation has connection points (a symbol that is not its component's own, I14) | `ModifyRepresentation`: points re-read from the new definition by key |
| A text slot moved | nothing stored: the text follows its slot (§2.3) |
| Superseded version now unused (project lineages only) | `RemoveDefinition` (FP8) |

The project's other derived views follow from these ops by their existing update maps (nets,
references, contact tables, BOM).

### 5.4 Promotion writes

`EmbedDefinition`; `UnlinkRepresentation` (drawn); `RemoveItem` per drawn item;
`AddItem` (the `SymbolInstance` placed at the drawing's spot, rotation 0, no mirror);
`LinkRepresentation` (symbol form, no connection points); `SetComponentDefinition { before:
None, after: new }`; `RemoveTerminal` + `AddTerminal` of one ID where a key is
written. Conductors and their attachments are untouched (DOC-03: connectivity is by ID).

## 6. Edit symbol and the review (screen k, owner answer 10)

### 6.1 Flow

1. **Edit symbol** on a placed symbol's wheel (or Library ▸ a tile ▸ Edit). The builder opens on
   the version that copy shows. Editing an older version than the newest asks first: `This copy
   shows v2; v3 is newer. Edit v3 / Edit v2.`
2. Edit as in §3.3.
3. **Save** opens the drawer's **Before saving** body (`drawer.symbol-review`) instead of saving:

   - Header: `<name> v3 → v4 · 12 placed copies on 7 pages · 2 would clash`.
   - One row per placed copy of the lineage (any version), grouped by page in page order:
     tag, page and zone, a **now** and an **after** thumbnail (64 × 64 px, ink only, the changed
     points ringed in `sheet.warning`), and one line on what changes: `Point 3 added · A2 moves
     2.5 mm, wire 24V-05 follows · label 4 → 14`. A clash row starts with a `sheet.error` disc:
     `Point 2 is removed; wire 105 is attached to it.`
   - A checkbox per row; rows that would clash cannot be ticked (tooltip: "Move or remove wire
     105 first").
   - Choice (radio): **Update all** · **Update selected** · **Save as a new symbol**.
     Pre-selected: Update all; **Update selected** with the clashing rows unticked when any
     row clashes (owner answer 10). Update all is disabled while a row clashes.
   - Buttons: **Save** (`drawer.symbol-review.save`), **Back to the drawing**. Clicking a row
     goes to that copy (Back returns).

4. Save writes one transaction: the new version and the chosen updates. Untouched copies keep
   their version and read "update available" (§8.4).

Element names: `drawer.symbol-review.row.<rep id>`, `.row.<rep id>.check`,
`drawer.symbol-review.choice.all|selected|new`.

### 6.2 Clash rules (`symbolimpact`)

A copy **clashes** when the update would:

1. remove a connection point that has a wire end attached;
2. put a wired point where another of the same page's wires or points already is (a short that
   was not drawn);
3. change a label a cross-reference or contact table names in a way that makes two of the
   device's points share a label (018's label rule).

**Not** clashes, said in the row's line: points added, unwired points removed, points moved (the
wire end follows), labels changed, graphics changed, slots moved, the body growing over other ink
(`overlaps -K03's symbol`: the row line says it; Q8).

An edited **built-in**: placed starters are rows too, unticked by default (their copies are of
the starter's lineage, not the new one: "Update all" means the project copy's lineage only), with
"Also update the 9 placed built-in copies" as a separate tick above the rows.

### 6.3 Save as a new symbol

The draft becomes version 1 of a new lineage (key required: Details asks for a new one). No copy
changes.

| `symbol.<key>.description` (new, every symbol) | text ≤ 200 | the definition's `description`; a starter's name | Standard, Project |
| `symbol.<key>.rating` (new) | text ≤ 40 | the definition's `rating`; none for starters (034 ruling holds: no value until a family needs one) | Standard, Project |
| `symbol.<key>.join` (new, project symbols only) | `device` / `part` | the definition's `join` | none (definition only) |
| `symbol.point-grid` (new) | length 1–10 mm | 5 mm | Standard, Project |

A **family entry** is one static entry whose key has the symbol's key in its middle; `defaults`
lists one line per symbol the project can place. The built-in of a family entry for a project
symbol comes from the newest version's `defaults`, and its Source reads `definition` (new
`Source::Definition`, word `definition`). Project overrides of a prefix stay in
`settings.tag_prefixes[key]` (one project path, as 034).

### 7.2 Where they are edited

- In the builder's Details: the values are the **definition's** (a new version on save).
  Each field shows its origin badge (042) when a project override hides it: "Project overrides
  this: K" with "Go to Standards".
- In Settings ▸ Standards (042): the project level, as for every entry.
- Changing a definition's default changes only new placements (devices store their own
  description and rating once placed, as today); the review's header line says so:
  `New placements use description "Float switch, high".`

## 9. Commands (part a), JSON first

Every one is one transaction (or a read), refused with writes off, recorded with its author.

### 9.1 `symbolnew`

```json
{"name": "Float switch", "key": "float1", "graphics": [<Primitive>…],
 "points": [{"key": "1", "label": "BN", "at": [0, 5]}, …],
 "slots": [{"text": "tag", "at": [-4, 0], "h": "right", "v": "middle", "rotation": 0}],
 "defaults": {"prefix": "B", "description": "Float switch", "join": "device"},
 "bridges": [], "from": null}
```

`from` (optional): a definition ID to copy from (a starter or another version), recorded in
`derived_from` for a starter. Result: `{"definition": <id>, "lineage": <id>, "version": 1}`.

### 9.2 `symboledit`

`{"definition": <id of the version edited>, …content as symbolnew…, "update": "all" |
"selected" | "none" | "new", "copies": [<representation id>…], "builtins": false}`. `none`
saves the version and updates nothing; `new` is "Save as a new symbol" (needs a new `key`).
`all` with a clashing copy is refused naming them: `2 placed copies would clash: -K03 (p. 4),
-K07 (p. 9). Use update "selected" or move their wires.`

### 9.3 `symbolimpact` (read only)

Same input as `symboledit` without `update`; returns the rows of §6.1 as data: `[{"rep", "page",
"tag", "changes": [...], "clash": null | "..."}]`. The drawer reads it; agents call it first.

### 9.4 `symbolupdate`

`{"copies": [<rep id>…] | "lineage": <id>, "to": <definition id>?}` (default: newest). Refused
when any named copy clashes.

### 9.5 `makesymbol`

`{"handles": [...] | "component": <id>, "points": [...], "slots": [...], "name", "key",
"defaults", "replace": true}`. With handles: plain geometry (refused if any item has meaning:
`Wire 24V-05 is not plain geometry; Make symbol takes lines, arcs and text.`). With `component`:
promotion of its drawn representation (§4.2).

### 9.6 Actions (041 action table, part b)

| Action | Command | Where |
| --- | --- | --- |
| `symbol.new` "New symbol" | app: open builder | Library browser header; Ctrl+K ("symbol builder", "draw symbol") |
| `symbol.edit` "Edit symbol" | app: open builder on the copy's version | **Device wheel TopLeft** (Q1: Mirror keeps key X and the selection wheel) |
| `symbol.make` "Make symbol" | app: open builder from selection or drawn component | Selection wheel **Right**; Device wheel TopLeft for a drawn-form component; Ctrl+K |

`symbolnew`, `symboledit`, `symbolimpact` and `makesymbol` are reached from the builder's Save

## 11. Update maps and cost

### 11.1 Symbol index (`symbol_index.rs`)

Holds: lineage → versions (DefinitionId, `library_seq`, keys ever used); key → lineage; definition

| Op | Does |
| --- | --- |
| `EmbedDefinition` / `RemoveDefinition` | add or drop that version; recompute that lineage's newest and key set |

## 13. Format proposals (overseer rulings, 2026-11-13)

All eight have a ruling. FP5 changed from the proposal: it is now a new op.

**FP1 Text slots.** `Definition.texts: Vec<TextSlot>` (§2.3), skipped when empty, so every
existing definition's hash is unchanged. Proposal §4.2's deferred field.

**FP2 Symbol defaults.** `Definition.defaults: BTreeMap<String, String>` (§2.4), skipped when
empty. Inside the content hash: a symbol's defaults are part of what it is, and travel with it to
a library (proposal §5.2: a library owns "default properties").

**FP3 Project-symbol origin.** One fixed `PROJECT_SYMBOLS: LibraryId`; lineage =
`origin.definition`, version = `library_seq`. No new field. Alternative rejected: `origin: None`
for project symbols (no version, no hash check, no lineage).

**FP4 `derived_from: Option<Origin>`**, skipped when none, inside the hash. LIB-04's "modified
from …". Invariant: never equal to the definition's own origin; the reader does not follow it, so
a cycle cannot loop.

*Ruling on FP1–FP4 (overseer, 2026-11-13): approved.*

**FP5 New op `SetComponentDefinition { id, before: Option<DefinitionId>, after:
Option<DefinitionId> }`.** Changes `Component.definition` and nothing else. Inverse: the same op
with `before` and `after` swapped. Apply refuses when the component is missing or its definition
is not `before` (as `holds` does). The touched set holds the component, so I9 and I14 run on it.
It needs apply, inverse, diff, merge (020), invariants and the file arms (op version 1, new name
in the v1 record), with round-trip and merge tests. Merge: a `SetProperty` on the same component
from another branch does not conflict with it. Two branches setting different `after` values
conflict, like two `ModifyItem`s of one item. History shows it as "symbol changed to v4".
Connection points are still rekeyed by `RemoveTerminal` + `AddTerminal` of one ID (036's
pattern).
*Ruling (overseer, 2026-11-13): use the new op, not the Delete + Create pair. A component carries
properties and representations, so with the pair, another branch's `SetProperty` would conflict
with the delete in a 020 merge, and history would show a delete.*

**FP6 Registry family entries.** `defaults/mod.rs` (lane T's file): an entry flag `family` and
`resolve_for(doc, entry, key, at)`; `Source::Definition`. Not a file format change; it changes the
registry contract 042's Standards screen reads, so the overseer tells lanes T and U.
*Ruling (overseer, 2026-11-13): approved. 042 is merged, so 048's worker updates the Standards
screen's reader for `Source::Definition` (badge word "definition") in the same PR.*

**FP7 One key namespace.** Starter keys win; a project symbol may not take one (refused at save).
A future starter whose key a project already uses: Place resolves the project's symbol and Find
Symbol shows both with their sources.
*Ruling (overseer, 2026-11-13): approved as written.*

**FP8 Removing superseded versions.** An update that leaves a project-symbol version with no
placed copy and not the newest removes it (`RemoveDefinition`) in the same transaction. History
keeps the content (P9). Starter versions are never removed by this brief.
*Ruling (overseer, 2026-11-13): approved; the removal happens in the updating transaction, and
history keeps the content.*

## 14. Owner questions, each with a recommendation

1. **Where does Edit symbol go on the device wheel?** All eight slots are used. **Recommend
   TopLeft** (a left slot: "change it"), moving Mirror off the device wheel; Mirror keeps key X,
   Ctrl+K and the selection wheel. A drawn-form device shows Make symbol in the same slot.
2. **Placed text the user moved**: keep its offset from the slot when the slot moves? **Recommend
   yes** (lane T's Q2 rule), so an edit never undoes a hand placement.
3. **Builder drafts survive leaving and crashes** in app storage (not the project)? **Recommend
   yes**, at most 8 per project, deleted on Save or Discard.
4. **Project symbols join as "a device of its own" or "part of a device" only**, with fixed
   labels; contact-style numbering stays for edited built-in contacts? **Recommend yes for M1.**
   Vendor symbols in the drawing pack have fixed pin names; numbered user contacts can follow if
   missed.
5. **Text slots only for the listed device texts** (tag, description, rating, part number,
   maker, article number, function, location), not any property? **Recommend yes**; free property
   slots wait for the report and label work.
6. **Point grid 5 mm by default, 2.5 mm allowed** as a registry entry (`symbol.point-grid`)?
   Wires snap to 5 mm today. **Recommend yes**; 2.5 mm suits dense vendor pin rows.
7. **Make symbol: replace the drawing on the page by default?** **Recommend yes**: the user
   selected it to turn it into a symbol.
8. **A body that grows over neighbouring ink is a note, not a clash?** **Recommend a note**:
   overlaps are fixed by moving, never lose a connection.
9. **Deleting a project symbol** (all versions, none placed) is left for 2.2's library viewer?
   **Recommend yes**; until then FP8 keeps unused old versions from piling up.
10. **Editing a built-in leaves placed built-ins alone unless ticked**, even under Update all?
