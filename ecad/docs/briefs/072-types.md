## Goal

What every stored object is, and how it relates to other objects, is held in its own typed struct,
never worked out from names, symbols, strings or positions (owner, 2026-11-16). No property bags
are left at 0.3.0 except display choices.

## The rules every lane follows (design Part I)

- Data, not inference: no predicate walks to a symbol, no name matching, no cached guesses.
- One struct per object type; kind-specific data in enum variants.
- Shared behaviour as traits; each type owns its calculations as methods; checks and reports call
  them and never recalculate.
- Relationships stored as IDs, at the level they belong.
- Strict words and validated text: an unknown word or field, or text with a hidden or bidi
  character, is a read error and the project opens read-only; the file is never changed.
- No compatibility code: fixtures and test files are regenerated by the code that made them.
- Every guard of design §13 the lane owns ends at 0 with no allowlist.
- The inspector's Raw and Readable views show every new struct, field and op (hard rule, A15).
- Every command whose input or recorded op changes keeps working through `ecad-mcp` with the brief
  011 contract test.
- The lane that renames (`Device` in B, `Wire` in D) updates `docs/glossary.md`'s "In code and
  files" paragraph in the same commit.

## Steps inside each lane

Each step is one or more commits `072<lane> <step>: …`, each green: builds, clippy clean, tests of
the crates it touched pass, every guard at or under its count. Push after each green commit.

**A1.** (1) strum, `words.rs` (flag, digits, uint, the hidden-character set), `Text<N>` and
`LongText<N>`, `units.rs`, `ConductorColour` with `colours.toml` (every form: name, 2-letter, 3-letter, display hex; design §4.6) (A1). (2) `keys.rs` (A3). (3) `Word` and its macro;
`StyleCatalogue`, `Side`, page places (A2). (4) After 070's ecad-file batch: the strict read path
(A4, A15). (5) Guards as ratchets at exact counts (in the commit message).

**A2.** One area per commit (identity and tag; book and page keys; connectivity and wiring; BOM;
rating circuit keys; revisions and designations; front; text and symbol families), then defaults,
units, small enums and `StarterKey` with its 11 exhaustive match blocks. **Stop and report** after
the first two areas so the overseer can check the pattern.

**B.** (1) The device struct, `DeviceType` with every group's struct (PLC ones empty), `ModifyDevice`,
symbols declaring their type: **merge this step** so C can start. (2) Common fields, `Text<N>`, part
lines. (3) One group per commit: Protection, Switching, Sensor, Motor, Load, Indicator,
PowerSupply, TerminalStrip, Connector: fields into the variant, trait methods implemented, readers
and commands moved, keys to `RESERVED`. (4) Roles, `SlotText`, `SymbolDefaults`. (5) User fields,
device links. (6) Predicates deleted after the oracle A7 (recorded since step 1).

**C.** (1) Stations (`PlcRack` with `RackHead`), modules, channel groups; today's CPU cards become
stations with a CPU head, head modules stations with a coupler (A11). (2) Address blocks, I/O list
and station overview as methods. (3) `PointKey::Channel`; `body_type`, `of_body`, `is_rack` go.

**D.** (1) `Wire` fields and `ModifyWire`, colours as ordered `ConductorColour` lists (F35). (2) `Cable`, cores folding
members, `ModifyCable`. (3) `Circuit`, rating and volt-drop methods; checks call them (A10). (4)
After G's wire-type step: `wire_type` with size and colour overrides (F36).

**E.** (1) `Page`/`PageKind`, `ModifyPage`. (2) `Project`, the location and function lists with
code, tag and descriptions, revisions, `ModifyProject`; pages refer by id. (3) `Folder.start`. (4)
Title block strictness.

**F.** (1) Routes and `ModifyRoute`; today's conductor drawings become routes (F31). (2) Ordered
wires: `net_order`, `order_fixed`, the proposal rule (§17 call 1), the rewrite on point changes,
hand reordering; `AttachEnd` goes (F32, A12). (3) Junction dots, T indicators and **Show wire
order** drawn from routes and order; junction components removed. (4) Drawing aids
(continuations, boxes), `Subject::Aid`, `TerminalOwner::Aid`. (5) Boxes and the `fixed` rule, the
"Symbol tied to multiple locations" check (A13). (6) Loose parts. Ends with G4, G6, G11, G12, G13
at 0.

**G.** One catalogue per commit: text, wire types (rename, `insulation`, 230 V L/N built-ins),
cable types (default core colour schemes, F37), page types, frames, locations, rating tables.

## The private colour reference (lane G)

The default core colour schemes, and a check of the 2-letter codes, come from a third-party reference in the owner's private folder;
the overseer gives the worker its path. **Never copy it into the repo, quote it, or name it or its
tables in any committed file.** Write the schemes as our own data: the colour sequences as facts in
our TOML, in our own words, with no layout or text from the source.

## Stop and ask the overseer

- A device whose new group differs from what today's predicates imply (A7).
- A field that belongs to more than one group, or a holder the design didn't list.
- A drawn form (`Form::Drawn`) that needs its starter, which the role no longer carries.
- A net whose wires can't be made a chain (a point with more than two wires today) before the
  owner's call 2 is answered.
- Any stored field, word or op not in design §11.
- A guard that can't reach 0 without a change outside the lane.

## Checks per commit

`cargo fmt --all -- --check`, `cargo xtask test-changed` (or the touched crates by name when the
workspace `Cargo.toml` changed), `cargo xtask layers`. Before each push: `cargo clippy --workspace
--all-targets --all-features -- -D warnings`. Long output to a log file under
`C:\dev\ecad-features\_tmp\072-logs`. Never the whole workspace's tests and never the slow set.
