## Summary, most important first

1. **ECAD builds and passes `cargo xtask ci` natively on Windows** (140 tests; §1), and the trial
   window opens.
   - Plain `cargo test --workspace` does not compile: a test uses a feature-gated field.
   - CI still runs ECAD only on Linux.
   - The Windows gaps below were found by reading the code. The tests that would show them are gated
     to Unix, so they did not run.
2. **Two persistence guarantees are silently absent on Windows, and the code reports success**:
   - a project file replaced behind the writer is not detected, so a Save can "succeed" into an
     orphaned file (R-S1);
   - Save As and first save report `Durability::Confirmed` without any folder flush or write-through
     (R-S2).
3. **The trial's default save folder breaks on native Windows**: `~/ecad-projects` becomes a folder
   literally named `~` when `HOME` is unset (R-S3).
4. **The rest of the foundation is in good shape.**
   - Architecture: nothing is implemented ahead of approval (no stage 3, no checkpoints, no migration
     rewriting).
   - Upstream seams: all 22 files changed outside `ecad/` are listed and marked.
   - Layering is clean, and the never-crash discipline is good.
   - The model and file format (stage 1) are well tested.
5. **The documents have drifted behind the code and the 2026-10-31 decisions.**
   - `docs/decisions.md` still names crates and a three-seam design that no longer exist.
   - The proposal still says stage 2b is "for review".
   - The WSL-only location decision (E14) conflicts with the move to native Windows.
   - The concept spec's cable, tag and encoding statements are superseded but not marked as such.
6. **The quick-start headless tests check outcomes, not what the guide tells the owner to see.**
   Selection, IDs and saves go through the API, and the guide's banner, tab and debugger strings are
   almost never asserted.

### Minor

1. `apps/ecad-trial/src/main.rs:53`: `std::env::args()` panics on a non-Unicode argument. Use
   `args_os()`.
2. `apps/ecad-trial/src/main.rs:46` and `lib.rs:62` tell users to keep projects in the Linux home
   folder.
3. `apps/ecad-trial/src/lib.rs:384-387`: the own-file check compares paths as text, so a
   case-different spelling on Windows gives a needless "replace?" prompt (harmless afterwards).
4. Stale `.tmp-*` files left by a crash are never swept. `.lock` files are kept by design; both
   replicate in synced folders.
5. A `.ecad` file converted to CRLF is refused correctly (E5), but the message does not name the
   cause. There is no repo-root `.gitattributes`, so LF relies on each clone's `core.autocrlf=false`.
6. `crates/ecad-store/tests/disk_contracts.rs:86`: `mem::forget(lock)` leaks a handle, and on Windows
   the temp folder is then never removed.
7. `xtask/src/main.rs:110-111`: the patch guard diffs `base...HEAD`, so uncommitted edits outside
   `ecad/` pass locally (CI catches them).
8. `xtask/src/main.rs:33` registers `ecad-cli`, which does not exist.
9. `MemoryMedium::flush`: `u32 += 1` could overflow in debug (test use). Use `saturating_add`.
10. `crates/ecad-model/src/derive.rs` (`nets`): union-find without path compression is quadratic on
    large nets (performance only).
11. `ecad-trial` has no `windows_subsystem` attribute, so a console window opens beside the GUI.

### What is fine

- **Architecture and approval.**
  - Library files and checkpoint records are refused on open (`crates/ecad-file/src/read.rs:219-221`).
  - The only upcast is a test-only synthetic v0.
  - The cable model (`CreateCable`, `AddCableMember`, the `cableadd` command) belongs to the approved
    model and experiment, not to the future cable brief.
- **Upstream seams.**
  - Exactly 22 files differ from `00c7613` outside `ecad/`: 7 ECAD-owned documents or CI files, and
    15 code files for X1-X8.
  - All are listed in `UPSTREAM-PATCHES.md`, all code changes carry `ECAD-SEAM(owner)`, and nothing is
    stale.
  - The seams are generic. Owner callbacks run under `catch_unwind`.
- **Layering.**
  - `ecad-model`, `ecad-store`, `ecad-file` and `ecad-inspect` have no `cadcraft-*` or UI dependency.
  - Only `ecad-cadcraft` and `ecad-trial` touch CADCraft.
- **Never-crash rules.**
  - Every crate root has the required `deny` list, and `unsafe_code` is forbidden.
  - There is no `unwrap`, `expect` or `panic!` in non-test code, apart from the feature-gated
    `fault_panic`.
  - Indexing is only on fixed-size arrays, and the reader uses `get(..)`.
  - Suggestion: also deny `clippy::indexing_slicing` to lock this in.
